01
THE FIRST QUESTION

等等，知道中心还不够？

先从一个特别普通的盒子说起。

这次先缩小问题：目标已经找到了，几何信息也有了，夹爪怎么抓由人来规定。 暂时不用考虑让模型自己想抓法，只想把一个 Grasp Pose 算准确。

最容易想到的是物体中心。比如我要从一个长方形盒子的两侧夹起来，先找到中心，再把夹爪移过去，听起来好像就差不多了。

举个简单的例子：从长方形盒子的两侧夹起它。
绿色是目标盒子 · 棕色示意夹持方向 · 两幅图的中心点相同

但盒子只要在桌上转一下，中心可能一点没动，夹爪的方向却必须跟着变。要是盒子还倾斜了，问题就更多。

这时我才意识到，真正想知道的不是孤零零的一个点，而是：怎样让预先规定的抓取位置和方向，跟随物体在场景里的姿态变化？

这次真正想清楚的问题

需要一份能放置抓取姿态的空间参考关系。

找到物体中心只能解决部分位置问题；要按照规定的方式抓，还需要知道物体的方向，或者能把已有参考坐标系变换到现场。

02
THE TURNING POINT

那么，这份参考从哪里来？

两条路线不是突然冒出来的，而是来自一个很简单的判断。

既然抓取规则已经定义好，接下来就需要一个能描述这套规则的参考系，并弄清它在当前场景中的位置和方向。这样，规则才能被搬到真实物体上。

人工规定抓取关系相对参考系，夹爪应该怎么放
→
确定参考系在现场的位置位置与方向从哪里获得？
→
换算成 Grasp Pose得到当前相机坐标系下的抓取姿态

问题就变成了：这个参考系，是根据眼前的几何临时建立，还是有一个现成的模型可以拿来对齐？

顺着参考关系的来源，我把方法整理成两条路。

PATH A / CONSTRUCT

直接从几何结构构造参考系

没有适用的完整模板，就从当前点云中的位置、轴线、平面等结构寻找稳定的参考。

看看怎么构造 → PATH B / ALIGN

利用已知参考几何进行位姿对齐

如果已经有模板和定义好的抓取关系，就去估计它与眼前物体之间的空间变换。

看看怎么对齐 →

这是按照“抓取参考从哪里来”整理出的两条主思路，不是整个位姿估计领域的官方分类，也不意味着二者互斥。

03
PATH A · CONSTRUCT

从眼前的形状里，找一个方向

没有现成模板，当前点云本身能告诉我们什么？

假设眼前就是一份已经分离好的目标点云。它告诉我们物体的表面在哪里，但不会自动附带一个“正确”的物体坐标系。因此，这条路要做的，是找到足够支持抓取规则的几何结构，再约定怎样用它放置夹爪。

目标点云→提取几何结构→约定局部参考系→应用抓取规则
先处理位置

放在哪里？

如果接近方向已经固定，先根据目标范围、中心或其他几何位置确定抓取中心。

质心 · 包围盒 · 几何中心
再处理方向

朝哪个方向？

物体转动后，需要主轴或局部表面方向：比如盒子的长轴、平面的法线、圆柱的轴线。

PCA / OBB · 法线 · 平面 / 圆柱拟合
最后处理可靠性

点云不太干净呢？

缺失、噪声和离群点会影响几何估计。可借助稳健拟合与一致性检查，让方向更可靠。

RANSAC · 稳健估计 · 几何约束

对刚才的盒子，可以先用 PCA / OBB 找主方向，再按照事先规定的夹持关系摆放夹爪。换成有明确表面或轴线的物体，则可能用平面、法线或圆柱拟合更合适。这些不是固定的逐级升级关系，而是看物体提供了什么几何约束。

这条路容易踩的坑：主轴可能有正负歧义；对称物体的某些旋转本来就无法仅凭形状确定；一根轴或一个法线通常也不足以唯一确定完整 3D 姿态。RANSAC 是稳健拟合工具，而不是自动生成抓取姿态的算法。必要时还得结合桌面方向、夹爪约束等补足自由度。
04
PATH B · ALIGN

如果已经有参考，就把它对过来

不必每次都从现场点云重新猜一套物体方向。

另一种情况是：我本来就有一个物体的参考模型，也已经在那个模型上定义好抓取姿态。

那就没必要每次从几何主轴重新“发明”一个参考。只要知道参考模型怎样移动、旋转，才能与眼前的物体对上，模型上的抓取姿态也就能跟着搬过来。

参考模型抓取关系已标好
+
现场观测求模型到场景的变换
→
现场 Grasp Pose

这时，难点变成了两边有什么可用的对应信息。这也是为什么 PnP、Kabsch 和 ICP 虽然看起来不一样，却能出现在同一张方法地图上。

3D–3D 点已对应Kabsch / Horn / Umeyama

如果知道参考模型上的几个点分别对应现场哪些三维点，就可以直接估计刚体旋转和平移。

3D–3D 点云未对应ICP / GICP · FPFH + RANSAC

如果只有两份几何、没有逐点匹配，需要先建立或迭代寻找对应。粗配准帮助找初值，ICP 类方法做局部细化。

3D–2D 对应PnP / IPPE

如果手上还保留着图像，能找到已知模型三维点在图像上的二维对应位置，就可以通过投影关系求物体位姿。

为什么这里会出现 PnP？ 它本身是几何位姿求解方法，但需要额外的图像观测与 3D–2D 对应点。当前只有点云时，不会凭空得到这些对应。这部分可与 Route 1.2 的视觉约束获取结合起来。
这条路容易踩的坑：模板与实物几何差异太大，迁移的抓取关系就可能不适用；ICP 类局部配准对初值敏感；遮挡、重复结构和对称性也可能导致多个相似的对齐结果。求出物体位姿，不等于抓取一定可执行。
05
WHAT I KEEP

现在回头看，思路清楚多了

不用记住一串算法名，记住方法为什么出现就好。

起初我只是想从点云算一个 Grasp Pose，后来发现要先决定抓取关系依附于什么参考。这一点想通，两条路就很自然地分开了。

① 现场构造

有当前几何，没有合适模板。
从中心、轴线、平面等可观测结构定义局部参考，再应用人工抓取规则。

留意：方向歧义、几何缺失、噪声和约束不足。

② 参考对齐

有可用参考模型和对应的抓取关系。
估计参考模型到当前场景的空间变换，再迁移抓取姿态。

留意：模型适用性、匹配质量、遮挡和初值。

这两种办法不必非选一个：现场提取平面和法线可以帮助模板配准；配准完成后也可以用实际点云检查夹爪碰撞。它们都是在落实已知抓取规则，而不是让模型自主决定应该抓哪里。

年份方法它试图解决什么？优势与留下的局限资料

1992ICP没有显式逐点对应，如何迭代对齐两份形状？局部精配准经典；初值不好易落入局部最优。论文 ↗
2009EPnP3D–2D 对应较多时，如何高效估计位姿？计算效率高；对应误差、退化情形需额外处理。论文 ↗
