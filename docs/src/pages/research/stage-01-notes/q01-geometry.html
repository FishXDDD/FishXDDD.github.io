STAGE 01 · Q01 / POINT CLOUD GEOMETRY

原来点云里，
藏着这么多几何线索。

最早想做抓取时，我的想法其实挺简单的：深度相机不是已经看到了物体吗？既然能得到三维点云，能不能直接从里面量出位置和方向，再把夹爪放过去？

2026.10 · 研究随手记RGB-D / 几何测量 / Grasp Pose从一个很朴素的想法开始
起点 / 当时的直觉

先不想复杂的，看看点云里到底有什么。

脑子里最先出现的是一个很直接的画面：相机对着桌上的瓶子或盒子，能看到它的表面。那我应该能知道它在哪里，甚至估计一下它是横着放还是竖着放。

一开始我并没有什么完整的算法路线。只是觉得，如果夹爪要落在一个三维位置上，那么先从点云里把这个位置量出来，听起来就很合理。

最开始记下的一句话

我想要的并不是“把点云解释得多漂亮”，而是能不能直接从这堆点里找到夹爪摆放的依据。光是想到这件事可以从几何入手，就挺想继续往下看。

往下看 / 第一件有趣的事

深度图里的每个有效像素，原来都能对应到空间中的一个点。

RGB 图像告诉我物体出现在哪个像素，深度给出那个像素对应的距离；再配合相机内参，就能反投影到三维空间。把目标区域里的有效深度点取出来，就有了一团属于目标的点云。

这件事本身其实已经很有用了。以前图像里的“中心”只是一个二维位置，现在我可以讨论它的三维坐标、空间范围、高度、两点间的距离。抓取问题第一次有了能直接测量的东西。

第一个小发现：点云不是一堆需要先“识别”的数据。它本身就是空间测量结果。只要目标区域和深度可靠，我已经可以在相机坐标系里选出抓取参考点了。

顺手也理解了“质心”这类最简单的方法：把观测到的点作统计平均，能得到一个大致位置；但如果只看见瓶子朝向相机的半边，它就是可见点的中心，不一定是整个物体的中心。这个区别以后肯定得记着。

翻资料时 / 发现了一个特别巧的想法

原来一团没有顺序的点，也能自己显露出方向。

位置有了之后，我自然会好奇：物体是往哪个方向延伸的？例如一根横放的瓶子，看起来明显“长”在某个方向上，能不能直接从点坐标里看出来？

这时看到 PCA（主成分分析），感觉思路很漂亮：不必先知道瓶子、纸盒分别是什么类别，只要统计这一团点往各个方向分散得有多厉害，就能找出它最主要的延伸方向。原来统计方法也能用来理解三维形状。

PCA · 从点的分布里找方向认识笔记 / 不是实现教程

核心想法：寻找点云变化最显著的方向，把它当作整体形状的参考轴。

它测到的是观测点的分布方向。如果物体近似对称、只露出一面，或者深度点特别不均匀，主轴并不保证就是我们心目中的物体朝向。

顺着主方向再看 OBB（有向包围盒），就更容易有画面感了：既然有了大致朝向，能不能沿着这些方向给点云套一个盒子，估计它占多大空间、长宽高大致如何？这样不仅能看方向，还能开始量尺寸。

我很喜欢这个思路，它把抽象的点分布变成了一件很直观的东西。不过也得分清：PCA 是估计方向的一种方法，OBB 是几何包围表达；基于 PCA 的 OBB 通常只是近似包围盒，不等于真正的最小体积 OBB，更不等于抓取姿态。

顺手记一下：PCA 和 OBB 不是两个按顺序升级的“抓取算法”。前者帮助找参考轴，后者帮助看空间占据与尺寸。这是同一份点云能提供的两类测量结果。
再往里看 / 视线不再只盯着整个物体

更惊喜的是，一小块表面也能量出自己的方向。

看着那些点云方法，我慢慢发现：如果我想让夹爪接近物体侧面，未必需要先搞清整团点云的主轴。我更想知道的是眼前这块表面朝哪里。

这时就碰到了表面法线。取一个点附近的小片邻域，把它近似成平面，就能估计垂直于这片表面的方向。和 PCA 求整体主轴很不一样：它不是在概括整团物体，而是在测量一个局部位置的几何朝向。

后来才注意到一个挺有意思的联系：局部法线也可以通过邻域点的 PCA 来估计，只不过这次关心的是变化最小的方向。同样是分析点的分布，尺度一变，回答的问题就变了。

看整体点云

PCA / 主方向

一团点主要往哪里延伸？适合观察物体的大致姿态或长短方向。

看局部邻域

Normal / 表面法线

这一小片表面朝哪里？适合构造接触区域附近的方向参考。

而当目标上有一大片相对规则的平面，比如纸盒的一面，甚至可以直接拟合一个平面方程，从而得到整个平面的法线和位置。点云里有一点噪声、混进了一些背景点，也不是完全没办法——查资料时就顺便认识了 RANSAC。

RANSAC · 原来可以在杂点里找出靠谱的几何结构发现 / 鲁棒拟合

核心想法：反复抽取少量点提出模型，再看看有多少点支持它，寻找共识较强的几何结构。

这里的 RANSAC 不是另一种抓取姿态算法；它是帮忙稳健拟合平面、圆柱等模型的通用思路。模型假设如果本来就不合适，采样再多也解决不了根本问题。

当时挺开心的一点是：原来点云不只是“有多少点”，它还在告诉我接触表面的朝向，甚至能把一部分杂点排除出去。

又发现 / 形状本身还可以提供更多约束

如果它长得像个圆柱，就能量出更多东西了。

想到瓶子时，我又发现只看主轴或一小块表面似乎有点浪费：它的瓶身本来就接近圆柱，那为什么不试着把这个几何形状拟合出来？

这就认识了几何基元拟合（Primitive Fitting）。不去恢复复杂形状，而是寻找平面、圆柱等简单几何结构：拟合圆柱时可以得到轴线和半径，拟合平面时可以得到朝向和偏移。只要形状假设成立，这些信息比一个孤零零的点或方向丰富得多。

规则盒面

Plane fitting

量到一个面的位置和法线，就有了更明确的表面参考。

瓶身或管体

Cylinder fitting

量到轴线、半径等参数，就更容易估计圆柱状物体的几何中心与尺度。

当然，点云是相机看见的那一部分，不会因为用了拟合算法就自动补齐背面。尤其圆柱只剩很窄的一段弧面、瓶子被压扁、物体严重遮挡时，参数就可能不稳定。

但这反而让我更清楚了这条路线的意思：几何测量不是只选一个最厉害的算法，而是看眼前有没有值得利用的结构。 有长轴就量长轴，有接触表面就量法线，有明显的规则形状就尝试拟合。它们完全可以一起提供信息。

回到最初的问题 / 这些东西怎么用来抓？

原来离 Grasp Pose 已经不远了，不过还得再拼一块。

学到这里，我开始能把前面的几何量和夹爪联系起来了：位置可以从三维点或拟合的几何中心来，方向可以参考主轴、表面法线、平面或圆柱轴，尺寸也可以从包围范围或拟合参数估计。

但也终于理解：一个点、一根轴、一条法线，都不等于完整的 6DoF Grasp Pose。 夹爪还需要决定从哪边接近、手指沿哪边闭合，以及最终放在哪个位置。几何提供参考，具体抓法提供尚缺的约束；把这些方向组织成正交的夹爪坐标系，才是最终要输出的 Pose。

不是点云自己“猜出怎么抓”，而是从现场量到的线索里，构造一个有依据的抓取姿态。

拿侧面夹取瓶子作个脑内例子：圆柱轴线可以提供瓶身方向；局部表面或圆柱几何可以给出侧面的参考；再结合预定的接近方向和夹爪约束，才有机会构造出合理的候选姿态。这件事并不需要先把瓶子的每一处表面都解释清楚。

到这里最开心的收获：我最开始只是觉得“有点云总能量点什么”。现在至少看懂了一整条思路：从三维测量，到寻找几何线索，再到用线索约束夹爪姿态。

翻完资料 / 给自己留一页短短的备忘

这次真正认识的几件几何工具。

不写公式，也不急着把它们展开成教程。先留下每个方法最值得记住的核心思想。等真正需要实现或验证时，再单独记细节。

反投影 · Back-projection

结合深度与内参，从像素得到相机坐标系下的 XYZ。它让测量真正发生在三维空间。

质心 / 空间范围

用点坐标统计位置、距离和占据范围。注意观测中心不一定是物体真实中心。

PCA · 主成分分析

看点云沿不同方向的分散程度，找整体主轴。主轴是统计结果，不是抓取指令。

OBB · 有向包围盒

沿某组方向包住点云，估计大致占据与尺度。PCA-OBB 并非最小体积 OBB。

Normal / Plane

从邻域或一组平面点测量表面方向。对局部尺度、深度噪声和遮挡敏感。

RANSAC / Primitive fitting

稳健寻找平面、圆柱等几何结构，估计轴线和参数。前提是形状假设确实靠谱。

写在页尾 / Q01 暂时先记到这里

原来“直接用点云求抓取”，真的不是一句空话。

从一个像素的三维位置，到一团点的主方向；从局部表面法线，到能拟合出轴线和尺寸的简单几何体……几何里原来藏着这么多可以拿来用的东西。

我现在对这条路线的认识是：先弄清楚能从现场稳定测到什么，再想这些测量能为夹爪提供哪些约束。 不同算法没有必要排成一条谁替代谁的队伍，它们更像是一盒各有用途的测量工具。

下一次真正动手时，最想观察的反而很简单：点云只露出一半、形状有变化、深度出现缺口时，自己依赖的几何量还稳不稳？这部分就留给后面的实践记录。

至少今天的收获已经足够有意思了：原来一团点，也能一步步量出抓取的方向感。 ☺
