STAGE 01 · 关于抓取 Pose 的一点笔记

抓法定好了，
Pose 怎么算？

先约定好“怎么抓”，再看看抓手到底该放在哪儿。一开始只想着算几何，后来又补上视觉，也慢慢发现学习式方法不必照着固定流程走。这里先理清问题、方法和适用场景，具体怎么实现以后再细看。

先看场景，再选方法边走边想单次抓取 · RGB-D · 两指夹爪
01

先说清，这次固定了什么？

之前的写法让我误以为：既然抓法由人规定，那 Pose 也只能由几何公式来求。其实这是两件完全不同的事。

STAGE 01 · 这次先固定

抓取策略 / 任务约束

例如“从瓶身侧面夹”，或“沿盒子的短边方向夹”。可以指定抓取区域、接近方向、夹爪开度范围；不需要模型自主发明另一种抓法。

人决定：怎么抓
STAGE 01 · 允许探索

空间信息与 Pose 的求解方法

目标在哪里？轴线朝向哪里？如何从图像与点云找到稳定参考？可以用拟合、配准、学习关键点、类别位姿估计，或训练受约束的直接 Pose 预测。

算法解决：抓手具体放哪里

重新划边界：Stage 01 不等于“传统算法阶段”；它是“抓取决策已确定”的阶段。Stage 02 才进一步放开“抓哪里、从哪里接近、怎样生成候选”的决策权。

02

两件事，是怎么被我接起来的？

不是先设计好一套流程才开始研究的。最初只想着怎么算 Pose，后来补上“怎么看到目标”，再后来又发现，学习式方法不一定沿着我画的箭头走。

所以这张地图先不急着罗列算法。它只记下我为什么开始研究视觉，又为什么不能把视觉简单地叫作“几何的辅助”。接下来顺着这思路修正，把没想明白的问题一件件追下去。

03

然后，我就一路想到了这里

不是先列好几个方法，再把它们连成一条线。更像是试着解决一个问题，发现遗漏了什么，然后又往下多想了一点。

下面按我理解问题的顺序来写，不是算法的历史演进顺序。每一段都留下当时觉得它好用在哪里、后来又发现哪里不够。一个方法可以在很多问题里反复出现，它不会因为出现得早就失去价值。

先说一个贯穿全篇的前提

技术本身没有被后来的技术“淘汰”。几何明确、测量可靠时，传统方法完全可能更准、更稳、更省成本；模型已知时，模板配准也值得一直用。学习式方法扩大了可处理的场景，但仍有训练分布、误差与计算开销的限制。我在意的是条件与边界，不是谁更新。

01
第一段 · 从 Pose 开始

先拿几何试一试，后来又想到模板

我最先关心的是“怎么算 Pose”。当时一切都从已经有目标点云开始，顺着现场几何和已知参考两种思路往下走。

想法 01先从最熟悉的办法试试

既然有点云，能不能直接把抓取方向算出来？

刚开始我把「已经拿到目标点云」当成前提。瓶子大致是圆柱，盒子有平面和边，似乎用主轴、法线或形状拟合，就能构造夹爪的中心和方向。再仔细想才发现：求得一根轴线，不一定就得到了唯一的 6DoF Pose；还要看预定抓法到底约束了哪些自由度。

顺手记下的办法PCA / OBB、法线、RANSAC、圆柱与平面拟合、局部抓取坐标系

什么时候很好用

目标形状规律、几何可见、规则清楚时，计算轻、可解释；测量与标定可靠时，精度可以很好。

换个条件就要小心

遮挡、点云缺失、对称性或大变形时，几何参考可能不唯一，也可能估错。

这件事其实还能继续往里拆

主轴、法线和形状拟合，各自能约束 Pose 的哪些自由度？什么时候只需局部参考，不必求完整 Object Pose？

于是又想到 → 要是我本来就知道物体的形状，何必每次只凭这一小片点云猜？
想法 02再把已知信息利用起来

如果物体有 CAD 或模板，是不是更省事？

对已知瓶子、盒体或固定工件，与其从局部几何猜位置，不如把现场观测和参考模型对齐。只要得到物体相对相机的变换，模板上预先规定的抓取位姿就能直接变到相机坐标系。可是：参考模型、对应关系和初始位姿，又不是自动存在的。

顺手记下的办法2D–3D 对应 / PnP、3D–3D 刚体对齐、PPF 粗匹配、ICP / GICP 细配准

什么时候很好用

已知且形态稳定的对象可以复用同一套参考；匹配可靠时，定位精度和工程可控性都不错。

换个条件就要小心

依赖参考准确性与足够观测；遮挡、重复纹理、对称性、变形会让匹配困难或产生歧义。

这件事其实还能继续往里拆

CAD、参考点云和参考图像应该怎么分？为什么有的先全局找对应，有的必须先有较好的初值？

往里看看 ↗
于是又想到 → 等等，我一直在假设已经拿到「目标点云」了。可是现场相机看到的明明是一整幅图。
第一次回头看：我懂了怎么利用点云，却忘了问「这份点云从哪里来」。
02
第二段 · 补上视觉

原来目标数据，还得自己从相机里找

做了 Pose 才发现，真实输入是整幅场景：先在 2D 里找到目标，再借助深度把像素变成空间信息。

想法 03第一次发现前提没补齐

我得先在图像里找到要抓的东西吧？

到了真实场景才意识到：不能一直假设目标已经被单独取出来。相机看到的是地面、杂物和目标混在一起的画面。先从 2D 入手比较直观：检测告诉我大概在哪，Mask 能给出更细的范围，语义 Grounding 还能利用任务描述指定目标。

顺手记下的办法2D Detection、BBOX、Instance Segmentation / Mask、Grounding

什么时候很好用

RGB 里有丰富的外观和语义信息；定位入口灵活，通常也更方便和上层任务对接。

换个条件就要小心

2D 定位不等于三维姿态；Mask 边界可能不准，也不是所有 Pose 方法都需要 Mask。

这件事其实还能继续往里拆

BBOX 与 Mask 到底分别够做什么？什么时候该用语义 Grounding，什么时候连 2D 检测都可以省略？

往里看看 ↗
于是又想到 → 图像里找到了目标，但它还是像素位置。机器人要的是以米为单位的空间 Pose。
想法 04图像找到之后，空间在哪？

2D 已经找到了，怎样把它放回 3D？

这时才把 RGB、Depth 和相机内参真正连起来：先确认颜色与深度对应，再把有效深度像素反投影成三维点。根据任务，可以只用中心的深度、从 ROI 取点，也可以借助 Mask 得到更干净的目标点云。从这里开始，2D 的目标信息终于能参与 3D 几何求解。

顺手记下的办法RGB-D 对齐、内参 K、深度尺度、反投影、ROI / Mask 到目标点云

什么时候很好用

把语义/区域信息与有尺度的空间测量接在一起，后续就能算中心、法线、轴线和夹爪 Pose。

换个条件就要小心

反光、薄片、贴地物体、深度孔洞和 RGB-D 错位都会把误差传到 Pose；不是每个网络都显式生成点云。

这件事其实还能继续往里拆

一个像素加深度能得到什么？BBOX/Mask 怎样对应到深度？什么时候保留 Depth 图，比提前转成点云更合适？

往里看看 ↗
于是又想到 → 现在从找目标、取深度到求 Pose 都接上了。先回头看看：这套办法究竟在哪些时候会出问题？
第二次回头看：视觉和几何终于接上了。先别急着换模型，看看这条路还有什么前提。
03
第三段 · 再换个思路

Pose 是有了，再回头看看哪里不够

这次没有急着再找一个新算法。先看看已有做法是在哪些条件下好用、在哪些条件下会失效，才知道接下来值得学什么。

↶
走到这里，先回头看看 · 不单独算一个问题

Pose 终于算出来了，但好像还不能到处用。

把 2D、Depth、几何或模板接起来后，在规整瓶子、已知工件上，这套办法可以很准确、也很好解释。可一换成被压扁的盒子、变形的袋子，原来假设存在的“主轴”“稳定表面”或“参考模型”可能就不合适了。不是几何不好，而是我该先弄清楚，到底是哪一个前提没满足。

可能是看错了

目标没找准，Depth 缺失或错位；先解决观测问题。

也可能是算不稳

主轴含糊、匹配歧义、变形太大；需要换空间参考或求解思路。

甚至不是 Pose 的问题

原本预定的抓法不适合这个形状；那就已经接近下一阶段了。

所以我不急着说“几何不够先进”。形状规律、测量可靠时，规则法可能更准、更轻、更可控。 只是我也想知道：遇到很难手写规则的空间结构，能不能换一种表达方法？

想法 05换个角度看空间线索

有些特征不好手写，能不能让模型来学？

以前我会先规定“找主轴”“拟合平面”或“和模板匹配”。可是遇到形态变化大的物体，也许不是我要换一个更复杂的阈值，而是让模型从数据里学出有用的空间线索。 它可以学关键点、对应关系、类别共同的空间参考，也可以直接估计 Object Pose；几何求解仍然可以接在后面。

顺手记下的办法学习关键点 / 对应关系、学习初始化 + 几何细化、类别级空间参考（如 NOCS）、学习式 Object Pose

什么时候值得试

外观与局部形状变化较多、手工特征难稳定描述，而且有合适的数据与训练条件时，可以减少逐类制定规则的工作。

换个条件就要小心

学习到的先验仍有训练分布边界；难例、对称性和严重变形不会自动消失，标注与计算也有成本。

往里面看，原来并不是只有一种“学习 Pose”

网络究竟要学什么：关键点、对应关系、类别坐标，还是完整位姿？哪种还依赖实例 CAD，哪种能跨实例？为什么这些方法不该硬排成一条升级路线？

往里看看 ↗
再往下想 → 不过我绕了一圈一直在研究 Object Pose。我的目标只是把夹爪放对，真的每次都需要完整物体位姿吗？
想法 06最后又回到抓取这个任务

我只想摆好夹爪，能不能直接求 Grasp Pose？

模板已知时，先得到 Object Pose，再换算抓取位姿很自然。但要是物体没办法定义一个稳定的完整姿态，而抓取方式又已经规定好了，也许直接估计夹爪中心、方向和开度就足够。 这种输出可以由规则构造，也可以从 RGB-D / 点云学习；它不必经过一个显式的 Object Pose。

顺手记下的办法局部抓取参考、2.5D / 平面抓取预测、受规则条件约束的 6DoF Grasp Pose、几何校验

什么时候值得试

完整物体姿态没有必要或难以定义，而任务只关心规定接近方向、夹爪位置和开度时，可以省掉不必要的中间目标。

换个条件就要小心

直接回归也需要符合抓取策略、夹爪尺寸与局部碰撞要求；训练模型不意味着自动知道物体能不能抓稳。

这也能继续往里分

只从上方夹的 2.5D 与任意接近方向的 6DoF，究竟约束了哪些自由度？“模型直接给抓取候选”和“按规定抓法求 Pose”边界在哪？

往里看看 ↗
最后还留了个问题 → 如果连“怎么抓”也不能提前规定，只给出一个位置与方向就不够了吧？

一路看下来，问题不是从几何“升级”到学习，而是我不断发现前一种办法依赖什么条件。条件满足，就继续用；条件不满足，再找另一种可行的空间参考或 Pose 求解方式。

04

写到这里，暂时有了几条认识

先不急着宣布答案。记录一下，现在觉得哪些判断最值得保留。

关于规则与精度

前提清楚时，几何一点也不落后

规则明确、深度可靠、几何稳定时，求解结果可解释、精度潜力高。难点不是技术老，而是场景超出了它的前提。

关于视觉

2D 可以找目标，却不等于 3D Pose

有时要 Mask，有时 BBOX、点云聚类或学习特征就够。只有弄清空间信息如何进入求解，才算把链条接上。

关于学习

学习的是不同信息，不是一条必走的升级路线

学关键点、对应关系、类别参考或直接估计位姿，解决的前提不同。几何可以和学习结合，结果也都应结合场景检查。

关于最终选择

先分清哪一环出了问题

感知不准、Pose 不稳、抓法本身不适合，是三个不同问题；选方法前先弄清属于哪一种。

05

还有个问题，先记下来

如果一直规定从瓶身侧面夹，那 Pose 算准就有意义。但遇到被踩扁的盒子、卷曲的广告纸，这条规定未必还成立。

下一问 · STAGE 02

如果连“怎么抓”也不能提前规定呢？

这时问题不再只是估计空间关系，而是要从可用的接触区域和接近方式中生成、比较抓取候选。算 Pose 的知识依旧有用，只是它不再承担全部决策。

这次的边界先停在这里。先把预定抓法对应的 Pose 研究清楚，再走向“选择抓法”；碰撞、夹爪尺寸等局部约束仍需考虑，完整运动规划留给执行层。
