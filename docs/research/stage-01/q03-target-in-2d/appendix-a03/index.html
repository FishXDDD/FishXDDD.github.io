00
TECHNICAL ATLAS / 总览

从“找目标”到“怎样组织预测”

A01 把单幅图像转成区域和几何特征，A02 通过参考外观寻找同一实例。A03 则换了一种前提：目标类别来自训练数据，不要求为现场每个物体准备参考照片。 这条路线研究的是如何同时学习“是什么”和“在哪里”。

目标检测的主要输出通常是类别、置信度与 BBOX。有些模型扩展到 OBB、Mask、Keypoints，但那些属于不同的结构化输出任务，不能直接等同于普通 BBOX 检测。

初看检测模型很多：R-CNN、YOLO、SSD、RetinaNet、FCOS、DETR……但如果只按名字或年份排序，就会错过真正关键的设计区别。先把下面几个彼此交叉的维度分清。

PARADIGM 01Two-stage显式候选区域与 ROI 精化
PARADIGM 02One-stage / Dense特征图上直接预测大量候选
PARADIGM 03Query-based / Set一组查询负责输出目标集合
CROSS-CUTTINGFPN / Multi-scale让不同尺寸目标有合适的特征
CROSS-CUTTINGAssignment / Loss哪些预测被训练成目标、怎样算误差
INFERENCENMS / NMS-free如何处理重复预测与推理成本
这一页的研究方式

按求解机制认识架构，在每条路线中挑有代表性的节点。一个模型改进了计算效率，不表示它在所有观测条件下都替代旧模型；模型间的基准分数也不能离开数据集、输入尺寸和硬件讨论。

01
HISTORICAL FOUNDATIONS / 早期检测

深度学习之前：检测器已经有完整的设计思想

目标检测不是 CNN 出现以后才有的。更早的研究已经在考虑特征表示、滑动窗口、模型组件、候选搜索和运算效率。了解这段历史的意义，不是回去逐一实现旧方法，而是看清后来深度检测继承了哪些问题。

2001历史里程碑

Viola–Jones · 级联式快速人脸检测 原论文 ↗

利用积分图加速 Haar-like 特征计算，并通过级联分类器尽早排除大量容易判断的背景窗口，形成经典的实时检测体系。

条件 / 边界 高度依赖训练任务的形态与特征分布；多类复杂目标、强姿态变化需要更多适配。
2005经典特征

HOG · 方向梯度直方图 原论文 ↗

用局部梯度方向统计表达图像形状，配合分类器进行行人等目标检测；体现了“特征设计 + 分类器”的成熟思路。

条件 / 边界 手工特征依赖观测尺度与外观条件；复杂类别内形变和遮挡不能只靠梯度表示解决。
2008 / 2010经典结构模型

DPM · 可变形部件模型 原论文 ↗

使用根模型与部件模型表示目标外观及其空间关系，允许部件发生一定程度的相对形变。

条件 / 边界 依赖预先定义的部件与几何关系，训练和推理流程较复杂；并不直接支持开放类别泛化。

这几条路线不是 CNN 检测的“错误前身”。它们对应过不同阶段的硬件条件与建模能力，而级联筛选、局部特征和可变形表示等想法，在后来的系统设计中仍有影响。

真正发生的转变

早期检测器依赖显式设计的特征和结构。深度检测的一个重要变化，是由数据学习更强的视觉表示，再让定位与分类在统一框架中优化。

02
REGION-BASED / 两阶段检测

R-CNN 家族：候选区域不是负担，而是一种设计选择

R-CNN 的重要思想很清楚：先找到可能包含目标的区域，再用 CNN 提取特征、分类并回归边界框。这个方向后来连续出现了几次有意义的结构改进，主要是在降低重复计算和简化候选生成。

2014核心节点

R-CNN · 候选区域 + CNN 特征 原论文 ↗

使用 Selective Search 等外部候选区域方法提出目标区域，再为每个 ROI 进行 CNN 特征提取，最后分类和边界框回归。

条件 / 边界 逐候选计算特征造成大量重复；候选区域本身需要独立算法生成，训练流程也较繁琐。
2015核心节点

Fast R-CNN · 共享整图卷积特征 原论文 ↗

先对整张图像提取卷积特征，再通过 ROI Pooling 获得候选区域特征，将分类与回归更紧密地联合训练。

条件 / 边界 共享特征减少了重复计算，但候选框仍主要由网络外部产生；候选生成因此逐渐成为瓶颈。
2015核心节点

Faster R-CNN · 学习候选区域 原论文 ↗

引入 Region Proposal Network（RPN），与检测网络共享特征，使候选区域生成也进入学习框架。

条件 / 边界 保留显式候选与 ROI 处理链路，其成本取决于候选数量、网络与加速实现；不保证始终慢于单阶段模型。
2018后续重要发展

Cascade R-CNN · 逐级提高定位质量 原论文 ↗

使用级联检测器与逐级提高的 IoU 标准，使后续阶段聚焦更高质量的目标框回归。

条件 / 边界 需要更多级联计算与合适的训练分配；高质量候选有意义，但不是任何任务都需要这种复杂度。

从 R-CNN 到 Faster R-CNN，研究并没有否定“两阶段”的逻辑，而是在保留候选筛选能力的同时，让特征共享和候选生成变得更高效。Cascade R-CNN 则在定位质量上进一步深入。

这里不是速度排行榜

Two-stage 的优势不是“天然精准”，而是能够显式地给候选区域配置进一步的特征计算与精化。是否值得付出这些成本，要看目标密度、定位要求、硬件和实现。

03
DENSE PREDICTION / 单阶段检测

YOLO、SSD、RetinaNet：把候选预测放回整张图像

如果不经过显式的 ROI 级精化，能否直接在图像特征上预测目标的位置和类别？One-stage Detection 沿着这个方向形成了另一条成熟路线。要理解它的演进，不能只看 YOLO 的版本号，还需要看它怎样处理多尺度与大量背景候选。

2016核心节点

YOLO · 直接预测类别与位置 原论文 ↗

经典 YOLO 将检测组织为单个网络的直接回归式预测，展示了端到端训练与实时推理的潜力；与逐 ROI 处理的路线形成明显对照。

条件 / 边界 早期方案在小目标、定位精度与拥挤目标方面存在局限；后续 YOLO 家族内部架构变化很大，不能视作完全相同的预测机制。
2016核心节点

SSD · 多尺度特征图上的密集候选 原论文 ↗

在不同尺度的特征图上使用默认框进行目标预测，使不同大小的目标有各自的预测位置与尺度设置。

条件 / 边界 依赖 default boxes、特征尺度与训练分配；小目标表现也受到高分辨率特征质量的限制。
2017核心节点

RetinaNet / Focal Loss · 大量简单负样本怎么处理 原论文 ↗

将前景与背景样本不平衡作为密集检测的核心训练问题，用 Focal Loss 降低容易分类样本的权重；RetinaNet 验证了这一机制。

条件 / 边界 Focal Loss 主要调整优化权重，并不能直接修复漏标、类别语义混乱或定位标注偏差。

为什么“一阶段”不等于“完全没有后处理”？

传统密集检测通常从许多位置输出候选框。不同位置可能反复预测同一个物体，于是需要通过置信度筛选与 NMS 等方式去重。One-stage 只是在描述候选预测和 ROI 处理方式，并不自动意味着 NMS-free。

Focal Loss · 关注难样本的训练目标（简化式）FL(pₜ) = −αₜ (1 − pₜ)ᵞ log(pₜ)当样本很容易分类、pₜ 较大时，(1 − pₜ)ᵞ 会降低该样本的损失权重；γ 和 α 的选择取决于任务和训练配置。

这里也能看到算法发展的另一面：没有必要每次都重新设计整个网络。调整训练目标和样本权重，也可能让已有架构得到明显改善。

04
GENERAL TECHNIQUES / 跨架构工具

真正反复被解决的问题：多尺度、样本分配和框回归

检测模型换了很多名字，但有几项问题不断出现：目标大小差异很大、训练时哪些候选算正样本、框坐标如何优化、重复预测怎样去掉。这些更像目标检测的共同工具箱，不属于某一个模型品牌。

2017跨架构里程碑

FPN · 让高层语义与细粒度空间信息结合 原论文 ↗

自顶向下路径和横向连接，将较强语义信息传递到更高分辨率的特征层，使多尺度检测有了高效的通用特征结构。

条件 / 边界 小目标所需细节如果在输入采样阶段已经丢失，仅靠 FPN 无法凭空恢复；性能仍与 Backbone、分辨率和训练数据相关。
2018重要发展

PANet · 更充分地传递定位与底层信息 原论文 ↗

增加自底向上的路径聚合等设计，改善不同层级特征信息流通，成为多尺度特征融合的重要发展。

条件 / 边界 特征融合路径变复杂可能增加访存与计算成本，不代表路径越多越好。

Anchor、正负样本与训练目标

Anchor-based 方法在图像位置上预置多个尺度和宽高比的候选框。它提供了直观的候选参数化，但需要规定尺寸、比例以及候选与真实框之间的分配规则。

Anchor-free 可以避免预定义 Anchor Boxes，却同样需要判断哪些位置负责预测哪个目标。因此“Anchor-free”与“无需样本分配”不是同一件事。

2020训练机制

ATSS · 自适应训练样本分配 原论文 ↗

根据统计特性自适应划分正负训练样本，强调标签分配策略能够显著影响检测性能，也为理解 Anchor-based 和 Anchor-free 的差别提供了另一视角。

条件 / 边界 对密集、重叠或极小目标，分配策略仍然可能产生歧义；合理的样本定义依然依赖观测和目标设计。

框回归和 NMS 不只是最后两行代码

常见定位训练会使用 IoU 相关目标，后续还有 GIoU、DIoU、CIoU 等损失家族，尝试处理不重叠框的优化信号、中心距离或宽高比差异。还有 Distribution Focal Loss / Generalized Focal Loss 等概率分布式框表示路线。

而 NMS 根据候选之间的重叠关系抑制重复框。它可以减少冗余预测，但在密集目标、遮挡或多个真实物体高度重叠时，也可能产生误删。Soft-NMS 等方案尝试改善这种问题；另一条路线则从训练和匹配机制入手，使模型原生输出较少重复框。

值得真正深入的一点

很多“某一版本精度提升”的原因来自特征融合、样本分配或损失设计，而不是检测范式发生了变化。读论文时要分清这是新架构，还是对已有路线某个环节的有效改进。

05
ANCHOR-FREE / 位置表示

Anchor-free：不是新的一阶段，而是另一种目标框表达

预置锚框很自然，但它让框的尺度、比例和训练分配包含较多设计选择。于是另一批工作开始思考：能否直接通过角点、中心或像素位置来预测目标？这条路线被称为 Anchor-free，但它与 Two-stage / One-stage 的维度并不互斥。

2018核心节点

CornerNet · 两个角点组成一个目标框 原论文 ↗

把目标检测表示为左上和右下角点的检测及配对，采用 Keypoint-based 表示而不是预定义锚框。

条件 / 边界 角点的正确配对与多个相邻目标的区分有难度，候选组合同样需要约束。
2019核心节点

CenterNet · Objects as Points 原论文 ↗

使用目标中心点作为关键预测入口，并直接回归目标尺寸及必要的位置偏移，使检测表达更加紧凑。

条件 / 边界 相邻目标中心密集、极小目标以及热力图分辨率都会影响定位能力。
2019核心节点

FCOS · 每个像素点也能预测目标框 原论文 ↗

以特征图位置为单位直接预测至四条框边的距离，并配合中心度等机制进行密集预测，形成简洁的一阶段 Anchor-free 检测器。

条件 / 边界 仍需要位置分配、尺度选择与候选筛选；模型性能并不由是否存在 Anchor 单独决定。

这几个方法的联系是不必先铺设一组固定尺寸的候选框，但它们对输出几何采用了不同编码。CornerNet 的角点配对、CenterNet 的中心与尺寸、FCOS 的 l/t/r/b 距离并不能直接等同。

一个经常混淆的分类

FCOS 同时属于 One-stage、Dense prediction、Anchor-free。CornerNet 和 CenterNet 的 keypoint 也只是目标框的参数化方式；它们输出的中心/角点，不等于 Q02 中具有确定物体三维身份的 Keypoints。

06
TRANSFORMER & SET PREDICTION / 查询式检测

DETR：检测器能否直接输出一个不重复的目标集合？

传统密集检测预测大量位置候选，再依靠后处理得到最终实例集合。DETR 走了另一条路线：用 Object Queries 和一对一匹配，直接学习一个目标预测集合。这是值得作为独立范式研究的变化。

2020核心节点

DETR · 从候选筛选转向集合预测 原论文 ↗

利用 Transformer Encoder–Decoder 与可学习的 Object Queries，训练时通过二分图匹配让预测和真实目标形成一对一对应，常规推理无需传统 NMS。

条件 / 边界 原始 DETR 存在收敛较慢、处理小目标效率不足等问题；查询数、注意力和训练设置都会影响表现。

为什么需要 Hungarian Matching？

如果有多个预测框负责同一个真实物体，仅用独立的密集分类和回归训练可能产生大量重复结果。DETR 在训练中寻找预测集合与真实框之间的最佳一对一分配，让未匹配查询学习为“无物体”。

这种机制把去重约束放到了训练过程里。但它也带来了另一类设计问题：匹配代价怎样定义、查询如何初始化、模型怎样更快收敛。

2021重要发展

Deformable DETR · 稀疏采样的多尺度注意力 原论文 ↗

在注意力计算中聚焦少量参考位置附近的采样点，并利用多尺度特征，显著改善原始 DETR 的收敛和小目标问题。

条件 / 边界 采样位置、参考点和实现效率依然需要设计；不是所有场景都能直接获得同等收益。
2023重要发展

DINO · 去噪训练与查询初始化 原论文 ↗

将去噪训练、混合查询选择和更成熟的框预测设计结合，提高 DETR 家族的训练效果与定位表现。

条件 / 边界 更复杂的训练设计带来额外实现和调试要求，不能只看最终 AP 忽略训练开销。

这条路线的技术价值并不在于 Transformer 名字本身，而是候选表示、集合监督和空间注意力的组织方式发生了改变。Deformable DETR 与 DINO 则持续解决这一设计在效率和训练稳定性上的实际问题。

07
REAL-TIME & END-TO-END / 最近发展

实时与无 NMS：不同路线开始处理同一类部署问题

到了近几年，研究重心逐渐不只是谁的 AP 更高。对于真实部署，后处理、访存、输入分辨率、特征融合，以及框回归精度都会影响体验。YOLO 路线和 DETR 路线都开始围绕实际延迟与完整推理链路做设计。

2023 / 2024实时范式

RT-DETR · 查询式检测进入实时竞争 原论文 ↗

通过高效 Hybrid Encoder 和更有效的查询选择，控制 DETR 风格模型的多尺度计算开销，使无 NMS 的查询式检测具备有竞争力的实时性能。

条件 / 边界 论文的 FPS 只对指定 GPU、输入大小和框架配置成立；大分辨率与实际部署需要重新测量。
2024无 NMS 改进

YOLOv10 · Consistent Dual Assignments 原论文 ↗

使用训练阶段的 one-to-many 与 one-to-one 双分配思想，在保留丰富训练监督的同时，为推理端提供可不使用 NMS 的预测头。

条件 / 边界 具体库实现可能同时保留传统预测头；是否真正 NMS-free 取决于调用和导出模式，不能只看模型名字。
2025框定位重要发展

D-FINE · 把框回归做成细粒度分布精化 原论文 ↗

在实时 DETR 框架中，将固定坐标回归扩展成细粒度分布修正，并结合自蒸馏改进定位精度。

条件 / 边界 分布精化增加了目标函数与表示设计，收益取决于训练数据、目标尺度与部署优化。
2025注意力架构探索

YOLO12 / YOLOv12 · Attention-centric 原论文 ↗

探索让注意力机制更深入地参与实时检测特征提取，以控制计算代价的方式提升表达能力。

条件 / 边界 注意力算子、显存与部署后端对效果影响较大；社区研究架构和稳定量产模型不应混为同一判断。
2026工程发展

YOLO26 · 工程化端到端检测 原论文 ↗

Ultralytics 的产品模型线继续整合可选无 NMS 预测、简化框回归和部署接口等改进，使端到端检测更容易与现有工具链集成。

条件 / 边界 它属于产品与工程演进的代表，不宜等同于全新学术检测范式；具体默认调用模式仍要以当前官方文档验证。

这些节点反而很好地说明了一件事：2024—2026 的进展不应写成 YOLOv10 → YOLO12 → YOLO26 逐代取代。 有的研究查询式推理速度，有的研究训练分配，有的研究定位精度，还有的重视成熟的导出与部署。

保留的判断

YOLO 与 DETR 已经不是“实时 vs 高精度”的简单二分。要评估它们，需要给定同一类任务、准确的精度指标和相同的推理条件。

08
EVALUATION / 检测质量

mAP 很重要，但“框很准”并没有回答全部问题

目标检测的论文通常用 COCO AP、AP50、AP75、APs/m/l 等报告效果。理解这些指标能够帮助比较模型，却也需要避免把一个平均分数误认为在所有任务上都可靠。

AP 评价的是怎样的输出？

对给定类别，检测结果按置信度排序，按照 IoU 阈值与真实框匹配，再由 Precision–Recall 曲线计算 AP。COCO 的常用 AP 是在 IoU=0.50:0.05:0.95 等多个阈值下进行平均。AP50 更宽松，AP75 通常更强调定位质量。

Intersection over Union · 预测框与真实框的几何重叠IoU = |Bₚ ∩ Bgt| / |Bₚ ∪ Bgt|IoU 是重要几何指标，但不能独立表达目标身份、语义指代和后续深度可用性。
评价对象有意义的指标还需要单独检查
一般目标检测AP / AP50 / AP75误检和漏检分布、置信度阈值
小目标APs / Recall缩放后尺寸、可见像素数量、遮挡

真实系统端到端 Latency / P95预处理、后处理、GPU/CPU 传输和并发

泛化问题往往发生在数据分布上

一个检测模型在通用数据集上分数不错，不表示能够自动处理新的相机视角、反光物体或被挤压变形的包装。评价时更应该按照任务拆分：未见实例、尺寸分布、背景变化、遮挡、光照与目标形变。

此外，训练数据中的标注框并非完全客观。被遮挡的目标，究竟标可见框还是完整框？贴地薄片的边界如何定义？如果标注规则前后不一致，算法本身很难学出稳定输出。

与后续几何的接口

检测模块返回 BBOX，只能说明目标的大致像素位置。BBOX 精度好不等于 Mask 好，更不直接等于可恢复稳定 3D Pose；需要目标像素区域时看 A04，需要参考特征与对应时看 A02。

09
INDUSTRY / 学术与工程

部署时，论文里的“实时”只是一个起点

理论架构之外，还有一条成熟的工程技术线。真实视觉系统往往需要把数据标注、训练、导出、推理、阈值调整和异常样例回收组织在一起。这里应该关注工具怎样降低工程成本，而不是把框架排名。

MMDetection

模块化地组织 Backbone、Neck、Head、Loss、Assignment 和训练配置，适合比较不同检测架构与复现实验。

研究侧重点：模型族覆盖、配置可追溯、训练与评估接口。官方文档 ↗
Detectron2

包含经典 Region-based 与其它视觉模型的训练、评估和推理工具，适合参考成熟框架的组件设计。

研究侧重点：规范的训练流程与检测/分割共用生态。官方文档 ↗
Ultralytics

提供快捷的数据配置、训练、预测和多格式导出接口，有利于快速建立 YOLO 相关的工程基线。

研究侧重点：部署链路、支持任务和版本间接口差异；许可证应单独审查。官方文档 ↗

提供目标检测模型与产业部署工具链的实现，适合观察不同推理后端和部署形态的整合。

研究侧重点：推理加速与部署环境适配。官方仓库 ↗

更值得比较的是完整推理链路

对 RGB-D 机器人而言，图像获取、颜色空间转换、resize/letterbox、模型执行、后处理、BBOX 坐标还原与后续深度查询都属于同一条运行链路。

尤其是从 1280×720 图像缩放到模型输入尺寸后，预测框必须按照实际的缩放和 padding 逆变换回原图坐标；如果还要查询对齐 Depth，就必须确保 RGB/Depth 的像素坐标对应。这些工程错误有时比模型 AP 的细小差别影响更大。

对比速度和显存之前，先统一 GPU、推理框架、输入尺寸、精度格式、是否包含 NMS 与预后处理。否则看似精确的 FPS 数字很难支持实际决策。

10
COMPARISON / 方法放在一起

不同架构的能力边界：不是简单的先进与落后

把几条路线放回相同的维度，更容易解释它们为什么长期共存。Two-stage 擅长显式候选精化；Dense detection 有简洁而成熟的实时生态；Anchor-free 减少部分候选框先验；Query-based 通过集合训练处理重复预测。这些选择都附带特定成本。

技术思想特别值得研究的情况主要代价 / 风险并不意味着
Two-stage / ROI refinement希望对候选进行进一步分类和框精化ROI 计算、候选数量、部署复杂度永远比 One-stage 更准确
One-stage / Dense追求成熟、统一的高吞吐预测密集样本分配、重叠框筛选必然依赖 Anchor 或 NMS
Anchor-free想减少预定义框尺寸/比例先验位置编码、样本分配仍需设计无需正负样本规则
DETR / Query-set关注全局实例关系与 NMS-free 推理查询设计、训练策略、注意力开销所有 Transformer 都更慢
FPN / PANet图像内同时存在大小不同的目标分辨率、额外特征融合成本可以恢复根本不存在的细节
NMS-free希望减少去重后处理及部署节点匹配与训练监督设计所有重叠目标一定不漏检

例如需要快速实现一个固定类别的场景检测，成熟的 YOLO 模型可能非常合适；如果强调某种高质量候选精化机制，Faster / Cascade R-CNN 仍然值得了解；如果需要研究去重式目标集合和查询匹配，DETR 家族更有代表性。

但这些仍然是由技术机制得出的候选方向，不是没有实验就能下结论的绝对优劣。真正选型应该以目标尺寸、实例密度、训练数据、延迟和系统输出需求验证。

11
NOTES / 技术认识

目标检测这条路线真正不断优化的是什么？

回头看，A03 并不是从 R-CNN 一路升级到最新 YOLO 的直线历史，而是围绕几个长期存在的难题不断分叉：怎样提出目标候选、怎样表示目标框、怎样组织训练监督、怎样消除重复预测、怎样控制真实计算成本。

候选生成从外部 Region Proposal 到共享 RPN，再到密集位置或 Object Queries。
尺度处理从多尺度图像与多层特征预测，到 FPN 等高效特征融合。
目标参数化Anchor Boxes、角点、中心与距离、直接框回归或分布精化。
训练与匹配Focal Loss、Label Assignment、Hungarian Matching、去噪训练。
部署与效率模型本身与 NMS、特征融合、硬件算子、输入尺寸共同决定最终延迟。

每种方法都在某些条件下提供了有意义的解决办法，也保留自己的限制。技术发展增加了可选择的解法，而不是自动让旧方法变得错误。

A03 先到这里：这是一份关于目标检测架构、训练机制与工业应用的完整路线。下一篇 A04 再深入研究从 BBOX 到像素级 Instance Mask，不在这里顺带讲完分割与 Grounding。
