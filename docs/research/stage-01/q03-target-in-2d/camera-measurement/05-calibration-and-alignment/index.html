标定与配准

公式已经有了，
怎样让它对应真实相机？

CAMERA MODELS · CALIBRATION · RGB-D ALIGNMENT

前面已经知道投影、反投影怎样计算，也了解了深度从哪里来、怎样处理异常值。现在把 RGB 和 Depth 真正放在同一个场景里，却还需要回答一个基础问题：我正在使用的像素、深度和相机参数，究竟是否描述了同一个空间关系？

理想针孔公式只规定了坐标之间怎样变换；真实相机还需要确定镜头偏差、参数数值、两套传感器之间的安装关系，以及最终输出到哪一个图像坐标系。

这篇更偏向几何落地：每一部分先讲清数学上在求什么，再给一条最短的实现路径。不是要求每次使用深度相机都重新标定——很多时候，正确读取并使用已有标定，比重新求一遍参数更重要。

00 · 四件不同的事，不要混成一个“标定”

这四件事存在依赖，但不是每次都要从头运行。出厂 RGB-D 相机通常已提供内外参；实际工作中可以直接使用它们进行投影与对齐。如果设备变化、相机被重新组装、或实际误差不能接受，才进一步调查是否需要重新标定。

还要先约定术语：Calibration 是估计参数，Undistortion / Rectification 是利用参数变换图像，Alignment / Registration 是将不同观测放进共同参考网格。它们相互关联，但计算目标不同。

import cv2
import numpy as np

# 示例参数：实际使用时应替换成当前图像对应的 K、D
K = np.array([[900., 0., 640.], [0., 900., 360.], [0., 0., 1.]])
D = np.array([-0.12, 0.04, 0.001, -0.001, 0.0])
uv_raw = np.array([[[950., 520.]]], dtype=np.float64)

ray_xy = cv2.undistortPoints(uv_raw, K, D).reshape(2)
uv_ideal = cv2.undistortPoints(uv_raw, K, D, P=K).reshape(2)
print('归一化观察坐标:', ray_xy)
print('无畸变像素坐标:', uv_ideal)

这段可以独立运行；改变像素位置，观察去畸变偏移是否在图像边缘更明显。需要修正整张图像时可使用 cv2.undistort，实时处理则优先考虑 initUndistortRectifyMap + remap。如果图像已经去畸变，不能再按照原始镜头参数重复去畸变。

02内参标定

02 · 相机内参标定：那些未知参数怎样从图像里求出来？

2.1 标定到底在估计什么？

上一节是假设 K、D 已经知道，讨论如何使用它们。若参数未知，标定任务则倒过来：给出已知几何的参考物，观察它在图像中的位置，寻找最能解释这些观测的模型参数。

2.2 为什么要拍多个倾角和画面位置？

如果所有照片都几乎正对棋盘、棋盘又只在图像中心，很多参数的影响就会互相混淆，难以稳定区分焦距、主点和畸变。

因此需要让标定板覆盖不同位置、距离和倾角，并在图像边缘保留足够的角点观测。棋盘方格的实际尺寸也必须准确：标定结果中的平移量单位来自它，不是来自程序里的一个随意数字。

最常见的流程是：准备标定板 → 拍摄多姿态图像 → 检测并精细化角点 → 优化 K、D 和每帧位姿 → 检查重投影误差与独立几何效果。

最小实现｜OpenCV 棋盘格标定

把棋盘格图片放在 calib/ 文件夹，改成真实棋盘的内角点数量与方格边长。以下示例使用 9×6 个内角点和 25 mm 方格边长，只是演示配置。

import glob
import cv2
import numpy as np

pattern = (9, 6)           # 内角点，不是方格数量
square_m = 0.025          # 必须测量真实方格边长
obj = np.zeros((pattern[0] * pattern[1], 3), np.float32)
obj[:, :2] = np.mgrid[0:pattern[0], 0:pattern[1]].T.reshape(-1, 2) * square_m

object_points, image_points = [], []
image_size = None
for filename in sorted(glob.glob('calib/*.png')):
    im = cv2.imread(filename)
    if im is None:
        continue
    gray = cv2.cvtColor(im, cv2.COLOR_BGR2GRAY)
    size = gray.shape[::-1]
    if image_size is not None and image_size != size:
        raise ValueError('标定图像分辨率不一致')
    image_size = size
    ok, corners = cv2.findChessboardCorners(gray, pattern)
    if not ok:
        continue
    corners = cv2.cornerSubPix(gray, corners, (5, 5), (-1, -1),
              (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 1e-3))
    object_points.append(obj.copy())
    image_points.append(corners)

if len(object_points) < 6:
    raise RuntimeError('有效标定图像不足；检查棋盘、视角和图片路径')
rms, K, D, rvecs, tvecs = cv2.calibrateCamera(
    object_points, image_points, image_size, None, None)
np.savez('camera_calibration.npz', K=K, D=D, image_size=image_size)
print('RMS reprojection error:', rms, '\nK:\n', K, '\nD:', D.ravel())

这个例子会估计参数，但 RMS 很小仍不代表绝对几何一定准确。应另选未参与优化的视角检查重投影，核对棋盘尺寸、参数合理性及已知长度/平面的实际测量效果。若使用圆点阵、ChArUco 或鱼眼模型，检测与标定函数应相应变化。

03外参估计

03 · 多相机外参：Color 与 Depth 怎样共享一个空间？

3.1 相同像素不等于相同射线

RGB-D 设备中，彩色相机与深度观测的参考相机并不一定拥有同一个光心、光轴或内参。即使 Color 和 Depth 都输出 640×480，也不能据此认为像素 (320,240) 观察到同一个空间位置。

最小实现｜已有标定板位姿，组合相机外参

import numpy as np

def make_T(R, t):
    T = np.eye(4, dtype=np.float64)
    T[:3, :3] = R
    T[:3, 3] = t
    return T

# T_C_B 与 T_D_B：同一块标定板在 Color / Depth 坐标系下的位姿
# 真实使用时由各自标定结果填入；长度单位必须一致
T_C_B = make_T(np.eye(3), [0.10, 0.00, 0.90])
T_D_B = make_T(np.eye(3), [0.05, 0.00, 0.90])
T_C_D = T_C_B @ np.linalg.inv(T_D_B)
P_D = np.array([0.0, 0.0, 1.0, 1.0])
print('Depth → Color:', T_C_D @ P_D)

这里的输入位姿为示例数据，用于检查变换方向和矩阵组合；它不会自动从相机图像估计真实外参。真正重新标定时，需使用共同可观测的标定参考，或调用 OpenCV 双目联合标定。

4.2 D2C 与 C2D 为什么不完全对称？

D2C（Depth → Color）：对于每个有效的 Depth 像素，已经知道它的三维位置，可以把它投影到 Color 视角的目标网格上。若多个深度点落进同一 Color 像素，通常应保留对目标相机而言更近的可见表面，也就是 Z-buffer 的思想。

C2D（Color → Depth）：以原始 Depth 网格为输出，先使用每个深度像素计算其对应的 Color 位置，再从 Color 图像采样颜色。因为深度像素自带三维位置，找到对应颜色通常更直接。

注意：Color 图像自身没有每像素三维距离，不能仅凭一张 RGB 图对任意 Color 像素执行“反投影得到唯一 Depth 点”。因此这两种输出方向的算法细节并不相同。

4.3 遮挡、Z-buffer 与投影空洞

对齐后的问题有三类：

  • 遮挡：两个相机位置不同，一个相机看见的表面，另一个可能被前景挡住。这不是内参错误。
  • 深度冲突：多个 3D 点投到目标图像的同一像素，需要按照目标视角中的可见性选择前景；不能简单取平均。
  • 稀疏空洞：离散深度网格映射到不同分辨率的目标网格后，可能留出未覆盖像素。Splatting 或插值可以改善覆盖，但不能凭空恢复真实遮挡的表面。

import pyrealsense2 as rs

pipe = rs.pipeline()
config = rs.config()
config.enable_stream(rs.stream.depth)
config.enable_stream(rs.stream.color)
profile = pipe.start(config)
align = rs.align(rs.stream.color)

try:
    frames = pipe.wait_for_frames()
    aligned = align.process(frames)
    depth_aligned = aligned.get_depth_frame()
    color_frame = aligned.get_color_frame()
    if depth_aligned and color_frame:
        intr = depth_aligned.profile.as_video_stream_profile().intrinsics
        u, v = color_frame.get_width() // 2, color_frame.get_height() // 2
        print('对齐后深度 (m):', depth_aligned.get_distance(u, v))
        print('对齐后深度内参:', intr)
finally:
    pipe.stop()

FIELD OBSERVATION · 厂商实现观察

厂商实现观察｜几何对齐成功，也不保证运动边缘对齐

RealSense 和 Orbbec 都在 SDK 中封装了流间对齐，但封装程度不一样：用户有时拿到的已经是对齐后的深度，有时需要显式调用 Align 或设置 D2C 模式。

还需注意两个边界：几何对齐不能消除采集时间差，移动物体即使空间外参正确也可能产生彩色/深度边缘错位；输出到新网格意味着坐标定义已经变化，后续恢复 XYZ 必须使用与输出网格相符的内参及深度定义。

05验收检查

05 · 最后一次检查：怎样证明几何关系用对了？

现在将这四部分放在一起，实际面对 RGB-D 数据时可以先做三个非常具体的检查。

检查 最小做法 真正验证什么
参数与图像一致 核对当前分辨率、畸变状态、K、D、Depth 单位 投影所使用的像素坐标系是否正确
单相机重投影 把独立参考点投回图像，观察角点误差随位置变化 模型与估计参数是否能解释实际像素
Color–Depth 对齐 把深度边缘与 RGB 轮廓叠加，静态近/远目标分别检查 外参、目标网格、遮挡处理是否相互一致

如果参数来自设备 SDK，最先做的往往不是再运行一次标定，而是确认拿到的是哪个流、哪个分辨率、哪个图像处理阶段的参数。特别是彩色图裁剪、图像缩放、对齐输出和 ROS camera_info 的变化，都可能让原本正确的 K 被错误地使用。

重投影误差小，也不能单独保证深度的绝对测量准确；静态目标对齐良好，也不能证明动态场景已经解决了帧间同步。不同的误差需要不同的证据，不能都归结为“重新标定一次”。

一个适合保留的最小验收顺序

  1. 先读参数，不先改参数。 保存当前 Color / Depth 的 K、D、外参、分辨率和单位。
  2. 在原始与对齐图上分别做几何检查。 确认当前使用的是哪一套坐标定义。
  3. 选择静态、有明确边缘的场景验证。 同时观察近处与远处，避免只对准中心的一块平面。
  4. 如果仍有系统性偏差，再定位该重新估计哪个环节。 是单相机内参、两相机外参、深度测量本身，还是帧同步。

回头看｜从数学公式到真实的 RGB-D 观测

成像几何给出了像素和三维射线之间的计算方式；深度测量补上了距离；深度后处理改善了部分异常观测。

这一部分最终补上的，是让所有这些计算真正对应同一台设备、同一份数据、同一个坐标系的条件。

  • 相机模型决定原始像素怎样对应观察方向。
  • 内参标定回答模型参数怎样从真实观测中估计。
  • 多相机外参将不同传感器的空间坐标联系起来。
  • RGB-D 几何对齐利用这些参数，找到颜色与深度之间的正确对应。
