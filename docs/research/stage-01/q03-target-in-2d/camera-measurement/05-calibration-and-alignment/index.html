05 / CAMERA CALIBRATION · GEOMETRIC ALIGNMENT

公式已经有了，
怎样让它对应真实相机？

FROM OBSERVATIONS TO PARAMETERS · AND BACK TO PIXELS

前面已经学会了投影与反投影，也知道深度从哪里来。但把公式放进真实相机以后，很快遇到一个新问题：公式中的焦距是谁告诉我们的？不同镜头的畸变从哪里来？两台传感器之间的坐标关系又怎么知道？

这些东西不是一个 SDK 函数突然“算出来”的。我们必须先找到已知的几何关系，再观察它怎样出现在图像中，然后利用两者之间的矛盾一步步约束未知参数。

这一站想真正看懂的是：我们观测了什么，方程是怎么出现的，最后求出了什么，以及这些结果在什么情况下不可靠。

00 / BEFORE WE BEGIN

先分清四个问题：它们并不是四种标定法

同样是在处理像素与空间的关系，但每一步的未知量并不一样。

01 · MODEL像素如何产生？给定几何、K、D → 预测像素
02 · CALIBRATION参数怎样得到？已知角点 ↔ 图像位置 → 反求 K、D
03 · EXTRINSICS相机怎样相连？跨相机共同观测 → 求 R、t
04 · ALIGNMENT两种观测怎样对应？已知参数 + 深度 → 重投影

这几个过程有先后依赖，但不代表每次使用 RGB-D 相机都要亲手标定。设备通常已经提供出厂内外参。这里讨论求解过程，是为了知道这些参数为什么有意义、需要什么证据、出了问题应该怀疑哪里。

贯穿全篇的坐标约定

用 PB 表示标定板上的三维点，PC 表示 Color 相机坐标中的点，PD 表示 Depth 参考相机坐标中的点。TC←D 的含义固定为“把 Depth 坐标系中的点变到 Color 坐标系”；平移单位统一用米。相机遵循 X 向右、Y 向下、Z 向前的光学坐标约定。

01 / CAMERA MODEL & DISTORTION

先学会预测一个像素，才能反过来标定它

模型不是名词清单。它是一条可以实际计算的函数：给出空间方向，回答光线会落在哪个像素上。

1.1 · 不考虑畸变，相机怎样把三维点变成二维像素？

假设一个空间点已经位于相机坐标系，PC=(X,Y,Z)。沿相机光心投影到归一化成像平面，先得到：

x = X / Z，  y = Y / Z

然后由内参矩阵 K 把这个归一化位置换成像素。忽略 skew 时：

u = fxx + cx，  v = fyy + cy
FX / FY

焦距的像素表达

控制空间方向的变化在图像中被放大多少。不是简单的“镜头上刻的毫米焦距”。

CX / CY

主点位置

光轴与理想图像平面的交点，一般接近图像中心，但不必正好等于中心。

1.2 · 真正的镜头并不严格遵循这条直线关系

理想情况下，场景中的直线仍应投影成直线。但真实镜头在边缘可能发生弯曲。于是我们尝试在“归一化坐标 → 像素”的中间加入一层修正：畸变函数。

以常见的 Brown–Conrady 五参数模型为例，先计算 r²=x²+y²，径向缩放因子：

L(r) = 1 + k1r² + k2r⁴ + k3r⁶

再考虑切向畸变 p1,p2：

xd = xL(r) + 2p1xy + p2(r²+2x²)yd = yL(r) + p1(r²+2y²) + 2p2xy

最后再通过 u=fxxd+cx 和 v=fyyd+cy 得到真实像素预测。这就是所谓的正向投影模型。

代一个真正的数：令 x=0.16, y=0.08, k1=−0.2，其他畸变项为零；有 r²=0.032，因此 xd=0.16×(1−0.2×0.032)=0.158976。如果 fx=800,cx=640，预测列坐标从无畸变的 768 px 变成约 767.18 px。

1.3 · 那鱼眼镜头怎么办？

普通 Brown–Conrady 从归一化坐标出发，用半径多项式修正。某些大视场镜头用这一形式很难稳定覆盖整个视场。Kannala–Brandt 类模型则以光线入射角 θ 为核心，例如用：

θd = θ(1 + k1θ² + k2θ⁴ + k3θ⁶ + k4θ⁸)

再根据方向将角度映射为像素半径。两类模型的根本区别是：假设什么变量能够稳定地描述光线到成像位置的关系。这也解释了为什么不能直接把普通针孔相机的畸变系数传给鱼眼函数。

1.4 · 去畸变为什么不是把系数取反？

前面预测像素时，我们已知理想方向 (x,y)，计算畸变位置 (xd,yd)。但真正从相机拿到的恰恰是后者；要恢复观察射线，必须求解逆问题：

寻找 (x,y)，使 F(x,y;D) = (xd, yd)

由于径向半径本身依赖未知的 x,y，这个逆变换通常通过迭代求解或数值近似完成，不能简单把 k1 改成 −k1。`undistortPoints` 得到的默认是归一化射线坐标；如果另外传入投影矩阵，才把结果重新映射到指定的像素坐标系。

这一部分的边界

模型只能描述它所假设的投影关系，无法用几个固定参数修正运动模糊、滚动快门形变或任意温漂。对于已经校正输出的图像，D=0 不等于真实镜头毫无畸变，更不能对已经校正的数据再次执行同一套去畸变。

02 / SINGLE-CAMERA CALIBRATION

一张棋盘格，到底怎样把焦距算出来？

这是整篇的核心。先不调用任何标定接口，我们从最少的观测开始，看看未知参数如何一步一步变得可求。

假设桌面上有一块真实的平面棋盘格。它只是普通纸张，里面没有传感器，也不会主动告诉相机自己的位置。我们掌握的线索只有：每一个角点在棋盘格坐标系中的位置已知，以及它在照片中被检测到的像素位置。

已知角点 Pj=(Xj,Yj,0)，方格物理尺寸、每张图像中的角点像素 pij=(uij,vij)
未知固定不变的内参 K、畸变 D，以及每张图里棋盘格的姿态 Ri,ti
要做到找到一套参数，能同时解释所有照片中所有角点的像素位置

第一次尝试：正对着拍一张，为什么还算不出焦距？

棋盘格上一对角点的水平距离是 40 mm，照片中相差 64 px。理想情况下，如果棋盘格正对相机，有：

Δu = fx · ΔX / Z  →  64 = fx · 0.04 / Z

这只是一个方程，却有两个未知数——像素焦距 fx 和棋盘距离 Z。比如 fx=800,Z=0.5m 与 fx=1600,Z=1m 都符合这次观测。

由观测自然产生的新问题

如果在保持棋盘格内部几何不变的前提下，让它倾斜，近端与远端的透视差异会不会提供额外约束？

第二次尝试：把棋盘格倾斜，Homography 是怎样算出来的？

当棋盘格绕相机转动，它的格子在照片中会呈现近大远小的变形。但所有棋盘角点仍处于同一个物理平面。对于理想针孔相机，任意两个这样的平面坐标与图像坐标之间存在一个 3×3 单应矩阵 H：

s [u, v, 1]T = H [X, Y, 1]T

这里的 H 不等于 K。它暂时只是“这张棋盘格平面怎样变形成这张照片”的数学描述。

令 H 的 9 个元素依次为 h11 … h33，把两边展开：

u = (h11X + h12Y + h13) / (h31X + h32Y + h33)v = (h21X + h22Y + h23) / (h31X + h32Y + h33)

分母含未知的 H，先交叉相乘，就能把每个角点对变成两条关于 H 的线性方程：

Xh11 + Yh12 + h13 − uXh31 − uYh32 − uh33 = 0Xh21 + Yh22 + h23 − vXh31 − vYh32 − vh33 = 0

每个角点提供两条方程。H 有 9 个数，但把整张 H 同时乘一个非零常数并不会改变投影，因此只有 8 个独立自由度：理论上至少 4 组非共线三点所能导致的退化之外的点对，具体地说通常取不共线排列的 4 个点，便可以求 H。 实际使用许多角点，通过 SVD 求线性系统 Ah=0 的最小残差解（通常还会先归一化坐标以改善数值稳定性）。

如果只是为了把一张纸上的图案映射到照片，算到 H 就已经可以结束。但我们要的是相机内部始终不变的 K。所以下一步必须发现：不同 H 之间有什么共同约束？

第三次尝试：张正友如何从几张 H 中分离出 K？

棋盘格的所有角点位于 ZB=0 的平面。忽略畸变时，完整投影关系是：

s [u, v, 1]T = K [r1   r2   t] [X, Y, 1]T

和上一节比较，自然得到：

H ∼ K [r1   r2   t]

这个符号“∼”表示整体比例相同。这里 r1,r2 是一个旋转矩阵的前两列。旋转有一个非常特殊的性质：不同列互相垂直，而且长度都是 1。

r1Tr2 = 0r1Tr1 = r2Tr2

把 r1∼K−1h1 与 r2∼K−1h2 代入。令 B=K−TK−1，旋转正交关系变成：

h1TB h2 = 0h1TB h1 − h2TB h2 = 0

关键出现了：H 已经从角点计算出来，所以 h1,h2 是已知的；现在未知的是同一个 B。B 是对称矩阵，6 个独立元素，整体比例不影响最终的 K，因此一般情形中至少需要 3 张几何上不退化的图像提供 6 条约束，才能线性恢复 B 的比例形式。

这一步不是玄学公式，而是线性代数。

把 B 的独立元素排成向量 b=(B11,B12,B22,B13,B23,B33)T。每张 H 带来两行系数，把多张照片叠起来写成 Vb=0，用 SVD 解出 b。由 B 恢复 K（满足正定、正焦距等条件并做适当归一化）；本质上就是从已知的 B=K−TK−1 中进行矩阵分解。

之后对每张图计算 K−1H 的前两列，归一化得到 r1,r2；用叉乘得到第三列，再通过正交化得到有效的 R，同时恢复对应的 t。

为什么倾斜很重要

正对且变化很少的棋盘格，虽然也能算 H，但不同视角带来的约束可能几乎重复，导致系统退化或病态。多角度观测真正增加的是彼此独立的几何约束，不是单纯把图片数量堆起来。若额外固定了零 skew、主点等参数，最少所需的约束会随模型假设变化。

第四次尝试：得到 K 以后，畸变系数 D 又从哪里来？

现在已有一组 K、每张图的 R 和 t 的初始估计。于是可以把棋盘格角点重新“投影回照片”：在当前参数下，理论上每个角点应该出现在什么像素？

p̂ij = project(Pj; K, D, Ri, ti)

最初令 D=0。你可能发现，中心区域预测得还不错，但边缘总是偏一点。让 D 也成为未知数，并把 K 与每张图的 R、t 一起微调：

minK,D,{Ri,ti} Σi,j ‖pijobs − p̂ij‖²
所有照片、所有角点的重投影残差共同参与优化

优化器重复做同一件事：当前参数预测像素 → 与真实角点比较 → 调整未知量 → 再预测。K、D、姿态之间互相耦合，所以通常借助线性初始化和非线性最小二乘（如 Levenberg–Marquardt）细化，而不是指望一步求出全部准确值。

因此，D 不是拿尺子量出的“镜头弯曲程度”，而是通过大量角点观测拟合出的模型参数。如果使用错误的畸变模型、图片覆盖不足或标定板形变，优化也可能给出一套“看起来很能拟合训练照片”的错误参数。

走到这里，OpenCV 的函数才有了明确含义

下面代码只是把前面完整的求解过程交给现成库执行。它不是学习的起点，而是我们已经知道输入、未知量和目标之后的实现。

Python · 已有棋盘格图片时的完整数据入口
import cv2
import glob
import numpy as np

pattern = (9, 6)   # 内角点的列数、行数
square = 0.025    # 方格边长，单位 m
obj = np.zeros((pattern[0] * pattern[1], 3), np.float32)
obj[:, :2] = np.mgrid[0:pattern[0], 0:pattern[1]].T.reshape(-1, 2) * square

world_points, image_points = [], []
image_size = None
for path in sorted(glob.glob('calib/*.png')):
    im = cv2.imread(path)
    if im is None:
        continue
    gray = cv2.cvtColor(im, cv2.COLOR_BGR2GRAY)
    if image_size is not None and gray.shape[::-1] != image_size:
        raise ValueError('所有标定照片应使用一致的图像尺寸')
    image_size = gray.shape[::-1]
    found, corners = cv2.findChessboardCorners(gray, pattern)
    if not found:
        continue
    corners = cv2.cornerSubPix(gray, corners, (5, 5), (-1, -1),
        (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 1e-3))
    world_points.append(obj.copy())
    image_points.append(corners)

if len(world_points) < 6:
    raise RuntimeError('有效视角太少；重点检查倾角和覆盖位置')

rms, K, D, rvecs, tvecs = cv2.calibrateCamera(
    world_points, image_points, image_size, None, None)
print('K =\n', K)
print('D =', D.ravel())
print('RMS reprojection error (px) =', rms)

这里用至少 6 张有效图作为演示的检查阈值，并不是数学上固定的最少数量；实际标定通常应采集更多几何多样、清晰且覆盖充分的图像。

2.6 · 什么时候这套算法可能给你一个漂亮的错误答案？

出现了什么为什么会错意味着什么
全部正对标定板姿态变化太单一，约束弱K 与每帧姿态容易耦合；需要更丰富的倾角
角点只在中央边缘畸变几乎没被观测D 的估计可能不稳
照片模糊角点检测有系统偏差优化是在拟合错误测量
纸张翘曲“所有点在同一平面”的假设失效部分误差会被 K / D / 姿态吸收
模型过于复杂自由参数过多训练图像 RMS 可能改善，泛化不一定更好
RMS 很小只检验了观测与模型的一致程度不等于深度或三维尺寸一定准确

还有一个特别容易混淆的地方：棋盘格尺寸决定外参平移的单位尺度，不会让图像焦距随方格单位一起变化。 用 25 mm 还是 0.025 m 表达同一块板，应得到相同的像素内参；外参平移的数值则会随采用的长度单位改变。

真正应该怎样验证

除了看标定集 RMS，最好用没有参加拟合的独立视角观察重投影误差的分布；检查边缘是否系统性偏移、参数是否合理，再用已知长度或平面评估实际几何效果。一个平均误差数字不能替代这些证据。

03 / CAMERA-TO-CAMERA EXTRINSICS

两台相机都看到了东西，怎么知道彼此在哪里？

单相机标定告诉我们如何在各自坐标系里解释图像；现在要把两套坐标系连接成同一个空间。

Color 相机和 Depth 参考相机即使安装在同一设备里，也不一定有相同的光心或观察方向。一个点在 Depth 坐标系中的位置 PD，并不能直接当作 Color 坐标中的位置使用。

PC = RC←D PD + tC←D

这是未知的六自由度刚体外参：旋转 R 有 3 个自由度，平移 t 有 3 个自由度。问题变成了：两台传感器要观察什么，才能把 R 和 t 算出来？

3.1 · 第一种办法：两台相机各自求出同一块板的位姿

假设 Color 相机有可靠的二维角点，知道 K、D 以及板上角点的三维坐标，就可以用 PnP 求出标定板相对于 Color 相机的位姿 TC←B。PnP 的本质还是最小化这些板上三维点在 Color 图像里的重投影误差。

如果 Depth 传感器也能恢复同一个板坐标系 B 的完整位姿，记作 TD←B。那么同一个板上点满足：

PC = TC←B PBPD = TD←B PB

第二式取逆，代进第一式，就能消去作为中间桥梁的 B：

TC←D = TC←B · (TD←B)−1
一组极简数值：

假设两台相机方向完全相同，标定板相对于 Color 相机的平移是 (0.10,0,0.90)m，相对于 Depth 参考相机的平移是 (0.05,0,0.90)m，则求得 tC←D=(0.05,0,0)m。这表示一个点在 Depth 坐标中如果是 (0,0,1)m，换成 Color 坐标就是 (0.05,0,1)m。

这是为了说明变换方向的人造例子；真实相机还需要考虑 R。

这里有个重要限制：**Color 能检测棋盘角点，不代表只输出深度值的传感器也能识别同样的棋盘格坐标。** 如果 Depth 只看到一块无标记平面，单个平面可能提供法向和距离，却无法唯一确定平面内的位置与绕法向的旋转。需要额外可辨认的几何、纹理/IR 图像或其他约束。

3.2 · 第二种办法：如果知道两边的三维对应点，还能直接配准

有时候我们已经获得了两套三维对应 PD,i ↔ PC,i，就不一定非得求标定板 Pose。直接最小化：

minR,t Σi ‖PC,i − (R PD,i + t)‖²

这个问题与单相机的角点重投影不同。这里比较的是三维空间中的对应点之间的距离，而不是某个投影像素与图像角点的差异。

先消掉平移：为什么要减质心？

分别计算两组点的质心 μD,μC，并令 qD,i=PD,i−μD、qC,i=PC,i−μC。减去质心后，点集之间只剩旋转关系，原本的平移不再参与中心化点的匹配。

用 SVD 求出最匹配的旋转

建立协方差矩阵：

M = Σi qD,i qC,iT = UΣVT

在这个矩阵定义下，旋转解为：

R = V diag(1,1,det(VUT)) UT

中间的行列式项避免把镜像反射当成真正的旋转。这就是 Kabsch / SVD 求刚体旋转的关键。

最后恢复平移

t = μC − R μD

现在已有把 D 坐标转换到 C 坐标的 R,t，便得到了整个外参。

3D–3D 方法真正依赖的证据

必须知道“D 中哪个三维点对应 C 中哪个三维点”。两个未经关联的点云不能直接塞进上述 SVD；需要先匹配对应，或用 ICP 等方法迭代建立对应。此外，若三维点几乎在同一直线上，某些旋转自由度会变得不可观测；离群匹配也会强烈影响普通最小二乘解。

3.3 · 如果双方只有二维图像呢？为什么还有 stereoCalibrate？

当两台成像传感器都能检测同一块标定板角点时，也可以直接联合优化相对外参。对每张同时观测的标定板，利用固定的 TC←D 和各自的内参，使两边所有角点的预测位置尽量接近真实位置。若各自 K、D 已知，可固定内参，仅估计相对 R、t。

路径真正需要观测到什么求解方式主要局限
共同标定板位姿双方都能独立恢复同一个参考物的完整 Pose组合 TC←B 与 TD←BDepth 侧未必能确定标定板平面内坐标
3D–3D 对应多个可靠、分布良好的三维对应点去质心 + SVD + 恢复 t点对应错误、几何退化、深度噪声
双目联合标定两边成像设备都能检测同一个板的二维角点联合重投影误差优化双方视野、角点检测、同步与模型必须有效

这三条路径不是简单的“哪个算法更高级”，而是分别利用了不同的已知信息。对典型 RGB-D 设备，通常应先读取出厂外参，再判断现有观测是否足以支持重新估计。

04 / RGB-D GEOMETRIC ALIGNMENT

有了这些参数，一张深度图怎么走到彩色图里？

标定是在估计未知参数；对齐则是在使用已知参数，真正把一个深度像素关联到另一个相机的图像。

两张图分辨率相同不代表像素对应。因为两台相机位置不同，Depth 的 (uD,vD) 和 Color 的同一个数字坐标，通常不是同一条空间射线。正确路线必须经过三维：

INPUTDepth 像素 + Z已知测量深度
BACK-PROJECT深度相机三维点用 Depth 的 K / D
TRANSFORMColor 坐标中的点乘 T(C←D)
REPROJECTColor 的像素用 Color 的 K / D

4.1 · 先把一个像素完整地算到底

为了不被矩阵遮住，我们先取最简单的平行相机模型：两台相机没有相对旋转，都是 fx=fy=600 px，主点为 (320,240)，并且 Color 相机的光心比 Depth 相机向右 5 cm。

DEPTH PIXEL

(380, 240)

这个深度像素测得 ZD = 1 m。

CAMERA BASELINE

5 cm

Color 在 Depth 右侧，故 tC←D = (−0.05,0,0) m。

TARGET

Color 像素

要计算这个三维点在 Color 图上出现的位置。

Depth 像素先反投影到 Depth 三维坐标

XD = (380−320) / 600 × 1 = 0.10 mYD = (240−240) / 600 × 1 = 0PD = (0.10, 0, 1.00) m

再根据外参换到 Color 坐标系

PC = PD + (−0.05,0,0) = (0.05,0,1.00) m

最后投影回 Color 像素

uC = 600 × (0.05 / 1) + 320 = 350 px

所以，Depth 中第 380 列的一个点，在 Color 中对应第 350 列。这里使用的都是理想无畸变模型；一般情况还要分别处理去畸变和重新施加 Color 的正向畸变。

自己改一下深度：为什么对齐不能等于 resize？ 可交互

保持原始 Depth 像素 (380,240) 不变、基线 5 cm 不变，只修改测量到的 Z，看 Color 列坐标如何变化。

1.00 m
uC = 380 − 600 × 0.05 / 1.00 = 350.00 px

推导：XD=(380−320)Z/600，XC=XD−0.05，因此 uC=380−30/Z。不同深度有不同位移，整张图无法通过一个固定平移完成对齐。

4.2 · 为什么不能把 Color 的每个像素反过来直接找到 Depth？

因为 Color 图像只有二维像素坐标，未必知道沿射线哪个三维点存在。对于 Depth 图像中的有效像素，我们至少有一个 Z-depth，可以反投影到三维；而一个普通 Color 像素只能恢复一条观察射线。

DEPTH → COLOR

把深度投到 Color 网格

遍历有效深度，恢复三维点，再投影到 Color 图。目标是生成 Color 视角中的深度图；会遇到多个点落到同一个像素的问题。

COLOR → DEPTH

把颜色采样到 Depth 网格

仍从 Depth 的三维点出发，去 Color 图查对应颜色，再把取到的 RGB 填在原始 Depth 像素位置。

4.3 · 如果两台相机位置不同，有些表面注定看不到

物体边缘经常让人误以为外参算错了：深度看到了一小块物体侧面，但 Color 相机从另一个角度看，它可能已经被前景挡住。正确的几何参数也无法让“被遮挡”的信息凭空出现。

现象如何产生常见处理与代价
多个点命中同一像素投影取整、表面重叠可按目标视角的 ZC 做深度比较（Z-buffer）保留前景；不同 SDK 可能采用其他具体规则
目标像素没有深度分辨率变换、深度无效、几何不覆盖保留空洞或进行有条件的 splatting / 插值；不能保证恢复真实表面
物体边缘错位遮挡、混合像素、外参误差等区分几何可见性与参数错误，不能都靠平移图像解决
运动目标错位两路图像不是同一时刻采集几何对齐不能修复时间差，需要同步或运动补偿
一个必须写清的 Z 定义

理论上，如果输出是严格定义在 Color 坐标系下的 Z-depth，那么应记录对应三维点的 ZC。但某些 SDK 的对齐深度帧可能把源深度值重采样到目标网格，并保留设备所约定的深度数值含义。理解几何推导与核对实际 API 语义是两件事，不要把任意 Align 的输出默认等同于新坐标系下的精确 Z-depth。

4.4 · 在 RealSense 中，这一步封装成了什么？

SDK 已提供当前流的内参、畸变、外参和深度数据，`rs.align(rs.stream.color)` 把深度放到 Color 的目标网格中。调用代码可以很短，但它做的不是简单 resize，而是前面的几何关联与重采样。

Python · RealSense 对齐后的参数核对
import pyrealsense2 as rs

pipeline = rs.pipeline()
config = rs.config()
config.enable_stream(rs.stream.depth)
config.enable_stream(rs.stream.color)
pipeline.start(config)
align = rs.align(rs.stream.color)

try:
    aligned = align.process(pipeline.wait_for_frames())
    color = aligned.get_color_frame()
    depth = aligned.get_depth_frame()
    if depth and color:
        intr = depth.profile.as_video_stream_profile().intrinsics
        u, v = color.get_width() // 2, color.get_height() // 2
        print('aligned dimensions:', depth.get_width(), depth.get_height())
        print('aligned intrinsics:', intr)
        print('SDK depth value (m):', depth.get_distance(u, v))
finally:
    pipeline.stop()

这里演示的是确认“拿到什么图像，以及当前接口声明了什么参数”。对真实设备的高精度几何要求，仍需核查当前流与对齐语义、深度尺度和有效像素。Orbbec 等其他厂商也可能提供软件或硬件对齐，物理几何思想相同，但接口定义要分别核对。

05 / VALIDATION & LIMITS

一个参数拟合成功，究竟证明了什么？

我们终于完成了从已知几何到参数、再从参数到像素的闭环。现在要避免把不同层次的“准确”混在一起。

你观察到的证据能较好支持什么不能单独证明什么
标定 RMS 很小相机模型在这些角点上拟合良好绝对距离、深度尺度一定准确
独立照片重投影也很好K、D 对新的成像位置有一定泛化能力所有三维几何偏差已消除
RGB 与 Depth 静态边缘吻合外参、当前图像定义与对齐大致一致运动时也会对齐；遮挡完全消失
深度中的平面看起来平整重复性或局部一致性较好平面到相机的绝对距离一定正确

5.1 · 在真实 RGB-D 数据前，优先核对什么？

与其刚出现偏差就重新标定，先检查当前数据和参数是否真的是同一套定义：

DATA DEFINITION

当前是什么图像？

原始 Color、原始 Depth、去畸变后的流，还是已经 Align 的流？图像分辨率和裁剪范围是否改变？

CALIBRATION

对应哪套参数？

内参、畸变模型与系数、跨流外参，是不是为当前输出模式定义？长度单位是否一致？

GEOMETRY

算出来的几何对吗？

在不同画面位置用独立角点检查投影；在静态场景查看远近目标的 RGB–Depth 对齐边缘。

MEASUREMENT

深度自己准不准？

用已知长度、已知距离或可信平面检查几何。不要用二维重投影 RMS 代替深度精度评估。

5.2 · 这部分没有解决的事情

这章解决的是像素、相机模型和多传感器坐标关系。深度本身怎样产生系统性误差、运动中的帧同步，以及相机到机器人基座的手眼标定，属于相邻但不同的问题，不能靠已经求好的 K、D 和 Color–Depth 外参自动解决。

可以长期保留的判断

发现 RGB-D 几何不一致时，先分辨它属于模型错误、参数错误、变换方向或单位错误、深度测量错误、遮挡还是时间不同步。如果不知道错误来自哪里，重新运行任何一个标定工具都只是在碰运气。

END / LOOKING BACK

回头看：原来每一个参数，都来自某种观测约束

从棋盘格角点出发，我们先发现一张正对照片无法分开焦距与距离；于是倾斜标定板，用平面对应解出 H。H 仍然混合了相机内参与每帧姿态，但旋转矩阵的正交性让不同 H 共享了可求的约束。获得 K 的初值后，再让畸变、内参和姿态共同调整，拟合全部角点。

两台传感器之间也是类似的思路：只有找到共同参考物、可靠三维对应或联合可观测的二维角点，才能恢复跨传感器外参。等内外参确定之后，RGB-D 对齐才成为一次可以实际执行的三维重投影。

这一路真正需要记住的

不是某个函数的参数顺序，而是每一个求解问题背后的三个要素：

① 手里有什么观测？　② 这些观测提供了什么独立约束？　③ 求出来的量在什么条件下可信？

当这三个问题都能自己回答时，标定不再只是“对着棋盘格运行一次工具”。
