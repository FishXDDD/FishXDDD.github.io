训练与优化

Training & Optimization · From Gradients to Reliable Learning

上一篇已经知道，反向传播可以计算每个参数的梯度。可真实训练并不是算一次梯度、更新一次参数就结束了：数据有成千上万条，梯度会变化，步子可能迈大，网络也可能越训练越不稳定。

这一篇关心的是：拿到梯度之后，怎样组织训练、选择更新方式，并判断网络是否真的在学？

我们用最小的损失地形理解优化器；涉及完整的模型评测与数据泛化策略，只在这里建立必要概念。

00 PROBLEM & SCOPE

能计算梯度，为什么还要认真选择训练超参数？

反向传播回答“参数往哪个方向变化会影响损失”；优化器决定如何利用梯度执行更新；训练设置则决定“用哪些样本计算梯度、每次走多大一步，以及何时停止”。

01梯度从哪里来？用全部数据，还是分批近似整体方向？
02参数怎样更新？直接沿梯度走，还是利用历史方向与自适应步幅？
03学得是否可靠？损失是否稳定下降，能否在未见数据上工作？
样本批次→前向与损失→反向梯度→优化器更新→重复 / 验证
与上一篇的分工：上一站学“梯度如何算”；这一站学“多次迭代时如何有效地利用梯度”。具体图像模型的卷积结构、检测损失和数据集评测，留给后续对应专题。
① 数据如何组成更新

batch / accumulate / epochs 决定一轮看多少数据、多久更新一次参数，并牵涉显存和训练时间。

② 每次参数怎样移动

lr / optimizer / scheduler 决定更新方向如何平滑、移动多大、训练前后怎样改变。

③ 数值怎样保持稳定

init / norm / clip / precision 影响信号尺度、显存和溢出风险。

④ 怎样避免只记住训练集

weight_decay / dropout / augmentation / stopping 约束模型、增加数据变化并选择训练停止点。

这一篇不提供「一定最优」的固定数值；每个超参数都会明确写出调大或调小会怎样、成本在哪里、有哪些例外。下方示例使用教学数据，不能视为真实模型的测速结果。

01 MINI-BATCH TRAINING

数据很多，难道每次都要用完整训练集求梯度？

如果一共有 N 个样本，完整梯度需要遍历全部数据；也可以只用一个样本估计梯度。现代深度学习更常见的折中是 Mini-batch：每次取一小批样本，计算平均损失与梯度，然后更新一次参数。

机制图 · 一个 Epoch 中的 Mini-batch 更新
小批量梯度 · 对批次样本求平均
gt = (1 / |Bt|) ∑i∈Bₜ ∇θ ℓi(θt)
Bt 为第 t 次取出的样本批次，ℓi 是第 i 个样本损失。它估计整体训练集的梯度，估计值会因抽样而波动。

1.1 · Batch、Step 与 Epoch 到底是什么？

最后一批不满一个 Batch 时，是否保留取决于数据加载设置；使用梯度累积时，多次前向与反向计算也可能只对应一次优化器更新，因此 Step 的精确定义要看具体训练循环。

1.2 · 批次越小，梯度为什么越容易变化？

不同样本提供的梯度方向不完全一致。一次只看少数样本，算出来的平均方向可能偏离全数据梯度；批次增大，抽样误差的典型波动通常减小，但显存和一次更新的计算成本会增加。

1.3 · Batch Size 变大，换来什么？代价是什么？

先区分两件事：一个 Batch 的梯度更稳定，和整个训练更快、更准确，不是同一个结论。调大 Batch 通常会降低梯度的抽样波动，却可能增加单次前后向的显存需求，并减少固定 Epoch 中的参数更新次数。

考察角度Batch 更小Batch 更大
梯度波动抽样噪声较大，每步方向可能更不稳定平均更多样本，波动一般更小，但收益递减
峰值显存激活值占用通常较低激活值占用通常上升；模型参数/优化器状态不会随 B 同比例增加
每步计算样本少，但 GPU 可能利用不充分一次处理更多样本；单步通常更耗时，吞吐量可能更高
每 Epoch 更新次数在其他条件不变时，更新次数更多更新次数更少，不能直接沿用相同的学习率与调度步数
验证集表现可能从梯度噪声中获益，也可能不稳定不一定更好；需配合 LR、总更新步数和数据验证
为什么批次越大，梯度波动一般越小？
gB = 1B ∑i=1B ∇ℓi，　Var(gB) ≈ σ²B
后一个式子仅在各样本梯度近似独立、方差相同等假设下成立，用来解释平均梯度的统计波动；实际数据相关、重复样本和训练状态都会改变结果。梯度波动变小不等于泛化必然变好。
一个容易被忽略的代价：固定数据集与 Epoch 时，Batch 翻倍，优化器更新次数通常约减半。若想比较训练效果，应同时记录看到的样本数、优化器 Step 数、验证集指标和实际耗时，而不是只比较 Epoch。

1.4 · 显存不够，为什么可以用梯度累积？

梯度累积（Gradient Accumulation）把一个较大的有效 Batch 分成多次较小的前向/反向计算，先累加梯度，最后才调用一次优化器 step()。

有效 Batch · 数据并行训练的常用计算
Beffective = Bmicro × A × G
Bmicro：每张 GPU 一次微批样本数；A：累积次数；G：数据并行 GPU 数量。只有在正确平均梯度、按有效 Batch 更新时，这才对应期望的梯度统计规模。

1.5 · 梯度累积和真正的大 Batch 完全等价吗？

不一定。若损失平均方式一致、模型计算没有批内耦合、更新之前没有提前执行裁剪等操作，梯度累积可近似得到同一组样本的大 Batch 梯度。但 BN 使用当前批次统计量，Dropout 与随机增强也会改变逐次计算；最后一个不满的微批次还可能需要按样本数加权平均。

最小伪代码 · 4 个微批次形成一次优化器更新
optimizer.zero_grad()
for micro_batch in next_4_micro_batches:
    loss = criterion(model(micro_batch), target(micro_batch))
    (loss / 4).backward()  # 只累加梯度，不更新参数
optimizer.step()           # 第 4 次反向后才更新
假设四个微批次样本数相同、损失为微批平均；最后不满四批或各微批大小不同，应按实际样本数加权，不能无条件都除以 4。混合精度训练还要按框架要求处理梯度缩放与裁剪顺序。
选择原则：先选能稳定运行、吞吐尚可的单卡 Micro-batch；显存不足但需要更大有效 Batch 时再加累积。要获得更高吞吐，应实际测量 images/s 和显存，而不是仅凭 Batch 的数值判断。
02 OPTIMIZER FAMILIES

同样得到一组梯度，为什么还需要不同优化器？

优化器的核心职责是把梯度变成参数更新。三种经典思路可以这样区分：

2.1 · SGD：直接沿当前梯度更新

不带动量的 Mini-batch SGD
θt+1 = θt − ηgt
η 是学习率，gt 是当前批次梯度。简单直接，但方向可能随批次变化而波动；需要正确设置学习率。

2.2 · Momentum：为什么要记住之前的方向？

如果连续几个批次的梯度方向相近，可以把历史更新方向累积起来；对于频繁反向的方向，动量可能抑制部分振荡。但动量也可能让参数越过极小值附近。

一种常见的动量写法
vt = μvt−1 + gt  ;  θt+1 = θt − ηvt
v 表示累积的梯度方向，μ 是动量系数（通常小于 1）。不同框架的实现和学习率放置方式可能采用等价的不同写法。

2.3 · Adam：为什么不同参数可以使用不同的有效步幅？

Adam 同时估计梯度的一阶矩（均值趋势）与二阶原始矩（平方梯度的趋势），经偏差修正后，为不同参数构造自适应更新尺度。

Adam 核心机制 · 逐元素运算
mt = β₁mt−1 + (1−β₁)gt
vt = β₂vt−1 + (1−β₂)gt2
m̂t = mt/(1−β₁t)，v̂t = vt/(1−β₂t)
θt+1 = θt − η · m̂t/(√v̂t + ε)
gt2 为逐元素平方；β₁、β₂ 为平滑系数。偏差修正用于缓解初始时刻 m、v 从零开始造成的偏小。ε 用来保持数值稳定。
方法如何利用梯度主要关注
SGD直接使用当前梯度简单透明；学习率很关键
Momentum叠加历史方向减轻部分振荡，但可能超调
Adam均值趋势 + 平方梯度自适应缩放不同参数的有效步幅可不同

再认识一个常见名词：AdamW 在 Adam 的自适应更新之外，采用解耦式权重衰减（Decoupled Weight Decay）。这不是“Adam 换一个名字”，它对正则化更新的处理与把 L2 惩罚直接加入 Adam 梯度不同。这里先理解区别，具体使用时再看框架参数。

2.4 · 选 SGD、Adam 还是 AdamW，成本有什么区别？

方法可调的关键参数收益与代价
SGDlr状态开销小；较依赖学习率和训练设置，可能需要较多更新才能达到目标效果
SGD + Momentumlr、momentum利用历史方向缓解部分振荡；多保存一份动量状态，动量过大也可能超调
Adamlr、β₁、β₂、ε按参数自适应缩放，常便于优化；通常保存一阶和二阶状态，显存额外开销较大
AdamWAdam 参数 + weight_decay将权重衰减与自适应梯度更新解耦；正则化强度需根据任务单独选择

以浮点参数规模为 P 的常见实现估算：Momentum 需要约一份 P 大小的动量状态；Adam/AdamW 通常需要两份 P 大小的一阶、二阶状态。实际显存还受到参数精度、梯度、优化器实现和临时缓冲区影响，这不等于 Adam 总显存必然是 SGD 的三倍。

AdamW · 解耦权重衰减的简化更新
θt+1 = θt − η m̂t√v̂t + ε − ηλθt
λ 为 weight decay。式子说明：除梯度更新外，再按当前参数进行单独衰减。具体实现会涉及先后顺序与参数组设置；一般不直接给 Bias、Norm 的全部参数施加相同衰减。

2.5 · betas、eps、momentum 应该怎样理解？

Momentum / β₁：记住过去的方向

增大时通常使历史影响更持久，可能减轻方向抖动，但也更容易延续错误方向或超调。它不是学习率的替代品。

β₂：记住平方梯度的尺度

较高的 β₂ 使二阶尺度估计更平滑、响应变化更慢；较低值响应更快，但估计也可能更不稳定。

ε：分母的稳定项

防止很小的平方梯度尺度导致数值问题。改动它也可能改变实际更新幅度，通常不应当作首要调参旋钮。

weight_decay：约束权重

调大通常使参数衰减更强，但过强可能欠拟合；与学习率、训练步数和参数分组相关。

优化器没有脱离任务的“默认胜者”。 第一次建立基线时，固定优化器，先验证损失、梯度和学习率正常；不要同时改变优化器、Batch、学习率与正则化，否则难以判断是哪一项起作用。
03 LEARNING RATE & SCHEDULE

明明方向算对了，为什么学习率仍会让训练失败？

梯度给出局部变化方向，学习率决定沿这个方向移动的尺度。学习率太小，进展可能缓慢；太大，则可能在低损失区域两侧反复跳跃甚至发散。即使采用 Adam，也仍然需要合适的全局学习率。

机制图 · 相同地形，不同学习率的典型行为

3.1 · 为什么训练过程中要调整学习率？

训练早期往往希望较快探索参数空间，后期则更需要稳定地细化参数。常见做法包括阶梯衰减、余弦衰减，以及训练开始阶段的 Warmup。

余弦退火 · 一种常见的学习率计划
η(t) = ηmin + ½(ηmax−ηmin) · [1 + cos(πt/T)]
t 表示进度，T 为设定的衰减周期长度；该表达式表示从最大值平滑衰减到最小值。Warmup 可以在这段计划之前使用。

3.2 · 怎样区别优化器问题和学习率问题？

先检查学习率、损失尺度、梯度和数据，再考虑换优化器。直接从 SGD 改成 Adam，可能掩盖训练数值或数据本身的问题。

一个必要区分：Loss 曲线出现波动，不必然意味着训练失败。Mini-batch 本身引入梯度随机性，更重要的是观察趋势、梯度是否有限，以及验证集表现是否同步改善。

3.3 · 学习率到底是在控制什么？

学习率 η 不是“每次参数都会变 η 那么大”。对 SGD，实际更新量 = 学习率 × 梯度；对 Adam/AdamW，则还经过自适应缩放。因此，相同的 η 在不同优化器、不同损失尺度或不同参数组中并不代表相同的移动幅度。

η 太小

每步更谨慎，可能需要更多参数更新和更长训练时间；如果调度过早衰减，也可能还没学会就几乎停止更新。

η 太大

可能快速下降，也可能越过低损失区域、震荡、产生 NaN；并不能仅凭一次 Loss 抖动就判定过大。

Warmup

前若干步逐渐增大学习率，降低训练初期不稳定的风险；代价是这段时间更新较慢，不是所有任务都需要。

Decay / Cosine

后期逐渐减小步幅，便于细化参数；过早衰减会减少有效优化，调度必须与总更新步数对应。

同一局部梯度，不同学习率
Δθ = −ηg　→　|Δθ| = η|g|　（SGD，η≥0）
示例：g=0.2 时，η=0.01 对应更新 −0.002，η=0.1 对应 −0.02。但仅靠这组数不能确定哪个好，因为还需要知道损失曲率和其他参数。

交互实验 · 学习率与调度如何改变收敛轨迹？

一维教学函数 L(w)=½(w−3)²，起点 w=−3。仅比较机制，真实深度网络没有统一的稳定学习率阈值。

纵轴使用 log₁₀(L+0.0001) 映射，便于同时观察很小和很大的损失；超出展示范围的点会裁剪。对于该一维二次函数，固定学习率 SGD 在 0<η<2 时收敛；这不是神经网络的通用规则。

3.4 · Batch 改变以后，学习率要同步变吗？

Batch 变大时，每个 Epoch 的更新次数减少，而梯度统计也发生变化。因此学习率与 Batch 不是两个独立旋钮。有些大型分布式 SGD 实践采用过“Batch 放大 k 倍，初始 LR 也近似放大 k 倍 + Warmup”的经验规则，但这只在特定模型、训练配方和范围下有效，不能照搬到所有 AdamW、检测或小数据训练。

先问清训练预算：你是在固定 Epoch、固定优化器 Step，还是固定看到的样本数下比较学习率？三个条件不同，实验结果的意义也不同。学习率搜索时，每次只改变一个主要变量，并同时记录训练曲线和验证结果。
04 INITIALIZATION & NORMALIZATION

为什么网络越深，有时越难稳定训练？

参数的初始尺度不合理，或中间激活与梯度的数值范围失控，都可能让深层网络难以优化。这里先建立两项主要手段：合理初始化和归一化。

4.1 · 为什么权重不能随便初始化？

如果权重规模过大，激活或梯度可能被层层放大；过小则可能逐层衰减。此外，同一层神经元如果完全对称，可能无法学出有区别的表示。

He 初始化 · 针对 ReLU 类网络的常见近似尺度
Var(W) ≈ 2 / fanin
fanin 是每个输出单元连接的输入数量。不同激活、网络结构和初始化分布需要不同假设；Xavier/Glorot 初始化则是另一类常见选择。

4.2 · BN、LN 分别在归一化什么？

归一化是选定若干统计维度，计算均值与方差，然后标准化，并通常允许可学习的缩放与平移。

归一化的基本计算
z = (x − μ) / √(σ² + ε)，  y = γz + β
μ、σ² 来自选定维度的统计量；γ、β 是可学习参数。BN 和 LN 主要区别不是有没有这个公式，而是统计量沿哪些维度计算。
机制图 · 通过选定维度的统计量调整激活尺度
方法主要统计依据需要特别注意
Batch Normalization (BN)训练时使用当前 Mini-batch 的统计信息（卷积 BN 通常还汇总空间位置）训练与推理处理方式不同；推理通常使用累计统计量
Layer Normalization (LN)对单个样本的指定特征维度计算统计量不依赖同批其他样本的统计量；具体轴由实现定义

4.3 · 还有哪些常见数值问题？

梯度爆炸 / 消失

梯度在多层反向传递中可能变得极大或极小。可以检查梯度范数、激活值和初始化；梯度裁剪可限制过大的梯度，但不能解决所有根因。

训练 / 推理模式不一致

BN、Dropout 等层具有与模式有关的行为。训练中应使用训练模式，验证时切换推理模式，避免把运行模式错误误判为模型问题。

Residual Connection（残差连接）也是深层网络可训练性的重要思路，相关机制放到下一阶段的「深层网络与多尺度」重点研究；这里不重复展开 ResNet 结构。

4.4 · 梯度裁剪、混合精度，分别解决什么？

设置控制什么成本与注意
Gradient Clipping在更新前限制梯度范数或取值范围有助于抑制异常大梯度；阈值太小会压低有效更新，不能治愈错误标签或不合理学习率
AMP / BF16 / FP16部分计算使用低精度以提升吞吐或节省显存算子兼容、数值范围和框架实现影响收益；FP16 常需关注梯度缩放，BF16 也不是所有硬件都高效
Gradient Accumulation将多个 Micro-batch 梯度合并后再更新改善显存约束，不自动提升吞吐；与 BN 和梯度裁剪的执行时机有关系
BatchNorm / LayerNorm标准化特定维度的激活BN 小批次统计可能较不稳定；LN 统计不依赖同批其他样本，但效果仍取决于网络与任务

一个特别重要的连接：通过累积把有效 Batch 从 8 变成 64，并不意味着 BatchNorm 在每次前向时也看到了 64 个样本。它通常仍使用 Micro-batch 的统计量。这就是“有效 Batch 相同，训练行为不保证完全一样”的具体原因。

控制顺序：首先排除标签、损失定义和梯度计算问题；接着检查学习率和数据异常；确认确实出现极端梯度时，再评估裁剪与精度策略。不要把裁剪当成万能稳定器。
05 REGULARIZATION & GENERALIZATION

训练损失不断下降，就说明模型越来越好吗？

不一定。训练优化关注的是让模型拟合训练样本；我们真正希望的是它在未见数据上也能工作。若训练集损失继续降低，但验证集损失逐渐变差，就需要警惕过拟合或训练与验证流程的问题。

机制图 · 训练损失与验证损失可能朝不同方向变化

5.1 · 常见约束手段在限制什么？

方法主要作用不应误解为
Weight Decay抑制参数过大，形成一定的复杂度约束所有参数都应以同样强度衰减
Dropout训练时随机屏蔽部分单元或连接的贡献推理时仍应按相同方式随机丢弃
Data Augmentation通过合理的样本变换扩展训练变化范围任意增强都一定符合任务语义
Early Stopping根据验证表现选择停止点或最佳检查点训练损失最低就一定是最好模型

这里仅理解它们为什么被提出。数据集划分、指标选择、分布变化和数据增强的具体策略，后面「训练、评价与泛化」将单独研究。

5.2 · 正则化强度和训练轮数，代价是什么？

参数调大 / 调强通常意味着可能付出的代价
Weight Decay λ更强的权重衰减，减少某些过度复杂的拟合过强可能欠拟合；需区分 AdamW、参数分组和 LR
Dropout p训练时随机屏蔽的比例增加可能更难拟合训练集；不是越高越好，很多 CNN 结构未必需要大量 Dropout
Augmentation 强度训练样本变化增多不合理旋转、缩放、裁剪可能改变标签或使目标不可见；增加数据处理成本
Epochs / Max Steps更多数据遍历或参数更新机会训练成本增加，后期可能过拟合；在 Batch 改变时不能单独靠 Epoch 比较
Patience / Early Stop停止条件更宽松、等待验证改善更久更耗时间；过短容易误停，过长可能无效消耗

5.3 · 训练多久才算够？

区分三个量：Epoch 统计看过多少轮数据，Optimizer Step 表示真正更新了几次参数，Wall-clock Time 表示实际时间成本。若 N=12,000、有效 Batch 为 64，一个 Epoch 大约 188 次更新；有效 Batch 改为 16，则约 750 次。两种配置即使训练相同 Epoch，也经历不同数量的参数更新。

选择停止点时，应结合验证集目标指标、泛化差距和资源预算，而非简单追求训练损失最低。对于检测、分割等任务，最终依据应当包括与任务相关的 mAP、IoU 或其他指标，而不只是 Loss 数值。

06 HYPERPARAMETER TRADEOFFS

这些超参数怎样联动？先改哪一个？

看到一长串超参数时，不要同时优化全部。先判断当前的约束是什么：显存不够、训练不收敛、速度太慢，还是训练好但验证差？每种问题对应的主要旋钮不同。

主要旋钮改变的东西典型代价 / 风险观察什么
micro_batch单次前向样本数显存、算子效率、BN 统计GPU 峰值显存、images/s
accumulate多次梯度合成一次更新每次更新所需计算和时间有效 Batch、更新次数
lr + scheduler每次参数移动的步幅及其变化震荡、过慢、过早减小loss、grad norm、验证指标
optimizer / momentum / betas如何利用历史梯度状态显存、更新动力学更新稳定性、吞吐和显存
weight_decay / dropout训练约束的强度欠拟合或正则不足训练/验证差距
epochs / patience训练预算与停止策略训练时间、过拟合和过早停止最佳验证点、总计算成本
precision / grad_clip算术精度及异常梯度限制精度风险、过度裁剪NaN/Inf、数值范围、吞吐

6.1 · 三种典型情形，应该怎么判断？

显存 OOM，但还希望保留有效 Batch

先减少 micro_batch；需要原来的有效 Batch 时，增加 accumulate。对照 BN 行为、训练吞吐和优化器 Step。混合精度可评估，但要测实际收益。

损失暴涨或出现 NaN

先检查数据和损失是否有异常；再检查 lr、数值精度、梯度范数。必要时考虑 Warmup、梯度裁剪，而不是一上来把 Batch 改得很大。

训练曲线很好，验证却差

检查数据划分和训练/验证预处理，再考虑 augmentation、weight_decay、early stopping。并确认指标是否与真正的任务目标一致。

训练很慢

记录 samples/s、step/s、GPU 利用率，分清数据加载慢、GPU 计算慢还是 Batch 太小。更大的 Batch 不一定让总训练时间更短。

6.2 · 一次只改变一个主要因素

验证流程正确

在很小的数据子集上尝试过拟合；确认预测、标签、Loss、梯度更新和验证模式都对。

确定资源约束

找到不 OOM、运行稳定且吞吐合理的 Micro-batch，再决定是否需要梯度累积或 AMP。

确定优化轨迹

固定数据与总 Step，选择一个优化器和初步 LR；再研究调度，必要时做小范围 LR 对比。

处理泛化与停止

用验证集决定增强、权重衰减和训练停止点；记录准确率、代价及失败案例。

实验记录的最小单位：不止保存一组超参数，还要同时保存 Batch / 累积 / GPU 数、总更新步数、实际学习率曲线、耗时、峰值显存、训练与验证指标。否则“更快”或“更好”的结论很可能来自不公平的训练预算。
延伸阅读：PyTorch AdamW · PyTorch AMP 与梯度累积 · 大 Batch、LR Scaling 与 Warmup 的经典实践。这些是机制和实践来源，不表示所有场景应沿用论文配置。
07 MINIMUM TRAINING CHECK

训练不正常时，应该先检查什么？

不用一开始就遍历所有超参数。先确认训练循环本身正确，再判断是数据、学习率、梯度尺度还是泛化问题。

现象优先检查
Loss 变成 NaN / Inf输入是否有限、损失计算、学习率、梯度/激活范围、数值精度
Loss 基本不变是否真的更新参数、梯度是否为零、学习率、冻结层与标签
Loss 大幅振荡学习率是否过高、Batch 波动、异常样本、归一化状态
训练好而验证差训练/验证分布、数据泄漏、模式切换、过拟合与增强策略

7.1 · 一个最小的训练循环

伪代码 · 一次 Mini-batch 更新
optimizer.zero_grad()   # 清除上次梯度
prediction = model(batch_x)
loss = criterion(prediction, batch_y)
loss.backward()         # 计算梯度
optimizer.step()        # 用梯度更新参数
真实项目通常还需要数据加载、训练/验证模式、设备与精度管理、日志和检查点。此处仅展示最基本的“前向—反向—更新”关系。
学完后应能独立解释

① 为什么 B=1 和 B=64 的梯度不同？② Momentum 和 Adam 在原理上各利用了什么历史信息？③ 为什么学习率过大可能使训练发散？④ BN 与 LN 的统计维度有什么不同？⑤ 为什么训练损失下降并不等于泛化提高？

这一篇要建立的不是“最优调参表”，而是一个可验证的训练模型：
① Mini-batch 决定梯度如何估计。
② 优化器与学习率决定怎样更新参数。
③ 初始化、归一化和正则化帮助训练，但不能替代数据与验证。
