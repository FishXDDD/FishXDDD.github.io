02
DATA CURATION

训练数据：LVD-142M 为什么重要？

DINOv2 的进步不只是改 Loss，还依赖大规模、多样且经过筛选的视觉数据。

图 02 · 从网页图片到精选训练集的实际思路
1.2B初步过滤后的网络图片安全过滤、图像去重前置处理
去重图像表示与近重复检测减少重复，排除评测图像近重复
参考集多种精选视觉数据源用作视觉检索的查询分布
相似检索以视觉特征筛选图片聚类 / 近邻匹配
142MLVD-142M大规模多样图像预训练集
图像选择阶段可借助已有模型的视觉特征，但 DINOv2 的自监督训练 Loss 不使用这些图像的人工类别标签。
它解决了什么问题？ 训练图片越多，并不意味着越有效。大量重复、分布单一或者质量差的图片，会让训练资源浪费在冗余模式上。DINOv2 利用精选视觉数据源引导检索，从庞大的网络图片库中构造更有覆盖性的训练集。

这是数据工程贡献，不是网络前向传播里的一个新算子。

利用不同大小的裁剪学习 CLS 一致性；同时从 Global 的被遮挡位置学习 Patch 预测。

真实论文方法中的掩码是对 Student 的部分 Global Patch 进行替换，不是 MAE 那种直接删掉大量 Patch Token。

交互实验 A｜Student 的 Mask 和 Teacher 的完整视图有什么区别？

Teacher｜无遮挡的 Global 图像

所有 Patch 保留原始视觉信息；绿色外框标出 Student 将要预测的位置。

Student｜相同位置，但部分内容未知

被遮挡位置用 Mask Token 替代内容；该位置仍然保留在 Transformer 序列里。

一句话：Teacher 用完整信息给出答案，Student 看不到被遮挡位置的内容，却要预测该位置 Teacher 的特征分布。

与 MAE 的本质区别

MAE：Encoder 只接收可见 Patch；Decoder 补齐缺失位置，并通过 RGB MSE 学习。
DINOv2/iBOT：Student ViT 仍有全部 Patch 位置，其中部分是 Mask Token；它直接通过 Head 预测 Teacher 的 Patch 分布。

为什么 2 个 Global + 多个 Local？

让包含局部内容的小视图，也能学到与同一张图片的整体视图相一致的表示，降低模型对单一裁剪尺度的依赖。Patch 级任务则保持局部空间位置的一一对应。

CLS 特征：1 × 1536

作为当前 View 的图像级表示，进入 DINO Head；多个不同裁剪 View 的 CLS 分布进行跨视图对齐。

Patch 特征：256 × 1536

每个 Patch 都保留一个对应位置的输出，进入 iBOT Head；只挑选 Student 被遮挡的位置计算 Patch Loss。

Teacher/Student 的 ViT Backbone 结构相同；训练时参数不同，Teacher 按 Student 的 EMA 更新。大模型 ViT-g 的隐藏维度为 1536；小模型 ViT-S 的隐藏维度是 384。

为什么中间是 256？

把高维 ViT 输出投影到较小的训练表示空间。256 是 Bottleneck 维度，并不等于 Patch 数量，也不是类别数。

为什么再输出 65,536？

最后一层线性映射输出 65,536 个原型得分（logits），Softmax 或 Teacher 平衡后才是用于 CE 的分布。输出坐标不是人工类别。

Head 的两个用途：DINO Head 作用于 CLS；iBOT Head 作用于 Patch。论文方法强调两条任务采用独立 Head；公开代码提供 ibot.separate_head 开关，故不同配置可能共享或分开。

Student logits 通过 Softmax 形成 pCLS；这里的网络可接受 Loss 梯度。

LDINO = − Σk qCLS,k · log pCLS,k
对同一张图的有效跨视图配对计算交叉熵并求平均。K 为训练 Head 的原型输出维度（常见为 65,536），不是类别个数。

DINOv2 并不是让 Student 输出“猫”这个真实标签。它要求：来自同一张图的不同视图，最终能对训练 Head 的输出坐标形成相近的概率分布。

真实 2 Global + 8 Local：共有多少个配对？

教师有 q(g1)、q(g2) 两个目标。学生有 p(g1)、p(g2)、p(l1)…p(l8)。同索引的 Global 自身视图不计入，剩下 2×10−2=18 个有效匹配。

IMAGE-LEVEL LOSS · STEP BY STEP

精讲补充：DINO Loss 的“一个样本、一对视图、一遍计算”

下面不把所有操作压缩成一个交叉熵公式，而是跟踪从 Global/Local、CLS、Head 到 q/p、交叉熵和梯度的全部链条。

STEP 01 · VIEW
同一原图，采两张不同视图
Teacher 看 Global g1；Student 看 Global g2 或 Local l。两种裁剪不要求相同的像素坐标。
STEP 02 · BACKBONE
分别计算 CLS
以 ViT-g/14 为例：224² → 257 个 Tokens → CLS [1536]；Local 96² → 37 Tokens → CLS [1536]。
STEP 03 · HEAD
统一到原型得分空间
CLS → Head → [K] logits。K 可以是 65,536；坐标 k 不是“猫狗类别”，而是训练中学出的输出维度。
STEP 04 · TARGET / PRED
生成 q、p 并比较
Teacher 生成停止梯度的目标分布 q；Student logits 经过温度 Softmax 得到 p；计算跨视图交叉熵。

计算 Loss 后，梯度经过 Student Head 回传到 Student ViT。

q = TargetBalance(zt/τt)；p = softmax(zs/τs)
TargetBalance 可由配置选择 Centering+Softmax 或 Sinkhorn–Knopp；不是两种方法同时叠加。Cross-Entropy 用 q 作为固定目标。
CE(q,p) = −Σk=1…K qklog pk　　→　　反传到 Student
只对当前有效的跨视图对计算。训练时不是做概率向量的欧氏距离，也不要求两个 Crop 的 Patch 一一对应。

用三个输出坐标手算一次

设 Teacher 目标 q=[0.7,0.2,0.1]，Student 预测 p=[0.2,0.5,0.3]：

L = −0.7 ln(0.2) − 0.2 ln(0.5) − 0.1 ln(0.3) ≈ 1.385

如果 Student 逐渐预测 p=q，交叉熵变为约 0.802，达到该固定目标 q 的最低交叉熵。它不会必然降到 0：软目标有自身的信息熵。

Loss 究竟怎样推动 Student？

对 Student 的第 k 个 原始 logit 求导，交叉熵的梯度形式为：

∂L / ∂zs,k = (pk − qk) / τs

若第 1 个坐标 p₁=0.2 但 q₁=0.7，则梯度为负，梯度下降会倾向于提高 Student 的该 logit；反之会压低。之后梯度继续穿过 DINO Head 与 ViT。

真实配置：18 个 Loss 配对不是 18 个 Teacher 网络

设一个 Batch 有 B 张原图，每张各产生 g1/g2 与 8 个 Local。Teacher 为每张图输出 2 个 q，Student 输出 10 个 p。同一索引的 Global 自匹配不计，故每张原图 2×(10−1)=18 个有效配对。对这些 Cross-Entropy 求平均，再对 Batch 求平均，得到标量 DINO Loss。

Tensor 追踪（ViT-g/14）：Teacher CLS [2B,1536] → logits [2B,K]；Student CLS [10B,1536] → logits [10B,K]；每一对使用两个长度 K 的分布，最终 Loss 是标量。

为何对比不同视图？ 同一物体裁剪、颜色、尺度不同，但希望保留相对稳定的语义表示。多视图一致性提供学习约束；Teacher 的平衡分布与 EMA 等机制用于避免直接坍塌。

LiBOT = 平均i∈Masked [ − Σk qi,k · log pi,k ]
只对被遮挡的位置计算交叉熵；Teacher 的目标与 Student 的预测必须对齐到同一 View 的同一 Patch 索引。
图中高亮只是帮助定位同一 Patch。真实训练时会为 Global 生成随机掩码，通常在多处位置计算 iBOT Loss。

与 DINO Loss 的区别

DINO：CLS 对 CLS，允许不同 Global / Local 视图之间进行比较，不需要逐 Patch 位置对应。

与 MAE 的区别

MAE：缺失块 → RGB 回归 → MSE。iBOT：缺失块 → 教师的 Patch 分布 → 交叉熵。

为什么需要它？

图像级一致性不直接规定每个空间位置的表示质量。Patch 目标让模型额外学习局部上下文与位置相关的可迁移特征。

不要误解：iBOT 不要求 Student 把原图像素恢复出来。两个分支虽然都有 Head，但 Head 输出的是训练用的原型得分，并不是图像重建 Head。

精讲补充：iBOT Loss 的 Patch 到底怎样对应？

iBOT 不是让 Student 复原 RGB，也不是拿 g1 的第 35 块去对比 g2 的第 35 块；它要比较同一个 Global View、同一个 Patch 索引的 Teacher/Student 输出。

STEP 01 · PATCHES
提取对应的 Patch Token
Global 224×224，Patch14 → 16×16=256 个位置。Teacher 和 Student 同位置索引含义一致。
STEP 02 · MASK
Student 用 Mask Token 替代输入
Mask 发生在 Student ViT 的输入 Token 阶段；Teacher 保留真实像素内容。被 Mask 的位置仍在序列中。
STEP 03 · HEAD + q/p
分别输出 K 维概率分布
Teacher 第 i 个 Patch → qi；Student 同位置 → pi；都通过用于 Patch 级训练的 Head。
STEP 04 · MASKED CE
只对 M 内位置求损失
每个位置做一遍 −Σ q log p，再对被 Mask 的位置和 Batch 聚合。梯度回传 Student ViT + Patch Head。

iBOT 的完整公式，不要只看成一张图一个标量

CEi = −Σk=1…K qi,klog pi,k
i 是空间 Patch 索引，k 是 Head 的原型输出坐标。两个下标代表两种完全不同的维度。
LiBOT = (1/Bg) Σv=1…Bg [ (1/|Mv|) Σi∈Mv CEi ]
这是每个 Global View 先按掩码数量平均、再按视图/Batch 平均的直观写法，Bg 是参与训练的 Global View 总数；无 Mask 时需按实际训练分支另行处理。官方代码会将采样的 Mask 展平并采用 per-mask 权重进行归一化。

例如一张 Global 图遮挡 4 个 Patch，4 个 CE 依次是 1.4, 0.8, 1.1, 1.5，这张图的 iBOT 项就是 (1.4+0.8+1.1+1.5)/4 = 1.2。如果另一个 Global 遮挡 8 个位置，它不会仅因位置数量翻倍就自动贡献双倍权重。

真实维度：B=2，ViT-g/14

为什么它比 DINO 更关心局部？

DINO 对比 CLS，不强制某一个 Patch 学到什么。iBOT 则在缺失内容的位置用 Teacher 特征作为目标，迫使 Student 使用周围上下文推测局部表示。

这不是像素回归：目标 qi 是教师网络学出来的分布，因此即使 Student 的最终特征不是原图像素，也能形成局部语义/结构学习约束。

“同位置”指同一个 Global 裁剪图 的 Patch 网格索引。不同增强视图之间的图像级 DINO Loss 不要求 Patch 对齐。
两条 Loss 可以使用不同的 Head：论文的大规模实验采用独立 DINO Head 与 iBOT Head；官方通用 YAML 的 ibot.separate_head: false 则共享 Head。两种情况下 iBOT 都是 Patch 分布 CE，Head 输出维度 K_ibot 由配置决定，不是 Patch 数量。

TEACHER TARGET DISTRIBUTION

Teacher 的 q 如何变得稳定：Centering 与 Sinkhorn–Knopp

这一步是构建目标分布，不是训练另一个分类器。

为什么不能直接照搬普通 Softmax？

如果所有图片都长期偏向同一输出坐标，即使 Student 模仿 Teacher，表示仍然可能退化。DINOv2 因而关注 Batch 内输出分布的使用是否充分。

论文中的主要方法：Sinkhorn–Knopp

对 Teacher 的一批原型得分进行迭代归一化，让每个样本形成概率分布，同时尽量平衡 Batch 中不同原型的使用。

SK 试图改善的方向

仅为理解“避免独占同一原型”的示意，不代表 SK 会强制每张图独占不同坐标。

论文与代码需区分：DINOv2 论文强调 Sinkhorn–Knopp；官方训练配置同时允许传统 centering 与 sinkhorn_knopp 两种模式，且公开的通用默认 YAML 写的是 centering。不能把 SK 写成所有公开训练配置都固定启用的操作。

预训练大 Teacher

ViT-g/14：CLS 特征 [B,1536]；Teacher Head → q [B,K]。参数在蒸馏全过程保持固定。

训练小 Student

ViT-S/14：CLS 特征 [B,384]；Student Head → p [B,K]。只需要最终 q、p 的坐标数一致，不要求 Backbone 的 1536 与 384 相等。

核心：ViT-g 的知识通过 q 传递，而不是将大模型的 1536 维 CLS 直接复制成小模型的 384 维 CLS。Cross-Entropy 的监督目标来自冻结的强教师。

这一阶段还是不是“自监督”？

不需要人工类别标签，目标来自之前无标签预训练好的 ViT-g。但严格说它不再是从零开始的“同规模模型自蒸馏”，而是固定教师的无标签知识蒸馏。

“Teacher 会不会更新”要按阶段回答：大模型自监督阶段 会（EMA）；小模型蒸馏阶段 不会（冻结）。

论文明确列出的蒸馏差异

作者沿用 DINOv2 训练循环，但明确：① 使用预训练且冻结的 ViT-g；② 维护小 Student 的 EMA 副本作为最终模型；③ 蒸馏训练取消 Patch Masking 与 Stochastic Depth；④ 在两个 Global Crops 上应用 iBOT 目标。

因此，前面“Masked Patch iBOT”的讲解对应基础自监督预训练；蒸馏阶段不应照搬成“同样随机遮挡”。

精讲补充 B｜多分辨率并不是一种新 Loss：先解决位置编码，再做高分辨率适应

Step 2：为什么插值已经能跑，还必须继续训练？

位置编码插值 = 解决“形状不兼容”

原来学到 256 个 Patch 位置向量；新图像有 1369 个 Patch，不能直接与原位置编码相加。先将原来的 [16,16,D] 用双三次插值扩展为 [37,37,D]，再重排为序列。

这使同一个 ViT 可以处理新增 Token，但并不能自动保证高分辨率精度最优。

高分辨率继续训练 = 改善“特征质量”

模型的大部分训练在较低分辨率进行，局部细节和小目标可见的信息较少。提升分辨率后，通过相同自监督目标在更密集的 Patch 网格上继续优化，使高分辨率特征适应新输入分布。

主要训练结构与 Loss 并没有变成新算法。

新增图 11D · 两阶段训练时间线：不是“推理时插值”等于“训练过高分辨率”
阶段 I · 主要预训练224 × 224

训练 ViT-g 的自监督表示：DINO / iBOT / KoLeo。此阶段消耗大部分训练计算。

阶段 II · 继续预训练518 × 518 · 10k iterations

加载已训模型 → 插值 Pos Embedding → 较低 base LR → 使用原来的自监督训练程序继续训练一段。Teacher 仍按 EMA 更新。

阶段 III · 推理可变输入尺寸

满足 Patch Size 的实现要求，在不同分辨率生成 Token 并使用位置编码插值；极端尺寸仍应验证质量、显存与延迟。

论文在 §4 描述最终高分辨率适应使用 518×518；§6.6 的消融另外用 ViT-L/16 对比 224、416、224→416（10k 步），不能把两套实验中的数字混为一谈。

Step 3：计算成本为什么会上升？

224×224、Patch14：N=257。518×518、Patch14：N=1370。Token 数约增加 5.3 倍；如果仅比较标准全局 Attention 的 N×N 相似度矩阵元素数，增加约 (1370/257)² ≈ 28.4 倍。

28.4 倍不是整个模型 FLOPs 或训练耗时的真实倍数：Patch Embedding、MLP、算子实现和访存都影响实际成本。论文的 ViT-L/16 消融报告，416 分辨率相对 224 分辨率的训练计算成本约 3 倍，而末尾短期高分辨率训练以较小成本获得接近的特征效果。

一句话区分：ViT（2020）已经具备位置编码插值的基础能力；DINOv2 并未发明这一算子，它通过低分辨率大规模自监督预训练 + 高分辨率短期自监督适应，在训练成本与高分辨率特征质量之间做折中。
依据：原论文 §4 / §6.6 / Appendix B.2；ViT interpolate_pos_encoding()；原始 ViT 论文 §3.2。

后续的 Registers 变体

在 Transformer 输入中增加 4 个可学习 Register Tokens，用于提供额外计算/存储空间，改善部分 Patch 特征出现的伪影。

1 CLS + 4 Reg + 256 Patch = 261

Registers 来自后续独立研究《Vision Transformers Need Registers》，并非 2023 年原论文核心训练 Loss 的组成部分。

真正需要记住的升级路线：原始 DINOv1 主要依赖 CLS 的跨视图一致性；DINOv2 在此基础上学习 Patch 的局部特征分布，再加上 KoLeo、精选数据和规模化训练；Registers 属于后续结构改进。
