00

研究问题：CNN 已经有多层特征，为何还需要 FPN？

不是缺少不同分辨率的特征图，而是不同层的“语义强度”不一致。

图 01｜三种旧思路与 FPN 的真正区别研究动机 · 不同尺度目标如何获得既精细又有语义的特征
IMAGE PYRAMID

方案 A · 图像金字塔

把图像放大缩小多次，各尺度重新提取 CNN 特征。语义强，但计算与显存成本高。

SINGLE MAP

方案 B · 单层检测

只在 C4 或 C5 上预测。省计算，但高层分辨率粗，小目标细节容易丢失。

SSD-STYLE

方案 C · 直接多层预测

SSD 已在多个不同深度的特征层分别预测，但各层语义能力不均衡。

FPN · 2017

新方案 · 多层先融合再预测

先将高层语义向浅层传递，再结合细粒度位置细节，最终在每一层独立预测。

核心矛盾：浅层“看得细”，高层“看得懂”。FPN 要求所有输出尺度尽量兼具二者，而不只是额外增加几层卷积。
先建立一个定位：FPN 自身不是一个完整目标检测器。它通常插在 Backbone 和检测头之间，形成更强的多尺度特征供 RPN、Fast R-CNN 或其他检测头使用。

1.1 Bottom-up：为什么从 ResNet 的 C2、C3、C4、C5 开始？

Backbone 的前向计算本就逐级降低分辨率。选取 ResNet 每个 stage 最后一层特征，得到 C2–C5；它们是有层次差异的特征，还不能直接看作“每层同等语义水平”的多尺度检测输入。

1.2 Top-down + Lateral：从 C5 的语义传到 C2 的高分辨率

STEP 01

1×1 Conv · 横向投影

将 C2–C5 的通道统一成 256。它是可学习的通道线性组合，便于同尺寸特征逐元素相加；不会放大空间分辨率。

STEP 02

Upsample ×2 + Add

把上层 M 特征最近邻上采样 2 倍，与下层对应 C 的 1×1 投影逐元素相加。上层贡献语义，下层贡献空间细节。

STEP 03

3×3 Conv · 平滑输出

将相加后的融合结果再经过可学习的 3×3 卷积，减轻最近邻上采样带来的混叠；生成最终 P2–P5。

M5 = Conv1×1(C5)
Mℓ = Conv1×1(Cℓ) + Upsample×2(Mℓ+1),　ℓ=4,3,2
Pℓ = Conv3×3(Mℓ),　ℓ=2,3,4,5
这里的加法要求两个输入具有相同的 H×W×256 形状；原论文用最近邻上采样与逐元素加法。3×3 平滑卷积在各层各自学习，不是共用一个固定滤波器。
02

核心算法：为什么这样融合，而不是把所有层直接拼起来？

把“语义向下传递”和“细节横向补充”真正看成数值运算。

为什么使用相加，而不是 Concatenate？

原论文采用逐元素相加：两条路径投影到相同的 256 通道后，输出仍是 256 通道，结构简单、额外计算少。拼接并非不可用，但会增加通道数，后续一般还需卷积融合；FPN 的核心贡献不在“只能用加法”。

为什么有 3×3 Conv，还不是普通 Backbone？

3×3 平滑层并不是直接替代 Backbone 的新 stage。它作用于已经混合语义与空间信息的 Mℓ，将其加工成可以提供给预测头的 Pℓ。这些 P 层才构成 FPN 的真正输出金字塔。

03

FPN + RPN：多尺度如何真正参与候选框生成？

与 Faster R-CNN 原始单层 RPN 不同：在多个 P 层上运行同一套 RPN 预测头。

RPN 的逻辑仍是“对 Anchor 判断前景/背景，再回归框偏移量”。FPN 改动的是从哪层特征预测、每层负责什么 Anchor 尺度，没有另造一种全新的 RPN 分类损失。

重要区分：RPN 的各层 Anchor 面积尺度已经预先分配，但训练时 GT 不需要先按尺寸显式分派到某层；它依旧根据不同层 Anchor 与 GT 的 IoU 完成正负样本匹配。

3.1 每个尺度为什么只需要 3 个 Anchor？

原始 Faster R-CNN 单层特征图同时放多个尺度与宽高比；FPN 在不同 P 层分配不同面积尺度，每层只保留 3 种比例（1:2、1:1、2:1）。因此“5 个尺度 × 3 个比例 = 15 种 Anchor 模板”是跨所有层统计，不是每个空间位置都有 15 个框。

每层 3 个不同形状的 Anchor。P6 是在 P5 上做 stride-2 下采样得到的更粗特征，仅用于 RPN 覆盖更大目标，并不送入原论文第二阶段 RoI Pooling。

训练时怎样选正负样本？

Anchor 对任一 GT 的 IoU ≥ 0.7，或是该 GT 的最高 IoU Anchor → 正样本；与所有 GT 的 IoU 都低于 0.3 → 负样本；中间的通常忽略。RPN 正样本同时计算前景分类与边框回归损失。

“可训练”发生在哪里？

RPN 的前景分类与边框回归会产生梯度，传回 RPN Head、FPN 及可训练的 Backbone。训练所依据的 Anchor 匹配、Proposal NMS 等离散步骤本身不需要由第二阶段 Loss 直接求导。

4.1 尺寸映射公式：为什么 224 像素对应 P4？

k = ⌊4 + log₂(√(w · h) / 224)⌋，用于 P2–P5 时限制在 [2,5]
w、h 是输入图像坐标尺度上的 RoI 宽高；√(wh) 是等效边长；k0=4 表示 224×224 的 RoI 被分配给 P4。向下缩小一半，通常前往更精细的 P3。

这个规则是 RoI Head 的尺寸选层，不要与上方 RPN 的 IoU Anchor 匹配混为一谈。公式中 floor 的取整让不同尺寸范围映射到离散层，限制在 P2–P5 属于实际实现时的有效层边界。

为什么小 RoI 去高分辨率层？

一个 40 像素宽的目标，在 stride=32 的 C5/P5 上跨度只有约 1.25 个单元，位置表达过粗；在 stride=4 的 P2 上跨度约 10 个单元，更有利于 Pooling 捕捉细节。

为什么大 RoI 不都放到 P2？

大目标需要覆盖更广的区域，高层特征有更强抽象能力；如果所有目标都从 P2 提取，不仅难以体现适配尺度的优势，也增加高分辨率上的计算量。

相比传统 Faster R-CNN，候选框从“单层 RPN”转为“金字塔 RPN”；RoI 特征从“同一张特征图”转为“按尺度选中的 P 层”。分类、回归、NMS 等基本机制仍继承原检测器。

一个目标从头到尾只选一个 P 层吗？

不一定。RPN 阶段在不同尺度的 Anchor 上竞争提议目标位置；得到 Proposal 后，第二阶段依据这个 Proposal 的尺寸选一个 P 层提特征，两者是不同任务、不同规则。

FPN 能直接替代 ResNet 吗？

通常不能。ResNet / VGG / ConvNeXt 等主要负责提取底层到高层的视觉特征；FPN 接收多层 Backbone 特征并增强多尺度语义。它更接近后来的Neck / 多尺度特征融合模块，而不是独立完整的 Backbone 或检测器。

SSD（2016）不同深度的特征层原始 SSD 检测层间无 FPN 式自顶向下融合不同分辨率分别预测不同大小目标
YOLOv2 Passthrough（2017）26×26 浅层特征重排接入 13×13局部跨层拼接向单个检测尺度补充细粒度信息
FPN（2017）C2–C5 的主干特征自顶向下 + 横向加法输出多层强语义特征 P2–P5 用于预测
PAN / PANet（后续）在金字塔基础上扩展进一步加入自下而上的路径增强改善特征与定位信息的双向传递

总结与论文出处

把 FPN 放进目标检测演进史时，只保留一个足够准确的历史定义。

FPN 的里程碑：不是首次提出多尺度检测，也不是发明了检测头；而是用 Top-down + Lateral Connections，把深层强语义与浅层高分辨率信息结合，构造了低成本、多尺度且语义更强的特征金字塔。
