00

2014 年：R-CNN 明明有效，为什么还不够好？

先找对问题：并非 CNN 不会检测，而是处理候选区域的方式浪费了重复计算。

一张图片经过 Selective Search，可能得到约 2,000 个候选框。R-CNN 依次裁剪这些框并缩放到固定大小，然后对每个框运行一次 CNN。不同候选框往往覆盖相同像素，底层边缘、纹理、局部形状被反复计算。

01

网络结构：一张图片怎样变成候选框分数？

不只画一个 SPP 模块；必须从原始像素、区域、共享特征一直追到最终 BBox。

1.1 Selective Search：候选框仍然来自哪里？

SPPnet 是否已经让 CNN 自己预测候选区域？

没有。原始 SPPnet 仍使用 Selective Search 的 fast mode，得到约 2,000 个类别无关的候选矩形。每个框先只有 (x1, y1, x2, y2)，还没有类别或检测分数。它只表示“这里可能存在一个物体”。

边界：SPPnet 改造的是候选框之后的特征提取方式，而不是候选框产生方式。没有被 Selective Search 覆盖的目标，后续仍难以检出。

1.2 共享卷积：为什么 CNN 可以一次处理整张图？

之前 CNN 总是接收 227×227 图像。为什么这里突然能够接收任意尺寸的图片？

关键是把 CNN 分成两段理解。Conv1–Conv5 等卷积与局部池化运算，并不天然要求整张输入固定为 227×227；真正要求定长输入的是后面的全连接层。因此可以让整张图片先经过卷积，输出空间尺寸随输入变化的 Feature Map。

前半段 · 卷积

输入大小可变，输出网格也随之变化

卷积核在整张图滑动。原图越大，往往得到更多空间位置的特征响应；这些位置可被不同候选区域复用。

后半段 · FC

输入向量长度必须固定

如果 FC6 权重的输入维数固定，那么任意尺寸特征图不能直接 Flatten 后进入 FC6。SPP 正是解决这个接口问题。

I ∈ R^(H×W×3) → Conv1…Conv5 → F ∈ R^(h×w×C)H、W 为图像大小；h、w 随之改变；C 是输出通道数。原论文检测示例使用 C=256。多个候选框 Pᵢ 共享同一个 F（同一输入尺度）。

1.3 核心桥梁：图像上的候选框怎样找到 Feature Map 中的区域？

Selective Search 给出的是像素坐标；Conv5 的 Feature Map 又不是原图大小。究竟在 Feature Map 的哪里池化？

设候选框为原图像素坐标 P=(x1,y1,x2,y2)。先按整图缩放比 α 得到缩放图上的坐标，再通过卷积层的总步幅和感受野对齐关系找到对应的特征图窗口。接下来 SPP 仅在这个窗口里分块池化，而不是把整张特征图都当成同一个候选框。

ROI 坐标示意
教学版映射使用固定缩放后的线性示意，便于观察“哪块区域被选中”。原始实现需要考虑卷积步幅、起始偏移和感受野边界，不能在所有网络中直接简单使用 x / stride 做精确索引。
示意：x′ = α·x，y′ = α·y；u ≈ x′ / S，v ≈ y′ / Sα = 缩放后图像尺寸 / 原图尺寸；S = 特征图相对输入图像的总步幅。真实 SPPnet 的投影采用与具体网络卷积、池化参数相匹配的坐标映射规则，此式用于建立直觉，不是逐像素精确复现。

1.4 Spatial Pyramid Pooling：为什么任意大小的区域都能输出 12,800 维？

一个框在 Feature Map 上可能是 7×11，另一个框是 14×18，FC6 却只接受固定长度向量。怎么做到？

SPP 不再对每个区域统一要求同一个网格尺寸。它先在候选区域内部生成固定数量的分块（bins）：例如 1×1 时整个窗口取一个最大值；2×2 时分成 4 块分别取最大值；3×3、6×6 再提供更细粒度的空间信息。最后将所有块的池化结果按固定顺序拼接。每块的实际像素尺寸可以变化，但每层的块数固定。

理解完整的 12,800 维：上面只展示 一个通道、当前一级的输出。真实网络对 256 个通道分别做四级池化，最终拼接 50×256 个数。不是把所有通道求一个共同最大值。

SPP 使用的是位置相关的统计。假如同一只狗的大多数响应集中在候选框左上角，那么 2×2 或 6×6 网格会保留“左上角更强”的信息；如果只用 1×1 全局池化，这些相对位置的信息就会大幅损失。

1.5 SPP 后接什么？为什么这里还有 SVM 和 BBox 回归？

12,800 维是检测结果吗？网络是不是像现代 YOLO 一样直接输出类别和框？

不是。12,800 维只是候选区域的定长视觉表示，并不等于类别分数或位置坐标。原始 SPPnet 基本延续了 R-CNN 的分阶段检测路线：池化表示进入 FC6/FC7 得到用于检测分类的特征，再由各类别线性 SVM 评分；另一路用池化 conv5 特征预测边界框修正参数。

类别分支 · Classifier

SPP(12,800) → FC6 → FC7(4,096) → SVM

每个类别一个线性 SVM，输出候选区域属于该类别的判别分数。它不是单独训练一个“SPP 输出概率”的简单模型。

scorec(P) = wcᵀ · φfc7(P) + bc
定位分支 · Box Regression

SPP pooled conv5 → 类别相关的线性回归器

通过监督预测候选框到 GT 框的四个几何修正量，帮助更准确地贴合真实边界。该回归器与 SVM 分别训练。

t = (Δx, Δy, Δlog w, Δlog h)

框修正可以沿用 R-CNN 的几何形式，例如以中心点和宽高表示候选框 P 和 GT 框 G：

tx = (Gx − Px) / Pw； ty = (Gy − Py) / Ph
tw = ln(Gw / Pw)； th = ln(Gh / Ph)中心偏移按原候选框宽高归一化，尺度变化用对数比表示。预测值经反变换得到校正后的框；这里只介绍原理，不展开回归器求解。

1.6 为什么还需要多尺度？已经有 SPP，不是可以处理所有大小了吗？

SPP 解决的是“区域输出长度不固定”，还是也让不同尺寸目标在视觉上同样容易识别？

SPP 保证每个候选框都能池化出固定长度的向量，但一个极小目标在低分辨率 Feature Map 上可能只剩几个空间位置，难以保留细节。原始检测实验因此使用了单尺度版和五尺度版。五尺度版为整图建立 5 张不同分辨率的 Conv5 特征图，然后为每个候选框选择最合适的一张来池化。

02

完整训练：SPPnet 到底更新了哪些参数？

沿用 R-CNN 的“分阶段训练”思想，并严格区分 ImageNet 预训练与检测域微调。

读 SPPnet 时最容易产生的误会是：“既然已经有共享卷积和 SPP，是不是最终 SVM、框回归的 Loss 可以一起反向更新整条网络？”原始 SPPnet 的目标检测实现并没有这样做。它先得到预训练卷积网络，在检测微调中仅训练 FC 层，再单独训练 SVM 和框回归器。

2.1 第一步：先学会分类，得到一套预训练 SPPnet

原论文先使用 ImageNet 的大规模分类监督，训练带 SPP 层的 CNN。对于训练分类器，FC 后接 ImageNet 多类别 Softmax，使用交叉熵，反向传播更新卷积和全连接层权重。这时 CNN 学的是图像视觉表示与分类判别，还没获得任何 VOC 检测框预测能力。

多输入尺寸训练（Multi-size Training）

原文提供了交替使用 224×224 与 180×180 输入尺寸的 ImageNet 训练办法；两个不同输入尺寸的网络共享同一套参数，不同训练 epoch 切换尺寸，以利用 SPP 的固定长度输出。这是分类预训练方案；不要把 224/180 和检测推理用的 5 个尺度混为一谈。

2.2 第二步：VOC 检测微调，为什么只更新 FC？

来到检测数据后，一个候选框可能只包含狗的一部分，也可能是纯背景。需要让高层特征适应这种候选区域输入。SPPnet 的做法是：把所有候选的 Conv5 区域经过 SPP 池化成定长特征，将这些特征送入 FC6、FC7、新 FC8（21 类），用检测标签做 Softmax 微调。卷积部分保持冻结。

Lfine-tune = −log py(P)P 是候选框，y 是 IoU 标注出的类别（20 个 VOC 类别之一或背景）；p_y 是 21-way Softmax 给真实标签 y 的概率。这个 Loss 不训练独立 SVM，也不训练 bbox 回归器。
为什么这是局限？它能让 FC 适应“整图卷积后截取区域”的新分布，但检测任务的监督无法进一步调整 Conv1–5。后来的 Fast R-CNN 借助 RoI Pooling 与统一网络训练，使检测 Loss 能反向影响共享卷积层。

2.3 第三、四步：SVM 和 BBox 回归如何分别学习？

第三步 · Class-wise SVM

给每个类别训练一个线性判别器

输入：固定 CNN 的 FC7 特征。原论文用相应类别的 GT 框作为正例，与对应正例 IoU 不高于 0.3 的候选框作负例，并进行困难负例挖掘。学习的是各类 SVM 权重，不回传到 CNN。

最终检测打分用 SVM，而不是直接把微调阶段 21-way FC8 Softmax 作为最终检测器。

第四步 · Bounding-box Regressor

让候选框更贴合 GT 边界

输入：已经池化的 conv5 特征。论文使用与 GT IoU ≥ 0.5 的候选训练框回归，目标为四个平移/缩放量。只优化回归器参数。

这个回归器和 SVM 不是一个端到端共同训练的检测头；推理时两者按各自用途处理同一候选区域。

2.4 交互：同一个候选框，在不同训练阶段到底是什么样本？

一个 IoU=0.70 的候选框，为什么对 FC 微调是正例，但对于 SVM 并不必然是正例？

因为两个阶段想学的东西不同。FC 微调需要学习较宽泛的候选区域分类；SVM 的分类正例采用实际 GT 框，以确保较严格的定位标准。对于普通 Selective Search 候选，即使和 GT 很接近，也不能自动将其当成 SVM 正例。

一个候选框最终对应什么？它可能同时获得 dog、cat、car 等类别的判别分数，以及相应候选框位置的校正。对某个类别保留高分候选，再做重叠去重，就得到最终这一类的检测框。

再从计算复用角度看：假设同一张图有 2,000 个候选框，单尺度版只有整图的卷积计算运行一次；之后仍然要做约 2,000 次的区域池化、FC 计算、SVM 评分和框回归。SPPnet 减少了最昂贵的重复卷积，而不是把候选框判断本身缩减为一次。

概念关系

SPP 和 RoI Pooling 是什么关系？

二者都在卷积特征图中的候选区域执行空间池化，将可变大小窗口转换成固定尺寸的表示。SPP 强调多层级网格（如 1×1、2×2、3×3、6×6），原始 Fast R-CNN 的 RoI Pooling 通常采用单一固定网格，并与统一检测训练结合。

概念边界

和现代 YOLO 里的 SPPF 是不是一回事？

SPPF 继承了“通过不同感受范围的池化汇聚多尺度信息”的思想，但通常是 Backbone/Neck 中的局部特征融合模块；它不等于原始 SPPnet 在每个检测候选 ROI 上执行固定 bins 并接 FC的流程。

05

最后检查：真正理解 SPPnet，应能回答什么？

不用记住一堆论文超参数，先抓住最有复用价值的机制。

CHECK 01

SPPnet 为什么不需要每框做 CNN？

因为 Conv 特征先对整图提取并被各候选共享。各个 ROI 只在 Feature Map 上找到自己的区域，随后池化/FC 仍按候选执行。

CHECK 02

不同宽高的 ROI 为什么都能接 FC6？

SPP 按固定的 1²+2²+3²+6² 个 bins 汇聚，而不是固定每个 bin 在特征图上覆盖多少像素。输出固定 50×256 维。

CHECK 03

检测训练时哪个参数被更新？

ImageNet 预训练可更新 Conv；SPPnet 原始检测微调只更新 FC；最终 SVM 与框回归器各自独立学习，不反向更新 Conv。

CHECK 04

SPPnet 留下的真正瓶颈是什么？

外部候选区域生成开销、候选级高层计算、分阶段优化与无法在检测微调中更新共享 Conv；这些促使 Fast R-CNN 和 Faster R-CNN 继续发展。
