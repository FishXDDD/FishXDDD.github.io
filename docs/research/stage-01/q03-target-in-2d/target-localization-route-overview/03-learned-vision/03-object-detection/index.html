N 随图像改变：可能 0 个、1 个或很多个；还要避免对同一物体重复输出。

D = {(bᵢ, cᵢ, sᵢ)}，i = 1,…,N bᵢ 为边界框（如 x、y、w、h），cᵢ 是类别，sᵢ 是置信分数；N 未知且会变化。检测框通常是轴对齐框，旋转框 OBB 是进一步扩展。

因此所有检测架构，归根到底都要回答下面四组问题。后面每出现一个里程碑，你都可以用这五个问题衡量它改了什么。

① 在哪里预测？

先产生候选区域，还是每个特征图位置直接预测，还是由一组 Query 预测？

② 从什么特征预测？

只使用最后一层，还是使用多尺度特征图？细节与语义怎样结合？

③ 什么样的框算正确？

如何设计 Anchor、正负样本分配、框回归与训练损失？

④ 如何得到最终集合？

密集预测的重复框是否需要 NMS？还是直接学习“一物一预测”？

先建立一个重要区别：Backbone 负责特征表征；Neck 常负责多尺度特征融合；Head 将特征转成类别与框。RPN、RoI、NMS、Matcher 等通常属于检测机制，不是 Backbone 本身。

先约定：以后每个检测器，都必须追踪到最终坐标

你已经理解 Backbone 会把 RGB 图像变成特征图。因此本教程不再反复解释卷积提取特征，而是从“特征图之后怎么变成检测结果”接着讲。一个真正的检测结果不是一堆 Feature Map，也不是 RoI 特征，而是可在原图上画出来的目标集合：

detections = [ {"class":"cat", "score":0.90, "xyxy":[110,100,330,244]}, ... ]
必须追踪的问题需要答到什么程度
① 谁提供位置？Selective Search 的 proposal？RPN 的 proposal？密集特征点？Object Query？
② 提取了什么？整个特征图 H′×W′×C，或固定大小的区域特征 7×7×C，或 Query 向量。
③ Head 输出什么？类别 logits/probabilities、objectness、坐标偏移、边界距离或分布；写清张量大小。
④ 怎样变成像素框？根据 Proposal / Anchor / 特征点 / Query 约定进行 box decode，恢复输入/原图坐标系。
⑤ 如何得到最终 N 个？类别分数、阈值、Top-K、NMS；或 Query 的 no-object / one-to-one 输出处理。

2013 · 深度检测前夜并行前史

OverFeat：分类网络的卷积特征，能否直接用于定位？

具体问题： AlexNet 已经证明 CNN 很会分类，但分类结果只有标签，没有位置。滑窗逐块分类又容易重复计算。

核心设计：具体改变了什么

OverFeat 尝试把分类、定位与检测结合：在共享卷积特征上进行密集预测；对目标位置做回归，并把多个尺度的结果融合。它是 CNN 检测史的重要早期尝试，不能把所有深度检测的起点都归于 R-CNN。

01
密集卷积而非反复分类

把原来分类网络末端的全连接视为卷积运算，在不同空间位置共享计算；得到保留空间布局的类别得分图，而不是只返回整张图的一个类别。

02
跨尺度定位

对多个图像尺度运行网络，使相同感受野对应不同物体尺度；从高分位置推导相应原图窗口。

03
框回归与结果合并

定位分支修正候选窗口的坐标；原论文还对重叠结果做融合处理，不能理解成“分类热图就是精确边框”。

例如一个 20×20 的类得分图，并不代表有 400 个真实目标：每个格点代表一个感受野窗口的响应；映射回原图需知道步长、感受野和图像缩放比例。

R-CNN：候选框是怎么来的，CNN 之后又得到什么？

2013 预印本 / CVPR 2014 · Selective Search → CNN Feature → SVM → Box Regression
历史问题：分类器只会告诉你“这张裁剪图像像不像猫”，但你不知道原图应该裁剪哪块。能不能不枚举所有位置，而是用图像自身的区域结构产生候选框？

第一步：Selective Search 到底做了什么？

一句话：它不识别“猫/狗”，而是先把图像切成很多小区域，再根据相似程度不断合并相邻区域；每次合并后取包围该区域的矩形框，积累成一组“可能存在物体”的坐标候选。

输入是什么？

一张 RGB 图像。例如 640×480×3；没有类别先验、没有物体标签，也不需要训练 CNN。

输出是什么？

多个矩形框坐标：[(x1,y1,x2,y2), …]，例如约两千个候选框。这里没有猫狗类别概率。

阶段 A｜先生成许多小区域（初始过分割）

经典 Selective Search 使用图像分割（常见的 Felzenszwalb–Huttenlocher 图分割）先得到很多互不重叠的小区域。这些区域可能只是猫耳、猫脸、猫身的一部分，并不保证一个区域等于一个物体。算法记录每个区域包含的像素、边界框、颜色直方图和纹理描述等统计量。

阶段 B｜只比较相邻区域，反复贪心合并

对相邻区域 A、B，评价它们是否值得合并：颜色相似（Color）、纹理相似（Texture）、合并后大小合理（Size）、两块拼在一起是否紧凑（Fill）。将这些分数按照某一策略组合，选择当前最适合合并的一对，生成新区域 A∪B，再更新与邻域的相似关系。

s(A,B) = scolor + stexture + ssize + sfill典型组合策略示意；原论文采用不同颜色空间、相似度组合的多种策略以增加候选区域的多样性。
例如 ssize = 1 − (|A| + |B|)/|Image|；sfill = 1 − (|BBox(A∪B)| − |A| − |B|)/|Image|。|A| 是区域像素面积，BBox 是包围盒面积。

阶段 C｜每形成一个新区域，就把它变成矩形框

例如合并后的不规则区域由猫头和猫身体组成，它本身不一定是矩形。算法求该区域像素的 min(x)、min(y)、max(x)、max(y)，存成一个候选框。不是等到全部合并完才输出一个框，而是将各个合并阶段的候选区域都保存下来，这样会得到不同尺度的建议框。

交互实验｜看看“分割 → 合并 → 建议框”

点击四个阶段，看一个玩具分割图怎样逐步合并。不同颜色代表区域；这是帮助理解层级合并的示意，并没有运行真正的 Selective Search。

对每个 Proposal，R-CNN 先在原图按这个框裁剪像素，再 Warp 到固定大小；CNN 对这块区域提特征（例如得到 4096 维向量）。提特征不是终点：原始 R-CNN 再把这个向量送入类别专用的线性 SVM，获得类别判别分数，并用类别专用的框回归器预测相对 Proposal 的坐标修正。训练阶段 CNN 微调、SVM 训练、回归器训练是不同步骤。

具体假设：有一个框 [100,100,300,260]

proposal               = [100,100,300,260]
裁剪并 Warp 后输入 CNN → feature.shape = [4096]
SVM 分数（示意）       = {cat:+2.40, dog:-0.80}
针对 cat 的回归偏移  = (tx:+0.10, ty:-0.05, tw:ln(1.1), th:ln(0.9))
解码后的猫框           = [110,100,330,244]

这里 SVM 的 +2.40 是决策分数，不能不经校准就解释为 90% 概率。它与后面 Fast R-CNN 的 Softmax 是不同的分类输出。

x' = x + txw，y' = y + tyh，w' = w·etw，h' = h·eth这里使用中心点 (x,y) 与宽高 (w,h)。框回归器学的并不是“绝对像素坐标”，而是相对于候选框的平移和比例变化；解码后再转成左上右下的 xyxy。
R-CNN 的最终结果：对所有候选框分别得到类别分数与修正框，然后按类别筛掉低分框、对大量重叠候选运行 NMS，最终返回 (class, score, xyxy) 列表。
遗留问题：同一个目标周围可能有几十个高度重叠的候选框，R-CNN 仍让这些框分别运行一次 CNN。许多像素计算被反复执行；候选产生和分类回归也没有共享统一训练流程。

2014 · 共享特征的先声区域检测

SPPNet：为什么非得把每个候选框都重新送入 CNN？

具体问题： R-CNN 每个 Proposal 都要单独卷积，重叠区域反复计算；但 CNN 已能输出空间特征图。

核心设计：具体改变了什么

SPPNet 先整图计算卷积特征，再把候选框映射到共享 Feature Map；用空间金字塔池化（如 1×1、2×2、4×4）汇总每个 RoI 的固定长度表示。这是从逐框 CNN 走向共享卷积的关键桥梁。

网络计算怎样一步步流动？

整图 → 共享卷积特征图
外部 Proposal → 映射到 Feature Map
SPP 层在多个分辨率网格池化
固定长度特征 → 分类器 / 位置修正
机制拆解 · 计算过程4 个可追踪步骤

SPP 的 1×1、2×2、4×4 到底做了什么

01
先共享卷积

整张图只算一次空间特征图 F∈R^{H′×W′×C}。Proposal 仍由外部算法提供，先按图像/特征尺度映射为 RoI。

02
逐级分箱

一个 RoI 按 1×1、2×2、4×4 三种划分，各自对每个通道每个格子做 max pooling；输出长度与 RoI 原尺寸无关。

03
拼接成向量

三个尺度得到 1+4+16=21 个空间 bin；把每个 bin 的 C 个数拼接为 21C 维向量，再送入后续分类层。

04
与 Fast R-CNN 的区别

SPPNet 在当时的检测微调流程中并未像后来的 Fast R-CNN 那样方便地端到端更新较早卷积层；Fast R-CNN 采用单尺度 RoI Pool 并联合分类/回归训练。

把数值真正走通

若 C=256，则 1×1 分支输出 256 值、2×2 输出 1024 值、4×4 输出 4096 值，合计 5376；SPP 结果是特征描述，绝不是 5376 个候选框。

容易混淆的边界：SPP 不生成候选框；它只把任意尺寸的候选区域转换成固定长度特征。

Fast R-CNN：CNN 的整图特征究竟怎样变成每个目标的类别和框？

2015 · 共享卷积特征图 → RoI Pooling → FC → 双分支输出 → 解码 / NMS
历史问题：R-CNN 对约 2000 个重叠区域反复运行 CNN。能否先对整张图像做一次卷积，再从共享特征图里提取每个候选框对应的局部特征？

先抓住一个事实：Fast R-CNN 的 Selective Search 没有消失。外部算法仍然提供候选框坐标。变化发生在“候选框进入 CNN 的方式”和“特征向量之后的两项预测任务”。

第一步：整图 CNN 得到什么？为什么还能找回框内特征？

假设 RGB 图像大小为 640×480，Backbone 的输出步长 stride=16，得到共享 Feature Map，按 H×W×C 记为 30×40×512。它不是“512 个检测框”，也不是“30×40 个已经分类的目标”——它是 每个空间位置有 512 个特征通道的网格。

Selective Search 给出 Proposal R=[100,100,300,260]。根据图像缩放及特征步长将它映射到特征图，理想化坐标约为 [6.25,6.25,18.75,16.25]。现在你已经知道在 30×40×512 的特征图上应该读取哪块区域。

第二步：RoI Pooling 到底怎样处理一个不规则大小的特征区域？

不同 Proposal 在特征图中覆盖的区域可能是 13×10×512，也可能是 7×22×512。全连接层需要长度一致的输入，因此 RoI Pooling 将每个区域划分为固定的 7×7 个格子，在每个小格、每个通道里执行 MaxPool，输出始终是 7×7×512。

你看到的是“特征值的空间归并”，不是得到目标中心、不是得到类别，也不是自动把框画准。真实的 7×7 RoI Pool 对全部 512 个通道分别执行，再将 7×7×512=25,088 个值展平供后续 FC 使用。原始 RoI Pooling 对坐标做量化，RoI Align 是后来解决部分对齐误差的改进。

第三步：固定长度特征如何产生分类与框回归？

通过全连接层后，区域得到一个高维表征，例如 4096 维。Fast R-CNN 将它接到两个并列输出分支，不是先分类后把分类概率当成坐标：

分类分支（Softmax）

输出 K+1 个概率，K 个前景类别 + 1 个背景。若只有 cat、dog 两种前景类别，则每个 RoI 输出三个数：[p(background), p(cat), p(dog)]。

[0.05, 0.90, 0.05]
框回归分支（Bounding Box Regression）

原始 Fast R-CNN 输出 4K 个实数：对每个前景类别都预测一组 (t_x,t_y,t_w,t_h)。例如 K=2，就有 8 个回归值；这里并不直接输出 xyxy 绝对坐标。

cat: [0.10,-0.05,ln1.1,ln0.9]
dog: [ ... 另外四个数 ... ]

第四步：框回归偏移怎么还原成原图的像素坐标？

还是刚才的 Proposal [100,100,300,260]。它的中心和尺寸是 (cx=200,cy=180,w=200,h=160)。按分类分支最可信的 cat 类别，读取 cat 对应四个偏移，用下式解码：

cx' = cx + txw，cy' = cy + tyh
w' = w·exp(tw)，h' = h·exp(th)先从 proposal xyxy 换到中心+宽高；偏移被定义在这个参考框坐标系内。解码完成后，再换回 xyxy 像素框。

交互实验｜回归 Head 输出的 4 个数，究竟怎样改动真实框？

蓝色框是 Proposal；橙色框是根据预测偏移解码得到的修正框。移动滑块并查看实际坐标。比例项是 exp(t)，而不是给宽高直接加几个像素。

cx'=220, cy'=172, w'=220, h'=144 → xyxy=[110,100,330,244]

第五步：一张图有数千个 RoI，为什么最后只留下两三个框？

每个 RoI 都会得到类别概率与修正框。先根据类别分数筛掉低分候选，对剩余框进行坐标还原、必要时裁剪到图像边界，再按类别分别执行 NMS，抑制大量指向同一物体的重复框。最终不再是 2000 个 RoI，而是少量 (类别,分数,xyxy)。

Faster R-CNN：候选框本身，为什么不交给网络预测？

2015 · Region Proposal Network（RPN），Two-stage 完整成形
历史问题：Fast R-CNN 已共享特征，剩下的 Selective Search 仍是瓶颈。能否直接在特征图上学习哪里可能存在目标？

Faster R-CNN 在共享 Feature Map 上增加一个轻量的 RPN。RPN 会遍历特征图位置，对预设 Anchor 预测两类信息：是不是物体（objectness），以及框应该怎样调整。

Faster R-CNN：两阶段不是跑两次 Backbone

这里第一次必须理解 Anchor 是什么

对于 Feature Map 的某个位置，不预先知道目标宽高。RPN 因此在该位置放置几种不同尺度和长宽比的参考框 Anchor，网络学习如何从参考框调整到真实框，而不是从零预测所有坐标。

tx = (x − xₐ)/wₐ，ty = (y − yₐ)/hₐ
tw = log(w/wₐ)，th = log(h/hₐ)(xₐ,yₐ,wₐ,hₐ) 是 Anchor 的中心与大小；(x,y,w,h) 为目标框。公式表示相对 Anchor 的平移与尺度偏移，是经典 RPN 框编码的形式。
Faster R-CNN 的关键价值不是“再加一个检测头”，而是将候选区域生成也变成可学习的网络计算，并与后续精细检测共享特征。

RPN 如何在共享特征上造出真正的 Proposal

01
① 选定滑动位置

假设 F 的空间大小为 40×40，stride=16。特征格点 (i,j) 映射到原图附近的中心 ((j+0.5)×16,(i+0.5)×16)。

02
② 给每个位置放 A 个 Anchor

例如 A=9 来自 3 种尺寸×3 种长宽比。它们是事先定义的参考矩形，尚未识别出任何物体。

03
③ RPN 共享 3×3 特征

每个位置经过小卷积后输出 2A 个前/背景 logits 和 4A 个 box 偏移；A=9 时是 18 个分类值和 36 个回归值。

04
④ 从 Anchor 解码 Proposal

对 Anchor 中心 (xa,ya)、宽高(wa,ha)，预测 (tx,ty,tw,th)：x=xa+tx·wa，y=ya+ty·ha，w=wa·exp(tw)，h=ha·exp(th)。

05
⑤ 筛选后进入二阶段

RPN 的 objectness 先排序/截断并 NMS，得到如数百至上千个 Proposal；RoI Pool/Align 根据这些框从共享 F 中取区域特征，第二阶段才做类别判别与再次框回归。

06
⑥ 训练时谁监督 RPN

将 Anchor 与 GT 的 IoU 匹配生成正负标签；正 Anchor 同时学 objectness 和相对 GT 的回归偏移。第二阶段用另一套 RoI 匹配训练类别及边界框。

把数值真正走通

数值追踪：Anchor 中心(208,160)、尺寸(128,80)；若 RPN 输出 tx=0.125、ty=0.1、tw=ln(1.25)、th=ln(0.8)，则 Proposal 中心=(224,168)，宽高=(160,64)，xyxy=[144,136,304,200]。这是第一阶段的候选，不是最后检测框；RoI Head 还会再次分类、精修。

容易混淆的边界：关键不是“RPN 给了一个框就完成检测”：RPN 只输出目标性与粗框，不识别具体类别；最终类别来自第二阶段。

DEEP DIVE / TECHNIQUE

从真实框到 RPN Target：训练监督究竟怎么算

先把物体框写成 GT=[x₁,y₁,x₂,y₂]。训练前，特征图每个位置配置 A 个 Anchor。每个 Anchor 和所有 GT 计算 IoU，依规则被赋予前景、背景或忽略标签；“被标成前景”只说明这个 Anchor 应该学习某个 GT，并不说明模型已经找对目标。

RPN 的监督标签cls_target ∈ {0,1,ignore}1：前景参考框；0：背景参考框；ignore：不纳入该分类项。
RPN 的回归目标tₓ*=(x_gt−x_a)/w_a
t_y*=(y_gt−y_a)/h_a
t_w*=ln(w_gt/w_a)
t_h*=ln(h_gt/h_a)只有适用的正 Anchor 承担框回归监督。

例如 Anchor 中心 (200,150)，尺寸 (100,80)；GT 中心 (210,154)，尺寸 (120,64)，那么目标偏移就是 (0.1,0.05,ln1.2,ln0.8)。RPN 学会这些偏移后，在推理中即使没有 GT，也能把 Anchor 解码为候选框。候选框随后依次经过 clip、score 排序、pre-NMS Top-K、NMS 与 post-NMS Top-K，再送入 RoI Head。

重要区分：RPN 的输出 (objectness, proposal) 不包含 cat/dog 等具体类别；RoI Head 的输出才是 (K+1 分类分数, 每类/共享的边框修正)。这是两次有不同任务的预测，不是重复计算同一个东西。

YOLOv1：能不能把整个检测问题直接变成回归？

2015 首次公开 / CVPR 2016 · You Only Look Once
历史问题：候选区域机制已经比较成熟，但能不能从整张图像直接预测目标框和类别，省掉显式 Proposal 流程？

YOLOv1 将图像划分为 S×S 网格。一个物体由其中心点所在的网格单元负责预测。每个单元预测 B 个框及各框置信度，同时预测一组类别条件概率。原始 VOC 配置中 S=7、B=2、C=20。

输出张量：S × S × (B·5 + C) = 7 × 7 × 30 每个框有 (x,y,w,h,confidence) 五个数；每个网格单元还有一组 C 维类别条件概率。注意原始 YOLOv1 不是每个框各自输出一套独立类别分布。

交互 ①｜移动目标中心：YOLOv1 哪个网格负责？

拖动图中的橙色目标中心。高亮的网格就是负责该目标的 Cell。演示仅表达 YOLOv1 的“中心归属”思想，并非模型真实输出。

它到底怎么预测框？

每个 Cell 的预测并不是直接输出原始像素坐标。中心坐标 (x,y) 相对该单元的边界定义，框宽高 (w,h) 相对整幅图像定义。置信度结合了“是否有物体”与预测框质量的含义。

confidence = Pr(Object) × IoU(pred, truth)原始 YOLOv1 的置信度定义。类别分数由 Pr(Class | Object) 与该框 confidence 相乘形成；与后续 YOLO 的具体 Head 形式不能直接混为一谈。
最大的创新是统一检测：一张图像、一次网络前向，直接输出所有网格的预测结果。YOLO 的名字强调的是统一执行，而不表示完全没有任何后处理。

7×7 网格里的 30 个值究竟怎样变成框

01
划分责任格

原始论文以 448×448 为输入，划为 S=7 的网格。物体中心落在哪个格，哪个格负责该物体；不是每个格都必须有物体。

02
每格输出向量

VOC 20 类、每格 B=2 个候选框。每个格输出 B×5+C=2×5+20=30 个值；全图输出 7×7×30。两框各有 (x,y,w,h,confidence)，类别概率是每格共享的一组。

03
解码位置

中心 x,y 用相对于网格单元的归一化偏移；w,h 用相对于整张图的归一化尺寸。像素坐标可用 xpix=(j+x)/7×448，ypix=(i+y)/7×448，wpix=w×448，hpix=h×448。

04
预测分数

训练中 confidence 目标与 Pr(object) 和 IoU 相关。测试时将类别条件概率与 confidence 相乘得到类别特定分数，再阈值与 NMS。

05
训练的责任分配

含物体中心的格内，两个预测框中与 GT IoU 更高的框负责坐标学习，另一个不承担该对象的框回归；这是 v1 定位行为的重要来源。

把数值真正走通

数值例子：中心处于网格列 j=3、行 i=2，预测 x=0.5、y=0.25，则原图中心 x=(3.5/7)×448=224，y=(2.25/7)×448=144；若 w=0.25、h=0.20，则宽112、高89.6，得到 xyxy≈[168,99.2,280,188.8]。

容易混淆的边界：与后代区别：原始 YOLOv1 不是多尺度 Anchor-based、不是 DFL，也不是每个框独立预测全套类别。

2015 首次公开 / ECCV 2016 · Single Shot MultiBox Detector
历史问题：目标有不同大小和长宽比。只在一层特征图或单一网格结构上预测，难以兼顾小目标与大目标。

SSD 的“多尺度”

不同分辨率的特征图，各自执行预测；浅层分辨率高，深层语义更强。它已经意识到“检测不应只看最后一层”。

按多层特征布点

SSD300 经典配置在 38×38、19×19、10×10、5×5、3×3、1×1 等层检测，每层负责不同尺寸范围。

每个点配置多个 Default Boxes

每个位置放若干预设尺度/宽高比的矩形；假设某一层 38×38 且每点4个框，则此层产生 38×38×4=5776 个参考框。

03
卷积直接预测两类数值

某层若有 k 个默认框、C 个类别（含背景），分类卷积输出 kC 通道，定位卷积输出 4k 通道；重塑后对应每个默认框的类别概率和相对偏移。

04
训练匹配

每个 GT 先配最匹配的 Default Box，再把 IoU 高于阈值的其他框作为正样本；大量负样本用 hard negative mining 控制正负比例（经典常用约 1:3）。

05
解码+NMS

预测的中心平移和宽高对数尺度作用在 Default Box 上，得到像素框；按类别置信度筛选并用 NMS 去重。

把数值真正走通

以经典 SSD300 为例：六层特征对应不同数量的框，合计 8732 个默认框；每个框的预测包括 4 个偏移和 C 个类别分数。8732 是候选数量，不是一定检测出8732个物体。

容易混淆的边界：SSD 的“多尺度”主要是让不同分辨率层各自预测；FPN 进一步让高层语义向低层传播，二者解决的问题不同。

DEEP DIVE / TECHNIQUE

同一 GT 如何同时监督多层 Default Boxes

一张图片只有几个 GT，但 SSD300 可能吐出 8732 个先验框。训练时先构造匹配表 match[8732]：每个 GT 至少关联一个最佳匹配先验框；与 GT 的 IoU 超过阈值的其他先验框也可成为正样本。每个正样本有目标类别和四个偏移；未匹配样本进入背景分类候选。

定位回归训练L_loc = SmoothL1(t_pred − t_GT)按编码约定对中心坐标和宽高比进行归一化。论文还使用 variance 系数。

推理时没有 GT、没有匹配表，也没有 hard-negative mining；只对每个 Default Box 的预测偏移进行 decode，得到候选框，计算类别分数并进行 NMS。这也是为什么必须严格区分“训练怎么分正负”和“推理怎么输出 N 个框”。

Anchor 聚类、网格偏移、Pass-through 分别作用在哪里

01
用数据确定 Anchor 形状

在训练 GT 的宽高上做 k-means（论文使用 IoU 距离），学习常见宽高模板；这是设定先验，不是用 CNN 预测候选框。

02
格点输出 tx,ty,tw,th

中心限制在所处分格附近：bx=(σ(tx)+cx)×s；尺寸按 Anchor：bw=pw×exp(tw)，bh=ph×exp(th)。因此一格多个 Anchor 可以预测不同长宽比。

03
Passthrough

将较浅的 26×26 特征重排/传给较深的 13×13 预测层，在相同空间网格中增加细节特征；并不是 YOLOv3 的三尺度独立 Head。

04
多尺度训练

训练中定期更换输入分辨率（按网络步长要求），同一个卷积检测器适应不同推理尺寸。

把数值真正走通

容易混淆的边界：不要把“Anchor-based”误解成 RPN 的 two-stage：YOLOv2 使用 Anchor，但仍在一次密集预测中直接得到最终候选。

FPN：小目标需要细节，但识别又需要高级语义

2017 · Feature Pyramid Networks：自底向上 + 自顶向下 + 横向连接
历史问题：浅层特征有较高空间分辨率，却缺少高层语义；深层特征知道“是什么”，但空间分辨率太低。能不能两者兼得？

FPN 的精妙在于利用已有 Backbone 的天然多层结构：先得到自底向上的 C3/C4/C5，再让深层语义经过自顶向上采样，与同尺度浅层特征做横向融合，形成 P3/P4/P5。

FPN 的关键不是“使用三张特征图”，而是“建立反向信息路径”

简化示意：真实 FPN 还包含用于平滑输出的卷积，通常还有用于大尺度目标的额外金字塔层。关键是融合路径，而不是逐层名称。

Pl = Conv( Lateral(Cl) + Up(Pl+1) ) l 为金字塔层级；Lateral 通常用 1×1 卷积统一通道；Up 表示上采样；卷积进一步整合融合后的特征。
FPN 是一种可复用的特征融合思想，不是一种独立的“最终检测器”。它可以和 Faster R-CNN、RetinaNet 等不同检测头组合，也影响了后来 YOLO 的 Neck 设计。

逐个尺寸算清：C5 的语义如何到达 P3

01
先准备 C3/C4/C5

输入640×640时可设 C3=80×80×512、C4=40×40×1024、C5=20×20×2048；这些维度仅是常见配置的教学示例。

02
横向 1×1 投影

每层用 1×1 conv 将通道统一为 256：L3=80×80×256，L4=40×40×256，L5=20×20×256。此处只改通道，不改宽高。

03
自顶向下融合

P5=L5；把 P5 最近邻上采样到40×40，与 L4 逐元素相加得到融合 P4；再上采样到80×80与 L3 相加得到 P3。

04
平滑卷积

常见 FPN 对融合结果再接 3×3 卷积，缓和上采样造成的混叠；输出是 P3/P4/P5 多尺度特征。

05
接检测器而不是直接画框

若用于 RetinaNet，在每张 P 图上运行共享分类/回归 Head；若用于 Faster R-CNN，RPN 各层提议候选并由 RoI 根据尺寸选择层级。

把数值真正走通

尺寸追踪：P5 20×20×256 → Upsample 40×40×256 → +L4(40×40×256)=P4 → Upsample 80×80×256 → +L3(80×80×256)=P3。整个过程没有产生任何 class score 或 xyxy。

容易混淆的边界：精确概念：FPN 的 P3/P4/P5 是语义增强的特征层，不是“把三张预测结果平均”。

DEEP DIVE / TECHNIQUE

用两张图辨认：SSD 的多层预测 ≠ FPN 的多层融合

SSD 式：多层各自预测
低层 F₃ → 检测头₃ → 小框
中层 F₄ → 检测头₄ → 中框
高层 F₅ → 检测头₅ → 大框

检测位置来自不同大小的特征图，但不意味着这些特征图已经发生了高层向低层的语义融合。

FPN 式：先融合再交给 Head
C₅ → L₅ → P₅
　　　 ↓ 上采样＋相加
C₄ → L₄ → P₄
　　　 ↓ 上采样＋相加
C₃ → L₃ → P₃

P₃/P₄/P₅ 每一层都带着向下传播的高层语义，随后才接 RPN、分类头或位置头。

再看 PAN 风格双向融合：FPN 先自顶向下，高分辨率 P₃ 再经 stride=2 下采样，向 P₄、P₅ 传播信息。这是特征层之间的信息路径改变，不是“新增一种 bbox 格式”。

RoI Align 到底修正了 RoI Pool 的什么误差

01
为何 RoI Pool 有空间偏差

把原图 RoI 映射到较低分辨率的特征图时，RoI 边界和 bin 边界经常需要取整；两次量化对精细 Mask 尤其明显。

RoI Align 不粗暴取整

对 RoI 的连续浮点坐标精确保留，再在每个 bin 的采样位置用双线性插值：由相邻四个特征值按距离加权得到该位置的特征。

RetinaNet：One-stage 为什么常被大量背景样本淹没？

2017 · Focal Loss：真正重要的是“简单负样本的权重”
历史问题：密集检测器有大量 Anchor / 预测位置，大多数都是容易识别的背景。它们的损失累积起来，可能压过少数真正困难的前景样本。

RetinaNet 使用 FPN 构建多尺度检测架构，而其最具有代表性的创新是 Focal Loss：当一个样本已经被正确且自信地分类时，主动降低它在总损失中的比重，让训练更多关注困难样本。

Focal Loss 如何让大量简单背景的梯度变小

01
密集样本问题

假设有10万候选位置，其中绝大多数是简单背景。如果每个背景都按普通 CE/BCE 参与，总量可能压过少数困难正样本。

02
先看二分类置信度 pₜ

若标签 y=1，pₜ=p；若 y=0，pₜ=1−p。预测正确且自信时 pₜ接近1。

03
在 CE 前乘难度权重

FL(pₜ)=−αₜ(1−pₜ)^γ log(pₜ)。易样本 pₜ≈1 时，(1−pₜ)^γ 非常小，难样本保持较大权重。

04
与检测头相接

RetinaNet 在多尺度 FPN 各层用共享分类子网和 bbox 子网。Anchor 先定义参考框，分类 Focal Loss 学类别，回归 Smooth L1 等学偏移，推理时解码与 NMS。

把数值真正走通

γ=2、忽略 α：正确概率 pₜ=0.95 的权重是 (0.05)²=0.0025；pₜ=0.2 时权重是 (0.8)²=0.64，差256倍（这里只比较乘子，不是完整 Loss）。

容易混淆的边界：这里 Focal Loss 是“分类困难样本加权”；DFL 是“位置距离分布监督”，名称相似，任务和数学对象不同。

FCOS：Anchor 真的是检测必须的吗？

2019 · Fully Convolutional One-Stage Object Detection
历史问题：Anchor 需要人为设计尺度与长宽比，还需要计算每个 Anchor 与真值框的匹配。既然是卷积网络，可否在特征图每个位置直接预测一个框？

FCOS 给出的答案是：可以。每个特征点（映射到原图的位置）直接预测到目标框四条边的距离 (l,t,r,b)，同时预测类别和 centerness。它不再需要预设形状参考框。

Anchor-based 与 FCOS 的坐标预测有什么根本区别？

Anchor-based

参考框已知，网络学习相对 Anchor 的位移与形变。训练要决定哪些 Anchor 是正样本。

Anchor-free · FCOS

特征位置本身作为参考点，预测到四边的距离；仍需决定哪些位置负责目标。

b = (x−l, y−t, x+r, y+b) (x,y) 是映射到原图的特征点；l、t、r、b 是到左、上、右、下边界的非负距离。右侧的 b 同时用作 bottom 距离符号，实际实现中常用单独变量避免歧义。
centerness = √[ min(l,r)/max(l,r) · min(t,b)/max(t,b) ] 靠近目标中心的特征位置 centerness 较高，偏向边缘的位置较低；它用于调节预测排序质量。
Anchor-free 并不意味着“无需位置分配规则”。它只是减少了预定义框形状这层先验，训练仍然必须决定哪些特征位置属于哪个 GT。

FCOS 的 l/t/r/b 是怎样从一个像素位置变成矩形

01
在每层空间位置选中心点

stride=s 的特征点 (i,j) 映射原图位置 (x,y)≈((j+0.5)s,(i+0.5)s)。

02
四边距离回归

对于 GT [x₁,y₁,x₂,y₂] 中的点，监督 l=x−x₁、t=y−y₁、r=x₂−x、b=y₂−y；如果点在框外则至少一个距离为负，不作为该 GT 的普通正样本。

03
头输出类别、四边与 centerness

每个点回归非负 l/t/r/b，再用 [x−l,y−t,x+r,y+b] 还原框；centerness 降低靠近边缘的低质量预测的排序分数。

04
多层尺度约束

不同 FPN 层负责不同边界距离范围，减少同一物体在所有尺度随意分配引起的歧义。

把数值真正走通

容易混淆的边界：Anchor-free 不等于“无需预测参考位置”：仍有特征点 Anchor Point，只是不预设一组宽高比矩形。

你应该知道的三组回归损失

坐标回归

直接约束坐标或偏移差，例如 Smooth L1。优点是直观，但不一定直接对应最终检测 IoU。

IoU 家族

IoU / GIoU / DIoU / CIoU 等，将框的重叠、中心距离或形状纳入优化，不同版本具体目标不同。

DFL

Distribution Focal Loss：把边界距离表示为离散 bin 上的分布，再插值得到连续值。注意它不是 RetinaNet 的分类 Focal Loss。

展开：为什么 DFL 不是“角度精度”，也不是把框变成整数？

d̂ = Σi=0K i · softmax(z)izᵢ 是每个距离 bin 的 logit；该期望给出连续距离。不同检测器是否使用 DFL，应以相应版本实现为准。

Ultralytics YOLO26 采用更轻的 DFL-free bbox 回归、双 Head（默认一对多仍可 NMS，选择 one-to-one 时可 NMS-free），并在训练配方中加入 MuSGD、Progressive Loss、STAL 等策略。它不是单纯“YOLO11 改个名字”，尤其值得比较它对 DFL 的取舍。

01
DFL-free

YOLOv8/11 每个位置为4条边输出4×16 logits，YOLO26 设 reg_max=1，移去分布投影模块，回归分支直接输出4个连续数。

02
仍需 bbox decode

回归值与特征点/stride 结合恢复边界；删除 DFL 并不等于 bbox 只能是整像素，坐标由实数运算得出。

03
双分支训练

One-to-many 用密集正样本帮助优化；One-to-one 用更稀疏监督学习一物一预测。两条路径接同源特征，但推理路径需明确选择。

04
NMS-free 是可选执行模式

官方当前说明默认 one-to-many 路径仍可使用 NMS；显式选择 nms=False 才走 one-to-one 无传统 NMS 的路径。

05
训练配方

Progressive Loss 调整训练过程中两条路径的相对重视，STAL 重点改善小目标正样本覆盖，MuSGD 是优化器策略；它们不是推理图上的三个新算子。

把数值真正走通

以 K=3 为教学例：v8/11 回归 Head 每点64个分布 logits+3分类值；YOLO26 使用4个回归值+3个分类值。4是连续浮点回归输出，不是4档离散刻度。

容易混淆的边界：具体 GPU/CPU 加速还取决于其他层、导出图与算子；不能用“64变4”直接推算整网速度提升16倍。

两种去重路径：Query 一对一与 YOLO 双 Head 的计算差异

2024—2026 小结 · 端到端目标相同，但具体 Head 与训练匹配机制并不相同

传统密集检测器通常输出很多重复框，NMS（非极大值抑制）依据置信分数与框重叠程度，保留高分候选、抑制重叠明显的其他候选。

交互 ④｜NMS 到底删了哪些框？

四个候选框是预先设置的真实坐标。阈值越小，重叠框越容易被抑制。每次按照分数从高到低运行 Greedy NMS，并实时计算 IoU。

—

传统 NMS 很实用，但也有局限：属于非学习的后处理，在高度拥挤或物体紧邻时可能错误删除真实目标，而且还会影响整体系统的端到端延迟。

YOLOv10 · 2024

通过一致性双分配（Consistent Dual Assignments）等设计，使训练阶段保留丰富监督，而用于端到端推理的分支趋向一物一预测，从而可以不依赖传统 NMS。

Ultralytics YOLO26 · 2026

官方发布于 2026 年 1 月，提供可选的 NMS-free 端到端推理路径，同时还包含面向效率与导出的 Detection Head 改进。注意：不是所有模式默认无 NMS；官方文档说明其一对多路径仍可使用 NMS。

两条路线在目标上趋同：让模型学会输出一个质量高、重复少的结果集合。但 DETR 的 Query/匈牙利匹配机制，与 YOLOv10 的双分配训练方式不是同一套架构。
