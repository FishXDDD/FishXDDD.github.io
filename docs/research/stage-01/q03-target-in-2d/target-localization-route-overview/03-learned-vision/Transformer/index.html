01

从 CNN 出发：你的已有知识仍然有用

先知道两种模型最本质的对应关系，不提前陷入 QKV 细节。

图 01 · CNN 分类器与 Transformer 翻译器的共同骨架 教学归纳 · 任务不同
共同点：本质都是可微分计算图，特征网络 + 任务输出 + Loss + 反向传播。新问题主要出现在“序列位置如何交互”和“目标序列怎样生成”。

你已经会的

线性层、非线性、残差、梯度、分类 Head、CE、训练超参数。

这次必须弄懂的

Token 矩阵、动态 Attention、Encoder/Decoder 的信息流、目标序列右移。

最终要能回答的

一条样本经过哪些层？每层输入输出维度是什么？为什么可以一次训练多个预测位置？

这一章的结论：Transformer 没有改变“前向计算 → Loss → 反向传播”的学习范式；它主要改变了序列内部的信息交互和网络组织方式。
02

2017 年为什么要提出 Transformer？

不从今天的 GPT 倒推，而从当时机器翻译遇到的真实困难开始。

贯穿全篇的教学任务：英语句子 → 中文句子

图 02 · 我们希望神经网络学会怎样的映射
Ilovecats
→
我爱猫<EOS>

为教学简化为单词 / 字级 Token。原论文实际使用子词编码；这里的中文是自拟演示，不属于论文实验数据。

旧路径：RNN / LSTM

按时间步传递状态

hₜ = f(hₜ₋₁, xₜ)

词序列上的第 3 步等待第 2 步的隐藏状态。即使已有 Attention，很多模型的主干仍受循环步骤限制。

Transformer：重组后的主路径

用位置间的直接信息读取替换循环

Z = Attention(X, X, X)（概念记法，实际先投影 QKV）

每个位置的 Q、K、V 可批量投影，Attention 用矩阵乘法并行计算整层跨位置交互。

已有成果
Encoder–Decoder 是已有框架；早期 Attention 已能帮助 Decoder 对齐和读取输入；残差、归一化也不是 Transformer 发明的。
真实瓶颈
RNN/LSTM 的 时间步依赖限制序列方向并行。卷积式序列模型可并行，但任意远位置的信息仍需经过多个局部或扩张卷积层。
论文主张
把 Attention 从“辅助读取器”提升为主要序列特征计算机制，不用 RNN 或序列卷积来构造 Encoder/Decoder 的位置表示。
不要误解成“Transformer 推理不再逐词生成”：原始模型的 Decoder 仍自回归，只有已知目标序列的训练计算可以对所有目标位置并行化。
这一章的结论：2017 年的关键问题不是“发明一种全新 Loss”，而是如何消除序列网络对循环状态更新的结构性依赖。
03

先看整台机器：原始 Transformer 究竟有几个模块？

本章只建立全貌，明确 N 的含义、每个 Block 的结构和张量方向。

ENCODER

6 层

每层 2 个子层：Multi-Head Self-Attention、FFN；各自有 Add & Norm。

DECODER

6 层

每层 3 个子层：Masked Self-Attention、Cross-Attention、FFN；各自有 Add & Norm。

OUTPUT

1 个输出投影

最终 Decoder 特征 → 词表 Linear → Softmax；位置预测连接目标 Token Loss。

为了同时显示「真实 6 层」和各层组成，图中每层仅写内部模块简称；每个 Attention 都是 8-Head Multi-Head Attention。图中 Memory Z 由最终 Encoder 产生，六条蓝线分别表示 6 个 Decoder Block 都会通过 Cross-Attention 读取它。绿色 Head 是补充说明标签；实际计算链路为 Decoder 6 顶层输出 → Head → Softmax。

这一章的结论：原始 Base 是一个 6+6 层的 Encoder–Decoder 神经网络；Attention 是它的核心特征交互子层，输出词表的 Linear 才是任务 Head。

输入：一句话为什么会变成 3 × 512？Position 又是什么？

04.1首先，“3” 到底从哪里来？Token ≠ 字符 ≠ 固定单词

Transformer 不能直接对 Unicode 字符串做浮点矩阵乘法。第一步通常是用 Tokenizer 把文本分成词表中的离散符号，再把这些符号映射到整数索引。这个过程在神经网络计算前进行。

位置 pos（序列下标）分词后的 Token（本例）词表索引 Token ID（示例）下一步操作
0I17读取 Embedding 表第 17 行
1love204读取 Embedding 表第 204 行
2cats912读取 Embedding 表第 912 行

为什么不是“3 个词就一定 3 行”？

playing→play##ing

这是解释“子词可能拆分”的示意，实际切分依 Tokenizer 词表与规则决定。句子长度 n 统计的是切分后的 Token 个数，不是原文有几个空格。

为什么 ID 不能直接作为特征？

ID = 17≠语义数值 17

Token ID 只是词表行号。ID 204 不代表语义上比 ID 17 “大 187”。可以把它看作数据库主键或数组索引，而不是连续测量值。

这一阶段的输出是整数序列 [17,204,912]，形状只有 (3,)。 还没有 512 维；512 来自下一步可训练的 Embedding 层。

04.2那么，“512” 怎么来的？Embedding 就是一张可训练的查找表

预先为词表中每一个 Token 准备一个长度为 d_model = 512 的浮点向量。这些值是模型参数，开始训练时按初始化方案设置，之后通过 Loss 的反向传播不断更新；不是人手写入的语义特征，也不是 ID 自己运算出的 512 个数。

图 04-B · 一张大表 E 被三个 ID 取出三行 矩阵行选择 · 不是按 ID 数值大小计算
查表与对 One-Hot 向量做矩阵乘法在数学上等价，但实际无需构造巨大的 One-Hot 矩阵。矩阵中的浮点数随训练学习；行数 V 与当前句子的 Token 数 n 是两回事。
E ∈ ℝV×512 （V 为整个词表规模）
ID = [17, 204, 912] ∈ ℤ3
H = [ E[17] ; E[204] ; E[912] ] ∈ ℝ3×512分号代表按行堆叠。若 batch size = B，完整输入通常为 [B,3,512]，此处只讨论单条样本，所以暂时省略 Batch 维。
沿用已有机制

Embedding 不是 Transformer 发明的

RNN/LSTM 等文本模型早就用可训练词向量。Transformer 沿用了“离散 ID → 连续特征向量”这一步；它最重要的创新不在这里，而在后面的跨位置交互。

架构超参数

512 并不是从句子中测量出来的

论文 Base 主干宽度设为 512，是网络容量和计算开销的设计选择。词长是 3、20、100，都可以继续用 512 维；换一个模型也可以是 256、768 或其他宽度。

04.3POS 的概念：为什么光有 Embedding，模型仍然不知道词序？

这里的 pos / position 是“第几个 Token”，通常从 0 开始：0、1、2、…、n−1。它不是 Token 的 ID，也不是 512 个特征的通道编号。注意 NLP 里 POS tagging 还可指“词性标注”；本章 POS 只指位置索引，PE 才是 Positional Encoding（位置编码）。

三种完全不同的“编号”本例含义决定了什么？
Token ID17 / 204 / 912词表里是哪一种 Token查出哪一行内容向量
pos0 / 1 / 2在当前序列中的位置加上哪一个位置向量
channel index0 … 511一个 512 维向量内的坐标某一维如何计算位置编码
图 04-C · 仅看 Token 内容，交换顺序还缺少“位置线索” 为什么原始 Self-Attention 必须补上顺序信息

句子 A：dog bites man

dogbitesman
E[dog]E[bites]E[man]

在没有位置向量的情况下，这三个 Token 仅携带各自的内容查表结果。

句子 B：man bites dog

manbitesdog
E[man]E[bites]E[dog]

“dog”的词向量本身不会因为它由位置 0 移到位置 2 而改变。

关键机制：未加入位置信息、且没有依赖位置的 Mask 时，Self-Attention 对 Token 行的交换是置换等变的：交换输入行，只会相应交换输出行，单靠它无法知道“谁在前、谁在后”。这不意味着两个句子的输出矩阵完全一样，而是它们的行会对应重排。
图 04-D · 同一个词换位置，内容向量不变，位置向量改变

“dog” 在位置 0

E[dog]+PE(0)=x₀

读到“dog”的内容，也让下游网络知道它处于第一个位置。

“dog” 在位置 2

E[dog]+PE(2)=x₂

相同内容，却获得不同的最终输入特征。模型现在有机会依据顺序学习关系。

与 CNN 对照：卷积核天然处理图像网格邻域，RNN 天然按时间步顺序处理；原始无位置输入的全连接 Self-Attention 则没有这些顺序约束。因此 2017 Transformer 需要把位置信息作为单独输入信号注入。注意“加入位置后模型就能利用顺序”与“位置本身已编码了所有语法关系”是两回事。

04.42017 年的设计：用 sin/cos 把位置 pos 变成一个 512 维向量

最简单的做法是给第 0、1、2 个位置分配一个不同的编号。但单个整数 pos=2 只有一维，无法直接和 512 维 Embedding 逐元素相加。论文的办法是：为每个 pos 生成一整条 512 维位置向量，并且不同维度采用不同变化频率。

原论文 Section 3.5，d_model = 512：
PE(pos, 2i) = sin(pos / 100002i/512)
PE(pos, 2i+1) = cos(pos / 100002i/512) pos：Token 所在位置，如 0、1、2；i：通道对编号，从 0 到 255。偶数维使用 sin，奇数维使用 cos。各维输出范围均为 [−1,1]。PE 向量宽度始终为 512。
图 04-E · 从“位置整数”扩展为“多频率位置向量” 左图是 4 维教学版，论文 Base 右侧为 512 维

为什么要多种频率？

若只用一个频率，位置特征会周期性重复，能够区分的位置模式有限。让不同通道以不同速度变化，模型就能同时获得快变和慢变的位置信号。

为什么 sin 和 cos 成对？

它们形成相位信息的二维表示。把位置从 pos 移动 k，对应每个二维通道对内的旋转变换，为模型学习相对位移提供结构化线索。

令 θ = pos / 100002i/512，Δ = k / 100002i/512
[ sin(θ+Δ), cos(θ+Δ) ]T = R(Δ) · [ sinθ, cosθ ]T R(Δ) 是只由位移 k 决定的二维旋转矩阵（采用向量 [sin,cos] 顺序时，旋转矩阵为 [[cosΔ,sinΔ], [−sinΔ,cosΔ]]）。这解释了论文为什么认为正弦编码有利于模型学到相对位置关系；不等于保证注意力天然就会正确理解所有距离。

04.5把全部过程算一遍：为什么最后依然是 3 × 512？

为什么不是 Concat 拼接成 1024？

Concat 的确也是一种可设想的设计，但会改变后续层的输入宽度或需要另加投影。2017 原论文直接逐元素相加，使向量保持 512 维，并让 QKV/残差等模块继续在同一主干宽度下工作。它不是数学上唯一可行的选择。

为什么 Embedding 要乘 √512？

这是原论文明确使用的缩放设计，保持词向量贡献处于合适的量级，再与位置编码相加。不要把它当成“ID × 512”或“把维度扩展到 512”：维度早已由 Embedding 查表确定，√512 只是在数值上缩放整条向量。

04.6你问的关键：后续为什么会出现“学习式 Position”而不是固定 sin/cos？

先纠正一个时间线误解：不是“2017 使用正弦，后来研究发现错误，于是统一改成 Learned Position”。原始 Transformer 论文自己就比较过固定正弦位置编码与可学习位置 Embedding，在它的翻译实验中结果接近；作者最终选择正弦方案，原因之一是期待其更可能适应训练中未见过的更长序列。二者从一开始就是可选设计，而非简单的替代关系。

图 04-G · 两种方法往同一个位置添加信息：区别在于“这张位置表从何而来”
原论文采用

A. Fixed Sinusoidal Position

pos = 2→sin/cos 公式
PE(2) ∈ ℝ⁵¹²+E[Token]

相同 pos 永远得到相同向量；位置公式本身没有学习参数，Loss 不会更新 PE 表。可以在训练时未出现的位置上继续计算，但模型能否正确使用这些新位置并无保证。

可选路线，非统一升级

B. Learned Absolute Position

pos = 2→可训练位置表 P[2]
P[2] ∈ ℝ⁵¹²+E[Token]

位置 2 有一条可训练参数向量，训练时它与 Embedding / QKV / FFN 一起受 Loss 调整。但参数表只显式覆盖预先定义的位置范围；超出范围需要额外处理。

图 04-H · 学习式位置参数，到底是谁被梯度更新？ 它与 Token Embedding 的学习方式很像
此图描述简单的可学习绝对位置表。具体优化器、权重衰减及实现方式会影响实际参数更新细节；未出现位置对应的行不会从该样本获得位置查表路径上的梯度。

为什么有人选择 Learned Position？

原因是把“什么样的位置特征有用”交给训练数据与任务优化：不预设每一维必须是某个 sin/cos 频率；对于有限上下文长度、足够训练数据的任务，这是自然、实现简单的建模选择。BERT、ViT 等模型使用过可学习的绝对位置表，但这不等于证明其普遍优于正弦方案。

代价与不足是什么？

模型多了大约 L_max × d_model 个参数；没有训练过的位置不具备直接学到的向量。遇到更长序列或 ViT 更大图片分辨率时，往往需要扩展、插值位置表或更换位置机制。即使固定正弦可以继续计算新位置，也不保证模型长长度外推成功。

5.4 两个看似微小、实际上有目的的设计

为什么使用点积，而不是专门的复杂匹配网络？

加性 Attention 已存在，点积注意力也已存在。点积能把所有 Query–Key 匹配变为 QKᵀ，天然适合高效矩阵乘法。选择点积是计算效率考虑，不代表只靠点积就能解决任何关系学习问题。

为什么还要除以 √dₖ？

若 q、k 的各维独立、均值 0、方差 1，点积方差约为 dₖ。维度大时分数可能过大，Softmax 变得尖锐，梯度容易变小；除以 √dₖ 使分数尺度更稳定。这是简化假设下的动机，不是任意分布的严格定理。

Var(q·k) ≈ dₖ ⇒ Var((q·k)/√dₖ) ≈ 1
本章产物：给定 X，可以得到新的 Z；权重由 Q/K 匹配生成，输出由 V 加权汇总产生。2017 年的核心是让这种跨位置计算成为主要序列网络层。

为什么要 8 个 Head？不是重复做 8 次相同的事

一个注意力头学一套关联；多个头在不同特征子空间中并行寻找关系。

单个注意力头给每个 Query 产生一组权重。如果所有关系都挤在一个加权分布里，表达容易受限制。论文提出把 Q、K、V 通过不同的可学习投影映射到多个子空间；每个空间独立关注，再将结果拼接融合。

12.2 为什么训练策略也需要知道“沿用还是改进”？

沿用

Backprop + Adam

和 CNN 一样，Loss 通过链式法则影响每一层的可训练参数；Adam 不是 Transformer 首创。

架构使其成为可能

并行 Teacher Forcing

给 Decoder 整条右移序列，再用 Causal Mask 防止未来泄露。所有目标位置的网络层计算可以一起进行。

训练策略

Warmup / Dropout / Smoothing

都为训练稳定与泛化服务，不是新的 Backbone 子层；不能把它们当作网络结构的一部分。

13.1 训练与推理在时间维度上最重要的区别

项目训练阶段推理阶段
目标端输入已知完整正确目标句子，右移输入只有 BOS + 已经生成的 Token
Causal Mask必须，防止整句输入中未来答案泄露仍满足因果约束，不能使用未生成的未来 Token
目标位置计算在一层中可并行计算所有合法位置下一个 Token 依赖此前输出，通常逐步生成
Head 输出全部有效位置的 Logits → CE使用最后一个有效位置的下一 Token 分布做解码决策
终止条件来自目标长度/监督标签预测 EOS 或达到输出长度限制

Greedy 与 Beam Search

Greedy 每一步取概率最大的 Token，教学直观。原论文实验采用 Beam Search（beam size=4，长度惩罚 α=0.6），保留多个候选序列再作选择；这属于推理解码策略，而不是 Attention 新层。

KV Cache 是原论文的核心创新吗？

不是。现代 Transformer 自回归实现常缓存历史 K/V，避免重复计算旧 Token 的投影；这是重要的推理效率技术，但不应拿后续优化冒充 2017 原始论文的架构创新。

本章产物：完整闭环已形成：输入 → Encoder → Decoder → Head → 一个 Token → 追加前缀 → 再运行 Decoder，直到 EOS。

14.2 一个重要但经常被省略的代价

长序列的 n² 匹配

Score = QKᵀ : n×n
全局 Attention 的匹配项数 ∝ n²这里讨论经典标准全局 Attention；模型整体还包括 QKV/FFN 投影等计算。

长度翻倍，成对关系数量大约增加四倍。因此不能笼统说 Transformer 在任何输入长度都更快。

与 CNN 的关系，不是“谁淘汰谁”

CNN 利用局部、平移相关的结构先验；原始 Transformer 的注意力直接做位置间动态读取。它们的表达假设、训练资源需求、适用范围不同。后来 ViT 是把图像转换为 Token 再使用 Transformer，而不是原论文直接处理图像。

Self-Attn: O(n²d)（论文比较式）
RNN: O(nd²)（论文比较式）这是论文对典型单层机制的比较量级；完整 Transformer 层另外包含线性投影与 FFN 的 O(nd²) 项。
本章结论：这篇论文的里程碑不是一句“Attention 更准确”，而是提出了一个不依赖循环/序列卷积的序列模型，并通过并行计算、翻译实验和消融分析论证其可行与有效。

为什么 ViT 不需要原始 Decoder？

图像分类只需要学习整张图像的表征，再接分类 Head；不需要自回归生成目标语言，所以原始翻译任务中负责序列生成的 Decoder 并不是必要配置。

为什么 DETR 的 Decoder 不是语言生成器？

它使用 Object Queries 查询图像特征，最终直接构建目标预测集合。网络中的 Decoder 指一种条件查询/特征更新结构，不意味着必须逐 Token 生成句子。

最后的模型观：Transformer 首先是可复用的网络计算架构，不等于某一个固定任务。输入表示、信息流、Task Head、Loss 和推理规则共同决定模型在做什么。
