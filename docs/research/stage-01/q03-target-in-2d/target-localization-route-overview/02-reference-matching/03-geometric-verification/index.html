几何验证与可靠性判断

Geometric Verification · 从匹配点到可信位置

前一篇已经能通过描述子找到一批对应点，还能用 Homography 将参考图中的位置映射到当前图像。看起来目标好像已经找到了。

但如果盒子上有重复图案，几组错误匹配也可能“看起来很像”。相似的局部，不代表它们真能被同一个几何变换解释。

这一篇只补上最后一件事：怎样从错配中找出一致的对应，以及怎样判断定位结果可不可信。

输入：候选匹配点对核心：RANSAC · 重投影误差输出：内点 + 可信度判断
00 DEFINE THE TASK

先明确：验证的不是描述子本身

假设有参考图上的点 pᵢ 和当前图上的候选对应点 pᵢ′。我们想知道：它们能不能共同支持一个合理的二维几何变换？

INPUT
候选匹配点对

坐标 (pᵢ, pᵢ′)，可能混有错误对应。

CORE
几何一致性

通过模型预测位置，衡量实际位置与预测的差距。

OUTPUT
可靠模型 / 拒绝

内点集合、模型参数、误差统计、目标位置或失败状态。

研究边界：上一篇已经介绍描述子距离、Ratio Test、Cross-check 与 Homography 的映射含义；本篇不重复提取特征或推导 H。重点是从大量候选匹配中剔除错配，并评估估计结果。这里只讨论参考图像的二维匹配，不研究三维 Pose。
候选匹配点对→几何模型与残差→RANSAC 找一致集合→可靠性检查→输出或拒绝

上图是常见的验证工作流程。前面的直接模板相似度匹配不一定需要这些点对步骤；不同任务选择不同的验证方式。

01 GEOMETRIC CONSISTENCY

两点外观很像，怎样判断几何上也对应？

想象我们通过几个匹配点估计出了一个几何变换 H。它可以告诉我们：参考图上的点 pᵢ，在当前图中本来应该出现在哪里。 如果真正匹配的点离这个预测位置很远，就不太符合这个模型。

1.1 · 重投影误差：预测位置和实际位置差多少？

REPROJECTION ERROR · 像素距离
ei = ‖ p′i − π( H · p̃i ) ‖2
p̃ᵢ 为参考点的齐次坐标；H 是由对应点估计的二维变换；π(·) 将齐次坐标转换回二维点；pᵢ′ 是当前图中实际匹配到的位置。eᵢ 就是预测位置与实际位置之间的像素距离。
机制图｜预测位置与实际匹配点不一致，就是重投影误差

举个数值例子：H 预测点应该在 (100, 80)，但实际匹配点在 (103, 84)，那么

MINIMAL EXAMPLE
e = √[(103−100)²+(84−80)²] = 5 px
如果允许误差阈值 τ = 3 px，这个点是离群候选；若 τ = 6 px，它会被判为内点。阈值和误差的单位都是像素。
一个必须区分的量：前篇 L2 / Hamming 距离是在比较描述子长得像不像；这里的重投影误差是在比较坐标是否服从同一个几何关系。它们不是一回事，阈值也不能通用。

1.2 · 同一组对应，应该用什么模型？

几何一致性离不开模型假设。如果目标只是平移，平移模型即可；如果存在旋转和尺度变化，可以使用相似或仿射变换；如果目标近似平面并发生透视变化，常用 Homography（单应矩阵）。

H 不适合用一个统一变换解释所有非平面表面。模型错了，真实匹配也可能被判为“离群点”。

02 RANSAC

一批点里有错配，RANSAC 怎么找到可靠的那一批？

如果直接用全部匹配点拟合 H，几个错误匹配就可能把结果拉偏。RANSAC 的办法恰好相反：先用少量点提出一个模型，再看有多少其他点愿意支持它。

STEP 01随机抽一小组

例如估计一般单应矩阵，理想情况下至少需要 4 组非退化对应。

STEP 02拟合候选模型

用抽中的点计算 H，再对全部匹配点预测位置。

STEP 03统计一致内点

重投影误差小于阈值的点，支持这个候选模型。

STEP 04重复并选出较优模型

比较多组候选，取一致性较好的结果，并在内点上重新估计。

INLIER COUNT · 最直观的一致性统计
Nin = Σi=1…N 𝟙( ei < τ )
τ 是允许的重投影误差阈值（像素）；𝟙(·) 表示条件成立时计 1，否则计 0。这里展示的是基础 RANSAC 的“按内点数选择模型”思想；实际鲁棒估计器还可能采用其他评分方式。
机制图｜候选 H 不同，支持它的匹配点集合也不同
示意图只表达“候选模型由不同数量的点支持”。真实 RANSAC 是通过误差阈值而非肉眼距离进行统计。

对平面参考匹配，通常是在候选匹配点中随机取 4 组来估计 H。若这 4 组恰好包含错配，候选 H 可能很差；多次重复就是为了增加抽到足够多正确匹配的机会。

不要把 RANSAC 想成“计算一个更准的相似度”。它不负责判断两个局部外观像不像，而是在已有点对的基础上，寻找能被同一几何模型解释的匹配集合。即使找到很多内点，也不能单凭这一点证明它们属于你想找的目标。
03 PIXEL THRESHOLD

阈值到底卡的是什么？调大调小会怎样？

和 Canny 的梯度阈值不同，RANSAC 用于几何匹配时常见的阈值是重投影误差的像素距离。例如设 τ = 3 px，意思是预测位置和观测点的偏差小于 3 像素，才属于当前模型的内点。

轻微定位误差也可能被当作离群点，内点数量下降，真实匹配可能被丢掉。

阈值较大
容忍误差更多

内点数量可能增加，但错误匹配也更容易进入一致集合，几何精度可能下降。

实际阈值要结合图像分辨率、关键点定位误差、变换模型以及任务对精度的要求来选。比如 3 px 只是示例，不是所有分辨率和场景通用的推荐值。

04 RELIABILITY

内点很多，就一定可以相信这个定位吗？

还不能。RANSAC 只是找到一组相对于某个模型比较一致的点。要判断这组点是否真的支撑目标定位，至少还得看误差、空间分布与模型假设。

INLIER RATIO · 一致匹配的占比
rin = Nin / Nmatches
例如 20 组匹配点中有 15 组满足误差阈值，内点率是 75%。它描述本组匹配中有多少被当前模型支持，并不等于“目标正确概率为 75%”。
需要检查它告诉我们什么只看这一项会有什么问题
内点数量 / 比例有多少对应支持同一模型重复图案也可能形成一致的错误对应
重投影误差预测坐标与实际匹配坐标有多接近误差小也可能是模型过拟合少量点
空间分布内点是否覆盖目标不同区域全部挤在一个小角落，外推到四角会不稳定
模型适用性目标是否满足平面 / 变换假设非平面物体不一定能用一个 H 描述
候选唯一性是否存在多个近似同样合理的目标位置不同重复纹理区域可能都能得到高内点率
机制图｜同样是 6 个内点，位置分布不同，几何约束也不同
广度优先的判断标准：不需要在这里推导矩阵条件数或置信区间，但必须记住有内点 ≠ 可靠定位。评价结果需要结合足够的支持、较小误差、合理空间分布，以及模型与场景是否匹配。
05 DECISION & TAKEAWAY

什么时候输出目标位置，什么时候应该拒绝？

如果几何关系得到足够支持，并且模型适用于目标，就可以使用估计得到的 H，将参考目标的四角映射到当前画面，形成一个二维四边形，再根据实际任务转换成 BBox、中心点等结果。

如果只有少量集中在一处的内点、多个候选都合理、模型预测误差很大，或者目标本身不满足几何假设，更合理的做法是拒绝本次定位，而不是强行返回一个看似精确的位置。

实际问题想到什么需要理解的核心
描述子匹配很多，但可能混有错配RANSAC抽样估计模型、统计一致内点
一个匹配点是否支持当前 H？重投影误差 eᵢ预测点与观测点之间的像素距离
怎样允许一定定位误差？阈值 τ内点划分的容忍范围，而非描述子阈值
模型支持度怎样量化？内点数 / 内点率一致集合的规模，不是成功概率
为何内点多也可能出错？分布、退化、模型假设匹配几何对目标是否具有足够约束
这一篇只需记住：描述子匹配负责提出“可能对应”，RANSAC 负责找到“几何上比较一致”的匹配，而可靠性检查决定“能不能相信这个定位”。
