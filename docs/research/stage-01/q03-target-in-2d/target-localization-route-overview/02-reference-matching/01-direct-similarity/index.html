DEEP DIVE · 01 / DIRECT SIMILARITY

直接相似性比较

Direct Similarity · 从已知外观寻找位置

已经拍过盒子上的标签，现在想在另一张图像中找到它。最容易想到的办法，是拿参考图片和当前画面逐个位置比较，找出最像的那一块。

不过，「最像」究竟怎样计算？如果光照改变、目标变大或发生旋转，原来的比较还能用吗？

这一篇先研究怎样定义相似性、怎样搜索位置，以及什么时候不应该相信最高得分。

输入：参考 + 当前图像数学：SSD / NCC / ZNCC输出：得分图 + 候选框
00 DEFINE THE TASK

先明确：这里究竟匹配什么？

我们已经拥有某种参考信息（一个图块、一段颜色统计或一条轮廓），希望在当前图像中找到与它相似的候选位置。直接相似性比较不要求先建立跨图像关键点对应关系。

INPUT
参考 R 与图像 I

已知目标图块、外观描述或轮廓；当前图像。

CORE
相似度 + 搜索

计算每个候选的相似程度，寻找得分较好的位置。

OUTPUT
响应图与候选位置

一个或多个匹配框、得分，或者无法可靠确定。

研究边界：这里只研究外观或轮廓的直接比较，不重新解释颜色、纹理、轮廓的提取算法；局部描述子对应与 Homography / RANSAC 验证留给后续笔记。
01 PIXEL-LEVEL SIMILARITY

两块图像有多像，怎样算出来？

最直接的做法是：把参考模板与一个候选图块对齐，比较相同位置的像素。这里不是识别「盒子」这个语义，而是在比较两个数值数组。

1.1 · SAD 与 SSD：比较像素误差

SAD · 绝对差之和
SAD = ∑i |Ti − Pi|
SSD · 平方差之和
SSD = ∑i (Ti − Pi)2
Ti 是参考模板第 i 个像素；Pi 是候选图块对应位置的像素。两者都是误差，越小越相似；SSD 对较大差异惩罚更重。

例如参考图块是 [50, 100, 150]，候选是 [55, 100, 145]，那么 SAD = 10，SSD = 50。没有任何神秘的「特征识别」，只是每个对应像素相减，再把误差汇总。

机制图｜同位置相减，再得到单个匹配分数

1.2 · 亮度变化之后，为什么 SSD 容易失败？

同一张标签，如果拍摄时整体亮了 40，所有像素都增加 40。物体并没变，但 SSD 会累计大量误差。为减轻这种影响，可以比较图块的变化模式，而不只比较绝对数值。

NCC · 归一化互相关
NCC = ∑i TiPi√(∑Ti2 · ∑Pi2)
比较两个像素向量的方向相似性。对于正比例增益变化较稳健，但不自动消除加法亮度偏移。
ZNCC · 零均值归一化互相关
ZNCC = ∑i(Ti−T̄)(Pi−P̄)√[∑(Ti−T̄)2 · ∑(Pi−P̄)2]
T̄、P̄ 是各图块的平均像素值。先减均值，再归一化，可抵消理想条件下的整体亮度偏移和正比例对比度变化；分数越接近 1 越相似。若图块几乎无纹理、发生饱和裁剪或局部光照变化，仍可能失效。

最容易记住的区别：SSD 看绝对误差；NCC 看归一化相关；ZNCC 先去掉平均亮度，再比较明暗变化模式。

最小交互实验｜同一个标签变亮了，还能找到吗？
对所有候选位置执行真实的 SSD 或 ZNCC 计算，并展示响应图
纯浏览器计算 · 无外部依赖
参考模板（3×3 灰度图块）
固定不变的参考外观
当前图像（绿色：真正目标；橙色：算法选中）
改变亮度后，真正目标与参考的像素值会整体偏移。
所有候选位置的匹配响应图（越深越匹配）

02 OTHER SIMILARITY EVIDENCE

逐像素不同，还能比较哪些信息？

像素匹配要求两块图像几乎逐位置对齐。若我们只知道目标大致是什么颜色、具有怎样的纹理，或者有一条特殊轮廓，也可以先把参考变成另一种描述，再计算相似程度。

2.1 · 颜色直方图：比较颜色比例，而非每个像素的位置

直方图记录不同颜色区间出现多少次。如果参考图和候选区域有相近的颜色分布，即使颜色排列顺序改变，它们的直方图也可能相近。

Bhattacharyya 系数 · 两个归一化直方图的重合度
BC(p,q) = ∑k √(pk qk)
pk、qk 是第 k 个颜色区间的概率占比，均非负且各自总和为 1。BC 越接近 1，两个分布越接近。它比较的是颜色统计，不保留颜色在哪里出现。
机制图｜不同空间排列，也可能有相同的颜色统计

2.2 · Backprojection：已知颜色分布，怎样在图中找候选区域？

先统计参考目标的颜色分布，再为当前图像的每个像素查询它落在哪种颜色区间，并赋予相应的响应值。这样就能得到一张颜色匹配响应图。但它本身不会告诉你每个高响应区域属于哪个实例。

参考颜色直方图→当前像素颜色查表→响应热图→候选区域组织

2.3 · 轮廓相似性：如果参考的是形状呢？

可以用 Hu Moments 比较形状的整体统计特征，也可以用 Chamfer Matching 比较两组轮廓点靠得有多近。后者的直观想法是：参考轮廓上的每个点，到候选轮廓的最近距离有多大？

单向 Chamfer 距离
D(A,B) = 1|A| ∑p∈A minq∈B ‖p−q‖
A 是参考轮廓点集，B 是候选轮廓点集。每个 p 找到 B 中最近的 q，算距离并取平均；越小越接近。它是单向的，且通常需要先考虑平移、尺度和旋转对齐。
这一节的共同点：我们改变的是「比较依据」，不是换了一种全新的目标识别能力。颜色统计、轮廓和纹理描述，都可能被不同物体共享；它们只提供匹配证据。
03 POSITION SEARCH

相似度会算了，怎样在整张图里找位置？

比较两块已经对齐的图像，只能回答「这两块有多像」。要定位目标，我们还不知道该取当前图像的哪一块，因此需要搜索候选位置。

3.1 · Sliding Window：每个位置都算一次分数

将宽 w、高 h 的模板，在宽 W、高 H 的当前图像上逐位置滑动。每个位置都会得到一个分数 S(u,v)，最后形成响应图。如果步长为 1 且不允许越界，响应图大小是：

模板滑动的有效位置数
(W − w + 1) × (H − h + 1)
例如 100×80 的图，20×10 的模板，有 81×71 = 5751 个整像素候选位置。这里还没有计入不同尺度和旋转角度。
机制图｜滑窗搜索把“相似性”变成一张位置响应图

3.2 · 目标缩放或旋转了，为什么要重复搜索？

固定模板隐含了「目标尺寸和方向与参考差不多」的假设。目标缩小、放大或旋转后，原来的窗口往往无法对齐。

MULTI-SCALE
图像金字塔 / 多尺度搜索

在不同缩放倍率下比较模板，等于为目标准备了不同尺寸的候选。

ROTATION SEARCH
多角度模板

在多个候选旋转角度下计算得分，补偿有限范围的旋转变化。

它们的代价直观：搜索的尺度、角度越多，需要比较的候选越多。复杂的透视变化、形变或遮挡，仍不一定能靠这种枚举解决。

3.3 · 响应图有多个峰值怎么办？

如果画面里有多个类似标签，就可能产生多个较好的匹配位置。可以取最高峰，也可以从响应图提取多个局部极值，再用非极大值抑制（NMS）去除空间上高度重叠的候选。

不要混淆：位置搜索回答「在哪里计算相似性」；相似度公式回答「怎么算相似」；候选筛选回答「返回哪几个位置」。它们相关，但不是同一类技术。
04 MATCH CONFIDENCE

得分最好的位置，就一定是目标吗？

不一定。即使参考目标根本不在画面里，只要我们扫描了所有位置，通常仍能找到一个得分「相对最好」的候选。

需要检查的现象意味着什么应该怎么理解
最好得分仍然很差没有任何候选足够像应设置拒绝条件，而非强行定位
第一名和第二名接近可能存在多个相似位置需要返回多候选，或标记歧义
背景纹理与参考相似低层外观线索碰巧一致高得分不等于目标身份一致
光照、遮挡、形变明显参考与现场不再满足匹配假设更换比较依据，或考虑其他定位路线

此外，不同相似度的分数不能直接相互比较：SSD 是误差越低越好，ZNCC 是相关值越高越好；阈值是否可靠也取决于模板大小、纹理和真实场景。

这里要学到的是：最优候选不等于可信定位。匹配算法提供证据，是否接受结果还需要明确标准。
05 SELECTION & BOUNDARIES

实际遇到一个参考，优先考虑什么？

已知条件可以先考虑主要代价 / 限制
外观、位置对齐关系相对稳定SSD / SAD 模板匹配对整体亮度、尺度和旋转敏感
亮度或对比度存在整体变化ZNCC低纹理区域、局部照明或遮挡仍有问题
目标的颜色分布具有特点直方图比较 / Backprojection失去空间排列，容易与相似背景混淆
已知轮廓形状，纹理不稳定Hu Moments / Chamfer需要可靠轮廓，位置与尺度对齐很重要
尺寸、旋转变化范围有限多尺度 / 多角度搜索候选数量增长，效率下降
这一篇的核心：先把「相似」变成可计算的分数，再在图像中搜索候选位置；得分最高只是候选，是否可信还要看任务条件。若参考与现场差别较大，下一篇再研究局部特征的跨图像对应。
