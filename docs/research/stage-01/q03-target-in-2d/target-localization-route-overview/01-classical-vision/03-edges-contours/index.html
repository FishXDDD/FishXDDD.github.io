边缘与轮廓

一处像素变化，怎样变成可用的物体边界？

刚研究完区域与分割，我原以为拿到 Mask 就能得到边界。可换到只有 RGB 的画面时，情况不同了：物体外沿、桌面纹理、阴影与反光都能产生突变。检测到一条线，并不意味着找到了目标轮廓。

这次从最笨的办法开始：先比较相邻像素的差值。每当发现噪声、粗边、断线、曲线冗余或定位误差，再看看缺少什么条件、需要哪种技术。最终保留一张按输入和失效问题分叉的技术地图。

00 · SCOPE

先分清楚：从 RGB 检测变化，与从 Mask 追踪边界，是两件事

之前学会了组织像素得到 Mask。若 Mask 已经可靠，沿它的内外分界追踪就能得到轮廓。但如果只有 RGB，根本不知道哪些像素属于物体，只能从局部亮度或颜色变化寻找潜在边界。两种输入依赖不同的证据，不能混为一谈。

路径 A · 从图像出发
RGB / 灰度 → 梯度 → Edge Map

判断局部变化有多强、方向是什么。纹理、阴影、反光和真实物体边界，都可能产生响应。

路径 B · 从 Mask 出发
二值区域 → 边界追踪 → Contour

既然前景归属已知，沿区域边界走一圈就能得到有序的曲线；不要求原图在边界处必须有明显梯度。

相同场景中的两种“线”
图像梯度是局部变化的证据，Mask 轮廓是区域归属的结果；它们可以互相验证，但不应当混为一谈。

01 · IMAGE DERIVATIVES

最简单的差分一试，为什么还要 Sobel 和 Scharr？

我们没有 Mask，先试着看相邻像素亮度差。理想图像里，一条明暗分界会出现显著差值；但图像是二维的，而且噪声一样会让亮度跳动。

先试什么

一维相邻像素直接相减，超过阈值就标成边。

马上发现

同一条斜边的响应依赖方向；单个坏点可能产生很大的差值，条纹也会响应。

于是引入

用 x/y 导数得到梯度方向和幅值；Sobel 提供局部平滑，Scharr 改善小核的方向一致性，LoG 则从平滑后的二阶零交叉出发。

连续形式： ∇I = (∂I/∂x, ∂I/∂y)
离散估计： Gx = I * Sx， Gy = I * Sy
梯度幅值： M = √(Gx² + Gy²)
梯度方向： θ = atan2(Gy, Gx)　（边缘法线方向）

1.1 · Sobel 到底对 3×3 邻域做了什么？

Sobel 用两个 3×3 卷积核近似一阶导数：横向变化由 Sx 响应，纵向变化由 Sy 响应。它不是拿一个像素和另一个像素简单相减，而是沿垂直方向进行带权平均，因而具有一定的平滑效果。

在垂直明暗边缘上，Gx 很大而 Gy 接近零。梯度方向垂直于边缘本身：这里法线近似水平，边缘切线近似竖直。把方向理解反了，后面的非极大值抑制就会做错。

1.2 · 为什么要有不止一种求导方法？

方法计算依据适合回答的问题核心局限
Sobel一阶差分 + 正交方向平滑有多大局部变化，方向指向哪里？小窗口有方向性误差，噪声会增强梯度
Scharr改进 3×3 导数核的旋转一致性小核条件下能否得到更准确的梯度方向？仍然是局部导数，不能区分纹理与外边界
Laplacian二阶导数 ∂²I/∂x² + ∂²I/∂y²变化速率再次变化的位置在哪里？对噪声更敏感，直接阈值并非可靠的边缘定位
LoG先高斯平滑再做 Laplacian能否利用二阶响应的零交叉寻找边缘？尺度 σ 改变边缘细节，需避免微小噪声交叉

一阶梯度通常在灰度跃迁最陡处出现峰值；经平滑的二阶导数常在理想边缘附近出现符号变化（零交叉）。二者是不同的测量思路，不能把“二阶导数越大越是边界”当成普遍判断。

这里的第一个边界：局部剧烈变化不等于物体边界。衣服条纹、桌面木纹、反光和阴影都可能比真正的物体轮廓拥有更大的梯度。
下一道问题

已经会计算“变化强度”了，可一条真实边缘往往出现一整条宽梯度带，零碎噪声点也还在。仅靠一个幅值阈值能解决吗？

02 · CANNY PIPELINE

一条边有好几像素宽，阈值也总在漏检与误报之间摇摆

Sobel 给出梯度幅值后，最自然的处理是直接阈值化。但如果你在原图里看到的是一条细边，结果却是一条宽带，那么首先缺的不是更高阈值，而是“边到底在哪里”的定义。

先试什么

给梯度幅值 M 设置一个阈值，大于阈值的全标白。

马上发现

阈值低会出现噪声和多像素厚的边；阈值高会把同一条边的弱段切断。

于是引入

先平滑，再沿梯度法线做 NMS 留局部峰，最后用高低双阈值与滞后连接处理弱边：这几件事共同构成 Canny 的核心链条。

灰度图→Gaussian 平滑→梯度幅值 / 方向→NMS 变细→双阈值 + 滞后连接

2.2 · 为什么“Canny 检测到线”还不够？

Canny 的结果是一个二值边缘像素图，不是“某个物体的一条完整闭合轮廓”。结果可以断裂、互相交叉，也可能出现多个同心边；Canny 本身不会给边缘线附上物体 ID。下一步必须区分两个不同任务：从边缘像素连接线段，或直接从二值 Mask 沿边界追踪。

参数不是越敏感越好。降低阈值可以保留弱边缘，也会保留不希望的纹理；增大 σ 能降低噪声，也会消除细线。合理选择取决于目标边界的空间尺度与对比度。
下一道问题

边缘图比梯度图干净了，但白点仍是像素集合：遇到断线、分叉或闭合区域，怎样知道这些点应该怎样连接？

03 · CONTOUR TRACING

有了边缘点，怎样把它们变成一条“能沿着走”的线？

把一张 Canny 图拿到手，会看到很多白色像素。直接统计它们个数没法知道曲线长度，也没法确定下一段的走向。此时要先区分：手里是边缘图，还是已经分好的前景 Mask？

先试什么

把所有相邻白点看成同一条线。

马上发现

分叉点可能有三个方向；Canny 允许开放边线，也未必围成任何区域。反过来，可靠 Mask 的边界即使原图梯度很弱，也依然明确。

于是引入

对边缘图先建立连接关系，必要时处理端点/分叉；对 Mask 用边界跟踪（Suzuki–Abe 等）直接提取有序的内外边界。

3.1 · 输入不同，能追踪的东西也不同

输入能够可靠进行的处理不能默认成立的假设
Canny Edge Map寻找 8 连通边缘像素、跟踪边线或图结构边线不一定闭合；交叉、分叉点无唯一行走顺序
二值前景 Mask沿每块前景和孔洞的分界追踪闭合边界归属 Mask 必须足够可信，追踪不会纠正分割错误
灰度 / RGB先定义阈值或边缘判据，再得到可追踪的二值结构findContours 并不是 RGB 物体边界识别器
先处理只有 Edge Map 的情况：可以把保留下来的边缘像素视为图节点，按 8 邻接连边，寻找端点、分支点，并沿相邻边跟踪线段。某条线断开时，“把两个端点补起来”还需要距离、切向连续性或其他先验；单纯最近距离连接可能把两件物体误接在一起。Canny 的滞后连接只筛选相连的弱梯度，不等于跨越空白补齐整条物体轮廓。
同样是线，输入不同，追踪能确定的东西也不同
仅为结构示意。边缘连接不会自动得到前景标签；Mask 追踪也不会替输入分割纠错。

3.2 · 从任意二值区域，如何让边界“走一圈”？

可以把边界追踪理解成三个动作：找到一个前景与背景接壤的位置；按固定规则寻找下一段边界；记录沿途的边界点，直到返回起点并满足闭合条件。这会把一个无序边界集合变成一条曲线。常见实现可采用边界跟踪（如 Suzuki–Abe 思想）与链码表示。

3.3 · 轮廓为什么可能不止一条？

一个甜甜圈形 Mask 至少有两条边界：外围一圈与中间孔洞一圈。边界方向还可以辅助判断内外（具体顺逆时针与坐标系有关），但仅靠轮廓数量并不能得到物体数量：一件物体有孔，两个物体紧贴，都会破坏简单的“一条轮廓对应一件物体”直觉。

对 OpenCV 要有清楚的预期：cv2.findContours(binary, mode, method) 针对二值图寻找轮廓。它能返回有序轮廓点和可选层级，但不会自动把未闭合的 Canny 边缘修成理想物体外轮廓。只要 Mask 存在粘连、空洞或噪声，轮廓就会忠实反映这些问题。

拿到一条轮廓后，逐像素都保存会很冗余。能否让表示更简洁，同时控制丢失多少形状？

04 · CONTOUR REPRESENTATION

曲线已经连起来，却有几千个点：能不能先删掉冗余？

轮廓追踪解决了“点之间是什么顺序”，但沿着一条接近直线的边，逐像素存储既浪费又不利于后续几何分析。先从表示层面尝试减少点数。

先试什么

把连续共线的中间点删掉，只留方向变化位置。

马上发现

这只能压缩栅格链码；如果边缘本身有一点抖动，就会保留许多细碎折线。

于是引入

CHAIN_APPROX_SIMPLE 处理规则直线段的冗余；Douglas–Peucker 用最大偏离距离 ε 控制整体折线近似，而不是指定“保留几个角”。

4.1 · 两种看起来相似，其实不同的简化

CHAIN_APPROX_SIMPLE
压缩重复的链方向

边界跟踪时删去水平、垂直、对角直线段的中间点，主要减少链码冗余。

Douglas–Peucker
允许有界的几何偏差

用一条线段近似一段曲线；如果最大偏离距离超过 ε，则保留那个最远点并递归分段。

给定折线端点 A、B，中间点 Pi 到线段 AB 的距离：di = dist(Pi, segment AB)
若 max(di) ≤ ε：用 AB 代替该折线；否则在最大偏差点处分成两段，递归处理。
交互实验 · Douglas–Peucker 究竟留下哪些点？示例为开放折线 · 距离单位为画布像素
灰色细线：原始有序点；橙色粗线：简化后的折线；深色圆点：被保留的顶点。闭合轮廓需要额外处理起终点和环形分段；本实验选开放曲线，是为了清楚观察递归机制。

这里的 ε 是允许的几何偏差，不是“希望留下几个角点”。ε 太小保留大量抖动，ε 太大可能把瓶口、狭窄凹槽和细小凸起整个删掉。approxPolyDP 的 ε 使用与输入轮廓一致的坐标单位，常见像素轮廓对应像素距离。

4.2 · 为什么简化不能代替平滑，平滑也不能代替定位？

Douglas–Peucker 从已有点中选子集，不会主动产生更精确的新边缘位置。轮廓平滑则改变点的位置，可能让锯齿更自然，却也会改变真实尖角。若要求亚像素定位，可以在边缘法线方向采样梯度峰或灰度跃迁，并用局部函数拟合峰位；这属于重新估计边缘位置，而不是把 findContours 的结果简单插值放大。

示意：若法线方向三个相邻梯度幅值为 m−1, m0, m+1，
用抛物线拟合局部极大值位置： δ = (m−1 − m+1) / [2(m−1 − 2m0 + m+1)]
仅在中心确为局部峰且分母有效时使用，并需限制 |δ| 的合理范围。
这里有一个尺度陷阱。细电线在图上可能只有 2～3 像素宽：高斯平滑、腐蚀或轮廓简化的尺度稍大，就可能彻底失去这部分几何。算法变得“更整齐”不意味着测量更真实。
下一道问题

但如果一条轮廓既有外圈又有内孔，仅保留坐标和简化结果，依然不知道这些线相互是什么关系。

05 · CONTOUR HIERARCHY

轮廓数变多了：外边界、孔洞与内岛怎样区分？

轮廓看似是一条条独立闭合线。试着取一个圆环形零件，会发现同一个前景区域至少有内外两条轮廓；若孔中还有前景，又多一层。

先试什么

把 findContours 返回的每条曲线都当成一个目标。

马上发现

一件有孔的物体会产生多条轮廓；把孔当作新实例，数量就错了。

于是引入

使用轮廓包含关系与 hierarchy，明确外边界、孔洞和内岛，决定应取 RETR_EXTERNAL、RETR_CCOMP 还是 RETR_TREE。

交互实验 · 同一张 Mask，切换不同的层级检索规则示意 A / B / C / D 四条轮廓
A 是大区域外轮廓；B 是洞；C 是洞中的独立前景岛；D 是另一块独立前景。包含关系：A → B → C，D 独立。
当前模式返回
模式返回的轮廓保留的层级什么时候用
RETR_EXTERNAL只取最外层轮廓不保留内部孔洞轮廓只关心各块最外侧边界
RETR_LIST取所有边界轮廓不建立父子关系只需要轮廓列表，不关心包含关系
RETR_CCOMP取所有边界轮廓组织成两级：外边界和洞；更深层前景岛回到顶级按连通成分和孔洞处理
RETR_TREE取所有边界轮廓尽量完整保留嵌套层级需要推断外轮廓、孔洞及层层包含关系

OpenCV 为每条轮廓提供一个四元数组 [next, previous, first_child, parent]，其中元素是返回列表内的索引，不存在时为 −1。不要假定具体轮廓的数值索引稳定；应该根据 hierarchy 读取关系。

与 05《骨架与拓扑》的分工：这里仅关心边界之间的父子包含与内外关系；形状内部如何连通、分支、产生骨架与拓扑骨干，放到后续专题研究。
下一道问题

现在曲线的拓扑与表示都有了；不过像素级坐标仍未说明真实边界精确落在哪里。想要更准确的位置，不能只做轮廓简化。

06 · ACCURACY & REFINEMENT

轮廓形状已经知道，可它为什么仍然偏了半个像素？

前面研究的简化与层级主要解决“如何表示一条边界”。但像素坐标并不天然等于真实光学边界：镜头模糊、采样、NMS 和阈值都会影响保留的位置。现在真正想改的是估计出的边界坐标。

先试什么

把整数像素轮廓插值成更多点，看起来更平滑。

马上发现

插值只是生成中间坐标，不会凭空增加观测信息；如果原线就偏了，插值后仍偏。

于是引入

沿法线拟合局部梯度峰，或从一条初始曲线出发按图像能量调整整条轮廓。

6.1 · 第一个朴素想法：梯度最大位置不一定刚好落在像素中心

假设某条边缘法线方向的离散梯度最大值在 x₀，但左右两个采样也很强。利用三点局部抛物线拟合，可以估计最大值相对于中心的偏移 δ。这是局部模型估计，不是无条件提高精度。

g₋₁ = g(x₀−1)，g₀ = g(x₀)，g₊₁ = g(x₀+1)
δ = (g₋₁ − g₊₁) / [2(g₋₁ − 2g₀ + g₊₁)]
估计峰位置：x̂ = x₀ + δ（需局部极大，且分母不接近 0）
交互实验 · 同一个中心峰，左右观测不对称时峰位会偏移多少？局部抛物线拟合 · 单位：像素
曲线只根据三点拟合；数值发生小数偏移不等于真实误差更小。实测需要验证噪声、模糊和边缘类型是否支持该局部模型。

6.2 · 如果不是一个点偏了，而是整条曲线没贴住边界？

另一条路线是 Active Contour / Snakes。从一条已有的初始曲线出发，让像素上的曲线点可以移动：图像证据吸引曲线靠近候选边界，内部正则项约束拉伸与弯曲。它解决的是曲线位置的整体优化，不是降低表示点数。

E(C) = ∫ [ α‖C′(s)‖² + β‖C″(s)‖² + E_image(C(s)) ] ds
α：拉伸/连续性约束；β：弯曲平滑约束；E_image：图像吸引代价
同一条目标边界：轮廓简化与曲线优化不是一回事

代价：如果图像中有比真实目标更强的纹理边线，或者初始轮廓距目标太远，优化可能被错误边缘吸引；内部平滑约束太强，也可能吞掉真实凹角。

Python · 法线方向三点拟合（最小数学实现）
def local_subpixel_peak(g_left, g_center, g_right):
    """输入已经沿梯度法线采样的 3 个幅值；返回中心像素相对偏移。"""
    if not (g_center > g_left and g_center > g_right):
        return None
    denominator = 2.0 * (g_left - 2.0 * g_center + g_right)
    if abs(denominator) < 1e-9:
        return None
    offset = (g_left - g_right) / denominator
    return offset if abs(offset) <= 0.5 else None

# 此处仅演示 1D 局部模型；实际二维边缘需沿梯度法线插值采样。
print(local_subpixel_peak(70, 100, 52))
下一道问题

边界能更细、更连续、更贴近图像，却仍没有回答“它是不是一个矩形的边”“哪里是可信角点”。这需要下一章的几何结构与拟合，而不是再调 Canny 阈值。

06 · METHODS & BOUNDARIES

最后只留下一个判断：我手里是哪一种边界证据？

现在已经看过变化检测、曲线追踪、表达、层级以及位置精修。它们并不是“一个比一个高级”的单向升级，而是解决不同层次的错误。

先试什么

遇到边界不好，直接改 Canny 阈值或轮廓近似参数。

马上发现

如果输入是错的 Mask，改 Canny 没意义；如果线段连接错误，简化只会把错误的线变得更整齐。

于是引入

先把失效归因到“变化检测 / 线的连接 / 区域归属 / 曲线表示 / 位置测量”之一，再选对应方法。

7.1 · 两种输入路线的最短 OpenCV 计算对照

下面把两条路径分开写。第一条从灰度图计算边缘；第二条从已经分好的二值 Mask 获得轮廓。不要把 Canny 的边缘二值图不加区分地当作完整前景 Mask。

Python · 路线 A：图像变化 → 边缘响应
import cv2
import numpy as np

gray = cv2.imread("image.png", cv2.IMREAD_GRAYSCALE)
if gray is None:
    raise FileNotFoundError("image.png")

# 原始一阶导数：保留正负符号，避免 uint8 截断
blur = cv2.GaussianBlur(gray, (5, 5), 1.1)
gx = cv2.Sobel(blur, cv2.CV_32F, 1, 0, ksize=3)
gy = cv2.Sobel(blur, cv2.CV_32F, 0, 1, ksize=3)
magnitude, angle_deg = cv2.cartToPolar(gx, gy, angleInDegrees=True)

# 独立的 Canny 处理链：阈值不是本页百分比实验的数值
edges = cv2.Canny(gray, threshold1=50, threshold2=120,
                  apertureSize=3, L2gradient=True)
cv2.imwrite("gradient.png", cv2.convertScaleAbs(magnitude))
cv2.imwrite("edges.png", edges)
print("edge pixel count:", int(np.count_nonzero(edges)))
Python · 路线 B：Mask → 有序轮廓 → 简化与层级
import cv2
import numpy as np

mask = cv2.imread("mask.png", cv2.IMREAD_GRAYSCALE)
if mask is None:
    raise FileNotFoundError("mask.png")
_, binary = cv2.threshold(mask, 127, 255, cv2.THRESH_BINARY)

contours, hierarchy = cv2.findContours(
    binary.copy(), cv2.RETR_TREE, cv2.CHAIN_APPROX_SIMPLE
)

canvas = cv2.cvtColor(binary, cv2.COLOR_GRAY2BGR)
if hierarchy is not None:
    h = hierarchy[0]  # 每条轮廓 [next, prev, child, parent]
    for idx, contour in enumerate(contours):
        if len(contour) < 2:
            continue
        perimeter = cv2.arcLength(contour, closed=True)
        epsilon = 0.01 * perimeter  # 示例比例，不是普适最优值
        simplified = cv2.approxPolyDP(contour, epsilon, closed=True)
        cv2.polylines(canvas, [simplified], True, (0, 170, 245), 2)
        print(idx, "points", len(contour), "->", len(simplified),
              "parent", int(h[idx][3]))
cv2.imwrite("contours.png", canvas)

7.2 · 下一站为什么还需要“几何结构”？

现在最多只能说：某处有明显图像变化，或者某个 Mask 的外边界可以被表示为一条有序曲线。它本身并不直接告诉我“这条边是不是直线”“这个物体是不是矩形”“哪个拐角最稳定”。这些需要建立几何模型、拟合误差与约束条件，将留到 04《几何结构》。

这一篇收束为四个结论：
  1. 边缘是观测证据：对亮度、颜色或纹理变化敏感，不自带物体归属。
  2. 轮廓是有序边界：依赖可追踪的二值结构，包含外边界、孔洞和层级。
  3. 简化只改变表示：能控制点数与偏差，但不会把错误区域变成正确物体，也不会自动完成几何识别。
  4. 精修改变估计：亚像素拟合与主动轮廓可以调整边界位置，但必须通过可验证的误差指标评价。
