几何结构

边界有了，怎么知道它是一条线、一个圆，还是四个真正的角？

03 已经能把像素边缘整理成有序的曲线。可在图上选一排点，轻轻一连，就有了一条“看起来挺直”的线；用一个矩形框住轮廓，也很容易。问题是：这些画出来的几何形状，真的被图像证据支持吗？

这次仍然从简单办法出发：先用两点连线，再试所有点共同拟合；发现异常点后引入鲁棒估计；遇到弯曲边界换圆或椭圆；需要四角时再比较外接框、轮廓拐点和相邻边求交。最终建立一份知道何时选模型、怎样算、怎样证伪的工具地图。

00 · SCOPE & THE QUESTION

先把边界划清：观测点不是几何模型，外接框也不是物体四角

上一章提供了一串有序轮廓点 p₁, p₂, …, pₙ，或尚未分组的 Edge Map 像素。点在哪里和这些点遵从什么几何规律是两个不同问题。一个矩形的外接框、四条拟合线，以及物体表面真实的四个投影角点，也完全不是同一组参数。

因此这一篇采用最小充分的几何模型：给出明确输入 → 计算候选参数 → 用残差、覆盖范围和几何条件验证。几何模型不是识别结果，更不会因为参数算出来就自动变成 3D 位姿。

同一组轮廓点，可以有不同层次的几何解释
边界点是观测；直线、圆和矩形是模型。越强的模型假设，越需要用残差、覆盖范围及结构约束验证。
输入 · OBSERVATION
轮廓 / 边缘点 / Mask

有序轮廓、无序的候选边缘点，或由分割得到的目标区域。

本篇计算 · FIT & TEST
模型参数 + 误差

选模型、求参数、剔异常、检验几何约束与退化。

输出 · GEOMETRY
直线、圆、矩形、四边形

附带角点、中心、方向和拟合质量；不宣称是真实 3D Pose。

边界：本篇研究二维几何模型及其估计方法。轮廓追踪和边缘检测已在 03；骨架、分支结构留给 05；局部关键点与描述子留给 06。二维旋转角 ≠ 三维物体姿态。

01 · LINE ESTIMATION

只用两点就能连成线，为什么还要拟合和检测？

从 03 拿来的一段轮廓，看起来很直。最省事的做法当然是取首尾点画线，可只要某个端点偏一两个像素，整条线的角度就可能跟着改变。若点的归属还未确定，问题则又不同了。

先试什么

取两个端点决定一条直线，或者写 y = kx + b。

马上发现

端点噪声放大了角度误差；竖直线的斜率失去稳定性。更关键的是，全图 Edge Map 根本没有告诉我们哪些点属于同一条直线。

于是引入

对“已知同一条边”的点用 TLS 正交拟合；对“未知属于哪条边”的混合边缘用 Hough 或局部线段检测，再检查支持范围。

最朴素的两点直线：p₁=(x₁,y₁), p₂=(x₂,y₂)
方向向量 v = (x₂−x₁, y₂−y₁)，法向量 n = (−vᵧ, vₓ) / ‖v‖
缺点：只有两个观测决定参数；若 ‖v‖ 很小，方向对坐标误差极敏感。

让更多点参与拟合，是为了降低随机定位误差的影响；但前提是这些点真的属于同一条边。先从直线的表示和求解开始。

1.1 · 直线应该怎样表示？

熟悉的 y=kx+b 在接近竖直时会变得不稳定。更适合二维图像的一种表达是单位法向量形式：

ax + by + c = 0，且 a² + b² = 1
点 p=(x,y) 到直线的垂直距离 d(p,L) = |ax+by+c|
等价的 Hough 法向量形式：ρ = x cosθ + y sinθ

这样水平线、竖直线和斜线可以统一处理，而且距离就是像素尺度下的正交残差。

1.2 · 为什么不能只做普通的 y 对 x 最小二乘？

OLS · 普通最小二乘
最小化竖直偏差

最小化 Σ(yᵢ−kxᵢ−b)²。适合 x 近似无噪且线不竖直的回归问题；对于任意方向边缘，误差定义会偏向坐标轴。

TLS · 正交最小二乘
最小化垂直距离

最小化 Σ(axᵢ+byᵢ+c)²，约束 a²+b²=1。它对任意朝向的直线保持一致的几何含义。

求 TLS 并不神秘。先算点集质心 μ，把每个点减去质心形成矩阵 A；对 A 做 SVD。最小奇异值对应的右奇异向量就是直线法向量。最后令直线经过质心。

μ = (1/N) Σpᵢ；A = [p₁−μ; p₂−μ; …; pₙ−μ]
A = UΣVᵀ；n = V 的最小奇异值对应方向
(a,b)=n；c=−n·μ；RMSE = √[(1/N)Σ(n·(pᵢ−μ))²]

1.3 · 如果只是找“可能的直线”，有没有不依赖连续点序的办法？

Hough Transform 换一个观察角度：一个边缘点 (x,y) 不直接宣称属于哪条直线，而是给所有满足 ρ=xcosθ+ysinθ 的参数组合投票。多个共线点的参数曲线会在同一位置聚集。

点空间与参数空间的对应关系
机制示意，不是逐点精确绘制的累加器。实际 Hough 将 θ、ρ 离散成投票格，峰值位置和误检受量化精度与投票阈值影响。
TLS 与 Hough 是在回答不同问题：若已经知道某一组点属于一条边，直接拟合 TLS；若整张 Edge Map 里还不知道哪几组点共线，Hough 可以提出候选直线。Hough 的投票峰本身还需要确定线段长度与支持点。

1.4 · Hough 投票找到的是“无限直线”，线段从哪里来？

标准 Hough 通过累加器给出 (ρ, θ) 候选，对应的是无限延长的几何直线。但工程上常需要有起点、终点的有限线段。可以根据支持边缘点的投影范围确定线段，也可以直接用 Probabilistic Hough（HoughLinesP）输出端点。

另一条检测路线是 LSD（Line Segment Detector）：从图像局部梯度方向的一致性形成候选线支持区域，再验证是否足够像一条线段。它不要求事先得到某个物体的完整轮廓，但仍可能把物体内部纹理线检测出来。

已知一段轮廓
TLS / cv2.fitLine

输出一条与这些点最匹配的直线参数；若要有限线段，再用点在方向轴上的最小/最大投影确定端点。

整张图里的未知线
HoughLinesP / LSD

直接提出线段候选；还需要验证端点跨度、边缘支持、与目标区域的关系。

Python · 从边缘图提出线段候选
import cv2

gray = cv2.imread("image.png", cv2.IMREAD_GRAYSCALE)
if gray is None:
    raise FileNotFoundError("image.png")

edges = cv2.Canny(gray, 50, 120)
segments = cv2.HoughLinesP(edges, rho=1, theta=3.14159265 / 180,
                            threshold=45, minLineLength=35, maxLineGap=8)
if segments is not None:
    for x1, y1, x2, y2 in segments[:, 0]:
        print("Hough candidate:", (x1, y1), (x2, y2))

# LSD 使用灰度图，不要求先输入 Canny 结果
lsd = cv2.createLineSegmentDetector(cv2.LSD_REFINE_STD)
lines = lsd.detect(gray)[0]
if lines is not None:
    for x1, y1, x2, y2 in lines.reshape(-1, 4):
        print("LSD candidate:", (x1, y1), (x2, y2))
Python · 任意朝向直线的 TLS 拟合 
import numpy as np

def fit_line_tls(points):
    pts = np.asarray(points, dtype=np.float64)
    if pts.ndim != 2 or pts.shape[1] != 2 or len(pts) < 2:
        raise ValueError("至少需要两个二维点")
    center = pts.mean(axis=0)
    _, s, vh = np.linalg.svd(pts - center, full_matrices=False)
    if s[0] < 1e-10:
        raise ValueError("所有点几乎重合，方向未确定")
    normal = vh[-1]                    # 法向量
    a, b = normal
    c = -float(normal @ center)
    residual = np.abs(pts @ normal + c)
    return (a, b, c), float(np.sqrt(np.mean(residual ** 2)))
下一道问题

直线方向虽然估计了，如果轮廓夹杂一堆来自背景或反光的点，直接全点 TLS 仍然会被拉偏。

02 · ROBUST ESTIMATION

多个点共同拟合，一旦混入别的边，为什么反而更糟？

TLS 用上了全体观测，随机小噪声下通常会比两点确定的线稳定。但这隐含一个很强的前提：每个点都属于同一个模型。现实图像里，背景边线、反光和遮挡会让候选点集不干净。

先试什么

把所有候选点一股脑交给 TLS，取平均意义下最好的线。

马上发现

平方残差对远离模型的点十分敏感；几颗错误点就可能改变方向，多一条强背景边甚至能形成竞争解。

于是引入

RANSAC 用最小样本提出候选，再按几何距离投票；由胜出内点重新做 TLS，并检查支持长度、残差分布和竞争结构。

这时可以不再一口气让所有点决定答案，而是先让极少的点提出假设，再由整个点集验证假设。这就得到 RANSAC。

随机抽 2 点→得到直线假设→计算全体点到线距离→统计内点并重新拟合
内点判定：|axᵢ+byᵢ+c| < τ（单位：像素）
k ≥ log(1−P) / log(1−wˢ)
直线最小样本数 s=2；P=目标成功概率，w=真实内点比例的估计

迭代次数公式来自“独立随机样本至少有一次全部落在内点”的概率；实际迭代有有限样本、退化样本、阈值和局部优化等影响。RANSAC 不能证明哪个模型代表真实物体，得票最多只代表当前规则下支持点多。

2.1 · 哪些时候 RANSAC 也会给出看似合理的错误答案？

场景 A
两条真实边并存

若两条线各有很多点，只找一条线时，最多内点的线不一定是目标边。

场景 B
阈值选择错误

τ 太小：同一边被拆碎；τ 太大：不同结构被一起当作内点。

场景 C
数据本来就不成线

短圆弧或弯曲边也可能被局部直线近似；低残差不代表全段真是直线。

一个可验证的几何模型，不仅要检查内点数量，还要看覆盖长度、空间分布、残差分布以及是否存在竞争模型。否则几个聚在一起的点也可能支撑一条“好直线”。

Python · 两点假设 + 内点 TLS 精化 
import numpy as np

def ransac_line(points, threshold_px=3.0, iterations=300, seed=0):
    pts = np.asarray(points, dtype=np.float64)
    if len(pts) < 2:
        raise ValueError("至少需要两个点")
    rng = np.random.default_rng(seed)
    best = np.zeros(len(pts), dtype=bool)
    for _ in range(iterations):
        i, j = rng.choice(len(pts), 2, replace=False)
        delta = pts[j] - pts[i]
        length = np.linalg.norm(delta)
        if length < 1e-9:  # 退化样本
            continue
        normal = np.array([-delta[1], delta[0]]) / length
        distance = np.abs((pts - pts[i]) @ normal)
        inliers = distance < threshold_px
        if inliers.sum() > best.sum():
            best = inliers
    if best.sum() < 2:
        raise ValueError("没有足够的内点")
    line, _ = fit_line_tls(pts[best])  # 用上一节函数
    a, b, c = line
    refined = np.abs(pts @ np.array([a, b]) + c) < threshold_px
    return line, refined

03 · CIRCLE & ELLIPSE

边界明明在持续弯曲，为什么还要强行画直线？

对一段弯曲轮廓，切线方向沿着弧不断变化。继续用更多直线段拟合当然可以逼近，但如果形状本身有规律，可能有更简洁的参数表达。

先试什么

先看这条弧的每一点离某个中心是不是差不多远。

马上发现

只露出一小段圆弧时，半径和圆心可能有许多近似解；斜视角里的平面圆投影也一般不是圆。

于是引入

先做圆的代数初值，再用径向几何残差优化；如果透视轮廓更像椭圆，采用椭圆模型，并用弧段覆盖和参数稳定性防止过度解释。

圆：(x−cₓ)² + (y−cᵧ)² = r²
几何残差：eᵢ = ||pᵢ−c|| − r
拟合目标：min₍cₓ,cᵧ,r₎ Σ eᵢ²

三个不共线的点可以唯一确定一个圆。方法是展开为 x²+y²+Dx+Ey+F=0，求 D、E、F，再恢复中心和半径。但三个点越接近共线，圆心越可能跑到很远的地方；因此“可解”与“稳定”是两回事。

3.1 · 圆的求解为什么有两种常见做法？

代数拟合
解线性参数 D、E、F

快、便于求初值，但最小化的是代数残差；短弧和噪声下可能有偏差，甚至出现不合理半径。

几何拟合
直接优化径向误差

以代数结果为初值，再用非线性最小二乘优化 cₓ、cᵧ、r，使误差更符合几何距离。

3.2 · 为什么圆不够，还需要椭圆？

从斜视角看一个平面圆，它的图像通常不再是圆而是椭圆（在常见的非退化成像条件下）。二维椭圆一般可以用中心、两个半轴和旋转角描述；也可以用一般二次曲线表示。

Ax² + Bxy + Cy² + Dx + Ey + F = 0
椭圆型二次曲线需满足 B² − 4AC < 0，并检查是否为真实非退化椭圆

一般二次曲线有 6 个系数，但整体尺度不影响曲线，因此需要至少 5 个满足条件的点才能约束它；实际估计需要更多分布良好的点。OpenCV 提供 fitEllipse、fitEllipseAMS 和 fitEllipseDirect 等方法，具体结果受采样分布影响。

必须保留的疑问：短圆弧也能被某个大圆“解释”，少量边界也能被椭圆拟合。小残差只能说明模型贴近已观测部分，不说明未观察到的背面真的延伸成完整圆或椭圆。

from scipy.optimize import least_squares

def fit_circle(points):
    p = np.asarray(points, dtype=float)
    if p.shape[0] < 3 or p.shape[1] != 2:
        raise ValueError("至少需要三个二维点")
    A = np.c_[2 * p[:, 0], 2 * p[:, 1], np.ones(len(p))]
    b = np.sum(p * p, axis=1)
    if np.linalg.matrix_rank(A) < 3:
        raise ValueError("圆参数退化：点近似共线")
    cx, cy, k = np.linalg.lstsq(A, b, rcond=None)[0]
    r0 = np.sqrt(max(0., k + cx**2 + cy**2))
    def residual(v):
        return np.linalg.norm(p - v[:2], axis=1) - v[2]
    result = least_squares(residual, [cx, cy, r0],
                           bounds=([-np.inf, -np.inf, 0],
                                   [ np.inf,  np.inf, np.inf]))
    return result.x, np.sqrt(np.mean(result.fun**2))

04 · BOUNDING GEOMETRY

只想框住一个物体，为什么三种外接框会给出不同结果？

现在不用先猜是直线还是圆，拿到一整块轮廓，只要围住它。最直觉的是取 x/y 的最小和最大值；但一旦目标旋转或斜视，框里就出现大片空白。

先试什么

直接用 boundingRect 取 AABB，然后改成一个能旋转的框。

马上发现

最小面积框与 PCA OBB 的优化目标不同；它们都只保证某种包围/主轴解释，而不是四条真实边和四个实际角点。

于是引入

比较 AABB、minAreaRect 和 PCA；如果需要投影后的四角，则转向凸四边形约束、分段直线拟合与交点估计。

AABB
图像坐标轴对齐

boundingRect 使用 x/y 的最大最小值；速度快、坐标简单，但物体旋转后空白区域很多。

Minimum-area rectangle
面积最小的旋转外接矩形

minAreaRect 寻找包住全部点的最小面积旋转矩形；对应的是包围约束，不是物体真实四角。

PCA OBB
点云分布主轴

利用协方差主特征向量定方向，再沿主轴取包围范围；优化的是方差方向，不保证外接面积最小。

交互实验 · 同一个四边形，换三种包围框图形是模拟的透视四边形

MinArea 面积—
PCA OBB 面积—

三种面积均指二维外接框像素面积。青绿色是原始四边形；最小面积框和 PCA 框通常不能与真实四角重合。在透视作用下，物体表面的直角也一般不能通过图像中的直角直接恢复。

4.1 · 既然已经有四角，为什么还需要区分矩形和四边形？

如果上游用了 approxPolyDP 得到了 4 个顶点，只能说明轮廓可以近似为四段线连接的多边形；它还没有证明相邻边正交，更没有证明这些角点是物体真实的四个物理角。

对于一张真实拍摄的平面矩形，透视会改变角度与长度比例。它在图像中通常是一个凸四边形，而不是矩形；强行用 minAreaRect 的四个角替代真实角点，会引入系统误差。

二维图像中四类容易混淆的几何对象
示意图强调几何定义不同；使用了透视的真实四边形不一定与任何正交矩形模型一致。

4.2 · 怎么从轮廓验证“四边形”或“近似矩形”假设？

先对轮廓执行多边形逼近，并检查 4 个顶点、顶点顺序、凸性、非零面积。如果需要进一步称其为图像平面内的近似矩形，才检验相邻边的夹角接近 90°、对边近平行等约束；这些检验必须考虑透视与噪声。

相邻边 e₁、e₂ 的夹角余弦：cosφ = (e₁·e₂)/(||e₁||||e₂||)
矩形的图像几何测试：|cosφ| ≈ 0（仅在假设图像中近似正交时）
凸四边形测试：连续叉积 cross(eᵢ,eᵢ₊₁) 符号应一致（排除共线退化）
真实透视矩形可以明显不满足图像上的 90° 约束。因此不应把“检测到非直角”直接等同于“物理上不是矩形”；更不能把最小外接框角点当成实物的几何角点。
Python · 三种包围框 + 四边形候选 
import cv2
import numpy as np

def contour_geometry(contour):
    cnt = np.asarray(contour, dtype=np.float32).reshape(-1, 1, 2)
    x, y, w, h = cv2.boundingRect(cnt)          # AABB
    min_rect = cv2.minAreaRect(cnt)               # (center, size, angle)
    min_box = cv2.boxPoints(min_rect)             # 旋转外接框的 4 点

    pts = cnt.reshape(-1, 2)
    center = pts.mean(axis=0)
    _, _, vt = np.linalg.svd(pts - center, full_matrices=False)
    axes = vt[:2]                                 # PCA 两条正交轴
    local = (pts - center) @ axes.T
    lo, hi = local.min(axis=0), local.max(axis=0)
    local_corners = np.array([[lo[0], lo[1]],
                              [hi[0], lo[1]],
                              [hi[0], hi[1]],
                              [lo[0], hi[1]]])
    pca_box = local_corners @ axes + center

    epsilon = 0.02 * cv2.arcLength(cnt, True)
    poly = cv2.approxPolyDP(cnt, epsilon, True)
    is_quad = len(poly) == 4 and cv2.isContourConvex(poly)
    return (x, y, w, h), min_box, pca_box, (poly if is_quad else None)

05 · CORNER ESTIMATION

我需要的是四个物体角点，为什么拿外接框或四个拐点还不够？

minAreaRect 的四角是最小包围矩形的结果；approxPolyDP 的四角是轮廓折线近似的结果。如果应用需要抓取平面物体的四个可见边界交点，这两个结果只能是候选，不能当成已验证的物理角。

先试什么

让轮廓逼近成四边形，直接用四个顶点作为角点。

马上发现

点的位置受轮廓噪声和 epsilon 影响；一个局部缺口就可能让角点偏到缺口上，且斜视时角度未必是 90°。

于是引入

先分出四段直边，对每段独立做稳健直线拟合；相邻边求交后再检查凸性、边支持及交点稳定性。

5.1 · 把角点当成两条边的交点，而不是一个跳得很厉害的像素

若两条局部拟合线分别为 a₁x+b₁y+c₁=0 和 a₂x+b₂y+c₂=0，交点可以通过一个 2×2 线性系统求出。每条线的参数由多点支持，通常比仅取某个轮廓采样点更可控。

有序轮廓→四条候选边段→每段 TLS / RANSAC→相邻线求交→质量检验
[a₁ b₁; a₂ b₂] · [x; y] = −[c₁; c₂]
det = a₁b₂ − a₂b₁
|det| 接近 0 ⇒ 两条边近似平行，交点位置对线参数误差非常敏感。
相同的投影四边形，框角与边线交点可能明显不同
位置仅为机制示意；包围框没有模拟特定 OpenCV 算法的精确输出。

5.2 · 两条边接近平行时，角点为什么会飞到很远？

就算每条直线的误差只有 1 px，当两条边的夹角很小，交点误差也可能被大幅放大。下面把第一条线固定为 y=0，理想第二条线穿过原点；现在把第二条线竖直平移 1 px，观察交点 x 坐标的变化。

5.3 · 工程里怎样把四条线变成四角？

Python · 由四条已拟合的相邻直线求交点
import numpy as np

def intersect_lines(line_a, line_b, min_sin_angle=0.10):
    # line = (a, b, c), 且 (a, b) 为单位法向量
    a1, b1, c1 = map(float, line_a)
    a2, b2, c2 = map(float, line_b)
    A = np.array([[a1, b1], [a2, b2]], dtype=float)
    det = float(np.linalg.det(A))
    if abs(det) < min_sin_angle:  # 夹角过小 / 近似平行
        return None
    point = np.linalg.solve(A, -np.array([c1, c2]))
    return point

def quadrilateral_from_lines(lines):
    """lines: 按轮廓顺序排序的四条已验证的直线。"""
    if len(lines) != 4:
        raise ValueError("需要四条直线")
    corners = [intersect_lines(lines[i], lines[(i+1) % 4])
               for i in range(4)]
    if any(p is None for p in corners):
        return None
    return np.array(corners)  # 还需检测凸性、支持范围、交点位置
容易误读的两件事：透视下真实矩形的图像四角通常不是 90°；即使识别出了四个像素坐标，依然不是三维姿态。如果要校正平面，可在明确四角对应关系后计算 Homography，但恢复真实尺度、方向还需要额外几何条件。

四条线求交得到四角，或拟合出一个完美圆，都只是候选参数。怎样证明它们不是数据不足、模型选错或局部噪声带来的伪成功？

05 · MODEL CHECKING

看上去非常贴合，模型就一定可靠吗？

到这里已经能估计直线、圆、椭圆以及四角。甚至一小段弧也可能被拟合成一个残差极低的大圆；一片纹理线也可能满足 Hough 投票条件。漂亮的数值不等于物体的几何真相。

先试什么

只比较一个拟合 RMSE，数值小就当作模型正确。

马上发现

短线、短弧可以得到低残差却没有足够覆盖；噪声点相关、遮挡、多个模型竞争，也会让结果不可辨识。

于是引入

除了残差，还评估几何覆盖、独立边段支持、参数稳定性、退化与竞争假设。达不到要求时允许输出“几何不可靠”。

验证项具体要看什么典型伪成功
残差点到线距离、径向距离、边到边距离的均值/RMSE、分位数与空间分布大多数点很好，少量局部边界明显错位
覆盖范围直线的支持长度；圆弧的可见角度；四边形每条边的支持点5 个小范围点拟合一条很长的直线
参数稳定性扰动采样点、少量移除点后，角度、圆心、半径是否大变短圆弧拟合出极大的圆心和半径波动
模型约束圆的等半径、矩形的正交、四边形的凸性、平行性等四点是四边形，却被当成旋转矩形
竞争模型直线、圆弧、分段线是否都能解释同一段数据把缓慢弯曲的边界强行拟合成直线
最小验收建议：线段至少报告内点支持数、投影长度和正交残差；圆至少报告可见弧度、圆心/半径扰动稳定性；四角至少报告每条边的支持长度、凸性、交角退化及是否位于合理的轮廓邻域。指标是质量证据，不是单一打分就能证明“真物体”。

6.1 · 直觉上的“模型越复杂越好”，为什么也不对？

让一个高阶多项式穿过每个轮廓点，残差甚至可以接近零，但得到的形状会跟随噪声大幅摆动。相反，简单直线虽然略有误差，却可能更稳定、更容易解释。这里遇到的是数据拟合与模型复杂度之间的取舍，不是说所有曲线都要换成一个更复杂的模型。

一个可复现的最小实验
重复抽样 / 加噪声

对同一轮廓随机取 70% 的点反复拟合，记录每次的参数、残差和覆盖率，观察估计是否稳定。

一个容易忽视的陷阱
输入点不独立

沿轮廓连续采样的 1000 个像素并非 1000 次独立测量。更密的采样未必带来同比例的可信度提升。

6.2 · 模型参数的几何含义要分清

模型结果它是什么它不自动意味着
拟合线方向图像平面里的切线或边界方向三维表面的真实方向
圆心与半径图像像素坐标下的圆模型参数真实物体的物理半径

一个可靠的二维几何结果，不应只有 (x, y, w, h, angle)。至少还应该能追溯：原始支持点、选择的模型、拟合残差、内点/覆盖范围，以及假设在哪些情况下可能退化。这样下游做目标定位时才知道哪些数据可以相信。

06 · TOOLBOX & CONCLUSION

现在遇到一段轮廓，究竟应该先试哪一种模型？

方法已经不少，但这些方法不是同一条进化链。真正能指导实际工作的判断，应当是先看已知证据和目标输出，再选一条最短的方法路线。

先试什么

习惯性把 Hough、RANSAC、最小外接框和四角拟合全都跑一遍。

马上发现

算法之间可能没有输入输出上的依赖；例如 Hough 适合尚未分组的边缘点，而已知四条边的轮廓不必先做全图投票。

于是引入

按“线从哪来 / 模型是什么 / 是否混入异常 / 要框还是要真实角点 / 可验证指标是什么”选择方法。
