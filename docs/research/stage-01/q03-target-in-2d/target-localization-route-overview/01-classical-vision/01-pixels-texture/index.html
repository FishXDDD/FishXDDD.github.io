颜色与纹理

先从图像里看得见的差异找起。

前面已经把问题大致理清楚了。相机能够提供 RGB 图像和深度数据，但知道物体离相机有多远，还不等于知道我要找的东西在哪里。

现在终于可以开始试着找目标了。

先从最直观的地方入手：一只红色瓶子放在桌上，颜色似乎就是很好的线索。可光照、阴影、反光都会改变颜色；碰上颜色相近的东西，或许还得看看表面的纹理。

这一篇就先研究这些看得见的差异，试试能把图像中的内容初步区分到什么程度。

单张 RGB 图像不训练模型颜色 · 统计 · 纹理可离线阅读
00 · DEFINE THE PROBLEM

问题与边界

这次要做的事

利用颜色、亮度和纹理等外观信息，对图像内容进行初步区分。

输入是一张 RGB 图像，也可以附带已知颜色条件或少量参考外观信息。通过比较外观特征，判断哪些位置符合条件，或者把外观相近的像素分成不同类别。

得到的结果：特征图、判别响应、分类标签，或初步的候选 Mask。它们只是图像证据，并不自动带有物体类别和身份。

暂时不解决：前景是否连通、边界是否完整、是不是同一个物体，以及三维位置。那些是后续需要继续回答的问题。

01 · ROUTE OVERVIEW

技术路线

先看结论。外观差异大致可以从三种角度利用：已知条件就直接判断；条件说不清就观察数据分布；颜色差不多时，再研究像素怎样排列。

ROUTE A

规则判别

按照已知颜色或亮度条件筛选像素。

阈值 · 颜色范围 · Otsu
ROUTE B

统计与聚类

根据数值分布建模，将外观相近的数据归类。

Histogram · K-means · GMM
ROUTE C

纹理描述

不只看数值，还利用像素的空间排列。

LBP · GLCM · Gabor
三种角度不是互斥的算法流水线。例如，纹理特征也可以拿去做阈值判别或聚类。RGB、HSV、Lab 是共用的颜色表示基础，而不是第四条路线。
02 · COLOR REPRESENTATION

颜色表示

先试最简单的。既然要找红色瓶子，那把 R 通道较大的像素挑出来，是不是就够了？

2.1 · RGB：一个像素的三个数

一张常见的 8-bit RGB 图像可以写成 H × W × 3 的数组。每个位置的 R、G、B 通道通常是 0～255。先试一个条件 R > 180，马上就会发现它把白色和黄色也选进来了。

同样满足 R > 180，却不是同一种颜色

这不是阈值调得还不够好，而是单个通道并不能完整表示颜色。需要联合比较三个通道，或者改用更方便表达色相的坐标。

2.2 · HSV：能不能单独描述颜色和明暗

HSV 用 H（色相）、S（饱和度）、V（明度）描述颜色。对于某些彩色目标，直接约束色相和饱和度，比在 RGB 里分别写三套条件直观得多。

空间通道含义适合回答的问题需要注意
RGB红、绿、蓝通道值图像原始数值是什么？颜色与亮暗混在通道变化里
HSV色相、饱和度、明度颜色主要偏向哪个色相？低饱和度时 H 不稳定；红色跨 H 环边界
LabL* 明度、a*/b* 色彩轴两种颜色相差多少？数值尺度和转换约定必须统一
小实验 · 色相近似不变，明度改变时会怎样？
HSV → 可见颜色
观察结果
H=0° · S=75% · V=70%

OpenCV 读取图片默认使用 BGR 通道顺序；转换为 8-bit HSV 后，H 通常为 0～179，S/V 为 0～255。这与常见的 H=0～360° 表示不同，写阈值时必须先统一约定。

2.3 · Lab：颜色之间有多接近

假设已经有了一个参考颜色，下一步不一定是硬性指定三个范围，也可以度量样本与参考颜色的差异。Lab 允许把颜色差异表示为距离。

ΔE*ab = √[(L₁*−L₂*)² + (a₁*−a₂*)² + (b₁*−b₂*)²]

这是基础的 CIE76 色差。它计算简单，但并不保证相同数值距离对应完全一致的感知差异；精细色差还会用到 CIEDE2000。特别要注意，OpenCV 8-bit Lab 的编码数值不是未经缩放的 L*a*b* 坐标，计算色差前应转换到正确的尺度。

Python · 三种颜色表示
import cv2

bgr = cv2.imread("scene.png")
if bgr is None:
    raise FileNotFoundError("scene.png")

rgb = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)
hsv = cv2.cvtColor(bgr, cv2.COLOR_BGR2HSV)
lab32 = cv2.cvtColor(bgr.astype("float32") / 255.0,
                     cv2.COLOR_BGR2Lab)

print(rgb.shape, hsv[0, 0], lab32[0, 0])
这一站得到的结论：颜色空间决定我们怎样表达和比较颜色，但换了坐标系，并不代表已经把目标找出来。
03 · THRESHOLDING

阈值判别

颜色终于可以比较了。那就真的动手：指定一个条件，把符合要求的像素挑出来。

3.1 · 固定阈值：从条件到 Mask

最基本的判别是对某个特征值 x 设置阈值 t。满足条件的像素设为 1，其他设为 0。这张二值图叫 Mask。

M(u,v) = 1, 当 f(u,v) ≥ t M(u,v) = 0, 其他情况

如果要筛选红色，还可以对 HSV 的 H、S、V 同时给出范围。这里的「符合条件」只是一个判别结果，不意味着它一定属于指定物体。

3.2 · 直方图：阈值应该放在哪里

阈值不是只能拍脑袋设。可以先把每个灰度值出现的次数统计出来，看看是集中成一团，还是出现两个明显的峰。

示意直方图 · 两群灰度之间可能存在较自然的分界
手工构造的分布示意，不是某张真实照片的统计结果。实际分布未必有两个清晰峰值。

3.3 · Otsu：能不能自动选出分界

如果希望把灰度值分成两类，可以逐一枚举阈值，计算每个阈值下两类的均值与比例，选择使类间方差最大的阈值。这就是 Otsu 的基本思想。

ω₀(t) = P(X ≤ t), ω₁(t) = 1 − ω₀(t) σ²_between(t) = ω₀(t) · ω₁(t) · [μ₀(t) − μ₁(t)]² t* = argmax_t σ²_between(t)

如果画面里两类灰度大量重叠，或者背景明暗变化很大，选出一个全局最优阈值也不一定能正确分开前景。局部自适应阈值可以处理部分光照不均，但它同样依赖邻域大小与数据条件。

Python · 固定阈值、HSV 范围与 Otsu
import cv2

bgr = cv2.imread("scene.png")
if bgr is None:
    raise FileNotFoundError("scene.png")
gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)
hsv = cv2.cvtColor(bgr, cv2.COLOR_BGR2HSV)

_, fixed = cv2.threshold(gray, 145, 255,
                         cv2.THRESH_BINARY)
_, otsu = cv2.threshold(gray, 0, 255,
                        cv2.THRESH_BINARY + cv2.THRESH_OTSU)

# OpenCV 8-bit HSV：红色位于 H 两端
red1 = cv2.inRange(hsv, (0, 80, 60), (10, 255, 255))
red2 = cv2.inRange(hsv, (170, 80, 60), (179, 255, 255))
red_mask = cv2.bitwise_or(red1, red2)

cv2.imwrite("mask_fixed.png", fixed)
cv2.imwrite("mask_otsu.png", otsu)
cv2.imwrite("mask_red.png", red_mask)
这一站得到的结论：阈值能把外观条件变成像素选择结果；自动选阈值，也不能保证分出来的就是那个物体。
04 · STATISTICS & CLUSTERING

统计与聚类

有时候我能看出图像里有几类颜色，却很难把它们各自写成固定的阈值。能不能先不告诉算法每类是什么，让数据自己聚成几组？

4.1 · 从数值条件到样本分布

把一个像素的颜色写成向量 x = [R,G,B]（或其他颜色空间中的向量），一张图像就给出了大量三维样本。直方图是对这些样本分布的统计，而聚类进一步试图找到分组。

需要先想清楚：颜色聚类关注的是特征空间的相似性，并不知道两个像素在图像里是否挨着。若两只不同的物体颜色相同，它们可能自然地落进同一类。

4.2 · K-means：每一类找一个代表颜色

最简单的分组思路：先给 K 个中心，把每个样本分给最近的中心，再更新中心为各自样本的均值。重复执行，直到分组基本不再变化。

min Σᵢ ||xᵢ − μ_{cᵢ}||² 分配：cᵢ ← argminₖ ||xᵢ − μₖ||² 更新：μₖ ← mean({xᵢ | cᵢ = k})
示意实验 · 改变 K 值，分组会怎样变化
3
这是固定示意样本在二维特征空间上的聚类，不是物体分割。

K-means 计算简单，但 K 要提前指定，结果会受到初始化、特征缩放和距离度量影响。它产生的是编号类别，而不是「瓶子」「桌面」这样的物体名称。

4.3 · GMM：一个样本是否可以同时像两类

K-means 采用硬分配。如果两群颜色分布相互重叠，离某个中心最近不一定足以表达不确定性。GMM 用多个高斯分量表示数据分布，估计每个样本属于各分量的概率责任度。

p(x) = Σₖ πₖ · N(x | μₖ, Σₖ) γᵢₖ = πₖN(xᵢ|μₖ,Σₖ) / Σⱼ πⱼN(xᵢ|μⱼ,Σⱼ) Nₖ = Σᵢ γᵢₖ μₖ ← (Σᵢ γᵢₖ xᵢ) / Nₖ

这里的 γ 是 E-step 算出的责任度；M-step 用责任度更新均值、协方差和混合比例，反复迭代。GMM 比 K-means 更能表达不同方向、形状与重叠程度的分布，但也更依赖模型数量、协方差约束与初始化。

比较K-meansGMM
表示方式类别中心多个概率分布
样本归属硬分配责任度（软分配）
主要优化类内平方距离数据似然
常见限制K、初始化、距离度量分量数、协方差、局部最优
Python · K-means 的最小颜色聚类
import cv2
import numpy as np

bgr = cv2.imread("scene.png")
if bgr is None:
    raise FileNotFoundError("scene.png")

pixels = bgr.reshape(-1, 3).astype(np.float32)
criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER,
            40, 0.2)
_, labels, centers = cv2.kmeans(
    pixels, 4, None, criteria, 10, cv2.KMEANS_PP_CENTERS
)

result = centers.astype(np.uint8)[labels.flatten()]
result = result.reshape(bgr.shape)
cv2.imwrite("color_clusters.png", result)

# labels 的 0 / 1 / 2 / 3 仅代表聚类编号，
# 不能直接解释成某种目标类别。
这一站得到的结论：统计建模可以把外观相似的数据组织成若干类；分得像不像是一回事，哪一类是目标又是另一回事。
05 · TEXTURE DESCRIPTION

纹理描述

假设两块表面的平均灰度差不多，一块平滑，另一块布满条纹。只统计各个数值出现多少次，可能还不够，因为它漏掉了一个重要信息：像素是怎么排列的。

相同的黑白比例，不同的空间排列
两组示意图具有相同数量的明暗方块，但邻接、方向和重复规律不同。

5.1 · LBP：记录周围像素比中心亮还是暗

选一个中心像素，把周围邻居依次与它比较：大于等于中心就记 1，否则记 0。这样得到一串二进制编码。把大量位置的编码统计成直方图，就能描述局部灰度变化模式。

LBP 机制 · 一个 3×3 邻域怎样编码
灰度矩阵（中心值 90）
按左上开始顺时针比较

10110101

LBP 编码：181

这里只演示最基础的 8 邻居比较，邻居的遍历顺序决定编码整数。

LBP 对保持邻居大小顺序的单调灰度变换相对稳定，但容易受到噪声、邻域尺度和旋转的影响。真实应用通常使用 LBP 直方图，而不直接比较某个点的单一编码。

5.2 · GLCM：哪些灰度值经常挨在一起

选择一个距离 d 和方向 θ，统计灰度 i 与灰度 j 作为一对出现的次数，形成灰度共生矩阵。再从矩阵中提取对比度、同质性、能量等统计量。

P(i,j | d,θ) = 归一化的灰度对出现频率 Contrast = ΣᵢΣⱼ (i−j)² P(i,j) Homogeneity = ΣᵢΣⱼ P(i,j) / [1+(i−j)²]

这能描述纹理对比程度及相邻关系，但方向、距离、灰度量化级数都会改变结果。所以 GLCM 更像是一套统计描述框架，而不是一个直接识别物体的分类器。

5.3 · Gabor：只观察某个方向和尺度的图案

如果表面是斜条纹或重复细线，能不能专门去测某种方向和空间频率的响应？Gabor 滤波器相当于一个带方向和频率选择性的局部滤波器。

Gabor 滤波器的方向选择性（概念示意）
概念示意：实际响应还取决于频率、波长、尺度、相位和滤波器参数。

把多个尺度、多个方向的 Gabor 响应组合起来，可以得到更完整的纹理特征，但计算量也随滤波器数量增加。

方法主要记录的信息典型敏感因素
LBP邻域大小关系形成的模式噪声、尺度、旋转
GLCM灰度对共现的空间统计方向、距离、灰度量化
Gabor方向与空间频率上的滤波响应频率、尺度、方向、计算代价
Python · 一个最小 Gabor 纹理响应实验
import cv2
import numpy as np

bgr = cv2.imread("scene.png")
if bgr is None:
    raise FileNotFoundError("scene.png")
gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)

kernel = cv2.getGaborKernel(
    (31, 31), 5.0, np.pi / 4,
    10.0, 0.5, 0, ktype=cv2.CV_32F
)
response = cv2.filter2D(gray.astype(np.float32),
                        cv2.CV_32F, kernel)
visual = cv2.normalize(np.abs(response), None, 0, 255,
                       cv2.NORM_MINMAX).astype(np.uint8)
cv2.imwrite("gabor_response.png", visual)
这一站得到的结论：颜色描述数值本身，纹理进一步描述空间排列。纹理丰富不代表能识别物体，仍然需要明确怎样比较、判别并验证。
06 · EXPERIMENTS & TAKEAWAYS

实验与总结

方法已经有了，现在应该回到最初的任务：它们究竟能把图像区分到什么程度？这里不预设哪个方法一定最好，只设计几组能够观察到差别的实验。

实验对照方法记录什么
红色物体与背景RGB 条件 / HSV 范围候选像素、误选位置、阈值变化
同色物体的亮暗变化RGB / HSV / Lab同一目标在不同条件下的特征变化
多类颜色混合阈值 / K-means / GMM分组稳定性、类别重叠与初始化影响
同色不同纹理颜色统计 / LBP / GLCM / Gabor区分能力与参数敏感性

6.1 · 一次实验至少留下这些记录

  1. 输入：原图、目标条件，必要时记录人工标注的参考区域。
  2. 方法与参数：颜色空间、阈值、K 或纹理窗口等。
  3. 可观察输出：Mask、聚类标签、特征图，而不只记录一张美化后的结果图。
  4. 失败表现：漏选、误选、类别混合，以及参数略变时结果是否大幅改变。
  5. 判断：当前方法是否真的解决了本节定义的外观区分任务。

6.2 · 方法选择：根据手里的信息决定

已知条件优先尝试不要误以为
已知目标有明显颜色范围颜色空间 + 范围阈值选出来的同色像素就是整个目标
灰度分布有明显分界直方图 + Otsu最佳统计阈值就是正确语义边界
颜色分布复杂、类别未知K-means / GMM聚类编号天然具有目标身份
颜色接近、纹理不同LBP / GLCM / Gabor纹理相似就必然属于同一物体
回头看。这一篇从最简单的颜色筛选开始，逐渐用到更合适的颜色表示、阈值、统计建模与纹理描述。最后得到的仍然只是外观上的区分结果：它可以帮助我们找到候选像素或类别，却不保证区域连通、边界完整，也不保证一个区域就是一个物体。接下来研究的「区域与分割」，正是另一类问题。
