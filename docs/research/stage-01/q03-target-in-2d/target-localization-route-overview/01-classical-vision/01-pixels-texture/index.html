像素与纹理

一张图像的颜色、统计分布与空间排列，究竟能告诉我们什么？

01 · COLOR REPRESENTATION

颜色看起来一样，数值表示为什么会不同？

最直接的像素是 (R,G,B)。但如果想找“红色”，直接比较 R 的大小就会失败：亮灰色可能有很大的 R，暗红色可能有较低的 R。问题不在于再加一个阈值，而是先问：我们希望颜色中的什么属性被分开？

01.1 · RGB、HSV 与 Lab 分别重组了什么？

表示可直接读出的信息特别注意
RGB / BGR红、绿、蓝通道强度；利于直接计算与显示通道值同时受光照、材质与相机处理影响；OpenCV 常以 BGR 读图
HSVHue 色调、Saturation 饱和度、Value 明度低饱和度处 Hue 不稳定；Hue 是周期变量，红色跨首尾
CIE LabL* 明度，a* 绿—红方向，b* 蓝—黄方向计算基于色彩空间变换与参考白点；OpenCV 8-bit 输出存在编码偏置

HSV 将“是什么色调”与“有多鲜艳、多亮”部分分离，便于写颜色范围；Lab 让颜色差异的计算更有意义，但换空间并不能让光照变化自动消失，也不保证对所有相机处理后的图像具有严格感知均匀性。

HSV: H = 色调角，S = (max(R,G,B) − min(R,G,B)) / max(R,G,B)（max ≠ 0 时）Lab 简单距离: ΔE76 = √[(ΔL*)² + (Δa*)² + (Δb*)²]ΔE76 是基础欧氏形式；更精细的感知色差可使用 CIEDE2000。

01.2 · “颜色接近”需要先定义距离

在 RGB 中计算欧氏距离很方便，却不能保证距离和人眼感知一致。在 HSV 中，Hue 的数值相差很大也可能实际很接近——例如 359° 和 1° 仅相差 2°。因此，单纯将三个 HSV 通道当作普通三维坐标做欧氏距离并不妥当。

圆周色调距离：dH(h₁,h₂) = min(|h₁−h₂|, 360°−|h₁−h₂|)例如 dH(359°,1°) = min(358°,2°) = 2°。
OpenCV · 读取与颜色转换

import numpy as np

bgr = cv2.imread("scene.jpg")
assert bgr is not None, "图片读取失败"

lab8 = cv2.cvtColor(bgr, cv2.COLOR_BGR2LAB)

# 注意：OpenCV 的 uint8 HSV 通常 H∈[0,179]，S/V∈[0,255]
# 要获取常见的 Lab 实数尺度，可先变成 [0,1] float32
lab_float = cv2.cvtColor(bgr.astype(np.float32) / 255,
                         cv2.COLOR_BGR2LAB)
print(hsv[100, 100], lab8[100, 100], lab_float[100, 100])
别把 API 的编码范围当成数学定义：OpenCV 常规 8-bit HSV 把 0–360° 色调压到约 0–179；8-bit Lab 对 a*/b* 存在偏移编码。后续设置阈值与计算距离时，要明确数据类型和通道范围。
02 · PIXEL CLASSIFICATION & THRESHOLDING

有了颜色数值，怎样明确地判断一个像素？

最容易验证的办法是建立显式规则。对某个像素特征 v(p)，阈值法只是比较大小；对 HSV 则可以给多个通道设置范围。这里计算的是“是否满足颜色条件”，不是“是否属于指定物体”。

单阈值：M(p) = 1[v(p) > t]联合范围：M(p) = 1[H∈红色区间 且 S≥s₀ 且 V≥v₀]

02.2 · 阈值不想手动选：Otsu 从哪里得到 t？

先把问题收缩成单通道直方图有两个相对可分的分布。如果试一个阈值 t，像素会被分成 C₀ 和 C₁ 两组；我们可以计算两组所占比例 ω 和各自均值 μ。Otsu 遍历有效候选阈值，寻找两组统计上最分离的划分。

ω₀(t) = ∑i≤t p(i)，ω₁(t) = 1 − ω₀(t)μ₀(t) = ∑i≤t i·p(i) / ω₀(t)，μ₁(t) = ∑i>t i·p(i) / ω₁(t)J(t) = σ²between(t) = ω₀(t) · ω₁(t) · [μ₀(t) − μ₁(t)]²t* = argmaxt J(t)，空组阈值不参与比较

手算一次：像素 [20,20,20,20,20,20,80,80,80,80]，只要 t 在 20–79，得到 ω₀=0.6、ω₁=0.4、μ₀=20、μ₁=80，因此 J=0.6×0.4×60²=864。**最优阈值可能有多解**，它并不是某条真实物体边界上的灰度。

02.3 · 全局分界失效时：局部阈值与 Triangle

Otsu 假设全图某个单通道上存在有用的全局分组。目标占比很小、类间分布严重重叠，或局部亮度变化很大时，这个假设容易失效。

方法具体在计算什么主要限制
固定阈值每个像素比较同一个 t场景亮度漂移后需重新设定
Otsu寻找最大类间方差的全局 t单通道全局分布应具有可分性
Triangle从直方图峰到尾部构造线，选偏离该线最远的阈值对直方图形状敏感，适合偏斜/单主峰+尾部等分布
Adaptive Mean每个像素的阈值 ≈ 邻域均值 − C尺度取决于窗口，噪声和小结构易受影响
Adaptive Gaussian每个像素的阈值 ≈ 邻域高斯加权均值 − C仍依赖合适的窗口与局部亮度假设

03 · COLOR DISTRIBUTION & STATISTICAL MODELS

一种颜色不能用一个范围说清时，如何表示整群像素？

颜色可能有深浅变化、反光与阴影。此时“单个值是否超过阈值”不再足够，还可以转而研究像素集合在特征空间中的分布。这里必须分清三条路线：统计已有分布、将样本分组、用概率模型拟合分布。

03.1 · Histogram 与 Backprojection：已知参考分布怎么找相似像素？

直方图把特征空间划成 bins，统计每个区间出现的频率。它丢失像素原来的位置，却保留了颜色分布；二维 H–S 联合直方图还能部分表示色调与饱和度的联合变化。

H(k) = #{p ∈ ROI : feature(p) 落入第 k 个 bin}归一化直方图：P(k) = H(k) / ∑j H(j)反向投影：B(p) = P(bin(feature(p)))，得到每像素匹配分数图

如果事先选过一个红瓶子 ROI，可以统计其 H–S 分布，再将这张分布映射回整幅图像，得到每个像素与参考颜色分布的匹配响应。但这依赖参考样本；反向投影并不区分拥有相似颜色的另一件物体。

OpenCV · 使用参考 ROI 做颜色直方图反向投影
hsv = cv2.cvtColor(bgr, cv2.COLOR_BGR2HSV)
roi = hsv[60:160, 90:200]  # 示例：已经人为或由上游给定的 ROI
hist = cv2.calcHist([roi], [0, 1], None, [30, 32],
                    [0, 180, 0, 256])
cv2.normalize(hist, hist, 0, 255, cv2.NORM_MINMAX)
response = cv2.calcBackProject([hsv], [0, 1], hist,
                               [0, 180, 0, 256], scale=1)
# response 是匹配强度图；不是校准后的后验概率，也不是最终 Mask

03.2 · K-means：不知道类别名称，能否自动划分颜色群？

K-means 把 N 个像素的特征向量分给 K 个中心，要求每个样本到所属中心的平方距离总和尽可能小。对于彩色图像，可以选 RGB 或 Lab 三维特征；如果增加 (x,y)，分组也会受到空间位置影响——那已不再是纯颜色聚类。

min{μ₁…μK,c₁…cN} ∑i=1…N ||xᵢ − μcᵢ||²E-step-like 分配：cᵢ ← argmink ||xᵢ − μₖ||²更新中心：μₖ ← (1/Nₖ) ∑i:cᵢ=k xᵢ

03.3 · GMM：如果两类颜色分布重叠，为什么需要概率？

K-means 给每个像素一个硬归属。GMM（高斯混合模型）改用若干高斯分量表示分布，允许一个像素同时对多个分量有不同责任度，利用 EM 迭代估计参数。

p(x) = ∑k=1…K πₖ · N(x | μₖ, Σₖ)，其中 ∑πₖ = 1责任度 γᵢₖ = πₖ N(xᵢ|μₖ,Σₖ) / ∑ⱼ πⱼ N(xᵢ|μⱼ,Σⱼ)M-step: Nₖ=∑ᵢγᵢₖ；πₖ=Nₖ/N；μₖ=(∑ᵢγᵢₖ xᵢ)/Nₖ；Σₖ=加权协方差

04 · LOCAL TEXTURE DESCRIPTION

颜色相似时，为什么邻域排列能提供新信息？

考虑木纹桌面与同色涂层：它们单个像素的灰度可能一样，但邻近像素如何变化可能截然不同。于是研究对象从 I(x,y) 变成围绕它的一小片邻域 W(x,y)。这并不自动让我们理解材料种类，只是得到另外一种可比较的特征。

04.1 · 第一种线索：局部均值、方差与熵

局部均值：μW = (1/|W|) ∑p∈W I(p)局部方差：σ²W = (1/|W|) ∑p∈W [I(p)−μW]²局部直方图熵：EW = − ∑g PW(g) log₂ PW(g)

均值说的是亮度基线，方差衡量灰度波动，熵衡量量化灰度分布的多样性。但两块局部区域可以具有相同直方图与方差，却呈现完全不同的排列。所以，还需要把空间关系放进描述符。

04.2 · GLCM：不仅统计出现了什么灰度，还统计谁挨着谁

灰度共生矩阵（Gray-Level Co-occurrence Matrix）统计：沿指定偏移量 (Δx,Δy) 观察，一对相邻像素分别取灰度 i、j 的次数。它不追踪目标轮廓，而是在问某种局部灰度关系出现得多不多。

CΔ(i,j) = #{(x,y): I(x,y)=i 且 I(x+Δx,y+Δy)=j}PΔ(i,j)=CΔ(i,j)/∑a,bCΔ(a,b)Contrast = ∑i,j(i−j)²P(i,j)；Homogeneity = ∑i,jP(i,j)/(1+(i−j)²)ASM = ∑i,jP(i,j)²；Energy = √ASM

scikit-image · 构造 GLCM 并提取 Haralick 类统计
from skimage.feature import graycomatrix, graycoprops

# 灰度量化为 8 级，缩小 256×256 共生矩阵的维度
quantized = (gray // 32).astype(np.uint8)
P = graycomatrix(quantized, distances=[1, 3],
                 angles=[0, np.pi/2], levels=8,
                 symmetric=True, normed=True)
# 结果 shape: (8, 8, 2个距离, 2个方向)
contrast = graycoprops(P, "contrast")
homogeneity = graycoprops(P, "homogeneity")
energy = graycoprops(P, "energy")
print(contrast, homogeneity, energy)

注意：GLCM 通常把一个 ROI 或窗口转换成一组统计特征，不是天然返回逐像素 Mask。方向和距离属于描述符定义的一部分，旋转或纹理尺度改变就可能改变输出。

04.3 · LBP：把相邻像素的相对大小编码下来

LBP（Local Binary Pattern）取中心像素与周围 P 个采样点比较：邻点大于等于中心记 1，否则记 0。沿固定顺序组成二进制模式，得到一个局部编码。

LBPP,R(x,y) = ∑p=0…P−1 1[gₚ ≥ gcenter] · 2ᵖP = 采样点数；R = 邻域半径；采样点不落在整数坐标时通常使用插值。

04.4 · Gabor：为什么要主动寻找某个方向与频率？

如果纹理呈条纹或周期性排列，单纯比较灰度大小不够直接。Gabor 滤波器把一个方向性正弦波包在高斯窗口里；卷积之后，频率与方向匹配的局部结构通常会给出更强响应。

g(x,y) = exp{−(x′² + γ²y′²)/(2σ²)} · cos(2πx′/λ + ψ)x′ = x cosθ + y sinθ，y′ = −x sinθ + y cosθσ：高斯包络尺度；λ：波长；θ：法向/频率变化方向；γ：空间纵横比；ψ：相位。

OpenCV · Gabor 滤波器组
gray_f = gray.astype(np.float32) / 255.0
responses = []
for theta in (0, np.pi/4, np.pi/2, 3*np.pi/4):
    kernel = cv2.getGaborKernel((21, 21), sigma=4.0,
                               theta=theta, lambd=8.0,
                               gamma=0.5, psi=0,
                               ktype=cv2.CV_32F)
    kernel -= kernel.mean()  # 可选：减少常量亮度分量响应
    resp = cv2.filter2D(gray_f, cv2.CV_32F, kernel)
    responses.append(np.abs(resp))
# 如需相位相对稳定的能量，可设计正交相位滤波器组
texture_energy = np.max(np.stack(responses, axis=0), axis=0)
纹理工具关键机制输出容易失效的条件
局部方差 / 熵灰度分布的波动与多样性单值或响应图不能区分同直方图的不同排列
GLCM指定方向与距离的灰度对统计共生矩阵及统计量方向/尺度/量化级数敏感
LBP邻点相对中心的大小模式编码图及区域直方图噪声、极平坦邻域、尺度变化
Gabor局部方向性频率滤波一组方向/波长响应核参数和纹理频率不匹配
05 · LOCAL DESCRIPTORS TO MAPS

一个窗口的数字，怎样变成整张图上的可用特征？

这里容易发生一次“输出类型偷换”：单个 LBP 编码、某个 ROI 的 GLCM 特征、整幅 Gabor 响应图，虽然都叫纹理特征，实际却不是同一种数据结构。

结果层次形状示例怎样计算可以直接做什么
像素响应 / 编码图H × W逐像素计算 LBP 或滤波响应可视化、局部比较、阈值化
局部多通道特征图H × W × C多尺度 / 多方向滤波器组后续像素分类与聚类的特征输入
窗口特征向量D统计窗口 LBP 直方图或 GLCM 属性比较窗口、分类或相似性检索
分块特征序列Npatch × D按固定网格或滑窗提取寻找纹理变化与区域候选
局部位置先选半径 r、窗口尺寸 w，明确在图像哪个邻域上计算。
纹理计算根据方法输出单个响应、模式编码或 D 维统计向量。
组织回图像将窗口响应放在中心位置，或保留每块的独立向量与坐标。

不同尺度不能只靠放大结果图解决。3×3 的 LBP、11×11 的 LBP 统计窗口和 31×31 的 Gabor 核，观察的是不同尺寸的结构；窗口过小会被噪声干扰，过大又会把本来不同的表面混在一起。

例如：F(p) = [H(p), S(p), V(p), VarW(p), EGabor,0°(p), EGabor,90°(p)]F(p) 是可以交给后续分类/聚类算法的特征向量；它本身还不是类别判断。
如果使用颜色与纹理联合聚类，务必考虑特征尺度：HSV 的 H、S、V 编码尺度与 Gabor 响应可能完全不同。不能把各种特征未经标准化就简单拼接，再认为欧氏距离具有合理意义。
进一步理解 · 为什么 GLCM 通常不是“每像素一个四维向量”？

GLCM 先根据若干像素对的关系累积统计。一块 1×1 的窗口根本没有邻对；当窗口变大时，共生矩阵才逐渐具有统计意义。因此如果要生成逐位置 GLCM 特征图，实际需要对每个滑动窗口重复计算，代价远高于一次图像卷积。是否值得这么做，要看任务所需的空间分辨率与计算预算。

06 · COMPARISON & DECISION

方法这么多，究竟先用哪个？

算法选型不能只凭“新不新”或“高级不高级”。先判断你拥有的证据：是一种稳定的颜色范围？一份参考颜色分布？需要探索未知分组？还是局部排列才有辨别能力？

观察到的差异优先验证的工具验证失败时该检查什么
已知颜色，目标与背景色差明显HSV/Lab + `inRange` 或色差色域重叠、低饱和度、光照漂移
单通道分布形成两群Otsu类间重叠、目标像素占比、通道选择
背景亮度缓慢变化Adaptive Threshold局部窗口是否比目标结构更合理
拥有典型颜色 ROIHistogram Backprojection参考代表性、bin 大小、颜色相似干扰
未知类别，只想探索颜色分组K-meansK 的选择、初始化、颜色空间
一类颜色本身有多个分布峰GMM高斯假设、协方差、分量数与局部最优
颜色相似，局部排列不同LBP / GLCM纹理尺度、采样与噪声、方向变化
纹理方向/周期很明显Gabor Filter Bank波长、方向、核尺寸与相位

同一张真实图，至少做完这四件事

  1. 检查输入。保留原图；记录颜色空间、bit depth、输入尺寸及所选 ROI。
  2. 固定一个变化因素。例如只改变 Hue 阈值、GMM 分量数、GLCM 距离或 Gabor 波长。
  3. 保存可比较的中间结果。保存阈值 Mask、像素聚类图、响应图、局部特征数值与参数。
  4. 确认输出没有越界。颜色匹配响应只是匹配程度；聚类编号只是分组；纹理描述符只是特征。哪一个真正代表目标，需要另外的定义或监督证据。
