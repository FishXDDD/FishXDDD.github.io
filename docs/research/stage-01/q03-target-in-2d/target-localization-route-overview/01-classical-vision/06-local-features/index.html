局部特征与对应

不用先找出整个物体，能不能凭几个细节重新找到它？

一个盒子移动了、旋转了、被挡住一半——颜色和完整轮廓都不一定好用。先从简单的局部模板试起，逐步追问：什么局部值得记、怎么容忍尺度与角度、如何认出同一处、怎样排除那些看上去很像的错配？

独立研究路线 · 06 / 06Harris · FAST · SIFT · ORB匹配 / RANSAC / 2D 几何单文件离线交互
00 · SCOPE

从“完整识别物体”，换成“重新认出局部”

前面研究过像素、区域、轮廓、几何和骨架。但它们通常试图回答“这个物体的整体形状在哪里”。现在换一种场景：手上只有一张带文字与图案的包装盒参考照片，下一张图里，它可能换了位置、角度和大小，甚至只露出一半。

能不能不先找完整 Mask，而是记住参考图里几个独特的小地方，再去另一张图里把它们找回来？这就是局部特征与对应（Local Features & Correspondence）要解决的问题。

目标整体不完整，局部对应仍可能成立
机制示意，不是实际匹配结果。局部特征建立的是跨图像候选对应，不直接识别物体类别，也不保证目标的三维姿态。
INPUT
参考图 + 待搜索图

每张图可以独立提取关键点与描述子；不要求先得到完整物体区域。

EVIDENCE
可重复的局部外观

角点 / 纹理变化 / 尺度与方向 / 邻域的梯度或像素对关系。

OUTPUT
对应点与二维变换

候选匹配、几何内点、受适用条件约束的变换矩阵或参考角点映射。

研究边界：这是六条二维目标定位证据路线之一，不是其他五条方法处理完后的第六步。本篇只研究局部特征、描述、匹配和二维几何验证；不推导多视几何、6D Pose，也不把“局部匹配成功”直接等同于“物体身份确认”。

TECHNICAL ROADMAP

先画清楚：局部特征技术是怎样一步步产生的？

这条路线内部确实存在依赖：要匹配，通常得先找到局部位置并描述它。但每个环节都有并行的技术选择：检测器不是描述子，描述相似也不是几何一致。

现在先把技术名字放下，试着做最简单的局部像素匹配。它究竟在什么条件下有效？

01 · SIMPLEST ATTEMPT

直接拿一小块像素去搜，为什么不够？

从参考图裁一块 k×k 小窗口，在场景中逐位置滑动，计算 SSD（平方差和），选择最小的一处。这与模板匹配的想法完全一致。

SSD(u,v) = Σ₍ₓ,ᵧ₎ [ T(x,y) − I(x+u,y+v) ]²
NCC：对去均值后的窗口作归一化相关，减弱整体亮度 / 对比度变化的影响（在非退化窗口上）
先尝试

固定一个带纹理的模板，小范围平移搜索。

很快发现

旋转和缩放导致像素排列改变；纯色块处处相似；沿直边滑动可能得到一串同样好的候选。

于是引入

先挑出二维位置有区分度的局部，再针对尺度 / 方向建立稳健描述。

为什么“平坦—边缘—角点”不一样？试着平移观察窗口

边缘不是没价值：它可以很好地约束一个法向位置。但如果需要确定一个二维关键点，单条长边沿切向有位置歧义。这个差别可以用局部灰度的方向变化写成数学。

问题接力

具体怎样判断一个小窗口“向哪个方向移动都会改变”？这就引出角点检测的数学基础。

02 · KEYPOINT DETECTION

怎样挑出真正能定位的局部位置？

不妨把窗口在水平和竖直方向各挪一点，观察灰度差。如果一个方向几乎不变，它的位置就可能沿该方向漂移。

先尝试

人工观察局部角落，或者用两方向的差分判断。

很快发现

边缘也会有很大梯度，但只有一个方向敏感；单独看梯度大小分不出“角”与“边”。

于是引入

Harris / Shi–Tomasi 用结构张量分析两个主方向，FAST 则用圆周比较快速生成候选。

2.1 · Harris 与 Shi–Tomasi：为什么要看两个特征值？

E(u,v) = Σ_{p∈W} w(p) [ I(p+(u,v)) − I(p) ]²
一阶近似：E(u,v) ≈ [u v] M [u v]ᵀ
M = Σ_{p∈W} w(p) · [[Iₓ², IₓIᵧ], [IₓIᵧ, Iᵧ²]]
Harris: R = det(M) − k·trace(M)²　（常取 k≈0.04–0.06）
Shi–Tomasi: score = min(λ₁, λ₂)

结构张量 M 的两个特征值对应两个主方向的变化：都小是平坦；一个大一个小是边；都大才可能是稳定角点。Shi–Tomasi 直接考察最弱方向的变化。两种评分都还需要合适阈值、非极大值抑制和空间筛选。

2.2 · FAST：能不能不用完整张量就先找到候选点？

FAST 在像素周围半径 3 的 16 个 Bresenham 圆周像素上，寻找一段连续像素明显亮于或暗于中心值；常见 FAST-9 等变种按连续长度确定判据。它适合快速筛出候选，仍需角点评分或非极大值抑制。

角点的“可定位性”Harris / Shi–Tomasi

从窗口二维灰度变化判断稳定程度；适合解释机制与基于质量的筛选，并非天然具备旋转或尺度不变匹配。

角点的“快速发现”FAST

直接比较圆周像素而不是计算二阶矩阵；检测快速，但得到的是位置，不是可跨图像识别的描述。

03 · SCALE & ORIENTATION

相机远近和角度变了，关键点怎么办？

同一张标签在图像里从 30 像素变成 90 像素，固定大小的角点邻域可能观察到完全不同的东西。于是最先想到：给一张图准备很多种观察尺度。

先尝试

把图像逐级缩小，在多层上重复检测。

很快发现

不同层之间会出现重复点；同一位置的尺度到底选哪层？旋转后，即使找回点，邻域的方向也变了。

于是引入

SIFT 的尺度极值和主方向，或者 ORB 的金字塔、方向和旋转采样。

3.1 · SIFT：不仅“多层检测”，还要选择特征尺度

L(x,y,σ) = G(x,y,σ) * I(x,y)
DoG(x,y,σ) = L(x,y,kσ) − L(x,y,σ)
候选：与空间邻居、上下尺度的邻居比较，找 DoG 极值

SIFT 使用尺度空间的高斯差分（DoG）发现候选位置与尺度，再排除低对比度响应及不稳定的边缘响应；为每个保留关键点估计局部梯度主方向，使后续描述子能够按方向归一化。这里要分清：尺度定位、方向分配、描述子生成是三个作用不同的环节。

同一个局部，在多个尺度下观察
比例示意。Gaussian Pyramid 的逐层降采样，与 SIFT 中按 σ 构造的尺度空间及 DoG 极值搜索存在联系，但不应把它们当作完全同一计算过程。

3.2 · ORB 走了另一条工程路线

ORB 不采用 SIFT 的 DoG 极值检测，而是在图像金字塔各层利用 FAST 候选，再依据角点响应和分布策略筛选；用局部灰度质心方向为后续旋转 BRIEF 做准备。

尺度DoG 尺度空间极值与定位多级图像金字塔检测

后续描述梯度方向统计，浮点向量旋转后的二进制像素对测试
典型权衡描述更丰富，计算较重速度和存储友好，但同样存在失效条件
问题接力

即便同一个角点在两张图里都被找到，场景中可能还有几百个角点。仅凭位置或“都是角点”，为什么能认出同一个？

04 · LOCAL DESCRIPTION

两处都是角点，凭什么判断它们是同一处？

两个位置都被 Harris 评为角点，不代表它们来自同一物理位置。我们需要为每个关键点留下一个可比较的局部指纹，同时让这个指纹尽量容忍光照、尺度与角度的变化。

先尝试

直接保存关键点周围的灰度像素作为向量。

很快发现

曝光和方向改变时，向量差异可能很大；同一结构旋转后原坐标上的像素不再一一对应。

于是引入

用梯度方向分布描述局部形状，或把邻域编码为亮度比较的二进制串。

4.1 · 浮点描述：SIFT 的 128 维是怎么来的？

对齐关键点的尺度和主方向后，把局部邻域划为 4×4 个子区，各区累计 8 个梯度方向的加权统计，得到 4×4×8=128 维描述子，并进行归一化等处理。记录的是局部梯度的空间分布，而不是直接记住原像素值。

descriptor_SIFT ∈ ℝ¹²⁸　（常见 SIFT 结构）
d_L2(a,b) = √ Σᵢ (aᵢ − bᵢ)²

4.2 · 二进制描述：BRIEF 为什么只比两个像素？

对邻域取若干对采样位置 (pᵢ,qᵢ)，比较亮度关系，将结果记为 0 / 1。多次比较形成短二进制串，计算两段描述子间的 Hamming 距离，只需统计异或结果中不同位的数量。

τᵢ = [ I(pᵢ) < I(qᵢ) ]，描述子 b = (τ₁,τ₂,…,τₙ)
d_H(a,b) = popcount(a XOR b)
两种“局部指纹”，并不是精度档位的区别

4.3 · ORB、SURF 放在这里如何理解？

原始 BRIEF 对旋转敏感，因为采样点对坐标固定。ORB 通过关键点方向估计，旋转采样点对来构造 rBRIEF，并与多层 FAST 检测组合。SURF 则是另一套浮点特征路线：用基于 Hessian 的响应寻找兴趣点，以积分图和盒式滤波近似提高效率，描述阶段使用 Haar 小波响应统计。它与 SIFT 相近但并非同一种实现。

局限是可预期的：无纹理的纯色表面没有足够局部信息；重复栅格会产生很多“指纹相似”的位置；反光、模糊、遮挡和大视角形变可以让描述子失效。描述子不可能单凭“距离近”证明匹配正确。
问题接力

现在每个点终于有了“指纹”，只要找描述子最近的那个，不就能定位了吗？重复图案会让这个想法立刻遇到麻烦。

05 · CORRESPONDENCE

描述子最像，真的就是正确匹配吗？

先用最朴素的最近邻：对参考图每个描述子，在场景图里找距离最小的一条。对 SIFT 类浮点描述一般用 L2；对 ORB 类二进制描述一般用 Hamming。

先尝试

保留所有最近邻匹配，并根据距离从小到大排序。

很快发现

重复文字 / 网格 / 螺丝孔会给出多个相近候选，最近的一个只是“相对最像”，并不一定是正确的。

于是引入

Lowe Ratio Test 用次近邻衡量歧义；Cross-check 用反向最邻近检查一致性。

5.1 · Ratio Test 为什么要同时看第二名？

最近邻距离 d₁，次近邻距离 d₂，且 d₁ ≤ d₂
通过条件：d₁ / d₂ < ρ　（d₂ > 0；ρ 常以 0.7～0.8 作为实验起点）

Cross-check 与 Ratio 不同：前者要求 A 的最近邻是 B，同时 B 的最近邻也是 A；后者看最佳与次佳候选的相对优势。两者都只是在描述子空间里减少歧义，不能推出多个匹配一定属于同一个物体。

问题接力

筛掉歧义以后，剩下的点还可能落在多个相似的包装盒上。能不能增加一个要求：它们必须符合同一个二维几何变化？

06 · GEOMETRIC VERIFICATION

怎样让一组局部对应接受共同的几何检验？

假设参考物体是平面包装盒正面，我们可以要求所有正确匹配在场景里都由同一个变换解释。错配即使局部外观很像，也通常很难同时满足几何关系。

先尝试

直接对所有匹配最小二乘拟合一个变换。

很快发现

错误对应会严重拉偏模型；模型自由度过高时，极少数点可能产生看似完美却退化的拟合。

于是引入

用 RANSAC 在候选中反复抽样、拟合、计数内点，并对最终结果做残差与空间分布检查。

6.1 · 先选合理的变换，不要默认 Homography 最好

2 点起 · SIMILARITY
平移 + 旋转 + 等比缩放

自由度少，适合相似变换近似成立的目标。

3 点起 · AFFINE
允许剪切 / 非等比缩放

能解释一般仿射形变，但不能表达完整透视。

4 点起 · HOMOGRAPHY
平面投影的 3×3 单应性

适用于近似平面对应或纯旋转相机等特定条件；不等于真实 3D Pose。

Homography：s [x′, y′, 1]ᵀ = H [x, y, 1]ᵀ
重投影残差：eᵢ = ‖p′ᵢ − π(H·pᵢ)‖₂
RANSAC：采样最小点集 → 估计候选模型 → 统计 eᵢ < τ 的内点 → 最优模型重估与检查

估计 Homography 至少需要四组非退化对应，而且点不能集中或近乎共线；实际应有更多且分布合理的对应点。显著非平面、形变目标无法被单个 H 普遍正确解释。

6.3 · 内点多，就说明目标确认成功了吗？

仍然不能。重复印刷图案可能在错误位置产生局部一致变换；内点即使很多，集中在一个极小区域时也可能支撑不了整个物体的四角映射。除了内点比例，还应该检查残差分布、覆盖面积、关键点是否近共线、投影四边形是否合理。

几何一致 ≠ 物体真值：RANSAC 能支持“这一批对应符合某个模型”，却不能自动证明物体类别、实例身份或三维可抓取位姿。背景平面、重复图案和模型错误依然会造成假阳性。

到这里，整条路线终于能在两幅图之间建立经过验证的对应。最后该怎样测试，才能知道是检测失败、描述失败，还是几何模型不适合？

07 · VALIDATION

怎样验证整条路线，而不是只看到漂亮的匹配线？

回头看，这条路线并不是“先学 Harris，再用 FAST 替换，最后 SIFT/ORB 一步到位”。每种机制回答的问题不同：点能不能再次出现、出现后能不能认出来、认出来以后能不能在空间上自洽。

7.2 · 最小可运行 OpenCV 实验：ORB → 候选 → RANSAC

下面实现一条完整工程基线：对两张灰度图分别提取 ORB 特征，使用 Hamming KNN + Ratio 获得候选匹配，对近似平面目标估计 Homography，再投影参考图四角。每个中间结果都可检查，而不是只看最后那个框。

Python · 完整最小实验（OpenCV + NumPy）
import cv2
import numpy as np

ref = cv2.imread('reference.png', cv2.IMREAD_GRAYSCALE)
scene = cv2.imread('scene.png', cv2.IMREAD_GRAYSCALE)
if ref is None or scene is None:
    raise FileNotFoundError('需要 reference.png 和 scene.png')

orb = cv2.ORB_create(nfeatures=1500, scaleFactor=1.2, nlevels=8)
kp_ref, des_ref = orb.detectAndCompute(ref, None)
kp_scene, des_scene = orb.detectAndCompute(scene, None)
if des_ref is None or des_scene is None or len(des_scene) < 2:
    raise RuntimeError('关键点不足，无法构造二近邻匹配')

matcher = cv2.BFMatcher(cv2.NORM_HAMMING)
knn = matcher.knnMatch(des_ref, des_scene, k=2)
good = [m for pair in knn if len(pair) == 2
        for m, n in [pair] if m.distance < 0.75 * n.distance]
print('keypoints:', len(kp_ref), len(kp_scene), 'ratio:', len(good))
if len(good) < 4:
    raise RuntimeError('候选匹配不足，不能估计单应性')

src = np.float32([kp_ref[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
dst = np.float32([kp_scene[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)
H, inlier_mask = cv2.findHomography(src, dst, cv2.RANSAC, 3.0)
if H is None or inlier_mask is None:
    raise RuntimeError('未估计到有效 Homography')

inliers = inlier_mask.ravel().astype(bool)
pred = cv2.perspectiveTransform(src, H).reshape(-1, 2)
err = np.linalg.norm(pred - dst.reshape(-1, 2), axis=1)
print('inliers:', int(inliers.sum()), '/', len(good))
print('median reproj error (px):',
      float(np.median(err[inliers])) if inliers.any() else 'N/A')

h, w = ref.shape
corners = np.float32([[0, 0], [w-1, 0], [w-1, h-1], [0, h-1]]).reshape(-1, 1, 2)
projected_corners = cv2.perspectiveTransform(corners, H)
print('projected corners:', projected_corners.reshape(4, 2))
# 上面的成功只说明找到一个几何一致解。
# 实用系统还应检查内点数量/覆盖、点集非退化、
# 四边形自交/面积和目标是否近似平面，并独立验证身份。
这一篇真正得到什么？

我们获得了一条不依赖完整 Mask、利用局部外观建立跨图像对应的技术路线：可重复点 → 局部描述 → 候选匹配 → 几何验证。它适合带独特文字或纹理的平面参考目标、局部重定位和二维对齐；当目标弱纹理、重复纹理、严重遮挡或明显非平面时，必须承认信息本身不够。

这也说明前面六条研究路线并非谁取代谁：颜色、区域、边缘、几何、骨架、局部特征分别依赖不同的视觉证据。选择哪一条，取决于目标究竟提供了什么信息。
