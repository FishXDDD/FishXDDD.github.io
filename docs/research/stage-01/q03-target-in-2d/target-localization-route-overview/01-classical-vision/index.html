00 · WHY ANOTHER PAGE

先看问题，而不是先看算法

想找桌面上的红色瓶子，我的第一反应是：它这么红，不就直接找红色像素了吗？这确实可能成功。但如果桌上还有一本红色书，找到“所有红色”显然不等于找到“那只瓶子”。

场景一：颜色线索足够明显，是否就够了？
即使把所有红色像素找出来，也还需要判断哪一块才符合“瓶子”的约束。

换成一只白瓶子，颜色差异也许不够了，轮廓反倒更明显；换成一根弯曲的线缆，只有 BBox 甚至不能回答它在哪里弯、两端在哪里。至于瓶身上的标签角点，它们可能很容易被检测，却并不能自己宣布“我是瓶子”。

所以这里不是问「常见算法有哪些」，而是问「我已经观察到的证据能支持哪一种计算，最后能否得到目标的位置？」

第一件事：观察证据

颜色、纹理、边界、规则几何、细长结构还是局部细节？

第二件事：计算结果

获得的是像素类别、区域、线、中心线还是特征点？

第三件事：目标归属

当前规则是否足以唯一选出目标，并给出所需表示？

01 · SIX QUESTIONS

六个值得分别研究的问题

下面六条路线是六种不同的提问方式，不是必须按顺序执行的算法流水线。每一页都会从一个具体场景出发，做完关键计算，然后回到“能否找到目标”。

01 · DEEP DIVE

像素与纹理

颜色差异怎样成为目标位置？

输出：像素判别 / 纹理线索 / 区域候选
02 · DEEP DIVE

区域与分割

哪些像素才属于同一个目标？

输出：连通区域 / 多个候选 Mask
03 · DEEP DIVE

边缘与轮廓

颜色不够时，边界能告诉我们什么？

输出：边缘图 / 轮廓 / 边界
04 · DEEP DIVE

几何结构

怎样用直线、圆与曲线约束目标？

输出：直线、圆与曲线模型
05 · DEEP DIVE

骨架与拓扑

一根弯曲线缆应该怎样表示？

输出：中心线 / 端点 / 分支与连通性
06 · DEEP DIVE

局部特征

哪些细节值得被记住？

输出：角点 / 关键点 / 局部描述子

这里的“输出”代表该类方法可以提供的证据，不代表自动完成目标识别。

02 · WHAT COUNTS AS SOLVED

提取出一个结构，距离找到目标还有多远？

这是最容易在学习过程中丢失的一步：算法结果、视觉证据和目标答案是三个层次。

算出的东西它说明什么不能直接断言什么
红色像素 Mask这些像素满足红色条件它们都属于指定瓶子
一条 Canny 边缘这里存在一定幅度的图像变化它必然是物体真实边界
一条 Hough 直线有足够多的点支持某条几何直线该直线必然属于指定目标
一条骨架某个区域存在这种中心结构它必然是一整根线缆
一批 SIFT 特征点局部图案具有可检测、描述的结构已经知道这些特征属于哪个物体

因此每个子页都用相同的收尾方式：本来要找什么 → 实际得到什么 → 什么条件下任务完成 → 哪些情况不能宣称成功。

一个问题如果在明确条件下已经解决，就可以停下来；不需要为了展示更多算法，强行把它扩展成无限困难的问题。
03 · WHERE TO START

先去哪一页？从观察到的困难出发

你看到的场景建议先问什么开始探索
红色瓶子放在浅色桌面颜色是否已经构成唯一线索？像素与纹理 →
前景找到了，却碎成好多块哪些像素可以组成同一个候选？区域与分割 →
颜色相近但外形清晰能否从局部变化得到边界？边缘与轮廓 →
目标有规则的圆、直线或形状哪一种几何模型能被数据支持？几何结构 →
目标又细又长，还会弯曲Mask 与 BBox 是否真的合适？骨架与拓扑 →
局部图案复杂、角点明显哪些位置可以被稳定地记录？局部特征 →

当图像本身无法区分两个外观和约束完全一致的候选时，继续堆砌传统算子通常不会凭空产生身份信息。这也是后续研究目标参考、学习式检测和语言定位的原因。

这一页的终点

现在已经清楚：从单张图像可以计算不同层次的视觉证据，方法的输出不同，能解决的定位问题也不同。
