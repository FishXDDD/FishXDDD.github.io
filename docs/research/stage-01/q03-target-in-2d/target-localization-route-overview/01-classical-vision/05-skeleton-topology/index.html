05 / SKELETON & TOPOLOGY · 从区域到连接关系

形状不规则，
还能找到它的“骨架”吗？

前面尝试过利用直线、圆和椭圆这样的规则模型寻找结构。但一根弯曲的线缆、一片有分叉的薄片，并不一定能用少数几何参数描述。如果不再要求它符合某个固定形状，而是关心它从哪里延伸、在哪里分叉、是否连通呢？

本页研究：从二维前景区域出发，提取细线状骨架、整理分支和节点，并分析连通关系及其稳定性。
图中将粗的分叉区域压缩成细线，再把端点、分叉处和它们之间的线段表示成图。三个结果回答的是不同问题；骨架不是自动识别语义物体的工具。
关键词　连通分量 / 孔洞 / 距离变换 / Medial Axis / Thinning / 分支图 / 剪枝
00 / PROBLEM & SCOPE

先确认：这里要研究的不是另一种“曲线拟合”

一条弯曲的线可以用样条表示，但拟合出一条平滑曲线，不一定能解释它连接了几个分支、是否形成闭环。

这一节从另一种需求进入。假设分割已经给出一根弯曲线缆的前景 Mask，我们并不急着问它符合哪一个参数曲线，而是想知道：它的主体中心在哪里、从哪里到哪里、是否分叉、有没有环，以及这些结构是否稳定。

INPUT / 输入

二维前景区域

二值 Mask 为主；也可以由轮廓构造区域。图像中缺失的部分并不会被自动恢复。

STRUCTURE / 关心

局部形状与连接

区域宽度、中心线、分支节点、连通分量、孔洞与闭环。

OUTPUT / 输出

可计算的结构描述

骨架像素、端点和分叉点、路径长度、结构图及可靠性标记。

先划清两个概念

骨架（Skeleton）：把二维区域压缩成细线状表示，用来保留主要延伸形态；拓扑（Topology）：关心连通分量、孔洞及节点之间的连接关系。它们联系紧密，但并不等价：相同拓扑的形状可以弯曲得很不同，同一幅形状的骨架也可能因一点边界噪声而多出分支。

本节不做目标的语义类别判断，不把二维图像的交叉直接等同于三维物体的物理连接，也不研究自由曲线拟合的完整理论。把曲线看作骨架路径的表示方式可以，但不是这一页的主线。

01 / CONNECTIVITY & HOLES

先不提骨架：一个形状，究竟算几个部分？

如果“连不连得上”都没定义好，后面的分支数量和骨架路径就谈不上可靠。

设二值区域为 M(x,y)∈{0,1}。把相邻前景像素归到同一块，便得到连通分量（Connected Components）。看起来简单，第一处麻烦却立刻出现：对角接触的两个像素，到底算不算相连？

4-CONNECTIVITY

只看上下左右

每个像素只与上、下、左、右相连；纯对角接触保持分离。

8-CONNECTIVITY

再加入四个对角

允许对角连接。对细线尤其重要，但也更容易把仅在角上相接的区域并在一起。

对数字图像的前景和背景，通常要考虑互补的邻接约定（例如前景 8 邻接、背景 4 邻接），避免数字化边界产生自相矛盾的连通解释。这个约定会影响孔洞和 Euler 数的计算。

1.1 还要数孔洞：为什么圆环和实心圆不同？

C 是前景连通分量数，H 是孔洞数。它们是粗粒度的拓扑特征，而不是物体类别。
χ = C − H
二维前景的 Euler 特征数；结果依赖像素邻接规则与 Mask 质量

孔洞可能有用，比如区分一个封闭环和一块实心区域。但一个很小的分割缺口，就可能让“有孔”变成“无孔”。于是新的问题出现：连通关系算清楚了，怎样进一步得到形状延伸的方向？

一个常见误判

两根线缆在图像上交叉，Mask 可能把它们合成一个连通区域；但这无法证明它们在三维空间相接。此处的拓扑是二维观测拓扑，不是实际物体的空间连接拓扑。

02 / CENTERLINE EXTRACTION

一块有宽度的区域，怎样缩成一条中心线？

想得到线缆的走向，直接使用区域轮廓并不方便。我们需要一条更简洁的内部表示，最好还能保留分叉和闭环。

2.1 一个直觉：每个点距离边界有多远？

对前景像素 p，计算它到最近背景位置的距离：

D(p) = minq∈背景 ‖p − q‖₂
欧氏距离变换（Euclidean Distance Transform）

靠近边缘时 D 小，区域内部通常更大。对于一条较均匀的粗线，它的“中间”往往是距离场的脊线位置。于是得到一个比“取几何中心”更有用的想法：沿着区域内部的中心位置寻找连续路径。

示意：中轴点的距离变换值可用作局部内切圆半径；细长区域的宽度可粗略估为 2D(p)，但端点、拐角或形状突变处需要谨慎。

2.2 Medial Axis：利用到边界的距离定义中轴

连续几何中的中轴可理解为最大内切圆圆心的集合；在规则条件下，中轴点往往具有不止一个最近边界点。离散实现通常根据距离场和局部拓扑约束构造近似的中轴骨架。

它解决的事：不仅保留主体延伸方向，还能把距离场上的半径关联到骨架点，适合研究线状目标的局部宽度。但边界一个细小的凸起，就可能产生额外的中轴分支。

2.3 Thinning：如果只想留下尽量细的连接结构呢？

另一条思路不是显式寻找几何中轴，而是从二值前景的边界开始，反复删除可以安全删除的前景像素，直到得到细线。关键不是“删到最细”，而是删除时尽量不改变数字拓扑连接。

ZHANG–SUEN

逐步细化

观察每个候选边界像素的 8 邻域；按特定子迭代规则删除满足条件的点，直到稳定。

GUO–HALL

另一种细化判据

同样迭代删除边界像素，但用不同的邻域连通条件，得到的细节和分支形态可能不同。

Zhang–Suen 的最小计算机制

把 3×3 邻域中的中心点记为 p₁，北、东北、东、东南、南、西南、西、西北依次记为 p₂…p₉。设 N(p₁) 为前景邻居个数，A(p₁) 为沿环绕邻居遍历时 0→1 的跳变次数。

p₉p₂p₃
p₈p₁p₄
p₇p₆p₅

观察邻居数量和环上的 0→1 跳变。

2 ≤ N(p₁) ≤ 6A(p₁) = 1

还要满足当前子迭代的特定邻域乘积条件；两个子迭代的判断不同，不能仅靠这两条就删除。

展开：Zhang–Suen 两个子迭代究竟检查什么？

对每一个候选前景像素，满足 2 ≤ N ≤ 6、A = 1 后，还要检查：

子迭代 1：p₂p₄p₆ = 0，p₄p₆p₈ = 0子迭代 2：p₂p₄p₈ = 0，p₂p₆p₈ = 0

每一轮先同时标记、再同时删除满足条件的像素，重复直到不再变化。仅按公式逐点实时删除，会改变算法结果。这里列的是二值图像上的经典规则，而不是通用的所有骨架算法定义。

2.4 两条路线有什么实际区别？

路线它的主要依据更适合关心什么注意什么
Medial Axis边界距离与局部最大内切圆中心位置 + 局部半径 / 宽度边界噪声容易导致额外分支
Thinning迭代删除像素并保留连通性尽量细的连接与分支骨架不保证每点都是几何意义的中心
距离变换每个前景点到最近背景的距离构造宽度信息或中轴的基础距离图本身不是骨架，不能简单把所有局部极大值连成骨架

得到一条像素骨架后，新的问题更明显：一堆只有一个像素宽的线，还是不方便告诉程序“这是三个端点、一处分叉、两段主要路径”。下一步需要把它组织成结构图。

03 / SKELETON TO GRAPH

有了中心线，怎么知道哪里是端点、哪里是分叉？

骨架把区域变细了，但仍然是一张二值图。我们希望把它转成节点、边和可测量的路径。

一个朴素起点是：统计每个骨架像素在 8 邻域里有几个骨架邻居。对理想、无歧义的一像素曲线，邻居数为 1 常对应端点，为 2 常对应路径内部，为 3 及以上则可能对应分叉。

deg₈(p) = ∑q∈N₈(p) S(q)
S(q)∈{0,1} 为骨架二值值，N₈(p) 为 p 的 8 邻域
概念图：将分叉区域合并成一个图节点，把中间连续的骨架像素压缩为图的边，保留端点、分支、路径长度与方向信息。

3.1 从像素到图：具体怎样做？

  1. 找端点与候选分叉。 在约定好的像素邻接方式下统计骨架邻居，生成粗候选。
  2. 合并分叉区域。 数字骨架的一个真实分叉常表现为多个相邻像素，不能将每个度数 ≥3 的像素都当成独立节点。
  3. 沿骨架追踪路径。 从节点出发，沿非分叉像素走到下一个节点，记录经过的像素链。
  4. 处理闭环。 完全闭合的环可能没有端点，也没有分叉；必须额外检测和记录闭环，而不是只从端点开始追踪。
  5. 汇总图属性。 得到 G=(V,E)，并保留节点位置、路径长度、方向、曲率粗略指标和局部宽度。

3.2 “度数”等于分支数量吗？不一定

8 邻域的对角连接，容易在拐角或密集分叉处形成意外邻接。因此 deg₈ 是好用的候选检测规则，而不是完整的结构图构造算法。实际实现需处理 2×2 方块、相邻分叉像素和重复路径，或采用专用的像素图压缩算法。

拓扑和几何的分工

图的“节点—边—闭环”描述连接关系；边沿着哪里弯曲、长多少、局部有多粗，则是附着在图上的几何信息。后者可以变化很大，而图的连接模式保持不变。

04 / NOISE & STABILITY

为什么骨架看起来像树枝，细小毛刺到处都是？

骨架已经提取出来了，结果却常常比原来的区域更复杂：细小边界起伏可能变成一条长得很明显的“假分支”。

对同一根线缆，在 Mask 边界上多一个小凸起，或者少一小块像素，就可能生成新分支。原因不是“骨架算法毫无用处”，而是我们把较高维度的区域边界细节压缩到了少数中心线路径中，微小变化可能被放大。

BEFORE

原始骨架

主体路径之外，还出现了三条短枝。

AFTER

受控剪枝

可以减少局部误差，但删掉的也可能是真实结构。

4.1 三种常见处理路线

改善输入 Mask
针对锯齿、孤立噪声进行轻度处理；但开运算会删除细线，闭运算可能错误连接两个目标。先验形态学处理并非无代价。
剪去短枝
沿端点到最近分叉的路径估计长度，去除低于阈值的末端分支。应避免把主干或真实短分叉一起删除。
引入宽度或证据
结合距离变换半径、边缘支持或时序稳定性判断分支是否可信，而不是只凭像素长度做判断。

4.2 交互示意：剪枝阈值越大，就一定越好吗？

端点短枝剪除 · 示意实验保留 4 条末端短枝
22 px

这里只模拟“端点到分叉点的短枝按长度筛选”，不是实时执行骨架化。图中的分支长度是演示用数据。真实剪枝还需考虑迭代顺序、环路、宽度和主干保护。

细枝剪除以后，连接结构可能发生改变。面对本来就很细、很短的真实目标，简单的长度阈值尤其危险。

几何更平滑 ≠ 拓扑更正确。 两根线间的一个缺口若被补上，连通分量数就可能改变；闭环上断掉一个像素，孔洞也可能消失。要先决定哪些连接不能被破坏，再决定是否平滑或剪枝。
05 / TARGET LOCALIZATION

知道“怎么连”，对二维目标定位有什么用？

骨架和拓扑不是最终答案。它们更像一种结构证据：当目标由细长部分、分叉或孔洞构成时，能提供边界框不容易表达的定位信息。

CASE A

弯曲线缆

中心线的端点、延伸方向和局部宽度，比整块区域的矩形框更直接；但交叉处是否真连通，需要额外判断。

CASE B

有分叉的部件

分叉点、主干和支路连接可以作为结构锚点；但噪声造成的伪分叉会影响检测。

CASE C

环状或带孔物体

孔洞数量和闭环提供了形状线索；但遮挡或分割缺口会改变拓扑特征。

5.1 得到的定位结果究竟是什么？

可计算输出如何得到它没有回答的事
中心线像素序列骨架提取 + 路径追踪不知道它属于哪类物体，也不等于物体的三维轴线
端点 / 分叉点骨架邻域分析 + 节点聚合不保证每个端点都是现实中的物理末端
路径长度 / 局部方向沿骨架累积 2D 像素距离、局部差分透视与深度不同时，像素长度不是现实长度
局部宽度骨架与距离变换联合估计是图像平面尺度，且边缘与分割误差会影响数值
连通分量 / 孔洞 / 环路连通性、Euler 数与图遍历二维重叠不保证三维连接

5.2 一个很重要的边界：结构不等于实例

假设两根不同的线缆在图像里压在一起，分割器只给出一张合并 Mask。骨架可能产生一个 X 型交叉节点，却无法单凭这张 Mask 判断“这是一根四向分叉的线缆”，还是“两根彼此交叉的线缆”。

同一幅 X 形二维观测可有不同的物理解释。仅有二值区域的拓扑，并不能完成实例分离或空间结构恢复。
它在传统二维定位体系中的角色

颜色 / 纹理提供外观证据；区域分割提供目标候选；边缘提供边界；规则几何提供参数模型；骨架与拓扑提供内部的路径、分支和连接关系。这些是不同种类的证据，并非每张图像都必须按顺序运行所有方法。

06 / EXPERIMENTS & TAKEAWAYS

做哪些实验，才算真正知道骨架算法解决了什么？

不要只在一张漂亮的 Mask 上调用 skeletonize。更重要的是控制输入的变化，看输出的结构何时开始变得不可信。

实验只改变什么观察输出要回答什么
4 / 8 邻接两区域是否仅对角相接连通分量数 / Euler 数邻接约定为什么影响结果？
Medial Axis vs Thinning同一张细长 Mask骨架位置、分支数、距离半径中轴与细化在优化什么？
边界毛刺在 Mask 边缘增加凸起端点数、分叉数、路径长度小噪声为何造成结构变化？
断裂与错误连接制造小缺口或连接桥连通分量、闭环、骨架图后处理可能破坏什么？
两条线缆交叉分别提供实例 Mask 和合并 Mask骨架图是否出现假节点二维图能否区分物理连接？

6.1 最小可运行实验：直接看中轴和细化有什么不同

Python：二值 Mask → 距离中轴 / 细化 → 端点与分叉候选
import numpy as np
from scipy.ndimage import convolve
from skimage.morphology import medial_axis, skeletonize
from skimage.measure import euler_number, label

# mask: (H, W) bool；True 表示前景
mask = mask.astype(bool)

# 两条不同路线：几何中轴 vs 拓扑细化
medial, dist = medial_axis(mask, return_distance=True)
thin = skeletonize(mask)

# 中轴上的局部半径（像素）；近似宽度可从 2*dist 观察
radius_on_medial = dist * medial

# 对细化骨架统计 8 邻域数；仅作端点/分叉候选
kernel = np.ones((3, 3), dtype=np.uint8)
kernel[1, 1] = 0
neighbors = convolve(thin.astype(np.uint8), kernel,
                     mode="constant", cval=0)
endpoint_candidates = thin & (neighbors == 1)
branch_candidates = thin & (neighbors >= 3)

# 使用同一邻接约定观察整体拓扑
component_count = label(mask, connectivity=2).max()
euler = euler_number(mask, connectivity=2)
hole_count = component_count - euler

print("components:", component_count)
print("holes:", hole_count)
print("endpoint candidates:", endpoint_candidates.sum())
print("branch-pixel candidates:", branch_candidates.sum())

# 注意：相邻分叉像素尚未聚合；这不是最终分支数。
# 需要再进行节点聚合、路径追踪和闭环检测。

环境：NumPy / SciPy / scikit-image。注意 Python 中的 mask 要先由真实分割结果赋值。SciPy 的卷积只统计邻域数，不会自动生成简化后的图结构；输出的分叉像素数量不等于实际分叉节点数量。

可选：用 OpenCV 的 thinning 接口替换骨架提取
import cv2

binary = (mask.astype(np.uint8) * 255)

# 需要安装具有 ximgproc 模块的 OpenCV contrib 构建
thin_cv = cv2.ximgproc.thinning(
    binary,
    thinningType=cv2.ximgproc.THINNING_ZHANGSUEN
)
thin_cv = thin_cv > 0

这里的输出与 scikit-image 的 skeletonize 并不保证逐像素相同。实际项目优先固定输入、算法实现与邻接约定，再比较稳定性。

距离变换 / 中轴
用区域到边界的距离找到内部中心结构，并提供局部半径信息。
形态学细化
从二值区域迭代删除可删像素，得到细的连通骨架，不必要求精确几何居中。
骨架图
把骨架压缩成端点、分叉节点与路径边，便于计算、比较与匹配。
剪枝与验证
抑制假分支，同时检查是否删掉了真实结构、造成拓扑改变。
回到最初的问题

对不规则而细长的目标，我们不一定需要为整条轮廓寻找一条固定的数学曲线。从二维区域中提取中心线，并进一步整理成连接图，就能够获得端点、分叉、长度、宽度和闭环等实用的结构证据。但其前提仍是输入的 Mask 可信；错误连接、遮挡和实例混合，不能靠骨架化本身解决。

本页 00–06 是研究理解的递进次序，而不是固定的工程流水线。实际系统可能直接做连通域分析，也可能直接在 Mask 上做细化和图构造；何时需要中轴宽度，取决于目标特征。
