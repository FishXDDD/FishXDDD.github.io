骨架与拓扑

形状不规则，能不能找到它内部的连接关系？

前面已经研究过像素、区域、边缘和规则几何模型。可面对弯曲的线缆、分叉的枝条时，直线和旋转框都显得不够自然。我真正想要的不是一个“更复杂的框”，而是中心路径在哪里、从哪里分叉、是否连通，以及这些结果有多可靠。

这篇沿着这个问题，先从最简单的数字连通性出发，尝试把区域压缩成骨架，再将骨架组织为可计算的节点与路径；每引入一个方法，都要说明它解决了什么，以及又引入了什么新的失效条件。

00 · QUESTION & SCOPE

规则几何不够用时，我们真正缺的是什么？

上一站《几何结构》已经能对轮廓拟合直线、圆、椭圆，还能得到旋转包围框。但把这个思路用到一根弯曲线缆上就很别扭：它并不是“拟合得不够好”，而是我真正关心的东西变了。

面对同一块前景，外接框与连接结构回答的不是同一个问题
机制示意，不是对一张真实图像的算法测量结果。外接矩形可以正确包围目标，但不会表达内部的连接关系。
INPUT
二维前景 Mask

可能包含弯曲、分叉、孔洞、细线；其质量直接决定后续结构可信度。

QUESTION
形状怎么连、朝哪延伸

连通数、孔洞、中心路径、端点、分叉点和路径之间的关系。

OUTPUT
骨架像素与拓扑图

Skeleton、G=(V,E)、像素路径、二维长度及局部宽度估计。

先约束边界：研究的是二维 Mask 的几何和拓扑，不是实例识别、三维线缆重建或自由曲线拟合。两条线缆在图像里交叉，不代表它们在物理上真的连接；骨架上的分支也不天然代表物体真实分支。
新的问题

如果先不提骨架，最基础的“连接”应该怎样定义？

TECHNICAL ROADMAP · 连接关系与内部中心线

先画清技术路线：拓扑与骨架是两种证据

这个问题自然分成两种证据：一类只在乎通不通、有无孔洞；另一类在乎沿哪里延伸、中心线如何走。两条路线能合并使用，却不能说“先做 A 再做 B 才是正确算法”。

什么情况下应该拒绝一个结构结论？
这里不存在“越新越好”的方法排序：Medial Axis 与 Thinning 是两种骨架构造路线；连通数、孔洞是拓扑量；剪枝是后处理策略；图压缩是结构化表示。它们解决的不是同一种问题。
01 · DIGITAL TOPOLOGY

还不急着提骨架：两个像素究竟怎样才算连上？

最直觉的做法，是把前景像素归为连通块。这在 02《区域与分割》中已经用过；当时它是为了找到候选区域。现在要换一个角度：把连通关系本身当作需要保护和检验的结构量。

最初的尝试

只要两个前景像素能沿邻居一步步走到一起，就算连通。

哪里开始失败

斜角接触到底算连上了吗？一像素的连接桥可能让两段线合成一体。

引出的工具

明确前景 4 / 8 邻接；再统计连通分量和孔洞。

p ~ q ⇔ 存在一条前景邻接路径 p → … → q
C = 前景连通分量数，H = 内部背景孔洞数
χ = C − H　（二维 Euler 特征数）

邻接约定不可随便混用：常见做法是前景 8 邻接与背景 4 邻接互补（或反过来），避免对角接触时出现数字拓扑解释冲突。同一张 Mask 在不同邻接规则下，连通数、孔洞数及 Euler 数都可能变化。

还可以问有没有洞：同样是一个连通区域，实心圆满足 C=1、H=0；圆环满足 C=1、H=1。闭环上少几个像素，内部背景可能突然与外界连通，H 就从 1 变成 0。

不要过度解释：一张二维交叉线缆 Mask 的拓扑，无法判断实际是“一条四向分叉线”，还是“两根互不相连的线缆”。那需要深度、颜色连续性、实例线索或其他先验。
新的问题

连通数、孔洞数都清楚了，但它们不能告诉我线缆从哪里弯到哪里。能不能把一块有宽度的区域压缩成内部中心路径？

02 · SKELETON EXTRACTION

一整块有宽度的区域，怎样得到它的中心路径？

最简单的尝试是取前景的质心，可质心只是一个点：对弯曲、分叉的物体几乎没有表达力。于是换个问题：区域内部哪个位置离边界更远？这些内部位置是否可以连成路径？

最初的尝试

从区域算中心点，或者直接沿上下轮廓取中间。

哪里开始失败

一个质心表达不了多段弯曲；逐列取中点遇到竖直段和分叉立刻失效。

引出的工具

先计算距离变换，再分别研究 Medial Axis 和 Thinning。

D(p) = min {‖p−q‖₂ : q 属于背景}
若 p 在中轴附近：局部半径 r(p) ≈ D(p)，局部宽度可粗略看作 2D(p)
中心线从哪里来：距离场与边界剥离是两种不同的证据
概念示意：真实 Medial Axis 的位置依赖几何边界，离散细化的中心线也依赖数字网格与删除规则，二者通常并不完全相同。
路线 A · 几何中心证据Medial Axis（中轴）

连续几何中可由最大内切圆圆心刻画；在离散图像中结合距离场和拓扑规则得到近似中轴。优势是中轴点可关联局部半径；代价是边界小凸起容易产生额外中轴枝条。

路线 B · 拓扑保留证据Thinning（细化）

从边界开始反复删除满足约束的前景像素，目标是尽量保留原有连接关系并得到细骨架。优势是结构细；代价是不保证每个像素严格处在欧氏意义的区域中心。

2.1 · 最朴素的细化想法：只要在边界，就删掉？

这样很快就会把细枝和连接桥一起删断。真正重要的不是“越细越好”，而是哪些前景像素删除后仍能保持局部拓扑。经典 Zhang–Suen 将 3×3 邻域的 8 个相邻像素记作 p₂…p₉，分两个子迭代并行标记待删除点。

N(p₁) = p₂ + p₃ + ⋯ + p₉；A(p₁) = 8 邻域按环遍历的 0→1 跳变数
共同约束：2 ≤ N(p₁) ≤ 6，A(p₁)=1
第 1 子迭代：p₂p₄p₆=0，p₄p₆p₈=0
第 2 子迭代：p₂p₄p₈=0，p₂p₆p₈=0

按北、东北、东、东南、南、西南、西、西北的次序编号 p₂…p₉。每个子迭代是先扫描并收集需要删除的位置、再同时删除；不能逐点检查后立刻改写，否则结果与原算法不同。

2.2 · 换成 Guo–Hall 会怎样？

Guo–Hall 同属二值图细化算法，只是邻接与保连通判据不同。不同算法可能得到不同的转折、节点和局部粗细。这里真正要比较的指标不是“谁看起来更漂亮”，而是连接关系、路径定位和下游测量是否一致。

经验边界：距离变换本身不是骨架，不能把所有局部极大值简单连接起来；Medial Axis 不保证避开伪枝，Thinning 不保证几何中心绝对准确。若需要稳定物理宽度，还要检查像素尺度、边界误差与成像视角。
新的问题

现在已经拿到细细的一条像素线。但机器人需要“第几条支路、从哪个端点到哪个节点”，而不是一张 0/1 图片，怎样让它成为结构化数据？

03 · SKELETON TO GRAPH

细线已经提取出来，怎样得到端点、分叉和路径？

最容易想到的办法，是数一个骨架像素周围还有几个骨架邻居。对理想的一像素链，邻居数为 1 像端点，为 2 像链内部，为 3 及以上可能是分叉。

最初的尝试

逐像素统计 8 邻域骨架数量，再给出端点和分叉的坐标。

哪里开始失败

一个真实分叉经常对应多个挤在一起的“≥3 邻居像素”；一个转角也可能因对角连接误判。完整圆环甚至没有端点。

引出的工具

把局部候选聚合成节点，再追踪并压缩中间路径，特殊处理纯闭环。

deg₈(p) = Σ { S(q) : q ∈ N₈(p) }　（S 为 0 / 1 骨架）
通常的初筛：deg = 1 → 端点候选；deg ≥ 3 → 分叉候选
最终图：G = (V, E)，边存有序像素链、弧长、方向与局部宽度
同一条骨架：像素邻接图与压缩后的结构图
图是结构概念图，未直接对应像素的 8 邻接计数。真实分叉团块需要进行聚合，避免生成一堆重复节点。

3.1 · 真正压缩成图，需要处理四件事

  1. 找候选：计算 8 邻域度数，标记端点和疑似分叉。
  2. 合并团块：将相邻的分叉候选合并为一个逻辑节点，可记录节点区域与代表位置。
  3. 追踪边：从逻辑节点沿连续骨架像素追踪至另一节点，把中间像素作为一条边的有序路径。
  4. 处理闭环：没有端点的纯环需要创建辅助节点或单独记录 cycle，不能只靠“从端点出发”完成遍历。

3.2 · 为什么单看邻居数并不够？

弯折、2×2 像素块和分叉附近的对角连边，都可能使 deg₈ 出现比想象中更大的数。一个度数 ≥3 的像素只是分叉候选；实际分支数量应由图节点聚合、路径追踪和去重后的图定义。

图不等于实例：图节点描述的是 Mask 内的像素连接，不自动对应物体关节、真实线缆交点或三维接触点。
新的问题

可惜真正得到的骨架往往不像示意图那样干净：一个细小的边界锯齿就可能多出一条枝。怎样去除毛刺，同时不破坏真实结构？

04 · STABILITY & PRUNING

骨架为什么总长出毛刺？剪掉会更好吗？

刚开始容易误以为：只要把骨架做得足够细，结构就会变稳定。事实上恰好相反。骨架对边界的小扰动可能非常敏感：一粒凸起、一处缺口，都有机会改变局部端点、分叉甚至闭环数量。

最初的尝试

让 Mask 先平滑，再细化；或者把所有短枝全部删掉。

哪里开始失败

开运算会吃掉细线，闭运算可能连接两个物体；短枝也可能是真实的电线头。

引出的工具

分清输入噪声、拓扑错误和可修饰的支路；只在有证据的条件下剪枝。

改善输入小尺度形态学 / 缺陷检查

如果已知锯齿和洞为成像伪影，可做有限修正；但先记录细线最小宽度与连接的改变。

改善骨架短枝剪除 / 显著性筛选

追踪“端点→最近分叉”的路径，删除短于阈值的末端枝。必要时结合局部半径、原图边缘支持和多帧稳定性。

交互实验 · 短枝阈值提高，会保留什么？分支长度是示例数据；不执行重新骨架化
16 px

这种基于长度的剪枝，只能作为带假设的规则。更可靠的方案往往还要问：这个分支周围的 Mask 真的有对应细长凸起吗？附近的 RGB 或深度证据是否支持它？

最重要的取舍：边界更平滑、骨架更短，不等于拓扑更正确。一根 6 px 的真实细枝和一根 6 px 的噪声毛刺，仅凭长度无法区分。
新的问题

如果能得到可靠的节点、路径和宽度，它在真实定位里比一个包围框多提供什么？又有哪些事情绝不能仅凭二维骨架推断？

05 · FOR 2D LOCALIZATION

骨架结构到底能为二维定位提供什么？

对于圆形瓶盖或规则方盒，中心和外接框已能解决很多问题，不一定要提骨架。骨架真正有价值的场景，是目标的重要信息藏在“沿哪里走、在哪里分叉”里面。

CASE A · 线缆
端点与中心路径

选择端点、延伸方向、局部宽度，用于跟踪与局部接近；遮挡和交叉可能误导路径。

CASE B · 分叉结构
节点与分支方向

识别主要交汇点、主干与支路；注意伪分叉及数字网格的节点聚合问题。

CASE C · 环状物体
孔洞与闭环

闭环提供外接框没有的形状证据；极小缺口即可导致孔洞统计变化。

可获得的二维结构怎么计算不可以直接推断
端点 / 分叉候选骨架邻域计数与聚类物体真实末端、三维接头
路径像素序列节点间路径追踪不存在遮挡的真实连续路径
二维弧长与切线累计相邻像素距离 / 局部差分真实空间长度、世界坐标轴
局部宽度Medial Axis + 距离变换半径带透视校正的物理直径
孔洞 / 闭环拓扑计数 + 图遍历物理结构一定相连
为什么“X 形骨架”不足以说明是一个分叉物体？
示意仅强调二维投影的歧义；真实交叉次序必须依靠额外图像、深度或实例证据，不可直接从平面连通性得出。
新的问题

骨架方法已经知道不少了。下一步最值得验证的，不是能否输出一张好看的细线，而是输入哪一种扰动会改变它的关键结构。

06 · EXPERIMENTS & SELECTION

怎样验证这一套方法，而不是只做出一张漂亮图？

最后回到最实用的判断：不是什么目标都需要骨架。把问题与输出配对，比追求单张图片上的“最好骨架”更可靠。

遇到的问题首先尝试检验条件
只是问 Mask 有几块、有没有孔互补邻接 + C、H、Euler 数一像素桥 / 缺口是否改变结论
需要线状目标中心位置与粗细Medial Axis + 距离值半径和中心线对边界扰动是否稳定
需要离散路径、端点与分叉Zhang–Suen / Guo–Hall + 图压缩候选节点是否聚合；环路是否遗漏
骨架有很多短毛刺检查 Mask，再尝试有约束剪枝短真分支是否被误删；连接是否改变
两根线图像上交叉先检查独立实例、深度与外观仅凭二值拓扑不能断言物理连接

6.1 · 最值得做的五个小实验

EXPERIMENT 01
4 / 8 邻接

只改变对角连接，记录分量数和 Euler 数是否改变。

EXPERIMENT 02
圆环切一个口

在相同 Mask 上删除几个像素，观察孔洞是否瞬间消失。

EXPERIMENT 03
一粒边界凸起

测量中轴/细化骨架端点与分叉候选的变化。

EXPERIMENT 04
短枝剪除

逐步增大阈值，检查何时删除了真实短分支。

EXPERIMENT 05
两根线交叉

对照分开的实例 Mask 与合并 Mask，识别假分叉。

EXPERIMENT 06
Medial 与 Thinning

比较中心偏移、局部半径、端点与图节点差异。

6.2 · 最小可运行实验

Python · 中轴、细化、Euler 数和节点候选
import numpy as np
from scipy.ndimage import convolve
from skimage.morphology import medial_axis, skeletonize
from skimage.measure import euler_number, label

# 输入：单通道 bool mask，True 为前景
mask = mask.astype(bool)

# 几何中轴（同时返回像素到背景的欧氏距离）
medial, distance = medial_axis(mask, return_distance=True)
local_radius = distance[medial]

# 拓扑细化骨架（具体实现依版本与方法参数而定）
thin = skeletonize(mask)

# 8 邻域候选计数；不等于已合并的逻辑节点数
kernel = np.ones((3, 3), dtype=np.uint8)
kernel[1, 1] = 0
neighbors = convolve(thin.astype(np.uint8), kernel,
                     mode='constant', cval=0)
endpoints = thin & (neighbors == 1)
branch_candidates = thin & (neighbors >= 3)
