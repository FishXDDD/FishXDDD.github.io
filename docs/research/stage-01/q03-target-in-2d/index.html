00前面好像默认得太多了

相机看见了目标，
不代表我已经拿到了它的几何。

前面研究几何和已知参考时，我似乎一直默认了一件事：目标已经找到了，需要的点云、图像位置或者对应关系也已经准备好了。

可真正面对相机时，情况并没有这么方便。

假设桌上放着盒子、瓶子和易拉罐，我想抓左边那只瓶子。相机给我的只是一整个场景的 RGB 和 Depth，怎样从中找到我要的目标，又该把它描述成什么样的信息？

有时候，一个检测框就够了；有时候需要精确的目标轮廓，或者几个能够明确对应物体结构的位置。究竟需要什么，其实还得看后续准备怎样利用它。

但找到目标也只是其中一部分。图像中的位置，怎么对应到真实的三维空间？相机给出的深度，又真的值得相信吗？

比如一只透明瓶子，RGB 里看得清清楚楚，Depth 却可能缺了一大片，甚至测到了瓶子后面的背景。目标找对了，三维几何却未必正确。

这一篇想弄清楚
怎样指认正确的目标，怎样建立二维与三维的测量关系，又怎样判断这些观测是否足以支持后续的 Pose 求解。

研究边界：单视角相机、静态或近似静态场景，以 RGB-D 为主要例子；不在本篇研究 Grasp Pose 求解器、多候选抓法选择或完整相机硬件设计。

01研究之后，回头整理的地图

原来，从场景到有用观测，
要弄清的是三件事。

最开始把它们都叫作“视觉定位”，后来才发现，这个词把不同问题混在了一起。

目标指认解决观测属于谁；空间测量解决图像和三维怎样建立联系；而数据可靠性不是最后才加上的检查步骤，它贯穿前面每一件事。

所以我不再把“检测 → 分割 → 点云”当作所有情况的标准答案。应该先问目标由什么条件指定、后续需要什么证据，再决定从相机观测里获取什么。

技术地图可以先整理清楚，探索过程还是从最普通的问题开始：眼前有好几个物体，我究竟怎么把要找的那个指出来？
02回到最开始的想法

找到目标以后，我才慢慢开始怀疑自己拿到的是什么。

接下来的四个问题，是一路往下研究时逐渐暴露出来的。它们不是必须依次运行的四个模块；有些方法只需要二维信息，有些则必须进一步认真面对三维测量。

指认目标→理解相机→RGB-D 关联→检验测量
01先指出“它”

我说的是左边那只瓶子，怎么让相机知道？

最开始觉得，找个目标应该不难。如果它固定出现在一个工位，直接划定 ROI 就好了；如果颜色明显，就试试阈值和连通域；如果知道它长什么样，还可以拿一张参考图像去匹配。

这些做法并没有错。场景足够稳定的时候，用已知条件把问题直接约束住，本来就是很好的办法。

但当物体外观、光照和背景开始变化，规则越来越难维护。后来接触目标检测才发现，原来可以从样本中学习一个类别的外观，直接预测它可能出现的区域。

可是，检测出了三个 bottle，也还没有回答“最左边那个是哪一个”。类别识别与当前任务的实例指认，原来不是同一个问题。简单空间条件可以筛选检测结果；当目标由更开放的词语描述时，Grounding 也成为值得研究的方向。

接着又发现：指认对了，还得考虑带走什么信息

如果只是缩小搜索区域，BBOX 可能已经足够；如果想从 Depth 中提取目标的可见表面，更需要像素归属明确的 Mask；如果后续要建立参考与观测之间的几何约束，则可能需要具有明确身份的 Keypoints 或 Correspondences。

普通图像角点不自动等于物体上的已知关键点。 同样，Mask 比 BBOX 细致，也不代表它能代替有身份的对应关系。

于是开始接触实例分割、Mask R-CNN，以及通过位置或框提示分割的 SAM。它们可以和检测、Grounding 配合，也可以独立提供所需信息。这里没必要把所有目标都塞进“先 YOLO 再 SAM”的固定组合。

逐渐清楚的是：指的是谁，与要把它描述到什么程度是两件事。不同方法换来的是不同的适用条件、观测形式、部署和维护成本，而不只是“精度更高一点”。

02从像素开始理解相机

图像里已经找到位置，为什么还不能直接得到 XYZ？

现在假设瓶子的某个像素已经找到了。我最初的想法是：相机不是同时提供 Depth 吗？把深度拿过来，应该就能得到三维坐标。

可像素里的 (u, v) 只是图像平面上的位置。一个像素对应的是一条从相机出发的视线，光靠它，没办法知道物体究竟在这条线上的哪里。

这时候才真正开始理解相机内参。焦距和主点决定像素如何对应相机坐标系中的视线；若使用的是与该像素正确对应的光轴深度 Z，就能通过反投影恢复三维点。

X = (u − cx) Z / fx　 ·　Y = (v − cy) Z / fy
简化针孔模型：坐标已按相机模型去畸变，Z 是相机光轴方向的深度；不能直接把任意量程读数都当作 Z。

如果不只取一个像素，而是取一组属于目标、又有有效深度的像素，就能得到目标的部分可见表面点云。原来点云并不是凭空出现的另一份信息，而是把相机测量重新表达到了空间中。

但接着又冒出几个实际问题：Depth 图的单位是什么？图像是否经过畸变校正？应该使用哪一份内参？一个像素的偏差，到了远处会变成多大的空间误差？

这一段真正建立的是成像几何与空间测量的关系。二维位置、正确的深度、匹配的相机模型缺一不可；但如果后续是利用二维与已知三维对应做 PnP，就不需要为了“完整”而先生成点云。
03第一次发现数据不是天然对齐的

RGB 和 Depth 都拿到了，为什么不能直接按同一个像素取？

设想 RGB 上已经得到一张准确的 Mask。最自然的操作，就是到 Depth 图上读取同一位置，再批量反投影。

然而 RGB-D 相机里的彩色与深度观测，可能来自不同的成像器件。它们有各自的光学中心、分辨率、内参和视角。两幅图上相同的像素坐标，并不天然指向同一个空间点。

这才开始接触传感器间外参、重投影与深度对齐：需要知道两个成像坐标系之间的空间关系，才能把深度观测映射到彩色图像的视角下。对齐还可能遇到遮挡、视角差异与采样空洞，不能简单理解为缩放图像。

未对齐的 RGB / Depth同一 (u, v) 不一定对应同一条光线。直接用 RGB Mask 索引原始 Depth，可能混入背景或漏掉目标。
已对齐的 RGB / Depth能够按约定像素关联，但反投影仍要使用与对齐后图像坐标相匹配的相机模型，并处理无效区域。

如果场景或相机在运动，还要考虑两路数据是不是在同一时刻采集。空间上对齐了、时间上却错位，目标边缘仍然可能不一致。

到这里才理解，驱动发布“RGB 和 Depth”两个话题，并不意味着所有对应关系都已经解决。实际使用时，还需要确认发布的是原始深度还是对齐深度、对应哪一路 camera_info、图像时间戳能否配对。

要得到目标点云，Mask 正确、反投影公式正确还不够。被一起使用的像素、深度和相机参数，必须描述同一个几何观测关系。

04终于开始认真检查测量

点云算出来了，为什么我反而不敢直接相信它？

到这一步，目标也找到了，深度也对齐了，公式更没有写错。按理说，点云应该就是眼前物体的真实表面。

可换成透明塑料瓶，事情就没那么顺利。RGB 里的瓶子轮廓依然清楚，Depth 却可能缺失一大片，甚至得到瓶子后面桌面的距离。换成反光表面、弱纹理区域或深度边界，又会遇到不同的问题。

于是才开始关心相机究竟靠什么测到距离。主动双目立体、结构光与 ToF 的测量机制并不相同，它们受环境光、纹理、材质、距离和运动影响的方式也不一样。以 RealSense D435i 为例，主要深度原理是主动立体视觉，不能把所有 RGB-D 相机都想成同一种测距方式。

这也让我把之前容易混在一起的三件事拆开了：相机模型是否正确、标定关系是否准确、真实深度测量是否可信。 前两件事都处理正确，也不能保证透明表面一定被测到了。

更麻烦的是，数据“有值”也不等于正确。边缘附近可能混入背景点；滤波虽然让点云平滑，却可能抹掉薄结构；空洞填补虽然让画面完整，也可能生成根本没有实际测到的几何。

那该怎么判断？至少得看看测量有效区域、重复采集时是否稳定、空间结构是否一致、与已知尺寸或基准平面的偏差，以及真正需要的抓取区域有没有被可靠观测到。

这里最重要的收获不是找到一个万能后处理参数，而是开始区分：看到了目标、测得了深度、可靠地测到了目标表面，是三个不同层次的判断。

03回头整理条件与代价

相机给出数据，
不代表问题就已经解决了。

回到最初那只瓶子，我现在会把“拿到了目标信息”这句话说得谨慎一些。不同错误出现在不同环节，却都可能把后续的几何与参考式求解带偏。

关心什么实际得到的能力仍要付出的代价与检查
目标指认从完整场景中确定要处理的实例位置、类别、外观和语言条件是否充分；相似实例会不会选错
观测表达获得区域、像素归属或有意义的对应点边界误差、背景混入、关键点身份与精度；不同输出不可直接互相替代
空间关联将二维信息与深度或三维约束对应内参、畸变、深度单位、传感器外参、对齐与同步
物理测量得到部分可见表面的深度观测随机噪声、系统偏差、无效测量、材质与距离、遮挡边缘
任务可用性判断当前观测是否足以继续求解关键几何是否可见；不是单靠有效点比例或点云美观程度作判断

其中有两个区分我很想保留：标定正确，不代表传感器测得准确；数据有效，不代表数据属于目标。 从计算结果反推真实世界之前，必须先知道哪些关系是真的由测量支持的。

我是不是找对了？

类别与实例有没有混淆？拿到的输出是否具有后续需要的几何意义？

我是不是关联对了？

像素、内参、深度、RGB-D 对齐以及时间关系是否一致？

我是不是测到了？

关键区域是否真的被观测？噪声、缺失和偏差还能允许继续求解吗？

这也不是要把相机变成一台永远没有误差的测量仪。对某些任务，粗略区域就足够；对另一些任务，毫米级几何偏差可能就会影响结果。数据好不好，既要看相机本身的测量能力，也要看当前任务究竟依赖哪部分观测。
