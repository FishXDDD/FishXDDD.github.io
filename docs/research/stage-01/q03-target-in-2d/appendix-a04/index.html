00
TECHNICAL ATLAS / 总览

分割到底有几种任务，又有几种指定目标的方式？

A03 解决类别和边界框，A04 则继续追问：哪些像素真正属于目标？ 这看起来只是把 BBOX 换成 Mask，往下研究却会发现：给像素分类、区分相同类别的不同物体、根据一个点指定目标，根本不是同一件事。

把 FCN、Mask R-CNN、Mask2Former、SAM、SAM 3 按年份串在一起很容易，但会误以为后来者总在替代前者。实际至少有两条相互交叉的坐标轴：分割结果表达什么，以及目标通过什么条件被指定。先把它们分开看。

维度主要问题典型输出 / 约束
Semantic Segmentation每个像素是什么类别？像素类别图；同类物体未必彼此区分
Instance Segmentation像素属于哪个具体实例？各实例 Mask + 类别/实例身份；适合 Things
Panoptic Segmentation怎样统一实例与背景区域？覆盖全图的 Thing 实例与 Stuff 区域标签
Interactive / Promptable目标由点、框或其他提示指定时如何分割？目标 Mask；是否能定位所有实例取决于提示机制
Concept Segmentation给定文本概念或示例，哪些实例匹配？概念匹配实例的 Mask 集合；依赖语义识别能力
先把两个维度分开

Mask R-CNN 属于实例分割；SAM 属于可提示分割；SAM 3 进一步支持概念驱动的检测与分割。它们可以服务同一个工程目标，但并不是严格按年份替换的三代技术。

01
SEMANTIC / 像素分类

从整图分类走到逐像素预测：FCN、U-Net 与 DeepLab

语义分割的第一个重要转变，是从“图像中有什么”走向“图像中的每个位置是什么”。CNN 的深层特征有较强的语义信息，却经过下采样，空间分辨率往往较低。怎样既保留语义，又恢复边界位置，成了这个方向长期研究的问题。

2015关键节点

FCN · 全卷积的像素级密集预测 原论文 ↗

将分类网络转为全卷积结构，直接预测空间类别图；跳跃结构融合较深的语义特征与较浅的空间细节。

条件 / 边界 输出的是逐像素类别，不天然区分同类实例；上采样也不保证细边界恢复准确。
2015关键节点

U-Net · 编码器–解码器与跨层特征 原论文 ↗

在收缩路径提取上下文，在扩张路径恢复空间分辨率；跨层连接帮助保留局部细节，在数据较少的分割场景中影响深远。

条件 / 边界 性能依赖训练域、标注质量与尺度；U-Net 是架构思路，不等于无需类别训练或自动完成实例划分。
2017–2018重要发展

DeepLabv3 / DeepLabv3+ · 多尺度上下文与边界恢复 原论文 ↗

利用 Atrous Convolution 和 ASPP 扩大与组合有效感受野；DeepLabv3+ 再结合解码器精化结果。

条件 / 边界 扩大上下文不等于解决实例身份，膨胀率、特征步幅和目标尺寸仍会影响细节。
读到这里： U-Net 与 DeepLab 不是“精度从低到高”的关系。它们分别从编码解码与多尺度上下文切入；任务、训练数据和分辨率不同，选择也会不同。

这里还可以把 PSPNet、HRNet、SegFormer 作为延伸研究节点。PSPNet 关注金字塔上下文，HRNet 关注高分辨率表示的持续维护，SegFormer 则展示了 Transformer 编码器与轻量分割头的组合；这些路线没有必要全部当成一级主里程碑。

02
INSTANCE / 实例级输出

Mask R-CNN：当“同一类别”还不够时

假设两只瓶子贴在一起。语义分割可以把它们都标成 bottle，但不能单靠类别标签区分第一只和第二只。实例分割因此需要同时处理两件事：找到具体实例，以及为各实例生成像素区域。

2017关键节点

Mask R-CNN · 在实例检测基础上增加 Mask 分支 原论文 ↗

沿用 Faster R-CNN 的实例候选思路，通过 RoIAlign 提升特征与像素位置的对齐，再为每个候选实例预测 Mask；分类、框回归与 Mask 分支并行。

条件 / 边界 依赖实例候选和训练类别；遮挡严重、粘连、细结构可能影响实例边界。RoI 级 Mask 计算的总体成本还与候选数量相关。

Mask R-CNN 很适合帮助理解实例分割的任务结构，但它并不是所有实例分割方案都必须继承的固定框架。后来的研究开始探索：能不能绕开每个 ROI 单独计算 Mask 的方式？

03
REAL-TIME INSTANCE / Mask 表示

实时实例分割不只有一个思路：YOLACT、SOLO、CondInst

如果实例数量很多，为每个实例单独走一遍 Mask 预测分支，成本可能逐步增加。另一批研究于是把重点放在Mask 究竟应该怎样表示与生成上。

2019关键节点

YOLACT · Prototype Masks + 实例系数 原论文 ↗

为整张图像产生共享的 Prototype Masks，同时预测各实例的组合系数；通过线性组合和裁剪得到每个实例的 Mask。

条件 / 边界 共享原型提高计算效率，但复杂边界和小实例的质量依赖原型分辨率、组合能力及实例分离效果。
2019 / 2020重要分支

SOLO · 让位置参与定义实例 原论文 ↗

将不同实例分配到空间网格区域，让分割头按实例位置输出相应 Mask，探索不依赖传统候选 RoI 的实例预测。

条件 / 边界 目标中心的空间分配可能出现竞争与歧义；密集或重叠实例对位置分配提出挑战。
2020重要分支

CondInst · 条件化的动态 Mask Head 原论文 ↗

由实例相关预测产生动态卷积参数，结合共享特征生成 Mask，让不同实例使用条件化的 Mask 函数。

条件 / 边界 动态参数与共享特征的设计影响表达和计算成本；仍依赖实例定位与分配的可靠性。

YOLO-Seg 等工业常用模型也常采用共享原型与系数组合的思想；但它们的检测器结构、训练与后处理不一定与原版 YOLACT 相同。这里值得比较的是实际 Mask 表达与部署成本，而不是把所有“YOLO + Mask”的版本都视为一个新理论家族。

04
UNIFIED SEGMENTATION / 统一表示

MaskFormer 与 Mask2Former：把类别预测换成 Mask 级表示

在语义、实例与全景分割之间，任务标签不同，但输入特征和像素分组的基本结构高度相似。如果每一种任务都单独设计架构，是否能够进一步统一？

2021关键节点

MaskFormer · Mask Classification 原论文 ↗

将语义分割从传统逐像素独立分类思路转化为一组 Mask 及其类别的预测；同样的框架可以适配不同的分割任务。

条件 / 边界 训练与匹配机制依赖任务标签定义；输出的 Mask 集合仍需对重叠、背景和实例身份做相应处理。
2022关键节点

Mask2Former · Masked Attention 原论文 ↗

在 Mask Classification 框架上采用 Masked Attention，使查询聚焦于预测的 Mask 区域；同一架构覆盖 Semantic、Instance 和 Panoptic。

条件 / 边界 “统一”指架构可适配任务，不等于单套固定权重天然识别任意类别；小目标、边界和训练域问题仍然存在。
读到这里： Mask2Former 的关键价值是分割表示与架构统一，不等于“通用提示式分割”。它仍然和 SAM 所研究的“用提示指定目标”属于不同维度。
05
INTERACTIVE / 人参与分割

从交互式修正到可提示分割：RITM 与 SAM

在工业标注、图像编辑或机器人系统里，有时目标是谁已经明确了：用户点了一下，或者上游检测器给出一个框。此时还需要模型自己重新推断所有类别吗？交互式分割把外部输入当成有价值的条件。

经典 GrabCut 已经可以利用粗框与颜色模型优化前景；它属于 A01 的传统优化分割。学习式交互分割则进一步研究怎样理解点击、如何利用前一次的 Mask，以及怎样减少用户反复修正的次数。

2021交互分割节点

RITM · Iterative Mask Guidance 原论文 ↗

将前一轮分割 Mask 与新的点击一起作为输入，通过反复前向推理完成修正，不必在每次推理时都进行额外的反向优化。

条件 / 边界 依赖点击质量与训练数据分布；少量点击可能仍无法解决复杂边界或目标歧义。
2023关键节点

SAM · Promptable Segmentation 原论文 ↗

结合 Image Encoder、Prompt Encoder、Mask Decoder，利用 Points、Boxes、Masks 等空间提示生成 Mask；通过 SA-1B 数据引擎扩大泛化范围。

条件 / 边界 提示可能对应整个物体、子部件或邻近实例，故可预测多个候选 Mask；通用性不等于对任意细结构和特定域都有可靠表现。

SAM 值得单独深入的不只是模型结构，还有它的任务定义与数据引擎：先建立可提示的标注与预测循环，再用大规模 Mask 数据推动模型泛化。这是能力来源的重要组成部分。

容易混淆的地方

原版 SAM 论文探索过文本提示的可能性，但公开使用中最稳定、最典型的是点、框和 Mask 等空间提示。不要把它与 SAM 3 面向开放概念短语的全实例分割能力视为相同任务。

06
VIDEO & CONCEPT / 提示能力扩展

SAM 2 和 SAM 3：变化不只是 Mask 精度

SAM 已经能够在一张图像里根据空间提示获得区域。如果输入是一段视频，希望同一目标持续被分割，就需要处理时间信息、遮挡与重新出现；如果连目标位置都没给，只给出一个语义概念，模型还需要先决定哪些实例符合描述。

2024关键节点

SAM 2 · 图像与视频统一的可提示分割 原论文 ↗

引入流式记忆和时序传播机制，支持利用交互提示处理图像与视频；在视频中追踪已指定目标并传播 Mask。

条件 / 边界 记忆可以利用历史观测，也可能受到跟踪漂移、遮挡和目标变化影响；静态图像任务不必因为年份较新就强制替换 SAM。
2025关键节点

SAM 3 · Promptable Concept Segmentation 原论文 ↗

根据短文本概念或图像示例等提示，在图像/视频中检测、分割和追踪所有匹配实例；引入概念存在判断及检测、跟踪结合的结构。

条件 / 边界 短语概念匹配不等于任意复杂任务推理；同义词歧义、相近概念区分、罕见物体与小目标仍需验证。
读到这里： 如果已由 A03 检测得到正确 BBOX，SAM / SAM 2 可能足够完成静态目标分割；如果还需要通过文字寻找所有符合概念的实例，才真正涉及 SAM 3 这类新任务。
07
EFFICIENCY / 效率路线

小模型不只是缩小参数：FastSAM、MobileSAM、EfficientSAM

高质量提示式分割往往包括较重的图像编码。实际部署时，不仅要比较整体 FLOPs，还要看是否可以复用图像编码、多次 Prompt 的边际成本、显存和硬件算子支持。轻量化方法采用的思路并不相同。

2023高效化路线

FastSAM · 基于实时分割框架的提示式接口 原论文 ↗

以全实例分割候选为基础，结合后续的提示选择过程构建快速 Segment Anything 风格系统；与原版 SAM 的 Image/Prompt Encoder 架构并不相同。

条件 / 边界 候选 Mask 的质量与召回限制了后续提示选择效果；不要因名称相似就假定两者具有相同的泛化能力。
2023高效化路线

MobileSAM · 轻量图像编码器 原论文 ↗

通过蒸馏等方式获得更轻量的图像编码端，保留与 SAM 风格的提示解码接口相近的结构。

条件 / 边界 更小不保证任意域效果一致；要评估小物体、细边界、低对比度场景及真实设备耗时。
2023 / 2024高效化路线

EfficientSAM · 高效可提示分割训练 原论文 ↗

通过有效的特征预训练与轻量模型设计，探索较低计算代价下的提示式分割能力。

条件 / 边界 压缩和蒸馏通常存在精度与泛化权衡，实际性能还取决于 Prompt 类型和输入分辨率。
图像编码只执行一次

对于同一帧上多次点击/多个提示，能否复用图像特征，会直接影响交互时延。

完整系统延迟

视频解码、预处理、上采样、后处理、数据传输和实际分割调用都应计入，而不是只看网络一次前向。

不宜直接横向排名

FastSAM、MobileSAM、EfficientSAM 不共享完全一致的训练任务、数据分布和模型机制；只有在同样输入、Prompt、硬件、精度与后处理条件下，速度/质量对照才有意义。

08
EVALUATION / 分割怎么评估

Mask IoU、Instance AP、PQ 与交互次数，不是一种指标

研究到这里，已经可以看到同样叫 segmentation，论文评价目标可能完全不同。把数值直接放在同一列，会制造看似精确、实际不成立的比较。

指标常见任务需要注意什么
mIoU / Pixel Accuracy语义分割衡量像素类别吻合程度；同类实例错分开通常不单独计入实例错误。
Mask AP / AP50 / AP75实例分割需要匹配实例并考察 Mask IoU；与 BBOX AP 不可直接互换。
PQ（Panoptic Quality）全景分割联合考察区域匹配质量与识别质量，按 Things / Stuff 的任务定义评估。
Boundary F-score / Boundary IoU边界敏感任务对细薄结构、接触边界更敏感；但不是所有实际任务都把边界作为同等目标。
NoC / IoU-vs-click交互式分割在指定质量阈值下需要多少次修正，以及响应延迟。
概念召回 / 实例精度开放概念分割概念是否正确、目标实例是否完整检出，不能只看单个 Mask 的 IoU。

例如两个瓶子相互接触时，模型可以把整块 bottle 像素分类得很准确，却错误地合并为一个实例。此时语义 IoU 与实例 AP 可能给出截然不同的判断。另一方面，对于机器人的深度点云提取，边界是否混入地面、目标 Mask 内有多少有效 Depth，也不一定能由公开数据集的分割指标表达。

09
ENGINEERING / 学术与工业

从论文模型到可长期使用的分割模块

在真实系统里，Mask 不是终点，而是某个模块的输入。对于图像处理、工业测量或 RGB-D 抓取，选型必须考虑目标是否能稳定指定、实例能否被正确分开、输出是否与深度图对齐。

场景条件可以研究的技术路线最需要验证的事项
固定类别、有充分 Mask 标注Mask R-CNN / CondInst / YOLO-Seg新实例覆盖、遮挡、吞吐与长期误检
只需像素类别与场景结构FCN / U-Net / DeepLab / Mask2Former类别边界、背景标注、全局一致性
目标位置已有 BBOX / PointSAM / SAM 2 / EfficientSAM提示歧义、候选选择、细小结构与端到端耗时
开放短语或示例指定目标SAM 3 / Grounding + 分割概念匹配召回、相近物体区分、未知类别性能
多次提示或资源受限部署MobileSAM / FastSAM / 其他轻量实现准确率–延迟权衡、编码复用、算子兼容
RGB-D 几何提取实例 Mask + 有效 Depth 筛选RGB-Depth 对齐、深度空洞与边界混合

OpenCV 常承担 Mask 的形态学修正与后处理；Detectron2、MMDetection、Ultralytics 等提供训练和推理生态；Meta 官方 SAM 系列则提供提示式和概念分割能力的基线。框架是否好用与算法是否适用是不同维度，应当分别记录。

分割准确不等于几何可靠

一个完美的 RGB Mask 可以落在完全缺少有效深度的透明表面上。模型既没有计算出深度，也没有自动恢复真实三维几何。A04 与 Q01/Q04 的接口，是可信的目标像素集合，而不是直接的 Grasp Pose。

10
COMPARISON / 技术差异

用一张表回看：这些里程碑究竟改变了什么？

关键节点技术上的真正变化何时值得保留
FCN / U-Net像素密集预测与语义/空间特征融合目标类别固定、需要像素语义与边界
Mask R-CNN显式实例候选 + RoI Mask Head类别明确、要求分开各个实例
YOLACT / SOLO / CondInst共享原型、位置实例化、动态 Mask 函数对速度或实例 Mask 生成机制有特别要求
MaskFormer / Mask2FormerMask Classification 与统一分割架构想用类似的 Mask 表示覆盖多种分割任务
RITM利用连续点击与先前 Mask 修正分割标注、交互式微调或错误修正
SAM以空间提示指定目标进行泛化分割目标位置已知、希望降低固定类别依赖
SAM 2加入流式记忆与视频传播视频目标分割、跨帧连续性
SAM 3概念提示下的目标发现与实例 Mask类别开放、语义短语或示例指定多个实例
FastSAM / MobileSAM / EfficientSAM通过不同设计降低可提示分割成本真实硬件与任务允许一定效率/质量权衡

我更愿意把它们看作沿着不同限制生长出来的技术：有些优化 Mask 的表达方式，有些改变目标指定的接口，有些扩大任务覆盖，还有些专门处理实时性。技术的局限来自使用条件，而不是简单来自发表年份。

11
REFLECTION / 研究认识

学习分割的重点，已经不只是把边界画得更准

回看 A04，可以看到一条很清楚的变化：从像素分类，到实例级预测，再到统一 Mask 表示与可提示的分割能力。与此同时，实时实例分割和轻量可提示分割也一直在独立发展。

最值得留下的不是某个模型的排行榜，而是四个问题：分割结果表达什么？具体实例由谁确定？模型怎样生成 Mask？哪些数据和条件支撑了它的泛化？

对于目标类别稳定、标注充足的场景，专门训练的实例分割模型仍然很合理。对于已经明确指定目标框的任务，提示式分割可以减少针对每种物体单独训练的负担。对于需要通过语言或示例寻找未知类别实例的任务，概念分割又打开了另一扇门。

这些方案可以组合，也有各自的限制。最重要的仍是把 Mask 当作可验证的视觉观测，而不是把分割精度直接等同于下游操作成功率。

与下一篇附录的边界

A04 已经涉及 SAM 3 的概念提示，但这里主要研究 Mask 生成与分割任务的变化。文本定位、开放词汇检测、VLM Grounding 的完整发展放在 未来的 A05 · 开放词汇定位与 Grounding；该附录尚未创建，目前先保留 Q03 中的研究入口。
