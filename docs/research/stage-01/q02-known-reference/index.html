01 / TAKEAWAYS

先说结论：有参考，不代表对应关系会自己出现

Q02 研究到最后，最有用的不是记住 PnP、ICP、PPF，而是知道它们为什么会在不同条件下出现。

从 Q01 走过来，我原以为只要拿到 CAD，6D Pose 就能方便地算出来。后来发现：已知参考解决的是“物体结构是什么”，但没有自动解决“现在看见的是参考中的哪一部分”。

01 / MATCHES可靠对应 → 直接求变换

同名 3D–2D 或 3D–3D 点已知时，求 R、t 有明确约束；代价在于对应本身必须可信。

02 / SEARCH对应未知 → 寻找匹配

利用点对几何、局部特征或模型投影建立候选；减少人工给对应的要求，却转移到搜索、辨识性与歧义。

03 / REFINEMENT粗略初值 → 局部精化

已有候选时可降低匹配残差；但优化收敛不能证明找对了全局位置。

最重要的判断：已知参考不是一种万能方法，而是给求解引入了新的信息来源；真正的路线差异在于如何把它与当前观测建立关系。
02 / ROUTE MAP

先看完整技术关系：谁在提供约束，谁在寻找对应？

把“参考信息的类型”“观测形式”“对应/匹配机制”“局部精化”分开理解，才不会把 CAD 与 ICP 画成同层级的算法。

03 / FIRST QUESTION

到底“已知”了什么？这一点往往被跳过

有尺寸、四个参考角点、完整 CAD，是不同条件；它们并不会自动提供当前 Pose。

以一个长宽高已知、带非对称小孔的盒体为例：如果只知道外形尺寸，可以把形状参数写下来，却无法从尺寸本身知道它在相机下的位姿。如果还知道四个角点在物体参考坐标系的坐标，便可以尝试在图像中找到同名点。如果知道完整 CAD，则可以进一步利用表面与渲染预测，但需要处理模型与现场匹配的问题。

已知参考： Pᵢ in Object Frame
目标未知： camera_T_object = [R | t]
现场证据： uᵢ、Qᵢ、可见表面、轮廓……

同一组 R、t 可以由不同的约束求出，但不是“参考越完整，就必然越容易求”。对某些对象，清楚的四个同名点，比无法稳定区分的完整 CAD 更容易利用。

04 / REPRESENTATIVE WORK

代表方案 A：对应点准备好，就让投影几何求 Pose

从真实可使用的 OpenCV PnP / IPPE 开始，把三维坐标、二维像素、内参和输出变换一次讲清楚。

假设盒体一个矩形面的四角点已经在 RGB 图像中准确找到，四个角点在物体坐标系下的 3D 坐标也已知。此时不必先重建整片目标点云：可以寻找一个姿态，使这四个模型点投影到对应像素。

CASE 01 · REPRESENTATIVE METHOD成熟求解族

OpenCV PnP / IPPE：已知对应时直接求 R、t

代表来源：OpenCV · Perspective-n-Point & IPPE ↗

这是 3D–2D 对应下位姿求解的经典工程入口。对于同一平面上的四个角点，IPPE 可处理平面情况并给出待比较的候选；具体结果还需结合重投影误差、正深度等条件。

实际求解链 · 从输入到输出
01 · 参考给出四个物体坐标系下的 3D 点 Pᵢ
02 · 观测给出同名像素 uᵢ 与相机内参 K
03 · 求解让投影 K(RPᵢ+t) 与像素尽量一致
04 · 验证检查候选解、误差、坐标系及物理合理性

获得了什么

不需要每个关键点都拥有有效深度，可以直接利用已知三维结构与二维图像关系获得 Object Pose。

为此付出的代价

依赖参考点身份正确、像素定位精度和相机标定；共面与近正视角会带来候选歧义和数值敏感性。

区分原论文与工程借鉴：这里是代表性的 PnP/IPPE 解法，不是自动角点检测系统。对应点需要通过外部检测、几何规则或人工标记建立。
读完留下的判断：对应清楚时，优先把求解当成投影几何问题，复杂 CAD 匹配未必必要。

如果每个角点的深度也可靠呢？

把像素反投影成相机系三维点 Qᵢ，就转为已知 3D–3D 对应的刚体配准，可利用 Kabsch/SVD 估计旋转和平移。多了深度，不代表一定更准：边缘混合像素、反光或缺失深度，会把问题从像素定位误差换成空间测量误差。

3D–2D：uᵢ ~ K(RPᵢ + t)
3D–3D：Qᵢ ≈ RPᵢ + t
05 / REPRESENTATIVE WORK

代表方案 B：没有同名点，怎样从 CAD 与现场点云里找它？

Drost 等人（CVPR 2010）的 PPF，把问题转成“模型里哪些点对关系也出现在现场”。

上一节简单，是因为我们提前知道了四个角点的身份。可是大量无纹理工业件并没有容易识别的角点。现在给一份完整 CAD 和部分现场点云，谁对应谁仍是未知的。

CASE 02 · REPRESENTATIVE METHODCVPR 2010

Drost PPF：用模型点对几何投票寻找姿态

代表来源：Drost et al. · Model Globally, Match Locally ↗

模型阶段建立带法线的点对特征描述；现场点云中寻找类似几何关系，并在适当的姿态参数空间中投票形成候选，再对候选进行聚合与检验。它针对的是未知初始姿态的三维物体识别与定位。

实际求解链 · 从输入到输出
01 · 离线准备从模型表面采样带法线点，建立点对特征
02 · 现场提取获得场景表面点与法线
03 · 匹配投票用相似点对关系为姿态候选投票
04 · 聚合验证筛选、聚合候选并检查与观测一致性

获得了什么

不必预先给出四个同名角点或准确初值，能利用部分可见的几何结构寻找候选 6D Pose。

为此付出的代价

增加模型特征预处理、现场法线质量与匹配/投票开销；对称结构、重复局部几何可能生成多个候选。

区分原论文与工程借鉴：PPF 并不等同于 ICP，也不是从对应点求变换的 PnP；它首先需要解决“匹配在哪里”的问题。
读完留下的判断：参考与现场有可区分的三维几何、但对应未知时，几何全局搜索是一条有价值的路线。

这里的“后来的算法比 PnP 强”并不成立。PnP 在已经有可靠对应时更直接；PPF 只是愿意承担模型特征与匹配搜索成本，换取“不必预先指定同名点”的能力。

06 / COMPLETE PIPELINE

代表方案 C：先全局定位，再局部精化

Open3D 的官方教程给出了很清楚的组合范式，它不是新算法发明，而是可复现的工程求解链。

CASE 03 · REPRESENTATIVE METHODOpen3D 官方流程

FPFH + RANSAC → Point-to-Plane ICP

代表来源：Open3D · Global Registration Tutorial ↗

教程先对两组点云进行下采样、法线与 FPFH 特征估计，再通过 RANSAC 搜索粗配准；随后用 Point-to-Plane ICP 在已有粗初值下进行细化。这样把不同优化范围的任务分开。

实际求解链 · 从输入到输出
01 · 特征准备下采样、法线、FPFH 局部描述
02 · 全局粗对齐匹配候选对应，并用 RANSAC 拒绝假配对
03 · 局部精化以粗位姿为初值做 Point-to-Plane ICP
04 · 质量检查评估可见重叠、残差与姿态合理性

获得了什么

在初始姿态未知时先获得一个可能正确的粗解，再利用局部点面约束提高对齐精度。

为此付出的代价

全局阶段依赖局部特征与采样；增加运行开销。ICP 又依赖粗解合理，错误候选也可能精化到错误的局部最优。

区分原论文与工程借鉴：Open3D 教程示例是一般点云配准；应用到“完整 CAD 采样点云 vs 单视角部分点云”时，需要额外处理可见性、重叠度与对称性，不能照抄教程阈值就假设能用。
读完留下的判断：“找到大概位置”和“把位置对得更准”是两个不同问题，先粗后精是常见但非唯一的组合策略。
PPF 与 FPFH + RANSAC 之间，也不是严格的历史继承。它们是全局几何匹配的不同组织方式；ICP 主要承担局部精化。是否组合，取决于场景与时间预算。
07 / REPRESENTATIVE WORK

代表方案 D：为什么非得用三维点云匹配？

当深度不可靠而轮廓、梯度或表面特征可辨时，参考模型可以在图像空间发挥作用。

CASE 04 · REPRESENTATIVE METHODECCV 2012

LINEMOD：用视角模板匹配无纹理物体

代表来源：Hinterstoisser et al. · Model-Based Detection / LINEMOD ↗

这类经典研究利用多视角模板的图像梯度与深度法线等信息来检测、识别并估计无纹理刚体的姿态。模板可以离线准备，后续在当前图像中搜索相似的观测特征。

实际求解链 · 从输入到输出
01 · 离线准备围绕参考对象准备不同姿态的视角模板
02 · 特征表示记录图像梯度与表面法线等模板线索
03 · 在线匹配在当前 RGB-D 观测中查找相似模板
04 · 回收姿态由匹配视角得到候选位姿并做验证

获得了什么

把一部分三维几何任务转到图像观察空间，适用于某些纹理少但轮廓/法线线索清晰的物体。

为此付出的代价

需要视角模板库和覆盖范围；物体遮挡、轮廓相似、相机条件变化与模板密度会带来额外成本和姿态量化问题。

区分原论文与工程借鉴：此处强调 LINEMOD 的代表思想，不等同于“给任意 CAD 就自动从单张 RGB 照片精确恢复任意尺度的 Pose”；模板与尺度/参考视角必须明确。
读完留下的判断：深度几何不稳定时，图像投影和模板特征仍可能提供有价值的姿态证据。

因此，三维表面匹配与二维投影匹配不必被理解为谁淘汰了谁。它们在使用不同的观测证据：一种依赖深度几何，另一种让模型外观与当前图像相互解释。

08 / MODERN METHOD

代表方案 E：学习式方法改变了哪部分代价？

FoundationPose（CVPR 2024）代表了模型条件化下通过候选、学习评分与精化进行位姿估计的现代路线。

CASE 05 · REPRESENTATIVE METHODCVPR 2024

FoundationPose（CAD 模式）：候选 → 精化 → 评分

代表来源：Wen et al. · FoundationPose 官方论文与实现 ↗

在提供 CAD 的演示设置中，系统使用 RGB、Depth、相机 K、目标 Mask 以及三维模型；根据 Mask/深度估计中心、生成多姿态假设，然后通过学习式 refine 与 score 模块处理候选，返回姿态。

实际求解链 · 从输入到输出
01 · 参考与观测CAD mesh + RGB-D + K + 目标 Mask
02 · 初始化利用 Mask/深度估平移并生成候选旋转
03 · 学习精化对姿态候选进行多次 Refiner 处理
04 · 评分选择ScorePredictor 排序，输出位姿

获得了什么

能在提供模型和合理观测的条件下，用训练得到的匹配/评分能力减少手工设计某些对应规则的负担。

为此付出的代价

引入权重、GPU 资源、渲染环境、数据域差与目标 Mask 质量等工程依赖；没有可靠目标观测时，也无法无限制地推断姿态。

区分原论文与工程借鉴：这里仅讨论符合 Q02 边界的 CAD 模式。原论文也包含基于参考图像的设置，但涉及另行准备物体表示，本篇不引入那条建模分支。
读完留下的判断：它不是“无需参考或无需约束”的替代品，而是把一部分匹配判断交给学习式评分与精化，支付训练与部署成本。

这里我真正想比较的，并不是“深度学习是不是更高级”，而是：当人工几何匹配与手工特征不足以满足要求时，是否值得用模型训练、运行依赖与域泛化风险，换取更强的候选判别能力？

09 / OBSERVABILITY

还有一类代价：更多计算根本无法解决的信息缺失

即使 CAD 完整、优化收敛，也可能没有足够可见证据区分所有姿态。

一个没有可区分纹理的理想圆柱，绕其轴旋转仍得到相同几何观测；一个重复结构工件可能出现多个局部匹配候选；单视角只能看到一面时，背面关键结构不会自动变成传感器观测。这里的困难部分来自物体结构与信息可观测性。

误差小，不一定说明 Pose 真实正确。例如某个错误姿态恰好与局部可见表面对齐，也能取得很好的残差。需要查看候选一致性、姿态对称等价、可见区域和抓取目标对误差的敏感度。

10 / TRADE-OFFS

现在来讨论：不同求解路线用什么换来了什么？

这才是 Q02 的核心总结。把代价放在路线层级，而不是写成每个工具的简单优缺点。

路线主要获得的能力新增依赖与成本边界 / 失效机制
参数化参考约束利用已知形状/尺度减少未知量物体真实形状需符合已知参数化描述形变、遮挡、对称造成可用约束不足
明确对应求解已知 3D–2D / 3D–3D 对应时直接求变换要先准备准确、可辨认的对应与相机标定错配、共面/共线退化、深度噪声
三维全局匹配无需人为指定所有同名点与精确初值模型特征、法线、候选搜索与验证开销重复几何、对称、部分重叠造成多候选或误匹配
三维局部精化在已有近似 Pose 时细化几何对齐合理初始化与足够表面重叠局部极小值、虚假的低残差
二维模板 / 投影利用图像轮廓与外观证据弥补部分深度不足相机参数、模板覆盖或渲染描述遮挡、视角外推、轮廓相似
学习式候选与精化通过训练减少部分手工匹配判据模型权重、数据分布、推理算力及软件栈域偏移、Mask 错误、模型/实物不一致

需要强调：上面各路线不是互斥。甚至同一条系统里可能出现“图像定位 + PPF 粗位姿 + ICP 精配准 + 学习模型重评分”。路线级代价分析，不是要求必须二选一，而是弄清每多依赖一个模块究竟换来了什么。

对照 Q01：Q01 尽可能依靠现场几何，但受可见结构限制；Q02 引入参考，能够把缺失的结构作为先验使用，却必须承担模型一致性和跨坐标系匹配的代价。
11 / ENGINEERING JUDGMENT

真正拿到一个物体，我会先检查什么？

这里才把了解过的代表方案，转化为真实工程中的技术选择。

01 / CORRESPONDENCE READY四个角点已知且可见

先考虑 PnP/IPPE；有可靠深度也可比较 3D–3D。没有必要为了“有 CAD”就默认采用复杂全局配准。

02 / GOOD INITIAL POSECAD + 点云，已有初值

可以先尝试 ICP/GICP 精化。重点检查实际可见部分的重叠，不以算法收敛作为唯一成功标准。

03 / NO INITIAL POSECAD + 点云，初值完全未知

全局特征匹配或 PPF 更符合问题条件；后续仍可以通过局部配准精化与验证。

04 / IMAGE STRONGERCAD + 清晰轮廓，深度较差

考虑图像轮廓/模板/投影约束。若希望引入学习评分，则必须评估模型、Mask、显存与域差成本。

将来做实验，我会重点验证的事情

  • 相同物体：可靠角点 + PnP 与 CAD + 点云匹配，谁在实际相机噪声下更稳定？
  • 全局配准提供的初值，落在 ICP 合理收敛范围内的比例是多少？
  • 对称物体的等价 Pose 是否真正影响最终抓手姿态，还是只影响评价方式？
  • 学习式方案带来的鲁棒性提升，能否抵消权重、部署、推理与维护成本？
12 / FIELD NOTES

把这些方法串起来，我终于理解“已知参考”做了什么

已知 CAD 不是 Pose 的答案。它只是让我们有机会用更多结构解释当前观测。

原来我们总在交换两件事：已知信息与匹配成本。

对应已经可靠时，可以直接求空间变换；对应未知时，需要利用几何特征、模板或投影搜索姿态；已经接近正确位置时，局部精化才发挥作用；需要学习式评分时，又引入训练与部署的额外代价。

研究了代表方案之后，我不再把 PnP、ICP、PPF 和 FoundationPose 当成同一种输入问题的竞争者。它们解决了不同前提下的困难，能够组合，并且都有各自需要支付的代价。

现在更愿意先问：参考里有什么？观测中真的看到了什么？两者之间的约束能否被可靠建立？

这里选的是足以解释技术路线分化的代表方法，不按发表时间强行串成单线历史。

A01｜PnP、Kabsch 与 RANSAC 不在同一层级
PnP 是 3D–2D 对应的位姿求解问题及方法族；Kabsch 求已知三维对应间的刚体变换；RANSAC 是处理异常对应的鲁棒估计策略，可用于多种模型。不要画成“旧 → 新”的简单替代。
A02｜PPF、FPFH 与 ICP 的职责区别
PPF 和 FPFH + RANSAC 是不同组织的全局候选匹配思路；ICP 在已有合理初值附近通过当前对应迭代优化。相近发表年份或同时出现在一个流程中不代表存在直接技术继承。
A03｜学习式方法到底学习哪一步？
有的预测关键点或规范坐标，有的产生初始姿态，有的负责渲染与观测一致性评分，也有直接输出 Pose 的路线。判断学习方法是否值得使用，应看它消除了哪些手工前提，又增加哪些训练与部署依赖。
A04｜位姿对称性与抓取等价
完整 Object Pose 在对称观测下可能存在多个等价解。若这些候选经预设 object_T_grasp 转换后的夹爪姿态不同，仍需验证任务是否等价；不能只凭 Object Pose 数值差异判定抓取好坏。
