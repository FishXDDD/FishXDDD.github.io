00 / 一旦知道了点对应

不必先认出整个表面，
也有机会恢复完整姿态。

在 Q01，我尝试过只根据可见点云去估计位置、方向与局部几何。现在多了一份已知参考：物体上的几个点，在 Object Frame 中有确定坐标；相机里，也已经知道它们分别落在哪里。

这次先不研究对应是怎样找出来的。只接受一个前提：第 i 个参考点对应的，确实是第 i 个现场观测。剩下的是一个明确的刚体变换求解问题：

目标变换 · OBJECT → CAMERA\[{}^{C}T_O=\begin{bmatrix}R&t\\0&1\end{bmatrix},\qquad R\in SO(3),\quad t\in\mathbb R^3\]

这里的 R 表示旋转，t 表示物体原点在相机坐标系下的位置。按列向量约定，任意参考点都满足 \(P^C=RP^O+t\)。

01 / 3D–2D · 投影约束

只有像素对应，
为什么也能反推出三维 Pose？

P3P · EPnP · IPPE · ITERATIVE

1.1｜先把 PnP 的输入、输出写清楚

先拿一个盒子可见面的四个角点做例子。参考中知道每个角点的三维坐标 \(P_i^O=[X_i,Y_i,Z_i]^T\)，图像中则知道它对应的像素 \(u_i=[u_i,v_i]^T\)。相机的内参 \(K\) 已经标定。

如果已经知道 Pose，可以把三维点投影到图像上；现在反过来寻找一个 Pose，使预测像素与真实像素尽量一致。

参考点变换到相机坐标\[\begin{bmatrix}X_i^C\\Y_i^C\\Z_i^C\end{bmatrix}=RP_i^O+t\]
针孔投影 · 下式假定坐标已去畸变\[\hat u_i=f_x\frac{X_i^C}{Z_i^C}+c_x,\qquad\hat v_i=f_y\frac{Y_i^C}{Z_i^C}+c_y\]
重投影误差 / REPROJECTION ERROR\[E(R,t)=\sum_{i=1}^{N}\left\|\mathbf u_i-\pi\!\left(K(RP_i^O+t)\right)\right\|_2^2\]

其中 \(\pi\) 包含透视除法。计算误差时，如果使用原始畸变图像，还必须在预测中正确处理畸变。PnP 要寻找的，就是能够解释这些像素观测的旋转和平移。

换一个几何直觉：已标定相机中的每个像素，对应从相机光心出发的一条空间射线。未知三维点经过刚体变换后，应当落在对应射线上。单个点约束有限，多条射线和已知的参考点间距离共同形成 Pose 约束。由于参考点具有公制坐标，位姿平移也可带有公制尺度。

1.2｜三个点够了吗？——P3P

如果对应点很少，最自然的想法是先研究最小约束。P3P（Perspective-Three-Point）使用三个已知参考三维点与三条相机射线，利用参考三角形的边长、相机射线的夹角，反推出三角形在相机前方的空间位置。

两条射线上的余弦定理\[d_{12}^{\,2}=r_1^2+r_2^2-2r_1r_2\cos\theta_{12}\]

\(d_{12}\)：模型中两点距离；\(r_1,r_2\)：沿射线到相机的未知距离；\(\theta_{12}\)：两条归一化射线间的已知夹角。

三个点提供三组这样的几何关系。然而，满足这些方程的姿态不一定只有一个：P3P 在一般构型下可能产生多个候选解，最多可达四个。额外对应点或任务约束通常被用于区分解。

实现细节：OpenCV 的 solvePnP 在使用 SOLVEPNP_P3P、SOLVEPNP_AP3P 选项时，通常以四组输入对应点来选择解；不要将“P3P 的最小几何问题是三点”和“某个 API 必须传几组点”混为一谈。

第一层认识：方程数量看起来够了，不代表姿态必定唯一。需要区分“存在解”“有多个解”和“某个解在噪声下是否稳定”。

1.3｜对应点更多时——EPnP 与迭代优化

如果有十几个甚至几十个准确对应点，求解器可以利用冗余约束。EPnP（Efficient PnP）是一条代表性路线：不是把每个点的相机坐标都独立求出来，而是用少量虚拟控制点表示所有参考点。

EPnP 的控制点表示 · 一般三维参考点集\[P_i^O=\sum_{j=1}^{4}\alpha_{ij}C_j^O,\qquad P_i^C=\sum_{j=1}^{4}\alpha_{ij}C_j^C\]

这里 \(\alpha_{ij}\) 是由参考几何确定的仿射组合系数。刚体变换保持这类组合关系，于是大量点的投影约束可以转化为少量控制点坐标的求解，再恢复整体 Pose。

EPnP 的意义在于高效构造初始姿态。而使用全部观测最小化重投影误差的非线性优化，例如 Gauss–Newton / Levenberg–Marquardt，又是一类有代表性的精化办法。两者经常被组合：先求一个合理初值，再减小像素误差。

但要清楚，局部优化只在初值附近寻找更好的解，不能自动消除错误初值或全部姿态歧义。

1.4｜如果四个角点都在一个平面？——IPPE

盒子的单个可见面、标签、平面标记，都很容易得到共面的 3D–2D 对应。共面点不是一概不能做 PnP，而是它们具有特殊的投影结构。

当参考平面定义为 \(Z=0\) 时：

平面到图像的单应关系\[s\begin{bmatrix}u\\v\\1\end{bmatrix}=K\begin{bmatrix}r_1&r_2&t\end{bmatrix}\begin{bmatrix}X\\Y\\1\end{bmatrix},\qquad H\sim K[r_1\ r_2\ t]\]

这里 \(H\) 是平面到图像的 Homography，\(r_1,r_2\) 是旋转矩阵的前两列。从已标定的投影关系和旋转的正交约束中，可以恢复平面姿态候选。

IPPE（Infinitesimal Plane-Based Pose Estimation）专门研究平面位姿。它能返回两个姿态候选，并比较其重投影误差。特别是在平面投影接近仿射的情况下，两个姿态可能给出非常相近的图像解释。

这一节真正的代价：点数与精度不是唯一问题。参考点是否共面、是否近共线、投影是否足以区分不同姿态，同样决定了求解的可靠性。

1.5｜OpenCV 最简实现：给四个平面角点求 Pose

Python · cv2.solvePnP / IPPE
import cv2
import numpy as np

# 示例：Object Frame 中同一矩形面的四角，单位米
W, H = 0.12, 0.08
object_pts = np.array([
    [-W/2, -H/2, 0.0],
    [ W/2, -H/2, 0.0],
    [ W/2,  H/2, 0.0],
    [-W/2,  H/2, 0.0],
], dtype=np.float64)

# 现场真实检测/人工标注的同名像素，按上面顺序填写
image_pts = np.array([
    [512.0, 290.0],
    [684.0, 300.0],
    [677.0, 418.0],
    [519.0, 406.0],
], dtype=np.float64)

# 示例内参；实际应用必须换成当前相机标定值
K = np.array([
    [900.0, 0.0, 640.0],
    [0.0, 900.0, 360.0],
    [0.0, 0.0, 1.0],
], dtype=np.float64)
D = np.zeros(5, dtype=np.float64)  # 仅当图像已去畸变时适用

# IPPE 适用于共面点；返回两组可能的位姿解
n, rvecs, tvecs, errors = cv2.solvePnPGeneric(
    object_pts, image_pts, K, D,
    flags=cv2.SOLVEPNP_IPPE,
)
if n == 0:
    raise RuntimeError("没有找到有效的平面位姿候选")

for i, (rvec, tvec) in enumerate(zip(rvecs, tvecs)):
    R, _ = cv2.Rodrigues(rvec)
    T_C_O = np.eye(4)
    T_C_O[:3, :3] = R
    T_C_O[:3, 3] = tvec.reshape(3)

    projected, _ = cv2.projectPoints(
        object_pts, rvec, tvec, K, D)
    pixel_err = np.linalg.norm(
        projected.reshape(-1, 2) - image_pts, axis=1)
    print(i, "RMSE(px)=", np.sqrt(np.mean(pixel_err**2)))
    print(T_C_O)

# 此处只是示例数值。图像点、物体尺寸、相机内参
# 都必须替换为同一个真实标定与观测场景的数据。

这段代码展示输入输出约定，不是经过真实数据验证的抓取 Pose。平面候选应结合误差、物体朝向、可见性与任务约束共同判断。对象角点顺序与图像角点顺序必须严格一致。

02 / 3D–3D · 空间刚体约束

如果深度也可靠，
为什么还要投影回图像？

KABSCH · SVD · RIGID ALIGNMENT

2.1｜从像素反投影到三维

对于已与 RGB 对齐的可靠深度测量，可以把对应像素反投影到相机坐标系。这里 \(Z_i\) 指相机光轴方向的深度，而不是三维欧氏距离：

反投影 · 无畸变的针孔模型\[P_i^C=Z_i\begin{bmatrix}(u_i-c_x)/f_x\\(v_i-c_y)/f_y\\1\end{bmatrix}\]

于是每组对应变成 \(P_i^O\leftrightarrow P_i^C\)。这时求解的不是像素误差，而是两组三维点之间的刚体对齐。

刚体最小二乘目标\[\min_{R\in SO(3),\,t\in\mathbb R^3}\sum_i\left\|RP_i^O+t-P_i^C\right\|_2^2\]

在这条路线中，当前深度是输入证据。它有用，但如果深度来自透明表面、反光表面或物体边界的错误测量，三维约束反而可能比准确的二维关键点更差。

2.2｜为什么 SVD 可以求出旋转？——Kabsch

这套算法真正优雅的地方在于：先移除平移，再利用两组点之间的相对空间结构恢复旋转。

1

分别求中心。同名点的两个中心决定平移关系的一部分。

\[\bar P=\frac1N\sum_iP_i^O,\qquad\bar Q=\frac1N\sum_iP_i^C\]
2

两组点分别中心化。用 \(p_i=P_i^O-\bar P\)、\(q_i=P_i^C-\bar Q\) 消去整体平移。

3

建立互协方差并进行 SVD。在这份笔记的列向量约定下，取 \(H=\sum_i p_iq_i^T\)，再做 \(H=U\Sigma V^T\)。

最优正交刚体旋转 · 排除镜像反射\[R=V\operatorname{diag}\!\bigl(1,1,\det(VU^T)\bigr)U^T\]
4

将中心移回去。已经知道旋转，平移由两组中心直接恢复：

\[t=\bar Q-R\bar P\]

之所以需要 \(\det(VU^T)\) 这一项，是因为正交矩阵可能包含镜像反射。机器人刚体旋转必须满足 \(R^TR=I\)、\(\det(R)=+1\)，不能把反射误认为旋转。

一点重要的退化判断：对已知对应的 3D–3D 刚体配准，三个互不共线的三维点在无噪声时足以唯一确定一般刚体变换。四个点共面并不必然退化；但点全部共线时，绕该直线的旋转无法唯一确定。

2.3｜能直接运行的 NumPy 实现

Python · Kabsch / Object → Camera
import numpy as np


def kabsch(P, Q):
    """P: Object Nx3, Q: Camera Nx3, 每行是同名点。"""
    P = np.asarray(P, dtype=np.float64)
    Q = np.asarray(Q, dtype=np.float64)

    if P.shape != Q.shape or P.ndim != 2 or P.shape[1] != 3:
        raise ValueError("P 和 Q 必须是形状一致的 Nx3 数组")
    if len(P) < 3 or not np.isfinite(P).all() or not np.isfinite(Q).all():
        raise ValueError("至少需要三个有限的三维对应点")

    cp, cq = P.mean(axis=0), Q.mean(axis=0)
    X, Y = P - cp, Q - cq
    if np.linalg.matrix_rank(X) < 2:
        raise ValueError("参考点共线，旋转无法唯一确定")

    H = X.T @ Y
    U, S, Vt = np.linalg.svd(H)
    D = np.diag([1.0, 1.0, np.linalg.det(Vt.T @ U.T)])

    R = Vt.T @ D @ U.T
    t = cq - R @ cp

    return R, t


# 坐标约定：P_C = R @ P_O + t
# 最终可构造 T_C_O（Object → Camera）
# 检查：np.linalg.det(R) ≈ +1
# 验证：np.linalg.norm((R @ P.T).T + t - Q, axis=1)

与 PnP 相同，代码本身并不知道“谁是 Object、谁是 Camera”。传入参数的顺序决定返回变换方向。本例中求得的就是 \({}^{C}T_O\)，不是它的逆变换。

2.4｜为什么 3D–3D 未必比 PnP 更准确？

3D–3D 看起来提供了更多信息，但测量也引入了更多误差来源。深度噪声通常具有方向性，边缘像素容易发生深度混合，透明和反光表面可能直接缺失深度；RGB 与深度未对齐时，还会产生系统性误差。

一个二维角点可以在图像上清楚可见，却不一定拥有准确深度。强行把错误的深度反投影成三维坐标，可能比直接用可靠的二维角点求 PnP 更差。

第二层认识：多一个观测维度并不自动换来更高精度。真正决定效果的，是被拿来建立约束的观测是否可靠，以及采用的误差模型是否符合传感器特性。
03 / 错误对应与鲁棒估计

如果有几个对应点错了，
最小二乘还可信吗？

前面的 PnP 和 Kabsch 都假设对应点足够可靠。但现场可能出现关键点定位错误、点身份交换、错误深度或误匹配。若把它们全部放进平方误差目标，求解器会试图同时解释正确和错误的对应。

RANSAC 因而值得单独认识一次：它不是一个新的 Pose 几何模型，而是包裹在 PnP、三维刚体估计等最小求解器外面的鲁棒估计机制。

RANSAC 的基本动作
抽取最小样本 → 求候选姿态 → 计算所有对应残差 → 统计内点 → 重复抽样 → 利用内点重新估计。
PnP / 像素残差\[e_i^{2D}=\|\mathbf u_i-\hat{\mathbf u}_i(R,t)\|_2\]
3D–3D / 空间残差\[e_i^{3D}=\|P_i^C-(RP_i^O+t)\|_2\]

一个单位是像素，一个单位是米或毫米，因此阈值绝不能照搬。内点判断需要与测量噪声模型一致。

3.1｜为什么迭代次数会突然变得很多？

假设一个随机对应是内点的概率为 \(w\)，一次抽取 \(s\) 个样本。在独立、近似均匀抽样的假设下，一次全部抽到内点的概率约为 \(w^s\)。要让至少一次全内点抽样发生的概率达到 \(p\)，有：

经典 RANSAC 迭代估计\[N\geq\frac{\ln(1-p)}{\ln(1-w^s)}\]

例如，若 \(p=0.99\)、\(w=0.5\)、\(s=4\)，理想公式得到大约 72 次。实际工程中还需要考虑样本退化、内点率估计误差、重复解和计算预算。

当正确对应比例下降时，所需采样次数会迅速增加。这是 RANSAC 的一个真实计算代价，而不是把迭代次数设得越大越好。

第三层认识：RANSAC 提高了对一部分错误对应的容忍度，但若错误对应本身形成一致的几何解释，它仍可能稳定地输出错误 Pose。鲁棒估计不能代替可观测性或物体身份验证。
04 / 从求出姿态到信任姿态

求解器返回 success，
并不意味着抓取 Pose 已经正确。

拿到了旋转和平移之后，我反而需要开始认真检查这个答案究竟代表什么。单凭求解器返回成功，甚至单凭很小的优化残差，都无法排除几何退化、系统性测量误差或多解。

01 · 约束几何

点是否过于集中、近共线或共面？不同姿态在当前视角下是否可区分？

02 · 测量可信

像素、内参、畸变、深度、对齐和参考尺寸是否可靠？有无系统性偏差？

03 · 任务足够

投影误差小之外，恢复的抓取位置与方向是否满足预先约定的几何约束？

4.1｜对应点数量够了，为什么依然不稳定？

点都挤在同一个小区域，即使局部残差很小，旋转估计中的微小误差也可能在远处放大。近共线的空间点对于绕所在直线旋转尤其敏感；平面 3D–2D 观测则需要额外分析歧义，而 3D–3D 共面并不必然意味着刚体解不唯一。

同样地，对称或重复关键点可能让不同身份解释对应到不同 Pose。是否有足够独立的几何约束，比单纯统计点数更重要。

4.2｜数学误差小，真实姿态误差也一定小吗？

对 PnP 来说，关键点像素误差、相机内参和畸变参数、参考模型的实际尺度都会影响结果。对 3D–3D 来说，还要考虑深度测量的偏差、RGB-Depth 对齐以及坐标单位。

如果所有观测都朝同一个方向发生系统偏差，最小二乘依然可能给出很漂亮的残差。因此，误差要先用来验证模型能否解释测量，而不能直接当成真实 Pose 精度的证明。

4.3｜怎么做最基本的工程检查？

第一层：数值一致性。统计 PnP 重投影 RMSE、各点误差、RANSAC 内点数量/比例；对于 3D–3D，查看三维 RMSE 和异常残差分布。

第二层：空间合理性。验证 \(R^TR\approx I\)、\(\det R\approx 1\)，检查正深度、参考点重新投影、物体尺寸和可见方向是否与图像相符。

第三层：抓取可用性。把约定的 Object → Grasp 变换带到相机坐标系下，检查 Grasp Frame 是否落在约定位置、朝向是否正确。

从物体姿态恢复预先约定的抓取姿态\[{}^{C}T_G={}^CT_O\;{}^OT_G\]

如果关键点集中在物体的一端，那么微小角度误差对距离很远的夹持位置可能造成明显偏移。对于抓取任务，最终更值得评价的是 Pose 误差怎样传播到约定的 Grasp Pose。

05 / 把两种直接求解分清楚

它们求的都是 R、t，

06 / 回头看

少量对应点，
真正带来了什么能力？

一路看下来，已经不需要再把已知参考理解成“一个完整模型必须和整份点云匹配”。当几个参考位置与现场观测之间拥有可靠的一一对应关系时，位姿估计就能变成清楚的数学约束问题。

PnP 通过相机投影，从三维参考与二维像素恢复 Pose；Kabsch 借助两组三维点的相对结构，通过中心化与 SVD 恢复刚体变换。它们不是相互替代的先进版本，而是在不同观测条件下利用不同的几何证据。

沿途也逐渐认识了真正重要的代价：对应关系可能错、点的分布可能退化、相机观测可能有系统偏差；即使残差很小，Pose 也可能不是唯一或正确的解释。

明确对应的最大价值，是把 Pose 求解变成一个可以直接建模、计算和验证的问题；它最大的依赖，是这些对应点必须足够可靠，而且真的约束住了任务所需要的自由度。

于是下一条路线的问题就自然出现了：如果我拥有完整参考模型，却完全不知道参考中的哪个位置对应当前观测，该怎么办？
