00 / 从三维转向二维

前面尝试从三维点云中寻找形状关系，但这条路有一个前提：现场必须能测到足够可靠的三维表面。

如果物体反光、透明，或深度缺失严重，点云可能已经无法支撑几何匹配。但 RGB 图像中，物体的轮廓、边缘和外观依然清晰。

既然已经拥有 CAD 或参考视图，能不能换个方向思考：不再要求观测重建出完整的三维形状，而是预测模型在某个 Pose 下应该呈现什么图像，再与真实观测比较？

这样，问题就从三维形状之间的对齐，转向了参考投影与二维观测之间的匹配。

这条路线的共同思想
候选 Pose · T把已知参考放到某个姿态
→
预测图像 Î(T)轮廓 / 边缘 / 外观
→
与真实图像 I 比较检验并修正姿态
研究边界

如果已经知道可靠的 3D–2D 同名关键点，可以直接回到 Route 01 的 PnP。这里研究的是：没有稳定的离散同名点时，怎样利用整体图像证据寻找或优化 Object Pose。

01 / VIEW TEMPLATE MATCHING

先把可能看到的样子存下来

最直接的办法，或许根本不需要实时求解复杂的投影关系。

既然已经知道物体的 CAD 和相机参数，就可以提前把物体放在许多已知姿态下，生成对应的参考图像。例如，让一个盒子绕竖直轴逐渐旋转，每隔一定角度保存一张参考视图，同时记录它当时的 Object Pose。

真实图像到来后，找到最相似的参考视图，就可以得到一个姿态假设。

参考视图k ↔ Tk

连续位姿问题，暂时变成了有限模板之间的检索问题。

但很快会发现：即使姿态相同，真实图像与渲染图像也未必有相同的像素颜色。光照、反射、曝光、背景，都可能让直接比较 RGB 像素失效。

能不能不比较颜色，而比较图像中的结构？

LINEMOD｜用方向特征代替像素颜色

LINEMOD 是这条路线中很有代表性的方法。它不是计算整张图像的颜色差异，而是从已知视图中提取具有辨识度的局部方向特征，再检查这些特征在现场图像里能否得到支持。

第一步：提取图像梯度方向

对一条明显的物体边缘，像素亮度变化的方向，往往比该处的绝对亮度更稳定。图像梯度描述的就是亮度变化最快的方向。

gx = ∂I/∂x，　gy = ∂I/∂y，　θ = atan2(gy, gx)

工程上可以用 Sobel 等算子近似计算横向与纵向梯度，再把它们组合成角度。LINEMOD 进一步对梯度方向做离散化，以便快速匹配。

第二步：保存少量关键特征

不必保留模板中的每一个像素，而是在梯度明显且空间分布合理的位置选择若干特征，保存相对位置及梯度方向。

Mk = { (xj, yj, θj) }j=1…m

Mk：第 k 个已知姿态模板。

(xj, yj)：特征相对模板原点的像素位置。

θj：该处的梯度方向。

第三步：寻找方向一致的位置

把模板移动到现场图像中的某个候选位置。如果大部分模板特征都能在对应位置附近找到方向相近的梯度，就给该位置较高的匹配分数。

S(Mk, I) = (1/m) ∑j=1…m s(θj, θ′j)

这个公式只是匹配思想的简化表达。实际 LINEMOD 还包含方向量化、邻域容忍、高效响应图计算等设计，而不是直接逐像素遍历。

经典 RGB-D LINEMOD 还能结合深度法线方向：RGB 梯度反映图像边缘结构，法线则提供表面朝向证据。深度严重缺失时可以探索仅用颜色梯度的实现，但也会失去法线带来的区分能力。

匹配到了模板，就能得到准确 Pose 吗？

还不能。假设模板每隔 10° 保存一次，真实物体却旋转了 24°。匹配结果可能靠近 20° 或 30°，但模板库中根本没有精确的 24°。

而且二维图像位置与模板姿态之间的关系，必须结合参考视图的相机参数、深度或尺度约定，才能转换成有意义的 6DoF Pose。

因此，模板匹配更适合用于离散姿态发现和粗略初始化。若要更精确，就需要更密的姿态覆盖，或在匹配之后继续优化。

收获

不依赖稳定同名点，也不一定需要完整深度；利用预先准备的已知姿态模板，发现大致 Pose。

代价

模板密度、尺度与视角覆盖、遮挡、外观变化及错误匹配，决定搜索成本与结果可靠性。

02 / CONTOUR · EDGE · REGION ALIGNMENT

模板不可能覆盖所有姿态

模板方法已经说明，二维图像能够检验一个姿态假设。但物体在三维空间里连续运动，而模板只能存下有限个视图。

如果已经有一个接近真实姿态的初值，为什么还要继续在离散模板中寻找？

能不能直接改变 Pose，让模型投影逐渐与当前图像对齐？

先从轮廓入手

假设已经有初始位姿 T0。使用 CAD 和相机内参，把模型投影到当前图像里，得到一条预测轮廓；同时从真实图像中获得目标轮廓。

如果预测轮廓偏左、倾斜，或者显得过小，都说明当前 Pose 与真实观测之间存在某种不一致。于是可以调整旋转和平移，让预测轮廓靠近真实轮廓。

Distance Transform｜怎样把轮廓差异变成可优化的误差？

一种直接的想法是计算每个预测轮廓点，到真实轮廓的最近距离。Distance Transform（距离变换）可以提前计算一张距离场：图像每个像素存储它距离目标轮廓有多远。

这样，对于给定 Pose 下的预测轮廓点，只要查询距离场，就能得到一个匹配误差。

Econtour(T) = ∑q ∈ C(T) Dobs(q)2

C(T)：Pose 为 T 时，模型投影得到的轮廓点集合。

Dobs(q)：预测轮廓点 q 到实际轮廓的距离。

通过 Gauss–Newton、LM 等方法改变 Pose，寻找更小的轮廓误差。这个式子只是简化的单向距离残差；实际方法可能使用双向距离、轮廓对应、鲁棒核和遮挡处理，以免模型错误地贴合背景边缘。

FIG 02 · 待补插图
真实轮廓（鼠尾草绿）与投影轮廓（陶土橘）起初不重合；旁边显示真实轮廓距离场；更新 Pose 后两条轮廓逐渐对齐。

边缘不可靠时，再看区域

现场图像中不只有物体边缘：桌面纹理、阴影和背景图案也可能产生强梯度。单纯根据边缘对齐，容易把模型轮廓吸引到错误位置。

因此，另一个思路是利用投影轮廓内部与外部的图像统计差异，而不只是检验边界上的几个像素。

在候选 Pose 下，模型投影内部应该更像物体前景，外部则应该更像背景。Region-based 方法可以建立前景与背景的颜色或特征分布，并依据当前投影与这些分布的一致性更新 Pose。

PWP3D、SRT3D 是值得继续深入的代表。以 SRT3D 为例，它沿模型投影轮廓的稀疏线段建立前景和背景的概率关系，并使用这些关系优化刚体位姿，而不需要依赖丰富的物体纹理。

为什么还需要好初值？

无论轮廓距离还是区域一致性，误差关于 6DoF Pose 的关系通常都有局部极小值。如果初始姿态已经把盒子正面误认为侧面，局部优化未必能自己跳到真正的姿态。

更深一层的限制来自可观测性。例如一个理想圆柱绕自身对称轴旋转，投影轮廓并不会改变。此时轮廓对得再准确，也无法从轮廓唯一确定这个旋转自由度。

这不是优化器不够好，而是观测根本没有提供区分不同姿态的证据。

收获

无需穷举所有姿态模板，可以直接根据模型投影和二维结构的差异，连续修正 Pose。

代价

通常依赖合理初值；遮挡、背景边缘、局部最优与物体对称性，都会限制最终结果。

03 / RENDER-AND-COMPARE

轮廓对齐了，姿态就一定对吗？

轮廓是一种有用的几何约束，但也主动舍弃了很多图像信息。

想象两个外形相同的盒子，各个面的颜色和图案不同。它们在某些姿态下拥有几乎相同的轮廓，但内部纹理可能完全不同。

既然可以根据 CAD 和 Pose 预测物体轮廓，为什么不进一步预测整张图像？

这就引出了 Render-and-Compare，也常被归入 Analysis-by-Synthesis 思想：先假设三维姿态，生成对应的预测观测，再用真实图像检验它。

Î(T) = Render(M, K, T)
T* = arg minT D(Î(T), I)

M：模型，可能包含 CAD、材质与纹理；K：相机内参。

Î(T)：候选姿态下的预测图像；I：实际观测图像。

D：所选的图像差异，决定系统到底相信什么证据。

真正困难的问题，开始从「能不能渲染」转向「到底比较什么」。

直接比较颜色｜Photometric Alignment

最直观的做法是逐像素比较真实图像与渲染图像：

Ephoto(T) = ∑p ∈ Ω ‖ I(p) − Î(T,p) ‖²

如果物体纹理、模型材质、照明与成像条件足够一致，光度误差能使用比轮廓丰富得多的图像信息。

但 Pose 正确，不代表渲染颜色一定正确。实际光照、阴影、反光、曝光及材质建模误差，都可能让正确姿态产生较大的像素残差。对于透明和镜面目标，这个代价尤为明显。

所以，光度匹配并不单纯在检验 Pose，也同时在检验外观模型是否准确。

比较结构或特征｜Feature-based Comparison

如果绝对颜色不稳定，可以改为比较边缘、局部纹理描述，或神经网络提取的特征。这些表示试图保留对姿态敏感的信息，同时弱化一部分光照或外观变化。

但特征并不会天然消除所有歧义：外观重复、训练域差异和严重遮挡依然可能让错误姿态获得较高分数。

连 Pose 的修正方向也可以学习｜DeepIM

再往前一步：如果已经有一张真实图像和当前姿态的渲染图像，能不能直接预测二者之间需要怎样调整旋转和平移？

DeepIM 便是很有代表性的例子。网络接收真实图像和当前 Pose 对应的渲染图像，预测姿态修正；将修正后的 Pose 再渲染，重复这一过程。

学习式迭代修正
当前 Pose Tk渲染预测图像
→
真实图 + 渲染图网络预测 ΔTk
→
更新 Pose再次渲染、继续修正

它不是从零自动发现任意物体 Pose 的保证，而是一类需要初值、依赖训练数据与外观泛化能力的姿态精化方法。

一个容易混淆的边界

Render-and-Compare 不是某一个具体算法。 前面讲的轮廓对齐，也可以被看作广义的渲染—比较方法。这里分开讨论，是为了突出：轮廓/区域方法主要选择几何与统计证据，完整外观匹配则进一步利用颜色、纹理或学习特征。

收获

利用比轮廓更丰富的外观信息，在一些形状相似但纹理不同的情况下进一步区分 Pose。

代价

依赖材质、光照、参考外观或训练特征；渲染、搜索和局部优化也可能增加计算成本。

04 / 回头看

二维证据，究竟解决了什么？

走过这一圈，这些技术并不是沿着一条简单的「越来越先进」的道路发展。它们是在回答不同的问题：姿态从哪里来？用哪些图像证据验证？获得初值以后怎样继续修正？

思路核心机制换来的能力不能忽略的代价
视图模板
LINEMOD		匹配已知 Pose 的离散模板无明确初值时提出候选姿态模板覆盖、尺度、遮挡、误匹配
轮廓 / 边缘
Contour / Edge		优化预测与观测边界间的距离不依赖丰富纹理，连续修正局部最优、背景边缘、对称
区域统计
Region-based		用前景 / 背景统计检验投影不必逐点匹配纹理前背景混淆、颜色变化
外观渲染
Render-and-Compare		比较渲染与真实颜色 / 特征利用轮廓以外的信息外观模型、光照、计算成本
学习式修正
DeepIM		学习预测 Pose 增量学习复杂的图像对应关系训练数据、泛化、初始化

注：上表不是严格互斥的算法分类。模板属于姿态发现机制，轮廓/区域/外观属于观测残差类型，DeepIM 则属于学习式位姿更新机制；它们可以组合。

三个不能省略的判断

01 · 二维匹配不意味着不需要三维参考

如果目标是具有确定尺度的 6DoF Object Pose，通常仍需要 CAD、已知姿态和尺度的参考视图，或其他充分的空间先验。仅凭「两张图片很像」，并不能自动推出三维旋转和平移。

02 · 投影相符，不意味着 Pose 唯一

平面、对称物体、规则无纹理几何及弱透视场景，都可能产生多个相近的二维投影。必须区分：是算法没有找到正确解，还是当前图像本身就无法区分这些解。

03 · 姿态发现与姿态精化可以结合

模板检索可以负责初值，轮廓或渲染比较负责局部修正。如果已经有可靠的初值，就不必每次重新全局搜索；如果完全没有初值，也不能简单指望局部优化自动找对姿态。

一种可能的组合，而非必经流水线
模板检索发现候选 Pose
→
轮廓 / 外观检验区分候选
→
连续优化进一步修正 Pose

从三维几何匹配转向二维投影匹配，真正改变的不是求解目标，而是我们选择相信哪一种观测证据。

深度可靠时，可以依赖三维表面；深度不可靠但轮廓清晰时，可以利用二维几何；外观具有辨识度时，还可以利用纹理、颜色或学习特征。

这些路线没有简单的优劣顺序。可靠的同名点无须被复杂模板搜索取代，可靠的三维测量也不必为了使用二维算法而舍弃。

技术没有错，只有它所依赖的前提，以及为了获得某种能力必须承担的代价。

最终要确认的，仍然是：在当前参考与观测条件下，是否真的获得了足以确定所需 Object Pose 的约束？
