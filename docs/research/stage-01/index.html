STAGE 01 · 关于抓取 Pose 的一点笔记

抓法定好了，
Pose 怎么算？

最开始，想把抓取这件事变得简单一点。
先不考虑机器人该怎么决定抓法。对于一些熟悉的物体，坐标系可以自己约定，抓手相对物体的放法也能提前确定。
这样一来，似乎只需要知道物体现在在哪里、朝向哪里，就能把预先想好的抓取姿态放到真实空间中。
问题一下子有了着手的地方。
那就先从 Pose 怎么算开始吧。

关于抓取 Pose 的一点笔记单次抓取 · RGB-D · 两指夹爪
01

最初的想法

最先想到的，还是物体本身的形状。

瓶子有中心和轴线，盒子有边和表面。既然这些都能作为空间参考，那从相机看到的数据里找到它们，是不是就能得到想要的 Pose？

起初并没有考虑太多，只是觉得这件事应该可以从测量入手。

后来整理着整理着，才发现自己最初的设想里，藏着不少没有说清楚的前提。

02

原来只画了右半边

刚开始画技术路线时，注意力几乎都放在了怎么求 Pose 上。

至于目标点云从哪里来，似乎被很自然地略过去了。

真实相机当然不会把目标点云单独递过来。重新把现场观测考虑进去，原来的路线图便多出了另一半。

再往下整理，又发现视觉和 Pose 求解也并非只能按照一条固定流程连接。

现在回头看，这张图倒更像一份改过几次的草稿。

从最初只想着计算 Pose，到补上视觉观测，再到认识不同的求解方式，整个问题才慢慢展开。

下面就沿着这些想法，把遇到的技术和留下的认识记下来。

03

沿着这些问题，慢慢往下走

最开始只是想算出一个抓取 Pose，没想到顺着这个问题，慢慢发现了不少不同的技术。

这里就按自己理解问题的顺序，记下沿途遇到的几种思路。

01
第一段 · 从 Pose 开始

先从形状和已知信息入手

物体的形状、已知尺寸与结构，提供了最先想到的空间线索。

想法 01从形状开始

能不能直接从形状里量出 Pose？

既然瓶子有轴线、盒子有平面，最直接的办法就是从点云里测量这些几何特征。

沿途整理的技术

沿着这个方向，整理了 PCA、OBB、RANSAC、法线与形状拟合 等方法。

PCA 可以用来寻找点云的主要方向，OBB 能描述物体的空间范围，而 RANSAC 则适合从带有噪声的数据里寻找平面等符合模型的结构。

这些方法并不复杂，却能从离散的点云中提取出不少有用的空间信息。

逐渐明确的一点是：测量出物体的某些几何特征，并不意味着完整的 6DoF Pose 就确定了。 具体需要多少个自由度，还得回到预先约定的抓法。

深入笔记Q01 · 点云几何测量 ↗
想法 02利用已知信息

如果物体本来就是已知的呢？

前面一直在想怎样从点云里测量形状。但对于已知尺寸、结构甚至完整模型的物体，似乎还有不少现成的信息可以利用。

于是开始整理已知参考下的位姿求解方法。

沿途整理的技术

这里遇到了几条不同的技术思路：

ICP / GICP 利用三维点云之间的配准关系；PPF 利用点对的几何特征寻找已知物体的位姿；而 PnP 则通过已知的 3D 点和图像中的 2D 对应点求解位姿。

它们不是同一种方法的简单变体，所依赖的参考信息、对应关系和初始化条件都不太一样。

这样看来，物体有多少已知信息、现场又能观察到什么，本身就会影响 Pose 的求解方式。

第二段 · 回到真实相机

回到相机看到的场景

从图像中找到目标，再把像素信息与实际空间联系起来。

想法 03找到目标

目标数据从哪里来？

前面花了不少心思研究如何计算 Pose，却一直默认目标点云已经准备好了。

直到把真实相机放回问题里，才发现还得先处理一件很实际的事：从整个场景中找到需要抓取的物体。

于是又回到了熟悉的二维视觉。

沿途整理的技术

Detection 可以给出目标的大致范围，Instance Segmentation 能进一步得到物体区域，Grounding 则可以根据语言描述寻找指定目标。

这一部分本身就有不少成熟的技术路线。

整理下来也发现，目标定位并不一定非要得到精确的 Mask。不同的 Pose 求解方法，对前面的观测信息有不同要求。

深入笔记Q03 · 从图像里找到目标 ↗
想法 04回到三维

二维找到了，怎么回到三维？

图像里已经找到了目标，但像素坐标终究还不是机器人能直接使用的空间位置。

沿途整理的技术

这时再把 RGB、Depth 和相机内参放在一起，之前学过的投影与反投影就派上了用场。

有了对齐的深度，一个像素便可以恢复成相机坐标系下的三维点；如果把目标区域里的有效深度都利用起来，还能进一步得到目标点云。

到这里，最开始设想的那条路线终于接上了。

从相机观察场景，到确定目标、获取三维信息，再到计算抓取所需的 Pose，已经形成了一条比较清楚的求解思路。

当然，深度孔洞、测量噪声和对齐误差仍然需要认真处理。不过至少现在知道，这些原本分散的知识是怎样联系起来的。

第三段 · 再换个角度

再试试其他求解思路

学习空间特征，以及是否必须先求完整的 Object Pose。

想法 05学习空间特征

空间特征，能不能让模型自己学？

前面的路线已经能够处理不少形状规整、参考信息明确的物体。

但继续考虑那些形态变化比较大的目标时，手工规定中心、轴线、表面等几何特征，未必总能得到稳定的空间参考。

沿着这个问题，开始了解学习式的位姿估计方法。

沿途整理的技术

原来除了让模型识别物体，还可以学习 关键点、特征对应关系、类别级空间参考（NOCS），甚至直接估计 Object Pose。

这里逐渐形成了一个认识：

学习式方法不一定是直接替代几何求解，也可以只负责提供更有用的空间线索。

不同方法让网络学习的内容不同，对参考模型、训练数据和物体形变的依赖也不一样。

这部分的技术分支值得再单独梳理。

深入笔记Q05 · 学习式空间线索 ↗
想法 06直接求抓取 Pose

是不是不一定要先求 Object Pose？

研究到这里，又回到了最开始的问题。

这次的目的其实很明确：在抓法已经约定好的前提下，得到夹爪应该执行的 Grasp Pose。

对于已知刚体，先估计 Object Pose，再变换得到 Grasp Pose，是一条很自然的路线。

但如果并不需要完整的物体姿态，是否可以直接根据局部观测来确定抓手的位置和方向？

沿途整理的技术

沿着这个方向，又认识了局部几何抓取、GG-CNN 这类 2.5D 抓取预测方法，以及直接生成 6DoF Grasp Pose 的数据驱动方法。

它们不一定需要先恢复一个完整的 Object Pose。

当然，直接预测抓取姿态并不意味着让模型随意决定怎么抓。在当前阶段，抓取区域、接近方向和夹爪约束依然需要满足。

整理到这里，才更清楚地意识到：

求 Object Pose 再换算抓取姿态，与直接求 Grasp Pose，是两条可以独立考虑的路线。

04

写到这里

回头看，最开始只是想算出一个抓取 Pose，后来却沿着这个问题认识了不少不同的技术。

有些方法从形状出发，有些利用已知参考，也有些把空间信息交给模型学习。

它们并不是简单的新旧替代关系。很多时候，还是要看手里有什么信息、物体是什么样子，以及究竟需要求出什么。

这篇先把这些思路记下来。更具体的原理、技术历史和适用场景，就留在各自的笔记里慢慢整理。
