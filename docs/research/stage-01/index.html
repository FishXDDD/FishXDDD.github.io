STAGE 01 · FIELD NOTES / 2026.10

抓法定好了，
Pose 怎么算？

这次先给抓取加一点限制：单次操作、两指平行夹爪，抓取策略已经约定好。我要解决的，是怎样把这份约定落实成真实空间里的 Grasp Pose。

前面已经在研究地图上说过这个阶段要做什么。到了这里，先把现在整理出的结论摆出来；至于我是怎样一步步想明白的，就从最初的几何直觉慢慢说起。

单步抓取RGB-D / 相机观测固定抓取策略研究总结与沿途笔记
01　WHAT I LEARNED · 先给结论

现在，我会这样理解这个问题

原来以为只是找到物体位置、算个方向。整理完这些方法后，反而觉得有三件事应该先说清楚。

01

求 Grasp Pose，
不一定先求完整 Object Pose。

有时物体参考坐标系很有用；有时局部几何或抓取候选已经提供了足够的约束。最终需要的是符合约定抓法的夹爪姿态。

02

观测、先验和求解，
值得分开想清楚。

相机看到了什么、我们事先知道什么、怎样计算位姿，是三个不同的问题。它们可以由不同模块解决，也可能被同一个模型联合处理。

03

方法不是简单的升级替代，
而是不同条件下的选择。

几何、匹配与配准、学习式空间线索、直接抓取预测，各自依赖不同的信息与假设。首先要判断约束是否成立，而不是比较哪个名字更新。

如果只能记住一句话：先问自己手里有什么观测、什么先验，以及抓取究竟需要哪些自由度，再决定怎么求 Pose。

02　TECHNICAL MAP · 研究成果

研究完以后，技术路线应该怎样划分？

我不再把 Q01–Q06 当成六种并列算法。它们记录的是认识问题的顺序；真正的技术体系，要先把可用信息和求解组织方式区分开。

STAGE 01 / 已约定抓取策略 → 求解 Grasp Pose研究后的分类 · 不是执行流水线
OBSERVATION · 观测

真实场景给了我什么？

RGB、Depth、点云、目标区域、关键点、2D–3D 对应等。不同算法需要的输入并不相同。

PRIOR · 先验与约束

我事先知道什么？

形状与尺寸、几何假设、实例模型或参考、类别先验，以及已经约定好的抓取方式与夹爪条件。

在可用观测与先验下，选择合适的求解机制 ↓
ROUTE A · OBJECT / REFERENCE-CENTRIC

借助物体参考，间接得到抓手 Pose

  • 几何参考：中心、轴线、表面、局部坐标约束
  • 已知参考：PnP、ICP、PPF 等匹配与位姿求解
  • 学习式线索：关键点、对应关系、NOCS、Object Pose 估计
  • 输出：用物体参考与预定抓取关系推导抓手位姿
ROUTE B · GRASP-CENTRIC

直接面向夹爪，构造或预测 Pose

  • 局部几何：表面、接触对、接近方向、夹爪开度
  • 2.5D 抓取：图像平面内抓取候选及深度恢复
  • 6DoF 抓取：从观测生成空间抓取候选
  • 输出：在固定策略和夹爪约束内获得 Grasp Pose
两种组织方式可以互补，而非互斥 ↓
一个或多个候选 Grasp Pose 再交由后续规划与执行环节检验碰撞和可执行性
注：A 中的几何参考不一定能唯一恢复完整 6DoF Object Pose；B 中的“直接求抓取”也不意味着可以跳过既定抓法的约束。某些算法会同时使用几何求解和学习式空间线索。
关于 Q01–Q06Q03/Q04 主要回答观测怎样获得与表达；Q01/Q02/Q05/Q06 则从不同角度探索如何提供约束、估计位姿或直接构造抓取。它们不应被强行连成六步执行流程。
REWIND THE NOTES · 回到最开始

可我一开始，并不是这样想的。

上面是整理后的地图。下面才是沿途的草稿：从一个朴素的想法出发，碰到新的约束，遇见新的方法，偶尔也会发现自己漏掉了半个问题。

Q01 / THE FIRST GUESS · 先从形状开始

物体的形状，能不能直接量出 Pose？

瓶子有中心和轴线，盒子有平面与边。既然相机能得到三维点云，那最直观的想法就是：从这些几何信息里构造抓取姿态。

于是接触到 PCA、OBB、平面与圆柱拟合、法线估计等方法。它们分别擅长描述分布、方向、表面或形状；不是同一工具的不同名字。

但真正让我重新思考的，是“量到了几何特征”不等于“完整 Pose 已经确定”。例如圆柱的轴线可以很明确，但绕轴转多少未必有唯一答案。更重要的是，一次侧向夹取是否真的需要唯一确定这个角度？

这一步留下的认识

先定义这次抓取真正需要的空间约束，再讨论怎样从点云里测量它们。

继续翻笔记 · Q01 点云几何测量 ↗中心 / 轴线 / 表面 / 接触
Q02 / MORE INFORMATION · 试着借助参考

如果物体本来就有已知信息呢？

只从观测点云量几何，能利用的信息毕竟有限。可有些目标早就知道尺寸、结构，甚至有 CAD 或参考模型。既然如此，为什么不让这些信息也参与求解？

于是开始区分几类方法：ICP/GICP 利用三维几何配准；PPF 利用模型与场景的点对特征寻找位姿；PnP 则要求已知三维点与图像二维点之间的对应关系。它们利用参考的方式、所需观测和初始条件并不一样。

这让我意识到：“已知参考”不是一种算法，而是我们愿意引入多少先验约束。 参考更多，不代表任何场景都能稳定求出唯一姿态；遮挡、误匹配、对称性仍然存在。

这一步留下的认识

不要先选 PnP 或 ICP；先问自己到底知道什么参考，又建立了怎样的对应关系。

继续翻笔记 · Q02 已知参考与位姿求解 ↗PnP / ICP / PPF
A CHANGE OF VIEW · 一次回头
等等，目标点云是谁给我的？

前面一直在研究怎样从几何或已知参考求 Pose。可一旦把真实相机重新放回桌面，才发现自己默认了一个太顺手的前提：目标观测似乎已经被整理好了。

真实场景不会主动交出干净的目标点云；有时甚至不需要点云，而需要的是图像中的目标、关键点或其他线索。看来该回过头，把观测的来路补上。

Q03 / FIND THE TARGET · 回到二维视觉

先别急着算 Pose，目标在哪里？

相机看到的是整个场景，而不只是那个准备抓取的物体。于是开始整理检测、实例分割、Grounding 等定位方式：有的告诉我大致位置，有的提供更精细的区域，有的能根据语义描述锁定目标。

这时反而不必追求所有场景都输出同一种东西。只需要 BBox 的方法，不一定要为它额外准备完美 Mask；依赖对应点的方法，也未必需要先裁出完整点云。

这一步留下的认识

目标定位是在提供可用观测，而不是规定所有 Pose 算法必须执行的第一个模块。

继续翻笔记 · Q03 从图像里找到目标 ↗BBox / Mask / Keypoints / Grounding
Q04 / PIXEL TO SPACE · 补上空间联系

图像里找到了，怎样回到三维？

二维图像定位很好用，但一个像素位置不能直接告诉夹爪该去哪里。若有对齐且有效的深度，再结合相机内参，就能把像素反投影成相机坐标系下的三维点；目标区域的有效深度还可以形成局部点云。

不过，一个三维点提供的是位置，不是完整的 6DoF Pose。 要确定接近方向、抓手旋转或接触区域，仍需要额外的表面、几何、对应关系或其他约束。

这一步留下的认识

观测链终于接上了；但 2D→3D 是建立空间信息的办法，不等于已经解完抓手姿态。

继续翻笔记 · Q04 从 2D 走向 3D ↗K / Depth / Back-projection
Q05 / ANOTHER KIND OF CLUE · 不只手写特征

空间线索，能不能让模型来学？

用几何中心、轴线、表面构造 Pose 的路线慢慢清楚了。但面对复杂形状、遮挡和形变，如果每次都要提前定义稳定的几何特征，规则会不会越来越难维护？

于是开始看学习式空间线索：模型可以预测关键点、二维与三维对应、类别级规范坐标，也可以直接估计物体位姿。它们改变的首先可能是“信息从哪里来”，而不一定是把后面的几何求解完全替代掉。

当然，学习也有自己的前提：训练数据覆盖了什么分布、对形变和遮挡是否鲁棒、预测置信度是否可信，都需要重新验证。

这一步留下的认识

几何与学习不是必须二选一。学习能给出新的空间线索，而几何仍然可以约束、解释和检验结果。

继续翻笔记 · Q05 学习式空间线索 ↗Keypoints / Correspondence / NOCS
Q06 / BACK TO THE QUESTION · 回到终点

我只想摆好夹爪，真的必须先求 Object Pose 吗？

沿着 Object Pose 求解研究了一圈，再回到一开始的目标，发现想要的输出其实是夹爪应该到达的位置与朝向。对于刚体和已知抓手相对位姿，先恢复 Object Pose 再变换过去很直接。

但当完整物体位姿不可观测、没有实例模型，或任务只关心局部抓取约束时，也可以直接构造或预测 Grasp Pose。局部几何、2.5D 抓取、6DoF 抓取生成都是值得研究的方向。

需要再次提醒自己：这里的“直接预测”不等于让系统自由决定抓法。Stage 01 仍然要求候选满足提前约定的抓取策略与夹爪约束。

这一步留下的认识

把 Object Pose 当作常见中间表示，而不是所有抓取任务都必须经过的终点前一站。

04　AFTER THE JOURNEY · 放回真实问题

如果现在重新拿到一个目标，我会先问什么？

前面是怎样认识技术的。真正开始做项目时，我不会先从论文名字挑起，而是先检查观测、先验和任务约束。下面是当前比较愿意采用的判断顺序，还不是一份经过大规模实验验证的性能排名。

手里有什么条件优先考虑的思路还要警惕什么
已知物体尺寸或参考模型
考虑已知参考的位姿求解，如 PnP、ICP、PPF；如能建立可靠 Object Pose，可转换到预设抓手位姿。
对应关系、初始化、对称性
没有实例 CAD，但几何形态稳定
从中心、轴线、平面、局部接触区域等几何约束直接构造候选 Grasp Pose。
遮挡、采样偏差、自由度不足
图像能定位目标，深度有效
利用 BBox、Mask 或关键点寻找所需观测；必要时反投影到三维，再与求解方法结合。
深度空洞、内参与对齐误差
形状变化大，手工参考难稳定
考虑学习式关键点、空间对应关系，或在既定抓法约束内生成抓取候选。
训练分布、泛化、置信度
存在多种可能姿态
保留多个候选 Pose，让碰撞检测与运动规划进行后续筛选，而非执着于唯一输出。
夹爪碰撞、接触可行性

这里并不声称某条路线绝对更好。Stage 01 先建立问题与方法的对应关系；精度、鲁棒性、延时、部署成本还需要靠具体实验验证。

AN INSIGHT WORTH KEEPING

技术路线图，与研究经历图，是两张不同的图。

前者按照信息和求解机制组织，是现在的认识；后者按照问题出现的顺序组织，是这些认识的来路。学习时先后遇到的技术，未必需要按那个顺序执行。

STILL OPEN

还有一些问题，没有因为知道算法名字就消失。

不完整观测、深度缺失、姿态歧义、物体形变、接触与碰撞，都可能让“算出一个 Pose”与“真的抓起来”之间出现距离。

NEXT QUESTION · STAGE 02

如果连“怎么抓”，也不能提前约定呢？

Stage 01 里，抓取策略是一项已知约束；因此可以集中精力研究 Pose 怎么求。可面对更陌生、更多变的物体，抓取区域、方向和方式本身也可能需要判断。这是下一阶段想继续追问的问题。
