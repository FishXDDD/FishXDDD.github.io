Statistical Geometry从点的分布中
寻找几何线索

没有 CAD，也不预先假定物体形状。先看看仅凭一份单视角点云，可以怎样得到中心、主方向和空间范围；再弄明白，它们为什么有时候恰好有用，有时候却会稳定地算错。

Centroid / MedianCovariance / PCARobust EstimationAABB / OBB

拿到点云，最简单的路线是不去猜测它是什么物体，而是先统计这些点本身：它们集中在哪里、沿什么方向展开、占据什么范围。

这条路线看起来只有 Mean、PCA、OBB 几个名字，真正有意思的地方却在于：“中心”有不同定义，“方向”可能退化，“范围”也取决于优化目标。如果不分清这些问题，代码得到一个结果，并不意味着已经获得了物体的真实几何。

01

从一个中心开始，究竟在求什么？

中心估计值得认真学一次，因为它不是一个只有 mean() 的问题。不同方法背后，对“什么算中心”的定义本来就不同。

代码约定：以下所有简短片段都使用 P 表示形状为 (N,3) 的 NumPy 数组，坐标单位统一为米，且已经去除 NaN / Inf。它们是可复制的最小算法实现，不是机器人生产环境的整套流程。代码中的 np 默认来自 import numpy as np。

1.1 最直接的 Mean，其实有明确的优化意义

对点云 P = {p₁, …, pₙ} 的 XYZ 分别取平均，就能得到 Mean Centroid（观测点集均值中心）。这不是一个随手规定的位置：它恰好让所有点到这个中心的平方距离之和最小。

μ = (1/N) ∑ᵢ pᵢ  =  arg minc ∑ᵢ ‖pᵢ − c‖²
Mean：最小平方距离
import numpy as np
center_mean = P.mean(axis=0)  # [cx, cy, cz]

输出：一个 3D 位置。它可以不在任何实际测量点上。

所以 Mean 的代价也很容易理解：远处的点会因为平方惩罚产生更大的影响。如果点云混入几处深度飞点，结果可能被它们拉走；但数据干净且分布合理时，它简单、高效，也是非常好的基线。

一个可以拖动的小实验 · 一维也能看清问题

九个点聚在 0 附近，拖动右侧异常点的位置，看看均值与中位数如何移动。仅作为直观演示，并不代表所有三维点云的分布。

1.2 中心不止一种：先弄清楚它们在优化什么

如果目标是对离群点更稳定、或者必须从真实观测点中选一个代表位置，就会出现不同的中心定义。它们不是 Mean 的简单升级版，而是优化目标发生了变化。

A · Coordinate-wise Median 逐坐标中位数

分别求 X、Y、Z 的中位数；等价于最小化逐坐标的绝对偏差之和。对少量极端异常值更稳健，而且容易实现。

代价：依赖所选坐标轴，点云旋转后重新估计，结果不必等于原结果的同步旋转。

逐坐标把点排序，取每一维的中位数；最小化的是各维度的绝对偏差总和。
cⱼ = median(p₁ⱼ, …, pₙⱼ)
逐坐标中位数
center_xyz_median = np.median(P, axis=0)

注意：不是“在三维中寻找离大家最近的点”；XYZ 分开求会受坐标系旋转影响。

B · Geometric Median 几何中位数 · Weiszfeld

把最小化逐坐标距离，改成最小化三维欧氏距离之和。它具有旋转不变性；代表性的求解机制是 Weiszfeld 迭代，反复根据各点到当前估计的距离调整权重。

c* = arg minc ∑ᵢ ‖pᵢ − c‖

代价：需要迭代；靠近样本点时需要处理数值细节。仍然只代表观测点分布。

从均值附近开始迭代：离当前估计越近的样本，下一次平均时权重越大。标准 Weiszfeld 法对应欧氏距离和最小化。
wᵢ = 1 / ‖pᵢ − c‖，cₙₑₓₜ = ∑wᵢpᵢ / ∑wᵢ
几何中位数：Weiszfeld 简化版
def geometric_median(P, eps=1e-9, max_iter=200):
    c = np.median(P, axis=0).astype(float)
    for _ in range(max_iter):
        dist = np.linalg.norm(P - c, axis=1)
        w = 1.0 / np.maximum(dist, eps)
        nxt = (P * w[:, None]).sum(axis=0) / w.sum()
        if np.linalg.norm(nxt - c) < 1e-8:
            break
        c = nxt
    return c

center_geo = geometric_median(P)

细节：eps 仅用于数值保护；当最优解恰好落在样本上时，严格 Weiszfeld 需额外处理，该代码是实用近似。

C · Medoid 样本代表点

寻找使“到其他观测点的距离和”最小的某个原始点。如果输出必须对应真实测得的位置，它和允许落在点云外的均值、几何中位数有本质区别。

代价：直接计算两两距离通常为 O(N²) 量级；可以先下采样或近似搜索。

把每个已有点轮流当作候选中心，计算它到全部点的欧氏距离和；选得分最小的原始点及其索引。
j* = arg minⱼ ∑ᵢ ‖pⱼ − pᵢ‖，输出 pⱼ* ∈ P
Medoid：精确求样本代表点
from scipy.spatial.distance import cdist

def medoid_exact(P, block=128):
    best_idx, best_score = -1, float('inf')
    for start in range(0, len(P), block):
        # 只计算本批候选到全部点的距离
        score = cdist(P[start:start+block], P).sum(axis=1)
        j = int(np.argmin(score))
        if score[j] < best_score:
            best_score = float(score[j])
            best_idx = start + j
    return best_idx, P[best_idx]

idx, center_medoid = medoid_exact(P)

输出：索引 idx 和原点 P[idx]。时间约 O(N²)；批计算将距离矩阵内存降为 O(block × N)。

Medoid：大点云近似候选
rng = np.random.default_rng(42)
candidates = rng.choice(len(P), min(256, len(P)),
                        replace=False)
score = cdist(P[candidates], P).sum(axis=1)
idx = candidates[np.argmin(score)]
center_medoid_approx = P[idx]

思路：只让最多 256 个样本参与“竞选”，但得分仍对全部样本求和；约 O(MN)，不保证找到精确 Medoid。

D · Bounding-Box Center 包围范围中点

取各坐标最小值、最大值的中点。它主要反映点云的空间范围，而不是内部点出现的频次。

代价：极值对飞点敏感；它也不是物体的体积质心。

直接取坐标极值的中点；它回答的是当前坐标系中“点集占据范围的中间在哪里”，不是密集区域在哪里。
c = (min(P,axis=0) + max(P,axis=0)) / 2
AABB 范围中心
low, high = P.min(axis=0), P.max(axis=0)
center_box = (low + high) / 2
extent_xyz = high - low

输出：中心 + XYZ 范围尺寸；一个远离群点就可能改变极值。

E · Trimmed Mean / M-estimator 截尾均值与稳健损失

另一条思路是仍然保留“平均”或“损失最小化”的形式，但先剔除按规则判定的极端观测，或改用 Huber 等对大残差增长较慢的损失。适合在误差模型比较明确时改善估计。

代价：截尾比例、残差尺度等需要选择；多簇点云或真正的少数结构可能被误判。三维截尾应先明确距离与筛选基准，不能随意每轴剪裁。

截尾：先选一个稳健参考中心，再剔除离它最远的一小部分样本；Huber：近距离使用平方误差，远距离改用近似线性惩罚。
ρδ(r) = r²/2 (r≤δ)；δ(r−δ/2) (r>δ)
Trimmed Mean：按三维距离筛选
seed = np.median(P, axis=0)
d = np.linalg.norm(P - seed, axis=1)
keep = d <= np.quantile(d, 0.9)  # 留下 90%
center_trim = P[keep].mean(axis=0)

代价：90% 是示例，不是标准值；真实细部/离群簇可能被误判。

Huber 中心：IRLS 简化版
def huber_center(P, delta=0.02, loops=30):
    c = np.median(P, axis=0).astype(float)
    for _ in range(loops):
        r = np.linalg.norm(P - c, axis=1)
        w = np.minimum(1.0, delta / np.maximum(r, 1e-12))
        c = np.average(P, axis=0, weights=w)
    return c

center_huber = huber_center(P)  # delta 单位：米

数学思路：Huber 损失的 IRLS 权重 w=min(1,δ/r)；delta 需与噪声尺度匹配。

一个能分清三种中心的小例子：对同一直线上的位置 [0, 0.1, 0.2, 0.3, 8.0]（单位 m），Mean 会被远处的 8.0 拉偏；几何中位数接近 0.2；Medoid 也会从真实已有样本中选到 0.2。对于非对称三维点集，几何中位数可能落在两点之间，而 Medoid 始终是输入点之一。
不要混淆：Medoid 并不保证是最靠近均值的样本，正确目标是“到所有样本距离和最小”。
中心定义到底优化什么比较适合的情况值得警惕的代价
Mean平方距离和最小干净、采样合理的点集远离群点影响大
Coordinate Median逐轴绝对距离和最小简易稳健基线随坐标轴定义变化
Geometric Median欧氏距离和最小希望保留旋转一致性的稳健位置迭代、数值处理
Medoid从观测点中找距离和最小者需要真实样本代表点大点集计算成本
Box Center坐标极值中点描述观测空间范围极端值、遮挡
Trimmed / Huber减弱大残差影响离群点分布有依据时阈值及筛选偏差
到这里应该形成的判断
“中心”本身并不唯一。Mean 不是错误方法，Median 也不是处处更优；首先要定义想要的是哪一种中心，再谈求解算法。

1.3 算法换得再稳，为什么位置还是可能偏？

这时需要把三种完全不同的误差分开：离群点、采样密度不均、可见性缺失。它们会造成相似的中心偏移，却不能依靠同一种方法消除。

Noise离群点 / 飞点

少量不属于主体表面的错误测量。可以考虑稳健位置统计、SOR、ROR 等，但有可能误删真实细部。

Sampling采样密度偏差

点更多的区域，在普通均值与协方差中权重更大。体素降采样或合理加权可缓解，但不能保证严格表面积均匀。

Visibility单视角遮挡

背面根本没有测量。无论统计估计多鲁棒，都不能仅靠这份点云补全不存在的信息。

离群点：SOR 与 ROR 在做什么？

SOR（Statistical Outlier Removal）使用邻居距离的统计规律，删除局部邻域距离明显异常的点；ROR（Radius Outlier Removal）则看指定半径内是否拥有足够多的邻居。它们是点云清理机制，不是“求中心的新算法”。

Open3D：SOR 与 ROR
import open3d as o3d
pcd = o3d.geometry.PointCloud()
pcd.points = o3d.utility.Vector3dVector(P)

sor, _ = pcd.remove_statistical_outlier(
    nb_neighbors=20, std_ratio=2.0)
ror, _ = pcd.remove_radius_outlier(
    nb_points=8, radius=0.01)  # 半径 1 cm

SOR：相邻点平均距离的异常程度；ROR：半径内邻居数量。两者是不同筛选策略，这里分别处理原始 pcd。

对于单个孤立飞点可能有效；如果错误深度连成了密集片区，也可能无法识别。反过来，真实的细杆、尖角或稀疏边缘也可能被错删。

采样密度：为什么 Voxel 不只是为了提速？

深度相机给出的是有像素拓扑的采样，表面在不同距离、角度下可能对应不同数量的点。原始 Mean 统计的是这些测量样本的均值，不是严格的连续表面积中心。

Open3D：体素降采样
import open3d as o3d
pcd = o3d.geometry.PointCloud()
pcd.points = o3d.utility.Vector3dVector(P)
vox = pcd.voxel_down_sample(voxel_size=0.005)
P_vox = np.asarray(vox.points)
center_after_voxel = P_vox.mean(axis=0)

机制：按 5 mm 体素分组，非空体素给一个代表点；近似减弱密集区域权重，但不可用来补全背面。

Voxel Downsampling按空间体素划分点，每个非空体素保留一个代表点，可以减少高密区域的重复权重，同时降低后续统计成本。但体素太大又会吃掉薄结构、改变边界；体素代表点也未必具有完全相同的真实表面积权重。

遮挡：最值得保留的一次认知区分

同一圆柱截面：完整几何中心 ≠ 前半圈可见表面的均值中心

因此需要准确区分：观测点均值中心、可见表面面积中心、物体表面面积中心、物体体积质心、形状模型中心。除非有明确前提，它们并不能互相替代。

这里不是再找一种更强的统计方法
如果真正需要的是圆柱轴心，那么问题已经从“估计观测点的中心”变成“推断符合圆柱几何的轴心”。这是之后几何模型拟合的研究目标，不能靠把 Mean 换成 Median 来完成。
02

中心之外，怎样找到点云的主方向？

对于细长瓶身、条状零件或倾斜的盒体，只知道一个点的位置远远不够。接下来需要一种方法，描述整组点沿哪些方向分散、分散到什么程度。

2.1 从方差与协方差，走到 PCA

沿着某一个单位方向 v 投影点云，得到一组标量。假设所有点已经减去均值，那么这个方向上的投影方差可以写成 vᵀCv。

C = (1/N) ∑ᵢ (pᵢ − μ)(pᵢ − μ)ᵀ

其中 C 是 3×3 协方差矩阵。现在要寻找一条方向，使投影方差最大，同时要求这个方向长度为 1：

v₁ = arg max‖v‖ = 1 vᵀCv

这个约束优化问题的解，就是协方差矩阵最大特征值对应的特征向量。再选取与第一条方向正交的第二主方向，最后得到三个正交方向：

Cvⱼ = λⱼvⱼ ，  λ₁ ≥ λ₂ ≥ λ₃ ≥ 0

这便是 PCA（Principal Component Analysis）的几何意义：找出点集投影变化最大的正交方向。所以它并不是一个专门用来“求物体朝向”的黑盒，而是在回答一个清楚的统计问题。

PCA 与 SVD 的关系
可以不显式构造协方差，而直接对去中心化后的 N×3 点坐标矩阵做 SVD。其右奇异向量对应主轴，奇异值平方与协方差特征值成比例。对已经中心化的同一份数据，两条实现途径指向同一套主方向；工程中注意归一化约定与数值稳定性即可。
核心实现：先中心化，再算 3×3 协方差；对实对称矩阵使用 eigh，将特征值降序排列。PCA 实质上不是在识别物体，而是在对观测分布选主轴。
NumPy：Covariance → PCA
mu = P.mean(axis=0)
X = P - mu
C = X.T @ X / len(P)        # 3×3 协方差
lam, V = np.linalg.eigh(C)  # 特征值默认升序
idx = np.argsort(lam)[::-1]
lam = lam[idx]
R = V[:, idx]               # 三列：主轴向量
if np.linalg.det(R) < 0:
    R[:, -1] *= -1          # 保持右手系
main_axis = R[:, 0]

输出：lam 三个特征值、R 三条正交主轴；正负符号仍未解决。

NumPy：SVD 也能获得主轴
_, singular, Vt = np.linalg.svd(X, full_matrices=False)
R_svd = Vt.T
lam_svd = singular**2 / len(P)

理解：去中心点矩阵的右奇异向量就是主方向（允许符号差异）；对应特征值等于奇异值平方除以 N。

2.2 PCA 不只有一条轴，还告诉我点的分布像什么

三个特征值反映点在三个主方向上的分散程度。如果它们大小差异明显，便能分辨一些典型的分布形态。

LINEAR近似线状

λ₁ ≫ λ₂、λ₃
第一主轴通常更有辨识度。

PLANAR近似面状

λ₁ ≈ λ₂ ≫ λ₃
平面内朝向可不稳定，法线轴却可能稳定。

ISOTROPIC近似各向同性

λ₁ ≈ λ₂ ≈ λ₃
没有显著唯一的统计主方向。

由此可以得到几个常见的特征值描述量，用于粗略刻画点集的线性、平面性和三维分散性：

Linearity = (λ₁ − λ₂) / λ₁
Planarity = (λ₂ − λ₃) / λ₁
Scattering = λ₃ / λ₁

这些量在 λ₁ > 0 时才有定义。它们属于统计形态描述符，不是物体类别识别器：一个瓶子的局部可见表面和完整瓶子会表现出不同特征值结构。

计算 Linearity / Planarity / Scattering
if lam[0] > 1e-12:
    linearity = (lam[0] - lam[1]) / lam[0]
    planarity = (lam[1] - lam[2]) / lam[0]
    scattering = lam[2] / lam[0]
else:
    linearity = planarity = scattering = float('nan')

用途：比较形态与退化迹象；并不能直接判断物体属于哪种形状。

2.3 “PCA 算出了方向”，为什么仍然可能没法定义朝向？

这里至少存在三种不同情况，必须分别判断。

A · 结构轴与统计轴不一致 Systematic Bias

PCA 寻找投影方差最大方向，求得的是当前被采样点集的轴。瓶身一侧缺失、盒体只见一个角，或者形状本来不规则时，统计主轴都可能与真实结构轴偏离。算法即便完全正确，目标也可能选错。

B · 特征值接近 Degeneracy

当对应两个方向的特征值很接近时，微小噪声就可能使这两个特征向量明显旋转。但要看关心的是哪一条轴：一个平面点集的两个面内主方向可能不稳定，垂直平面的法线轴却可以很稳定。

检查方法：观察对应特征值间隔，并通过重复采样、加噪和帧间比较实际检验方向稳定性；不应只给出一个没有上下文的固定比值阈值。

C · 方向正负无法由 PCA 决定 Sign Ambiguity

v 和 −v 的投影方差完全相同。PCA 输出的是无向轴，无法仅凭它判断“瓶口朝上还是朝下”。即使拼出三根互相正交的轴，也还需要规定方向符号并保证右手系（det(R) = +1）。

补充约束：可以来自重力、桌面、视点、已知任务规则等，但这些都不是 PCA 本身得到的新信息。

同样叫“朝向”，可能是完全不同的三种要求

无向轴误差：忽略 v 与 −v
a = R[:, 0] / np.linalg.norm(R[:, 0])
b = np.asarray([0.0, 0.0, 1.0])  # 参考轴
cosine = np.clip(abs(a @ b), 0.0, 1.0)
axis_error_deg = np.degrees(np.arccos(cosine))

注意：只适合比较无向轴；如果应用要求瓶口朝上，不能取绝对值。

判断稳定性，不是只看最大特征值，而是看目标方向对应的特征值与相邻特征值之间有没有明显间隔。
例如主轴关注 (λ₁−λ₂)，法线轴关注 (λ₂−λ₃)

2.4 离群点也会带偏 PCA，值得学习哪些鲁棒做法？

普通 PCA 使用的协方差包含坐标偏差的乘积项，所以距离主体很远的少量点，可能显著改变主轴。改进并不一定意味着换掉特征值分解；很多时候，是要改进协方差从哪里来。

A · 清理后普通 PCA Baseline First

使用目标分离、有效深度过滤、适度 Voxel、SOR / ROR 等减少异常观测，再进行普通 PCA。优先级高、可解释性好。

代价：点云过滤过度可能删除有效边缘；清理无法修复单侧遮挡。

B · Weighted PCA 加权统计

根据可解释的测量可信度或采样密度补偿，为不同点赋予权重。加权均值、加权协方差的基本形式是：

μw = (∑ᵢ wᵢpᵢ)/(∑ᵢ wᵢ)
Cw = (∑ᵢ wᵢ(pᵢ−μw)(pᵢ−μw)ᵀ)/(∑ᵢ wᵢ)

代价：权重设计要有依据；一个随意的权重策略可能比等权统计偏差更大。

Weighted PCA：改变协方差权重
# 例：w 可以来自可靠的深度置信度
w = np.ones(len(P), dtype=float)
w = w / w.sum()
mu_w = np.sum(P * w[:, None], axis=0)
Xw = P - mu_w
Cw = (Xw * w[:, None]).T @ Xw
lam_w, Rw = np.linalg.eigh(Cw)
order = np.argsort(lam_w)[::-1]
lam_w, Rw = lam_w[order], Rw[:, order]

为什么有效：低置信度点的协方差贡献变小；这里的全 1 权重只是演示接口，实际必须有可信度来源。

C · Robust Covariance / MCD 鲁棒协方差

Minimum Covariance Determinant（MCD）通过寻找合适的样本子集来估计稳健的位置与协方差，再从鲁棒协方差提取主轴。这是独立于普通 PCA 的一类重要鲁棒统计思想。

代价：计算更贵，通常更适合单峰、近似椭圆/对称的分布。面对多片曲面、复杂非凸点云时，不应该默认它更正确。

MCD：用稳健协方差求主轴
from sklearn.covariance import MinCovDet
mcd = MinCovDet(random_state=0).fit(P)
lam_mcd, R_mcd = np.linalg.eigh(mcd.covariance_)
order = np.argsort(lam_mcd)[::-1]
lam_mcd, R_mcd = lam_mcd[order], R_mcd[:, order]
center_mcd = mcd.location_

前提：通常适合单峰、近似对称/椭圆分布；点云可能含有多个结构面，不能把它当成万能鲁棒 PCA。

如果污染来自“可见半个瓶身”而不是离群点，这些方法可能都改变不了偏差来源。鲁棒性与几何真实性必须分开评价。

如果只想比较两条无向主轴
先把两个向量单位化，再使用 θ = arccos(|v₁·v₂|)。绝对值使 v 与 −v 被视作同一条轴。不要把这个误差直接当成完整 6D 抓取姿态误差。
03

有了主轴，怎样描述点云占据的空间？

方差大，不意味着一定知道物体长多少。需要把统计方向转换成具体的边界和尺寸，这便引出了 AABB、PCA-OBB 与最小体积 OBB。

3.1 AABB：固定坐标轴下的边界

Axis-Aligned Bounding Box 分别沿 X、Y、Z 求最小值和最大值，构造与当前坐标系对齐的包围盒。它简单，适合做空间裁剪、粗碰撞检测、固定世界系范围描述。

但是同一个物体发生旋转后，AABB 的尺寸可能变化很大：它描述的是坐标系中的占据，不一定是物体自身的尺寸。

AABB：极值与中心
xyz_min = P.min(axis=0)
xyz_max = P.max(axis=0)
aabb_center = (xyz_min + xyz_max) / 2
aabb_extent = xyz_max - xyz_min

输出：XYZ 边界与轴对齐尺寸；旋转同一物体，尺寸可能变化。

3.2 PCA-OBB：把主方向变成尺寸描述

既然 PCA 已经给出了三根正交主轴，就把点投影到这些方向上，然后分别求投影范围。

sᵢⱼ = vⱼᵀ(pᵢ − μ)  ,  Lⱼ = maxᵢ(sᵢⱼ) − minᵢ(sᵢⱼ)

这样可以得到三条方向轴、三个方向的长度，以及投影极值中点对应的盒中心。注意：包围盒中心通常并不等于最开始的 Mean Centroid。

同一组倾斜点：AABB 与 PCA-OBB 描述的不是同一套边界

直接对原始点做 PCA-OBB
mu = P.mean(axis=0)
X = P - mu
lam, V = np.linalg.eigh(X.T @ X / len(P))
R = V[:, np.argsort(lam)[::-1]]
if np.linalg.det(R) < 0:
    R[:, 2] *= -1
Q = X @ R                 # 变换到 PCA 局部轴
lo, hi = Q.min(axis=0), Q.max(axis=0)
obb_extent = hi - lo
obb_center = mu + R @ ((lo + hi) / 2)
# R: 朝向，obb_center: 中心，obb_extent: 尺寸

特别注意：OBB 中心来自各方向投影极值中点，不一定等于 mu。若主方向退化，盒子朝向也可能不稳定。

3.3 Minimum-Volume OBB：为什么还要另一套算法？

PCA-OBB 先优化投影方差来获得主方向，再据此求边界。最小体积 OBB 则直接关注包围盒体积，希望在所有允许的正交方向中找到更小的盒子。

这是两个不同的目标函数。因此一个 PCA 主轴统计意义上非常清晰，也不代表它能产生最小体积；反过来，体积最小的盒子也未必代表物体语义或真实结构轴。

方法轴从哪里来关心什么使用时的判断
AABB固定 XYZ 坐标轴坐标系中的占据范围最快最直接；旋转敏感
PCA-OBB统计主轴沿主要分布方向的尺寸容易解释，但不保证体积最小
Minimum-Volume OBB搜索 / 优化方向尽可能小的包围体积算法成本更高，仍不代表真实物体轴线
Quantile Extent使用已确定方向主体点的稳健范围会主动舍弃部分点，不是严格包围盒
Open3D：两种 OBB 的不同目标
import open3d as o3d
pcd = o3d.geometry.PointCloud()
pcd.points = o3d.utility.Vector3dVector(P)
obb_hull_pca = pcd.get_oriented_bounding_box()
obb_min = pcd.get_minimal_oriented_bounding_box()
print(np.prod(obb_hull_pca.extent), np.prod(obb_min.extent))

API 定义：经典 Open3D 的第一项基于凸包 PCA；第二项寻找较小的包围体积。具体精度、退化处理需看安装版本。

3.4 极值会受飞点影响，分位数范围值得用吗？

OBB 一般根据投影最小值与最大值计算长度，这让单个远离群点就可能拉大整个盒子。对于仅需要主体范围的情况，可以沿已确定的轴取分位数，例如 2%～98% 区间。

分位数范围：只描述主体点
Q = (P - mu) @ R  # 上面 PCA 的局部坐标
lo, hi = np.quantile(Q, [0.02, 0.98], axis=0)
robust_extent = hi - lo
robust_center = mu + R @ ((lo + hi) / 2)

提醒：这是刻意舍弃部分点的“主体范围”，不能直接当成包含所有有效点的严格碰撞边界。

它不再保证包含全部观测点，而是用“舍弃少数极端样本”换取相对稳定的范围估计。若任务要求碰撞边界或严格覆盖有效点云，这种做法就不能被误认为严格包围盒。

一个容易忽视的实现差异
Open3D 经典几何 API 的 get_oriented_bounding_box() 通常采用凸包 PCA 近似构造 OBB，并非对原始全部点直接运行你手算的 PCA；它也不是严格的最小体积求解。Open3D Tensor API 另外提供 PCA、近似最小体积和更精确但较慢的 Jylänki 类方法。PCL 的 MomentOfInertiaEstimation 也明确说明其 OBB 不保证最小体积。比较不同工具前，先核对算法定义与版本。

这套技术怎样真正落地？

最值得自己理解的是统计量的定义、误差来源和退化条件；最近邻搜索、离群点清理、矩阵分解与包围盒构造，则可以充分利用现有库。

4.1 一条可执行的基本处理路线

确定输入点云代表的是什么

确认单位（通常为米）、坐标系、目标 Mask 对齐、深度有效性与是否混入背景。先检查点数与空间尺度。

为统计选取合适的观测集合

根据噪声与采样情况，选择原始点、Voxel 后的点、经过 SOR / ROR 清理的点，或带有可信权重的点；保留选择记录。

计算中心与分布

Mean 为基线；需要时并行比较 Geometric Median。再计算 Covariance、PCA 特征值 / 特征向量及简单分布形态指标。

构造范围表示

根据任务选 AABB、PCA-OBB 或较紧凑的 OBB；如采用分位数范围，应明确标注它不是完整包围。

输出可信度信息，而不只输出结果

记录有效点数量、尺度、特征值间隔、遮挡条件、离群点比例和不同预处理下的变化。对退化方向标注“不可靠”，而不是强行给确定 Pose。

为什么这些小代码分散在对应技术下面？ 因为这里已经是最下一层笔记。看到一种方法，就应该立即看懂优化目标和最小实现，而不是先读完整章，最后才在一段庞大的 Pipeline 里找接口。下面保留一个汇总代码，用于把统计计算连接起来；完整可运行的单文件示例也会一起提供。

4.2 一段足够透明的 NumPy 最小实现

下面的代码故意不封装成一整套框架，只做三件事：Mean / Geometric Median、原始点 PCA、沿 PCA 轴构造 OBB。这样可以直接核对每一个输出到底意味着什么。

geometry_stats.py · 只依赖 NumPy
import numpy as np


def geometric_median(points, tol=1e-8, max_iter=500):
    """Weiszfeld-like numerical estimate; adequate as a learning baseline."""
    P = np.asarray(points, dtype=np.float64)
    y = np.median(P, axis=0)
    for _ in range(max_iter):
        d = np.linalg.norm(P - y, axis=1)
        w = 1.0 / np.maximum(d, tol)
        nxt = np.sum(P * w[:, None], axis=0) / w.sum()
        if np.linalg.norm(nxt - y) < tol:
            return nxt
        y = nxt
    return y


def point_statistics(points):
    P = np.asarray(points, dtype=np.float64)
    if P.ndim != 2 or P.shape[1] != 3:
        raise ValueError("points must be N x 3")
    P = P[np.all(np.isfinite(P), axis=1)]
    if len(P) < 3:
        raise ValueError("need at least 3 finite points")

    mean = P.mean(axis=0)
    X = P - mean
    covariance = (X.T @ X) / len(P)

    # eigh is for a real symmetric matrix.
    eigvals, eigvecs = np.linalg.eigh(covariance)
    order = np.argsort(eigvals)[::-1]
    eigvals = np.maximum(eigvals[order], 0.0)
    R = eigvecs[:, order]

    # Obtain an orthonormal right-handed basis.
    # Axis signs remain ambiguous even after this operation.
    if np.linalg.det(R) < 0:
        R[:, 2] *= -1

    # Project raw points into PCA coordinates.
    Q = X @ R
    low, high = Q.min(axis=0), Q.max(axis=0)
    extent = high - low
    box_center = mean + R @ ((low + high) / 2.0)

    l1, l2, l3 = eigvals
    if l1 > 1e-12:
        features = {
            "linearity": (l1 - l2) / l1,
            "planarity": (l2 - l3) / l1,
            "scattering": l3 / l1,
        }
    else:
        features = None

    return {
        "mean": mean,
        "coordinate_median": np.median(P, axis=0),
        "geometric_median": geometric_median(P),
        "eigenvalues": eigvals,
        "R_pca": R,
        "obb_center": box_center,
        "obb_extent": extent,
        "distribution_features": features,
    }


if __name__ == "__main__":
    rng = np.random.default_rng(7)
    # An elongated 3D cluster. This is only synthetic data.
    cloud = rng.normal(size=(400, 3)) * [0.18, 0.025, 0.018]
    print(point_statistics(cloud))

如果想比较工具接口，请留意：以上代码的 PCA 是直接针对输入点集合计算的；Open3D 的某些 OBB 方法则会先使用凸包。两者在非均匀采样点云上可能产生不同方向，这是算法定义差异，不一定是 bug。

05

四组实验，把算法能力与代价分开

不需要先接入机器人执行。利用已知几何的合成点云，随后再用真实 RGB-D 数据复验，就能把这条统计技术路线的主要问题逐个观察清楚。

A离群点：不同中心与主轴，谁更容易偏？

输入：固定一份干净点云，逐步加入少量远距离异常点。

比较：Mean、Coordinate Median、Geometric Median、普通 PCA，以及清理后 PCA / 合适的鲁棒协方差估计。

记录：中心位移、主轴夹角、耗时、异常点比例；特别观察清理误删主体点的情形。

希望认识：鲁棒方法降低离群点影响，但不会自动提升所有类型的几何精度。

B采样密度：重复采到某块表面，会改变结果吗？

输入：保持底层几何不变，改变局部点密度；可以在同一平面或圆柱表面上的小区域加入更多采样。

比较：原始点、Voxel 后点、合理加权后的中心 / PCA。

记录：中心位移、协方差与主轴变化、保留点数、薄结构损失。

希望认识：观测点统计量会反映采样过程；降采样能减轻部分密度偏差，也会引入自己的分辨率代价。

C遮挡：没有异常值，统计中心也能明显错吗？

输入：由已知半径和轴线的圆柱生成表面点，再只保留单侧不同角度范围的可见点。

比较：观测 Mean、Geometric Median、PCA 主轴、PCA-OBB，与已知真实圆柱轴心和尺寸的差距。

记录：中心到真实轴心的距离、轴夹角、尺寸偏差、可见角度比例。

希望认识：即使全部测量点准确，观测统计量也可能偏离真实物体结构；这是观测范围导致的系统性偏差。

D退化：方向什么时候根本不可靠？

输入：构造细长点集、平面点集、近似球状点集；保持形态并多次改变随机噪声。

比较：各特征值的间隔、主轴扰动角、左右手系修正前后的输出、OBB 方向变化。

记录：主方向稳定性；对无向轴用 θ = arccos(|v₁·v₂|)，对后续完整有向姿态另外选择旋转距离。

希望认识：不是所有分布都具有唯一、稳定的主方向；判断可观测性往往比获得一个数值结果更重要。

实验的判读原则
先以模拟数据区分估计算法本身、噪声分布、采样方式、遮挡条件。再使用真实 D435i 等 RGB-D 数据检查问题是否仍然存在。不要在尚未有数据时为算法编造“成功率”和“提高百分比”。

走完统计几何，最终学到了什么？

本篇现在可以独立完成的事
已经覆盖中心定义（含 Medoid 的精确/近似搜索）、稳健中心、点云清理、PCA 与 SVD、特征值形态分析、加权/鲁棒 PCA、AABB 与两种 OBB，以及分位数范围。所有方法都交代了核心数学想法 + 简短实现 + 选择代价；下一条《几何模型拟合》不再承担补讲这些统计工具的任务。

回头看，Centroid、PCA、OBB 并不是三套相互割裂的技术。它们形成了一条非常连贯的统计求解路线：先定义位置，再描述相对位置的分布，最后利用方向和投影极值获得范围。

学到的能力代表性方法不会被它自动解决的问题
定义与估计中心Mean、Median、Geometric Median、Medoid、稳健损失观测点中心 ≠ 物体真实中心
处理统计偏差Voxel、SOR、ROR、加权估计无法凭空恢复遮挡信息
提取主方向Covariance、PCA、SVD、鲁棒协方差主轴 ≠ 结构轴；无向 ≠ 有向
判断分布形态Eigenvalue Features、特征值间隔不能直接识别物体真实形状
描述空间占据AABB、PCA-OBB、Minimum OBB、分位数范围包围盒 ≠ 真实物体尺寸
统计几何可以非常准确地回答：这份观测点云是怎样分布的？
它却不一定回答得了：这个物体原本是什么形状？

因此，统计几何真正提供的是一组计算便宜、定义明确、容易成为基线的几何线索。它可以帮助定位目标、估计无向主轴、描述粗略空间范围，也可以作为后续求解的初始化。

但在 Stage 01 的边界下，我们最终需要的是一个预先约定抓法的 Grasp Pose 能否被可靠求出。如果任务要求真实圆柱轴线、盒体规则面或隐藏的几何中心，单纯统计点的分布可能没有足够信息。
