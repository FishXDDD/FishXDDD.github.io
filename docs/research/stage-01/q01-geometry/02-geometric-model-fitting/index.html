00 / WHAT IS STUDIED

从点的分布，到几何结构

统计几何已经能从点集分布中得到位置与主方向。现在想继续看看：如果观测点近似满足某一种几何关系，能不能直接估计这条直线、这片平面，或这个圆柱的参数？

这里不依赖实例 CAD、预先测好的瓶身半径或已定义的物体模板坐标系。可以先假设一种通用几何类型，但参数应从当前观测中求出。这与 Q02 的已知参考配准不是同一件事。

01 / TECHNICAL MAP

技术路线｜先决定拟合什么，再决定怎样拟合

几何拟合不是把点云送进一个万能求解器。首先要看是否存在值得解释的结构：近似共线的棱边、近似共面的表面，或带有曲率规律的圆柱形区域。选定模型，才有明确的参数与误差定义。

A｜代表性的几何模型

模型假设想从观测中得到什么典型情况
Line · 直线线上一点、方向向量棱边、杆状局部结构；不自动获得线段端点
Plane · 平面法向、平面偏移盒面、桌面、局部平坦区域；不自动获得面内朝向
Cylinder · 圆柱中心轴线、半径瓶身、管体；不自动获得沿轴原点与绕轴朝向

B｜经典求解机制与现成工具

遇到的困难代表机制成熟实现
支持点已知，但有测量噪声TLS / SVD / 最小二乘NumPy、Eigen
混入了不属于模型的点RANSAC / Sample ConsensusOpen3D segment_plane、PCL SAC
参数与残差之间是非线性关系Nonlinear Least Squares / LM / Trust RegionSciPy least_squares、PCL Cylinder

这些不是互相竞争的三个模型：一个圆柱模型可以先经过内点筛选，再进行非线性求精；一个直线模型也可以直接由 SVD 求解。

02 / EXPLORATION · HOW THE IDEAS CONNECT

深入探索｜从一个几何假设，走到可以验证的模型参数

我真正想搞清楚的不是“直线、平面、圆柱分别有什么 API”，而是：为什么能通过这些模型解释可见点云？模型怎样被求出来？如果结果看着很漂亮，是否就能相信？

2.1

第一次转变：已知一个大致形状，能不能反过来估计它？

FROM DISTRIBUTION TO MODEL ASSUMPTION

面对一只近似圆柱形的瓶子，PCA 可以给出当前可见点集的主轴。但想要的可能是瓶身的几何中心轴。它们有联系，却不必然一致，尤其是相机只看见一部分曲面的时候。

这时我并没有瓶子的 CAD，也不知道准确半径；我只是在观测中发现了一种可能的规则结构。是否可以假设表面上的点到同一条轴线具有近似相等的距离，然后从点云反推这条轴线与半径？

探索的变化

不是再寻找一种“更高级的 PCA”，而是从描述数据分布转向解释数据：什么几何关系能够让这些点同时成立？

模型 M(θ)　→　定义残差 rᵢ(θ)　→　估计参数 θ*
θ* = arg min Σᵢ ρ(rᵢ(θ)²)ρ 可以是平方损失，也可以是鲁棒损失；关键是先定义模型参数与几何残差。

不过，选择模型并非自动完成。如果物体表面没有明显的线状、平面或圆柱规律，就不能仅因为 PCL 支持某个模型而强行拟合。这里的“无参考”指没有实例级已知模型，不等于完全没有几何先验。

2.2

假设是一条直线：为什么不能只用两个点？

ORTHOGONAL REGRESSION · TOTAL LEAST SQUARES

如果目标点云里已经提取出一段近似棱边，理想情况下两个不同的点就能确定直线。但 RGB-D 中两个点的误差足以让这条直线明显晃动。既然有一整组点，应该让它们共同决定方向。

将直线写成 L(t)=c+t·v，其中 c 是线上一点，v 是单位方向。对三维点 p，最自然的误差不是 X 或 Y 坐标差，而是点到直线的垂直距离。

eᵢ = (I − vvᵀ)(pᵢ − c)
min Σᵢ ‖eᵢ‖²　,　‖v‖=1它寻找使所有支持点到直线平方正交距离之和最小的轴线。

这就是正交回归 / Total Least Squares（TLS）的典型形式。解法反而很熟悉：点云去中心化，对坐标矩阵做 SVD，第一右奇异向量就是拟合直线的方向。PCA 和 TLS 可以共享一套计算机制，只是前者强调分布，后者明确地假设一条物理直线。

1901 · 经典研究线索

Karl Pearson · 最接近点、直线与平面的正交拟合

它值得记录，不是因为今天要重现百年前的全部证明，而是因为它明确了“让数据到几何对象的距离最小”这一类估计问题。现代 SVD / Eigen 已经可以高效完成其基础求解。

Python · 正交最小二乘直线拟合（可运行函数）
import numpy as np

def fit_line_tls(points):
    P = np.asarray(points, dtype=np.float64)
    if P.ndim != 2 or P.shape[1] != 3 or len(P) < 3:
        raise ValueError("points 必须是 N×3，N≥3")

    c = P.mean(axis=0)
    X = P - c
    _, s, Vt = np.linalg.svd(X, full_matrices=False)
    v = Vt[0] / np.linalg.norm(Vt[0])

    # 点到无穷直线的正交残差（米）
    e = X - np.outer(X @ v, v)
    dist = np.linalg.norm(e, axis=1)
    return c, v, dist, s
输入 N×3 点；输出线上一点、无向单位轴、逐点距离与奇异值。计算本身不保证输入确实呈线状；应检查 s[0] 相对于 s[1] 的差异。

有了这条线，也还没有获得线段长度。如果需要端点，只能在已识别的支持点上沿 v 投影，利用投影范围估计可见线段。缺失的棱边不会自动恢复。

得到的能力

从一组带噪、已知属于同一线状结构的点中，恢复一条有位置和方向的三维轴线，而不是只获得抽象的统计方向。

留下的代价

必须先有足够可信的线状支持点；如果实际输入是一片面或复杂曲面，直接 TLS 依然会输出轴，但这个轴未必具备想要的几何意义。

2.3

同一套方法，能不能从点里拟合一片平面？

PLANE MODEL · LEAST-SQUARES SVD

盒子的一侧或桌面的可见点云，可能更接近一片平面。若目标是表面法向，继续把它当成线状点集已经没有意义；需要改换模型，而不是一定改换求解器。

单位法向为 n 的平面可以写成 n·p+d=0。让每个点到平面的正交距离尽可能小：

min Σᵢ (nᵀpᵢ + d)²　,　‖n‖=1
c = mean(P)　→　d = −nᵀc
n = Vt[−1]（中心化点集的最小奇异方向）拟合直线取最大方差方向；拟合平面取最小方差方向。同一 SVD，不同的几何约束。
Python · 正交最小二乘平面拟合（可运行函数）
import numpy as np

def fit_plane_tls(points):
    P = np.asarray(points, dtype=np.float64)
    if P.ndim != 2 or P.shape[1] != 3 or len(P) < 3:
        raise ValueError("points 必须是 N×3，N≥3")

    c = P.mean(axis=0)
    X = P - c
    _, s, Vt = np.linalg.svd(X, full_matrices=False)
    n = Vt[-1] / np.linalg.norm(Vt[-1])
    d = -np.dot(n, c)
    distance = np.abs(P @ n + d)
    return n, d, distance, s
输出 (n, d) 使得 n·p+d≈0。n 与 −n 都表示同一平面；如需一致的有向法线，应利用视点或场景方向约定其符号。

这也给了一个不需要额外分类的数学判断：如果点集接近一个平面，最小奇异值通常较小；但若点几乎共线，平面法向就可能没有唯一性。求解器能输出结果，不等于参数可辨识。

对于明确的一片平面，TLS 简单且高效。但单个无限平面只提供法向与偏移：它不定义面内长边、边界、完整物体原点，更不自动等于一个 Object Frame。

得到的能力

从当前观测恢复有空间位置的参考平面和法向，为表面约束或场景参考提供基础。

2.4

有些点根本不属于这个模型，怎么办？

RANSAC · SAMPLE CONSENSUS · INLIER REFINEMENT

刚才的 TLS 有一个前提：输入已经是同一条线或同一片面的有效支持点。但一份 Mask 对齐后的点云，也可能包含无效深度残留、背景边缘、多个相邻面。

如果把它们全部交给最小二乘，模型可以被明显拉偏。这里的核心问题从“参数怎么解”变成了“哪些点值得用于当前模型”。

1981 · 经典里程碑

Fischler & Bolles · RANSAC

对一个给定模型，先用最少样本构造候选，再用残差阈值统计内点支持，反复尝试后保留较好的一致模型。它属于鲁棒估计机制，而不是新的几何模型。

一次平面 RANSAC 为什么需要“采样 → 统计内点 → 求精”？

对平面模型，一个简化流程是：抽三个不共线的点 → 构造候选平面 → 找到距离小于阈值的内点 → 多次比较 → 用内点 TLS 求精。

P(一次采到全部内点) ≈ wˢ
N ≥ log(1−p) / log(1−wˢ)w：内点比例；s：每次构造模型的最小采样数；p：期望至少一次全内点采样的概率。这里假设独立随机采样且内点判定合理。

这个公式的价值不是让人背诵，而是知道：内点比例越低、模型最小样本量越大，往往要付出更多采样次数。RANSAC 的残差阈值应与测量噪声、点云单位、距离及模型偏差一起确定。

Python · Open3D RANSAC 平面 + 内点 TLS 求精
import open3d as o3d
import numpy as np

pcd = o3d.io.read_point_cloud("target.ply")
if len(pcd.points) < 30:
    raise ValueError("点数不足，先检查输入")

# 以米为单位时，0.004 表示 4 mm；仅作示例
model, inlier_ids = pcd.segment_plane(
    distance_threshold=0.004,
    ransac_n=3,
    num_iterations=1000,
)

# 在 RANSAC 内点上重新做正交平面拟合
P = np.asarray(pcd.points)[inlier_ids]
n, d, errors, s = fit_plane_tls(P)
print("plane n,d:", n, d)
print("inlier_ratio:", len(inlier_ids)/len(pcd.points))
print("inlier_median_residual_m:", np.median(errors))

# 额外检查是否为目标需要的平面，而非最大桌面
这里调用前面的 fit_plane_tls。若只想快速提取平面，Open3D 的 segment_plane 本身已经返回模型系数与内点索引；额外 TLS 用于明确执行内点求精与残差检查。
RANSAC 不能替你选择正确的结构

例如桌面比盒体表面更大，支持点最多的平面可能是桌面。模型与抓取任务是否一致，仍然依赖目标筛选、空间位置与已知约束。

也不必把 RANSAC 提升成单独的“鲁棒几何 Level”：它属于这一层模型估计时会反复用到的基础机制；后面的局部法线估计也可能复用它。

2.5

直线与平面容易理解，圆柱为何更麻烦？

CYLINDER MODEL · NONLINEAR LEAST SQUARES

现在可以回到近似圆柱的瓶身。一个无限圆柱的几何结构，用轴线上一点 c、单位轴向 v、半径 R 就能表示。

与前面的直线拟合不同，圆柱表面点一般并不落在轴线上，而是到轴线的垂直距离接近一个共同半径。

d_axis(p) = ‖(I − vvᵀ)(p − c)‖
r(p) = d_axis(p) − R
min Σᵢ ρ(r(pᵢ)²)　,　‖v‖=1，R>0参数中轴线位置、方向和半径相互耦合。单次 SVD 通常不能完成一般三维圆柱拟合。

这里遇到了另一个重要问题：c 可以沿着 v 任意平移，而圆柱几何完全不变。因此它的七个输出系数不代表七个独立自由度。真正的无限圆柱通常只有五个几何自由度：轴方向 2 个、轴的横向位置 2 个、半径 1 个。

如果已知瓶子竖直放置、且现场有可靠的重力或桌面法线，可以先固定轴向，只在垂直于轴的平面中拟合圆。这样会比毫无约束地从三维空间估计整套圆柱参数容易得多。

怎样让复杂残差可以被优化？

这时才需要 Nonlinear Least Squares。Gauss–Newton、Levenberg–Marquardt（LM）和 Trust Region 一类求解方法，依据当前参数与残差函数，迭代寻找使误差减小的参数。

如果只是验证数学想法，不必自己重写优化器。SciPy 的 scipy.optimize.least_squares() 已经支持边界、不同求解方式和鲁棒损失。

Python · 已知轴向的瓶身圆柱拟合（可运行示例）
import numpy as np
from scipy.optimize import least_squares

# P 是目标瓶身点云 N×3，单位米
P = np.asarray(P, dtype=np.float64)
if len(P) < 20:
    raise ValueError("有效点过少")

# 前提：已经由场景约束确认圆柱轴向近似 Z
# 此时只拟合圆截面中心 cx,cy 与半径 R
xy = P[:, :2]

def residual(params):
    cx, cy, radius = params
    return np.linalg.norm(
        xy - np.array([cx, cy]), axis=1
    ) - radius

x0 = [xy[:, 0].mean(), xy[:, 1].mean(), 0.035]
result = least_squares(
    residual, x0=x0,
    bounds=([-np.inf, -np.inf, 0.02],
            [ np.inf,  np.inf, 0.06]),
    loss="soft_l1", f_scale=0.003,
    method="trf",
)

cx, cy, radius = result.x
print("success:", result.success)
print("circle center:", cx, cy)
print("radius:", radius)
print("median |radial residual|:",
      np.median(np.abs(result.fun)))
这里用“轴已知”的先验将问题降维，是用于理解参数残差与优化器的一条明确工程路线；它不是一般倾斜圆柱的完整 3D 拟合。示例的半径区间和 f_scale 不是通用推荐值。

如果轴向未知，就需要把轴线方向和横向位置一起放进优化参数。此时必须合理地初始化方向（例如 PCA 主轴、重力方向、局部几何约束），并处理轴向正负、参数冗余和局部极值问题。

不要从 API 的“收敛成功”推断圆柱已经恢复正确

少量可见圆弧可能由许多不同半径的圆柱近似解释。即使损失很小，半径与轴线也可能高度耦合，导致结果对微小深度扰动很敏感。

2.6

圆柱不一定要自己写优化：PCL 已有成熟工程路径

PCL · SACSEGMENTATIONFROMNORMALS · CYLINDER

对于未知实例但几何上近似圆柱的瓶身，PCL 的 SACSegmentationFromNormals 配合 SACMODEL_CYLINDER 是一条真正值得记录的经典工程实现。

它不仅使用三维点，还会结合表面法线。这很自然：理想圆柱侧面的法线沿径向，理论上垂直于圆柱轴；法线关系能够为轴的候选假设提供额外约束。

在这里我们只关心：为什么法线有帮助，以及 PCL 如何把这些条件放进模型拟合。 邻域 PCA、法线方向一致性、邻域尺度选择等细节，则留到 LEVEL 3 的局部表面专题完整研究。

C++ / PCL · 目标瓶身点云 → 法线 → 圆柱模型
#include <pcl/point_types.h>
#include <pcl/point_cloud.h>
#include <pcl/features/normal_3d.h>
#include <pcl/search/kdtree.h>
#include <pcl/segmentation/sac_segmentation.h>
#include <pcl/ModelCoefficients.h>
#include <pcl/PointIndices.h>
#include <iostream>

using PointT = pcl::PointXYZ;

// 前置条件：cloud 为已提取、过滤后的有限深度瓶身点云
bool fitCylinder(pcl::PointCloud<PointT>::Ptr cloud,
                 pcl::ModelCoefficients::Ptr coefficients,
                 pcl::PointIndices::Ptr inliers) {
    if (!cloud || cloud->size() < 50) return false;

    pcl::search::KdTree<PointT>::Ptr tree(
        new pcl::search::KdTree<PointT>);
    pcl::PointCloud<pcl::Normal>::Ptr normals(
        new pcl::PointCloud<pcl::Normal>);

    pcl::NormalEstimation<PointT, pcl::Normal> ne;
    ne.setInputCloud(cloud);
    ne.setSearchMethod(tree);
    ne.setKSearch(30);             // 示例：应验证邻域尺度
    ne.compute(*normals);

    pcl::SACSegmentationFromNormals<PointT, pcl::Normal> seg;
    seg.setOptimizeCoefficients(true);
    seg.setModelType(pcl::SACMODEL_CYLINDER);
    seg.setMethodType(pcl::SAC_RANSAC);
    seg.setNormalDistanceWeight(0.1);
    seg.setMaxIterations(2000);
    seg.setDistanceThreshold(0.005);
    seg.setRadiusLimits(0.025, 0.055);
    seg.setInputCloud(cloud);
    seg.setInputNormals(normals);
    seg.segment(*inliers, *coefficients);

    return !inliers->indices.empty()
        && coefficients->values.size() == 7;
}
可嵌入现有 PCL/ROS 工程；代码假设输入已经清理 NaN、背景与明显误测点。参数值只是示范，法线邻域、半径范围和阈值都必须结合实际目标重新验证。
输出的 7 个系数几何含义实际使用时的提醒
coeff[0:3]圆柱轴线上一点 c不是瓶底、瓶顶或天然的物体原点
coeff[3:6]圆柱轴向 v正负号不唯一，不能直接决定有向夹爪姿态
coeff[6]圆柱半径 R严重缺失弧面时可能不稳定
成熟工程链路 · PCL

目标分离 → 法线估计 → 圆柱一致性筛选 → 参数求精

PCL 官方的 Cylinder Segmentation 教程展示了这一整条链路，并直接提供 C++ 代码、模型参数及构建方法。对于需要自定义 C++ 工程的使用者，优先阅读其官方示例通常比从零实现 RANSAC 与 LM 更有效。

如果物体是透明玻璃瓶，这条算法链路仍然不能自动修复错误的深度。首先确认点云确实对应瓶身表面，然后再评估是否适合圆柱拟合。

2.7

拟合残差很小，为什么结果仍然可能不能用？

MODEL VALIDITY · OBSERVABILITY · TASK RELEVANCE

了解这些方法后，我反而觉得：最难的部分未必是把优化器跑起来，而是判断它有没有估计到正确的结构。

需要区分的疑问典型现象如何检查
模型选错了吗？变形瓶身被强行当成理想圆柱查看残差空间分布，比较模型与实际曲面趋势
观测足够吗？只有很窄的圆柱弧面，却得到稳定格式的 7 个系数改变采样子集、初值与点云噪声，比较半径和轴线漂移
找对结构了吗？平面分割成功，但选中了桌面而非目标盒面检查区域位置、内点空间覆盖与预定抓取区域
是求解器问题吗？圆柱结果随初值变化明显改变初始化，检查优化收敛与参数耦合
满足抓取需求吗？得到了圆柱轴，却不知道沿轴在哪里夹列出抓法要求的额外位置和方向约束

对于圆柱，残差评价最好同时查看内点比例、残差分布、观测弧度范围、轴线稳定性、半径稳定性。但“看到了圆柱多少弧度”本身也需要借助估计轴线计算，不能只依靠一个总 RMS 指标。

理论上，还可以利用非线性最小二乘的雅可比矩阵检查参数是否存在弱约束方向。如果几组不同的圆柱参数都能解释同一小块曲面，那么优化器可能收敛得很漂亮，估计仍然很不确定。

这次真正新增的认识

残差小 ≠ 模型正确；求解器收敛 ≠ 参数可辨识；参数被估计出来 ≠ 足以定义 Object Pose。

尤其是无限圆柱，它不定义有限物体的轴向端点，也无法通过理想对称侧面分辨绕轴的自转角。即使模型参数准确，物体完整位姿仍可能有自由度未被观测约束。

如果现在动手，我会怎样验证这条路线？

REPRODUCIBLE BASELINES · NOT YET TEST RESULTS

我不准备因为这篇整理了许多经典算法，就把它们全部接进实际抓取流程。更合理的做法是挑选能回答不同问题的对照实验，让每个工具的价值被真正验证。

实验准备的输入比较与记录什么
直线 TLS可控噪声的模拟棱边点，再加入异常点拟合轴与真值夹角、正交残差、异常点敏感性
平面 TLS vs RANSAC单个平面、多个相邻面、混杂背景法向误差、内点比例、阈值敏感性与速度
圆柱已知轴 vs 未知轴完整 / 半圆弧 / 窄弧瓶身点云轴线偏移、半径误差、不同初值下的稳定性

前面的代码都可以作为最小实验入口。对于真实 RGB-D 点云，先记录目标 Mask、相机内参与深度尺度、无效点过滤方式和采样范围，避免把输入条件不同造成的差异误认成算法性能差异。

暂时的工程尝试顺序

稳定 Mask / Grounding → 提取有效目标点云 → 判断能否用简单统计几何解决 → 若结构假设有明确意义，再试对应直线 / 平面 / 圆柱拟合 → 记录参数稳定性 → 按已约定抓法决定是否足够。
这是准备验证的想法，不是已经完成的实验结果。

03 / WHAT REMAINS

现在，几何模型拟合在整条路线中是什么位置？

与统计几何相比，这一层真正增加的不是更复杂的代数工具，而是模型结构本身成为信息来源。当我们有理由相信一组点近似属于某个圆柱或平面时，可以通过这个假设，估计仅凭点集整体分布不容易直接定义的轴线、法向和尺寸。

但它也不自动等于实例级 Object Pose 恢复。直线、平面与无限圆柱各自定义的参考自由度有限。只要预定抓法能够利用这些信息构造出足够明确的抓取约束，就可能不需要完整物体姿态；如果任务需要某个无法从几何中辨认的参考原点或有向角度，便应该诚实地承认信息仍然不足。

这层能做到

从现场点云和通用结构假设中求出有物理意义的几何参数。

这层做不到

凭空提供未知的实例坐标系、不可见的端点或对称自由度。

下一层值得研究

整体模型不适合时，能否只测量抓取局部的表面法线与曲率？

最后留下的一句话：不是所有物体都需要拟合模型；但当一个明确的几何假设能够提供任务真正需要的约束时，模型拟合值得优先考虑。
